# 对十月分析原文的补充与修正登记

状态：`analysis/planned/non-authorizing`

## 1. 新增设计来源

本批新增“世界模型与 AI 工作区”主题，来源包括：

- `docs/上下文不够用/对话4.md` 中关于 World Pack Compiler、分层模拟、World Action Harness、typed blackboard 和多模型协作的讨论；
- `docs/上下文不够用/LAWAM.md` 的隐空间世界动作模型研究笔记；

- WorldPlay2、UnifoLM-WMA、GigaWorld-Policy、Motus、FastWAM、LingBot-VA、LongLive 等公开项目资料。

## 2. 对原设计的补充

1. 在“世界真相、角色心智、表现层”之外，增加一个不拥有真相的 `World Runtime Contract` 工作区，用于承载模型输入输出、版本、时效、预测和 proposal。
2. 将视觉世界模型、隐空间世界模型、世界动作模型和 LLM 分成不同 adapter，不再笼统称作“世界模型”。
3. 增加 `World Pack Compiler` 作为生成 mesh/3DGS/点云、角色资产和场景候选进入 Godot/Unity/UE/Isaac 前的编译和准入层。
4. 增加 `Explicit3DZone`、`NeuralVisualZone`、`NeuralStatefulZone` 三种区域形态和切换协议。
5. 将上下文窗口上限转化为 context slice、空间/时间/因果检索、角色私有视角、摘要和 omission ledger 问题。
6. 将未来机器人兼容限制为共享观察/动作/结果/replay contract，不把机器人硬件控制纳入游戏 runtime owner。

## 3. 需要回写十月原文的表述

- 原文若写“世界模型生成可交互 3D 世界”，应改为“世界模型生成 3D 资产/场景候选；经实体绑定、碰撞、导航、affordance、物理和 authority 准入后才成为可交互世界”。
- 原文若写“世界模型修改 3D 世界”，应改为“世界模型输出 observation/prediction/proposal；authority commit 后由 Godot/环境适配器表现修改”。
- 原文若把 latent embedding 当作世界记忆，应改为“latent 只作预测和检索辅助，客观事实和角色私有记忆仍由既有 owner 管理”。
- 原文若把 HY World 2.0、WorldPlay2、LaWAM 或其他项目写成已接入本项目，应标记为外部 research input，直到达到本目录定义的 E1-E3 证据。

## 4. 当前不回写为实施授权的内容

- HY World 2.0 本地部署、模型权重下载和 CUDA 依赖评估只登记在计划阻断，不自动进入生产。
- 视觉到 GLB、自动碰撞和 NavMesh 生成只属于 planned asset qualification，不改变当前 actor/scene。
- 机器人硬件和神经世界运行时保持 deferred。
