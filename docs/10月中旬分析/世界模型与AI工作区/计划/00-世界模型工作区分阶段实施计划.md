# 世界模型工作区分阶段实施计划

状态：`analysis/planned/non-authorizing`

本计划只引用本目录规格，不授权立即修改代码。执行前必须完成十月中旬总批次的角色心智优先级和现有实现审查；自走棋、通用编辑器 control-plane、AD/Blender 正式动作资格链和机器人硬件路线保持 deferred。

## 1. 实施原则

1. 先合同和证据，再接真实模型。
2. 先复用现有 world truth、event/replay、L1、VLA、角色和 Godot owner，不建第二套运行时。
3. 先做 advisory/preview/denial，再开放 proposal/commit。
4. 先用小区域和单一交互夹具，再扩大到开放世界。
5. 任何模型质量声明必须同时有输入正确性、输出 schema、决策正确性、物理结果和回放证据。
6. 生成资产先 visual-only，再 interactive candidate，最后才是 admitted runtime asset。

## 2. 依赖顺序

```text
P0 现状/外部研究登记
  -> P1 World Runtime Contract
  -> P2 ContextSlice + model adapter gateway
  -> P3 proposal/preview/rollout/zero-write Harness
  -> P4 explicit 3D asset + World Pack qualification
  -> P5 action model + Laya/character integration
  -> P6 local HY/WAM provider readiness and bounded pilot
  -> P7 multi-zone handoff and scale evidence
  -> deferred robot hardware / stateful neural runtime
```

## 3. 阶段计划

### P0：现状与研究基线

**来源：**规格 00、02、05、06；审查 00；P7C；现有 `world_runtime` 和 Harness 文档。

**任务：**

- 固定 HY World 2.0、WorldPlay2、LaWAM、UnifoLM-WMA、GigaWorld-Policy、Motus、FastWAM、LingBot-VA 的来源、版本和证据等级。
- 清点现有 `simulation_clock`、`population_driver`、L1/PQF、VLA provider、action/affordance、ESM、Godot actor、replay、asset qualification owner。
- 建立 current/planned/deferred/forbidden 矩阵，确保不把外部 README 当实现证据。

**验证：**文档 profile、路径/链接检查、现有 `model-provider-readiness` 和 `vla-provider-backend` 只作为基线证据。

**阻断：**来源无法复现、工作树中存在未理解的 owner 改动、当前 `world_revision`/clock 边界不清。

### P1：World Runtime Contract

**规格：**01。

**候选责任文件：**未来 `backend/app/world_runtime/` contract models、context builder、proposal registry；先不落地第二 event store。

**任务：**

1. 定义严格的 `WorldSnapshot`、`ObservationFrame`、`ContextSlice`、`ModelOutput`、`Proposal`、`ExecutionResult`、`LatentSubgoalRecord`。
2. 复用现有 fact projection、capture clock、entity/anchor refs、private view 和 authority revision。
3. 为每个对象提供 `trace_id`、`input_digest`、`base_world_revision`、`expires_at`、`provenance`。
4. 对 stale、目录外 ref、私有字段、缺失 artifact、超时和 provider error fail closed。

**测试：**模型 schema、digest 稳定性、scope/redaction、stale revision、expiry、目录过滤、no writer dependency。

**Harness：**独立 WRC contract profile；输出 JSON/Markdown/NDJSON 和 replay fixture。

**回滚点：**只移除新 contract adapter/registry，保留现有 VLA/L1 路径不变。

### P2：ContextSlice 与 adapter gateway

**规格：**02、03。

**候选责任文件：**`world_runtime` context builder/router；provider adapter 仅通过 protocol；与角色 L1/Laya、VLA advisory 和 model readiness 对接。

**任务：**

- 按 purpose/observer/latency/risk 生成真相视角、角色私有视角、现场视角和 rollout 视角。
- 实现 token/latency budget、空间/时间/因果过滤、omission ledger、context debt 和 latent provenance。
- 接入 disabled/deterministic mock provider，随后才接 HTTP/local provider。
- 保证 Laya 继续通过 L1/ThoughtMode/CapabilityEnvelope/L4；工作区不扩大角色隐私范围。

**测试：**相同输入 digest、privacy boundary、缺失信息 request、模型超时、cache scope、provider routing。

**Harness：**context-slice、model-routing、model-provider-readiness 相关 profile；live provider 单独标记。

**回滚点：**关闭新 gateway，继续使用现有 VLA/角色 gateway；不改变 authority。

### P3：Proposal、Preview、Rollout 与零写入证据

**规格：**01、04、06。

**任务：**

1. 为 advisory、prediction、latent subgoal、action/content/asset candidate 建立统一输出分类。
2. 实现 preview branch 和 headless rollout，不写主世界 event store。
3. 实现 proposal admission：owner、能力、权限、前置条件、物理、冲突、expiry 和 rollback。
4. 为玩家输入、角色动作和模型 proposal 的同对象冲突建立 deterministic policy。

**测试：**zero-write、preview isolation、stale deny、player-wins/physics-wins、late result、requeue、receipt trace、branch replay。

**Harness：**proposal-boundary、rollout-replay、conflict-admission、no-world-write profile。

**回滚点：**禁用 proposal admission，只保留 advisory/preview；现有 action path 不变。

### P4：World Pack Compiler 与资产资格化

**规格：**05。

**任务：**

- 定义 `WorldPack` manifest、entity binding、asset provenance 和 pack revision。
- 首先支持已有 mesh/GLB 和 HY World 2.0 的 `gaussians.ply`/point cloud/depth/normal/camera 等候选；先做 visual-only admission。
- 增加坐标/尺度、LOD、材质、碰撞 proxy、NavMesh、物理 profile、affordance 和 runtime load 检查。
- 角色资产独立处理 skeleton/rig/animation/collision/socket；不因资产注册替换现有 actor identity。
- 对无法生成可靠 collider/nav/affordance 的 3DGS 资产标记 visual-only。

**测试：**pack schema、provenance、coordinate alignment、entity ID stability、collision/nav/rig qualification、load/reload/rollback。

**Harness：**asset-pack-qualification、entity-binding、godot-load-and-physics profile。

**回滚点：**pack 回退到上一 revision；运行时保留旧 scene/asset，不删除已提交事实。

### P5：世界动作模型与角色/Laya 协作

**规格：**02、04、06，以及十月中旬角色 01/03/05 规格。

**任务：**

- 将 action model/LaWAM 输出映射为注册的 action candidate，而不是 raw pose/transform。
- 让 B0-B3/激活角色和 Laya 的当前 typed decision 与 action rollout 共用 snapshot/revision。
- 让 Slow/Deep 只重规划目标/模式/短计划，回到 Laya 选择当前动作。
- 对近场动物/静物行为脚本使用现有 action/affordance/physics owner，不由视觉模型直接驱动。

**测试：**候选覆盖、action admission、Laya typed output、slow/deep 回落、physics evidence、角色私有视角和 memory write owner。

**Harness：**character-agent-execution、world-action-candidate、laya-provider/admission、physical-channel profile。

**回滚点：**动作模型降级为 deterministic action registry/continuity floor；角色智能体和现场物理继续运行。

### P6：真实 provider 与 bounded pilot

**任务：**

1. 单独测量 HY World 2.0、VLA、LaWAM/WAM provider 的显存、启动、吞吐、延迟和许可证/模型来源。
2. 本地有模型时通过独立 adapter；没有本地模型时使用 API adapter；两者都输出同一 WRC schema。
3. 先做离线场景生成/重建和单区域 visual-only pilot，再做单一可交互对象和单一动作 proposal。
4. 对中文角色心智、输入正确性、候选覆盖和决策正确性使用独立留出集；不能用慢模型回退宣称 Laya 质量达标。

**验证：**`model-provider-readiness`、真实 provider live proof、latency/VRAM report、replay digest、asset qualification report。

**阻断：**模型权重/许可证不可用、设备资源不足、真实输出 schema 不稳定、关键决策质量不达标、无法绑定实体或无法回放。

### P7：多区域和未来兼容

**任务：**

- 实现 Explicit3DZone ↔ NeuralVisualZone 的 camera/entity/revision re-anchor 和切回。
- 证明远景视觉生成不会泄露或改写 truth，玩家进入交互范围前可以显式接管。
- 为 headless game sim、未来 robot sim 保持相同 observation/action/result/replay contract。
- 仅在神经环境具备实体、空间、事件、snapshot/restore 和 authority adapter 后，再评估 NeuralStatefulZone。

**验证：**zone handoff、camera continuity、entity binding、re-anchor failure fallback、多模型 latency soak。

**阻断：**视觉漂移、关键实体无法绑定、切换时状态不一致、fallback 不可重建。

## 4. 最小可交付纵切片

第一条可执行纵切片只包含：一个已有 Godot 区域、一个已登记 entity、一个结构化 observation、一个 disabled/deterministic provider、一个 `PredictionProposal`、一个 preview branch、一次 stale denial、一次 owner receipt 和一份 Harness replay。它不要求接入 HY World 2.0，也不要求生成新 GLB。

第二条纵切片才接入 HY World 2.0 的离线输出，先以 visual-only WorldPack candidate 验证 provenance、camera/depth/geometry、scene load 和回退。

第三条纵切片才允许一个注册 action candidate 进入 Godot physics 和 authority commit。

## 5. 统一验收门禁

- 没有 P1 的合同和 P3 的 zero-write/preview 证据，不得接真实 world model。
- 没有 P4 的 entity/asset qualification，不得把生成几何当交互对象。
- 没有 P5 的 action admission 和物理证据，不得让 WAM/LaWAM 驱动角色动作。
- 没有 P6 的真实 provider readiness 和独立决策质量评估，不得宣称本地模型生产可用。
- 没有 P7 的 re-anchor/fallback 证据，不得把视觉生成区和显式交互区称作无缝运行。

## 6. 当前执行状态

本计划当前只完成文档和研究登记，未授权代码实施。实现时每个阶段必须先更新对应审查、测试和 Harness 证据，再进入下一阶段；任一阶段失败都回退到最近的已验证 owner path。
