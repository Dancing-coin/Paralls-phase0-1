## 1. 状态语义

| 状态 | 含义 |
|---|---|
| `[current]` | 当前代码、测试或正式文档可直接证明 |
| `[planned]` | 有设计来源和规格落点，但实现或验收证据未完成 |
| `[blocked]` | 存在明确 owner、接口、数据、provider 或证据缺口 |
| `[deferred]` | 用户已明确暂缓，不进入本批 active gate |
| `[forbidden]` | 本批不得采用的替代架构 |

## 3. 覆盖结论

### 已完成的文档工作 `[current]`

- 继承上下文原文已完整复制，包含原有 Mermaid 架构图、代码引用和案例。
- 新批次已建立独立的 `群体模拟升级/规格`、`计划`、`审查`、`回写` 和 `讨论归档` 结构。
- 每份新架构规格都有架构图、主流程时序图、数据流图，并明确 current/planned/deferred。
- 旧的十月中旬角色、Laya、图谱、B0-B3、司命和时间规格保留在 `既有中旬规格/`，没有被删除或冒充新实现。

### 仍然不能宣称完成 `[blocked]`

1. 全 roster 的生命、位置、关系、承诺、记忆游标和恢复回放。
2. 全体角色派生图节点、关系传播、非玩家焦点和长期社会因果。
3. B0/B1/B2/B3 唯一推进权、交接锁、回退和 receipt。
4. Laya 真实本地服务、质量阈值、独立留出集、角色差异和必要微调触发。
5. Life/Presence/Soul owner、统一时空 envelope、现场回引后台和物理 evidence settlement。

这些项目的详细解除条件见[既有中旬审查/00-实现映射与阻断登记](既有中旬审查/00-实现映射与阻断登记.md)和[总实施顺序与门禁计划](../计划/00-群体模拟升级总实施顺序与门禁计划.md)。

## 4. 审查使用规则

- 新线程继续讨论时，先引用本矩阵的编号，再回到原文段落和对应规格，不以一句总结替代来源。
- 任何改变 owner、时间语义、图谱边界、Laya 定义或范围的方案，必须新增一条回写记录。
- 任何把 `[planned]` 改成 `[current]` 的变更，必须附代码、测试或 Harness 证据；仅有设计图、模型输出或静态文档不够。
