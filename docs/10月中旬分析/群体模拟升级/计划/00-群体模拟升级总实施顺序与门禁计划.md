# 群体模拟升级总实施顺序与门禁计划

状态：`analysis/planned/non-authorizing`

本计划只引用本目录规格，不授权立即实现。目标是先形成角色连续性、世界真相、时间空间和 WRK 的可靠主干，再扩大群体模拟和现场行为。

## 1. 总顺序

```text
P0 来源/原文/代码映射
  → P1 角色档案、生命状态、记忆种子
  → P2 三本账、时间、空间和位置锚点
  → P3 WRK 窗口、调度、交接和回执
  → P4 全体角色群体模拟与社会图谱
  → P5 司命焦点、激活和关闭
  → P6 Laya 心智闭环和质量验证
  → P7 行为脚本、动物/静物和现场物理
  → P8 玩家抢占、案例回放和容量门禁
```

## 2. P0：来源和边界确认

**输入：**讨论归档全文、原文摘录、十月分析、当前代码、既有中旬规格。

**任务：**

- 完成线程要求覆盖矩阵；
- 标记 `[current]/[planned]/[deferred]/[blocked]`；
- 修复迁移后的相对链接；
- 把偏离十月分析的设计写入回写登记；
- 确认自走棋、编辑器、AD/Blender 和世界模型继续 deferred。

**门禁：**没有来源和 owner 映射，不进入运行时改动。

## 3. P1：角色连续性底座

**规格：**既有中旬规格 00、03；本批规格 07、09。

**任务：**

1. 固定 `character_id`、profile/dossier、life state、position anchor、relationship、obligation、behavior seed、memory seed 和 cursor。
2. 定义角色在 B0/B1/B2/B3 之间切换时的稳定 identity 和 revision。
3. 定义 activation handoff、close、pending action、requeue 和恢复。
4. 把 char_d 限定为评估夹具，不加入生产 roster。

**测试/Harness：**角色 seed、continuity receipt、activation lock、close/reopen、privacy/memory owner、replay。

**回滚点：**关闭新交接适配器，继续使用现有角色运行链。

## 4. P2：三本账、时间和空间

**规格：**07、08、09。

**任务：**

- 固定 event_time、known_time、presented_time；
- 明确 world/physics/render/cognition/operational clock mapping；
- 统一 world revision、window、cursor、receipt；
- 建立 truth/body/perception/presentation 四位置；
- 定义区域 fidelity 和玩家接近后的局部升级；
- 不创建第二套 clock/event store/authority。

**测试/Harness：**time mapping、stale/expiry、pause/recovery、position anchor、projection freshness、re-anchor。

**门禁：**时间和空间没有版本/回放证据，不能进入现场脚本。

## 5. P3：世界运行内核 WRK

**规格：**00、06、08。

**任务：**

1. 中央协调统一安排窗口、预算、依赖、队列和交接。
2. Processor 只产生候选，不直接写真相。
3. 领域 Owner 负责校验、结算、receipt 和 revision。
4. 跟踪 backlog、recovery cursor、失败窗口和有限 catch-up。
5. 统一群体模拟和角色智能体同一主动行为的 ownership lock。

**测试/Harness：**window replay、receipt ordering、duplicate prevention、failed window recovery、backlog fairness。

## 6. P4：全体角色群体模拟与图谱

**规格：**既有中旬规格 01、02；本批规格 00、03、05。

**任务：**

- 每个登记角色拥有稳定社会生命节点和可恢复游标；
- B0 推进生命/需求/阶段，B1 推进行为模块和社会影响；
- 图谱记录角色、关系、地点、组织、事件和影响边；
- 图谱只消费已确认来源，不拥有事实；
- 允许随机焦点、关系传播、区域压力和 due 产生非玩家事件；
- 角色私有记忆仍由 Character Core 管理。

**测试/Harness：**roster coverage、seed completeness、non-player focus、impact propagation、graph replay、private-memory isolation。

## 7. P5：司命焦点和激活生命周期

**规格：**既有中旬规格 04；本批规格 05、09、11。

**任务：**

- 司命先处理事件、压力、义务和预算；
- 再选择角色、精度、激活或关闭；
- 激活角色和普通居民共享 identity、truth、资产和记忆；
- 激活只接管同一角色的个人主动行动，不停止外部世界；
- 关闭后回到群体路径，不删除记忆。

**测试/Harness：**activation fairness、handoff lock、close/reopen、pending action、random focus、player focus coexistence。

## 8. P6：Laya 心智闭环

**规格：**既有中旬规格 01；讨论归档 02；审查 03。

**任务：**

- 使用 multilingual 官方 checkpoint 作为第一基线；
- 本地 `laya-serve` 优先，无本地模型时使用 API；
- 固定心智输入、候选集合和题目；
- 使用结构化可接受动作集合评估；
- Slow/Deep 只能重规划，最终回到 Laya typed decision；
- 领域微调由决策质量实测触发；
- 不得用慢模型 fallback 宣称 Laya 质量达标。

**测试/Harness：**input correctness、candidate coverage、decision accuracy、calibration、held-out set、provider readiness、timeout fallback、admission gate。

## 9. P7：行为脚本与现场物理

**规格：**10、11、12。

**任务：**

- 建立原子动作 registry；
- 建立静物模型脚本/状态机 registry；
- 区分动物自我意志、高级意志控制、身体反馈和物理限制；
- 现场行为由脚本组合，模型只提出合法候选；
- 物理证据回到 authority，结果回到三本账；
- 玩家抢占旧后台候选，保持可回放。

**测试/Harness：**horse/bun cage fixture、interrupt/recovery、player collision、object state machine、physics evidence、truth/presentation replay。

## 10. P8：容量和完整案例门禁

**任务：**

- 100/1000 角色短测和长测；
- backlog、内存、写入延迟、模型 timeout、焦点公平；
- 玩家离开三天、回到街区、资源竞争、非玩家事件、马撞包子笼；
- 服务器停止/恢复、投影过期和记忆恢复。

**通过标准：**

1. 不重复结算；
2. 不丢角色记忆；
3. 不让模型或表现直写事实；
4. 不让玩家中心吞没非玩家焦点；
5. 失败可恢复、结果可回放；
6. Godot 有真实运行证据时才宣称现场闭环。

## 11. 明确不执行

- 自走棋/装备/羁绊/奖励玩法包；
- 通用编辑器 control-plane；
- AD/Blender 正式动作资格化；
- 世界模型相关工作区内容。
