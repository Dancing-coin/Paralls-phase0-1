# 派生社会图谱与因果传播实施计划

状态：`analysis/planned/non-authorizing`

**Spec：** [规格 02](../../规格/既有中旬规格/02-全体角色社会生命图谱与记忆边界规格.md)、[规格 04](../../规格/既有中旬规格/04-司命调度自主焦点与世界因果规格.md)。

**Sources：** SGC-2、SGC-4、SGC-5；`authority_graph_projector.py`、`heavenly_graph_queries.py`、`siming_heavenly_graph.py`、角色 09/10/13；[实现审查](../../审查/既有中旬审查/00-实现映射与阻断登记.md)。

## 1. 目标与边界

复用 HeavenlyGraph 和当前 authority graph projection 能力，建立全 roster、受来源约束的 social-life projection，使司命和人口能力可查询受影响角色、关系邻域、地点/组织和待处理义务。

不新建 graph database、不合并 ability graph 与 private memory graph、不引入生产事实写权限、不把 graph hypothesis 提升为已确认事实。

## 2. 预期文件责任

| 文件/模块 | 责任 |

| `backend/app/services/authority_graph_projector.py` | 扩展经过审查的事件映射 allowlist；无 social event 直写承诺 |

## 3. 任务序列

### Task 1：图谱源字段和 allowlist 审计

逐个事件族登记：事件 owner、可投影字段、scope、valid/recorded time、redaction、correction semantics、消费者、来源 revision。优先复用已有 ESM、inventory、organization、economy、social 和 Character Core receipt；社交域当前未被 authority projector 全面映射，需逐项审查而非假定完整。

**产物：** `event family -> node/relation mapping` 清单；拒绝映射的字段和原因；source-of-truth 入口。

### Task 2：稳定角色节点 admission

1. 从 Plan 01 的 roster/identity admission 获取稳定 actor ref 和 profile ref。
2. 节点创建以 authority/Character Core/population committed projection 为来源，采用幂等 key。
3. 未有 profile 或 lifecycle owner 的字段以 unknown/unavailable 表示。
4. retired/dead/tombstone state 只接受对应 owner 事实；不把节点缺失解释为不存在。
5. 每个节点保存 source vector、scope、双时间和 derivation kind。

**门禁：** 不得从显示层 actor instance 反推持久登记身份。

### Task 3：关系边投影与修正

1. 只映射已确认的家庭、组织、雇佣、位置、承诺、参与、影响关系。
2. private trust/suspicion 作为 recipient-specific knowledge，不提升为公共 confirmed edge。
3. candidate/hypothesis edge 与 committed/derived edge 在类型和查询条件上可分。
4. relation correction 追加新 revision，隐私收紧使依赖 cache/checkpoint/summary 失效。
5. 来源 compensation、supersession 和 revoked event 不删除历史 replay 证据。

**验证：** dual-time query、source correction、privacy redaction、checkpoint rebuild、full/tail replay equivalence。

### Task 4：影响邻域与传播查询

1. 定义有界 query：direct event participants、关系 1-hop/授权多跳、区域/组织共同约束、obligation dependents。
2. 查询结果必须附 source refs、depth、scope、revision vector、freshness 和 truncation reason。
3. 稳定排序不依赖字典、数据库或网络返回顺序。
4. 传播候选最多影响 scheduling/fidelity，不写个人结果。
5. graph unavailable 时使用直接 Owner read 或明确 `graph_degraded/context_insufficient`，不猜测覆盖率。

### Task 5：L1 context assembler 边界

1. 图谱返回的是获权引用/摘要候选，不直接把节点全文送入 Laya。
2. L1 做角色视角、空间、visibility、freshness、knowledge availability 和 privacy filter。
3. private memory 只有通过独立 memory scope grant 才可引用。
4. 每次展开写 read receipt；撤权、revision 变化使旧 frame 过期。
5. 最终 MindFrame 带 graph revision 和 source vector。

### Task 6：因果和公平性数据面

建立候选来源摘要：world event、actor due、relationship spread、region pressure、organization duty、player interaction、fairness seed、narrative obligation。实际排序/调度合同由规格 04 和 Plan 03 实施；本计划只提供来源可查询且可解释的图谱数据。

## 5. 性能与规模

先证明每个角色 node 和常用索引的写读上限，再决定分区键。初期按 world/region/scope 做 query bounding；不能提前做无界多跳遍历。记录 nodes/edges 更新率、查询 fanout、深度截断、cache hit/invalidations、p50/p95 query latency 和内存占用。

性能不足时优先物化可重建索引、批量投影和 checkpoint；不能删除来源 vector、scope 或双时间字段。

## 6. 回滚点

- 新 projector mapping 可逐 event family 关闭；authority event 不删。
- graph query consumer 可回退 direct owner read / explicit degraded status。
- graph projection 可从来源事件和 checkpoint 重建；不回滚私有记忆历史。
- fairness/impact edge 只影响调度；关闭后继续处理已有 due queue。

## 7. 阻断

- 缺少 owner event/source mapping 的 edge 不准进入 active query。
- SocialFactAuthority 数据不在图谱中时不得报告“社会关系不存在”。
- private memory 和 public social relation 不能共享同一个未过滤 query。
- 图谱 query 尚无稳定回放证据时不得作为 B0/B1 个人结果依据。
