# 全体角色社会生命与混合心智总实施顺序计划

状态：`analysis/planned/non-authorizing`

## 1. 目标

按 [总规格 00](../../规格/既有中旬规格/00-全体角色社会生命与混合心智总规格.md) 完成一条开放世界纵向能力：每个登记角色保持连续身份和低成本生活推进，社会图谱能找到影响关系，角色激活后由 L1-L4/Laya 快循环接管，owner receipt 和 Character Core 接纳结果后回到人口推进与表现层。

本文件是顺序和门禁，不替代子计划中的任务级文件/接口/测试细节。状态 `non-authorizing` 表示不得据此直接开工，须先完成现有十月中旬文档审查和正式 implementation authorization。

## 2. 固定实施顺序

```mermaid
flowchart LR
    G0[Gate 0: 原文/现状/owner 基线] --> P1[Plan 01: 角色社会生命底座]
    P1 --> G1[Gate 1: roster 全覆盖 + cursor/replay]
    G1 --> P2[Plan 02: 派生社会图谱]
    P2 --> G2[Gate 2: 来源/隐私/回放/查询]
    G2 --> P3[Plan 03: 群体与 Laya 协同]
    P3 --> G3[Gate 3: Laya真实角色快循环 + owner receipt]
    G3 --> P4[Plan 04: 时空表现与局部活化]
    P4 --> G4[Gate 4: Godot真实边界 + 世界因果回写]
    G4 --> SCALE[规模、成本、公平性复测]
```

不得倒序做大规模 3D NPC、群体图谱全覆盖或局部表现规模化。每阶段先用有限样本证明正确性，再扩展数量。

## 3. 工作流门禁

### Gate 0：设计和实现基线

进入 Plan 01 前必须：

- 逐项核对规格与来源文档，具体到章节；
- 逐项确认角色 identity、生命状态、位置、关系、模块、记忆、世界真相的现有 owner；
- 把当前未提交的 `backend/app/character_agent/` 与十月文档变更映射进审查，不得覆盖或假设其已验收；
- 确认主线 owner、API、event type、revision 和 replay 接口；
- 形成变更影响表和需原文回写清单。

证据：静态映射、owner matrix、薄垂直切片方案和现状测试基线。

### Gate 1：全体角色连续性

Plan 01 通过条件：

- roster 内每个角色具有唯一 actor ref、可恢复状态和游标；
- B0 基础推进可批量、确定性、checkpoint/tail replay 等价；
- profile 缺失、生命 owner 不可用、cursor stale 等状态不被猜成 alive/safe；
- B1 只能走受注册模块和获准字段；
- 角色 lifecycle/memory 的 owner 合同有明确 evidence。

### Gate 2：派生社会图谱

Plan 02 通过条件：

- 每个 admitted roster actor 有可重建派生节点；
- 每条边可追到事件/owner、revision、visibility 和有效时间；
- 图谱不写 event store，不绕过 Character Core 私有记忆准入；
- source correction、privacy revoke、cache invalidation 和 replay 有证据；
- 社会事实没有图边时仍能通过 direct owner read 或显式 unknown/degraded 表示。

### Gate 3：群体与 Laya 运行时

Plan 03 通过条件：

- B0/B1 candidate 和 Laya decision 的来源/精度可辨；
- 激活锁保证唯一推进者；
- Laya 通过 L1、ThoughtMode、能力包络、候选编译、L4 和 owner；
- 真实 `/v1/systemone` adapter/admission/cancel/expiry/recovery 证据齐全；
- Laya 基础质量使用结构化可接受集合和独立留出集，Slow/Deep 不替代 Laya 达标；
- B/C 的隔离 Godot 场景证据按十月既定门禁取得，动作底座只使用 `StreetCombatActorDemo` 已验证部分。

### Gate 4：空间与现场回写

Plan 04 通过条件：

- Godot 现场 actor、物理证据、backend world tick 与 Owner receipt 对齐；
- spatial evidence 包含来源、时间映射、revision、scope 和关联 actor/object；
- 局部物理表现不直接改后端持久事实；
- 玩家可见对象、行为脚本和物理对象的范围可审计；
- fresh Godot/runtime evidence 证明现场显示的是已确认结果或可撤销预测。

## 4. 资源与范围

- 第一交付单位：小型可回放社会纵切，而不是千人/全城压力目标。
- 角色心智/Laya 是基础角色闭环的一部分，先于扩大社会模拟复杂度。
- 自走棋单局系统、装备玩法包、回合/羁绊/奖励适配保持关闭延期。
- 通用编辑器 control-plane 和 AD/Blender 正式资格化保持暂停，不作为本计划 blocker；执行相应规格/计划时再处理。
- 不能另建图数据库、NPC 主循环、世界时钟、事件库或 truth owner。

## 5. 规模验证顺序

```text
1 actor / 1 event / deterministic replay
→ small connected neighborhood / multiple owners
→ one populated region / player absent and present
→ multi-region simulation with graph partitioning
→ scale and cost profile on target hardware
```

每一级都要先达到 correctness gate，再做 performance gate。不得以吞吐指标掩盖个人连续性、因果和记忆错误。

## 6. 观测和退出门槛

每轮至少记录：

- registered/admitted/due/deferred/rejected actor counts；
- B0/B1/B2/B3 分布和每级成本；
- Laya 调用、token、首 token/响应延迟、取消、过期、requeue；
- graph node/edge 更新、stale query、privacy rejection、传播深度；
- owner/Character Core receipt 和恢复队列；
- 玩家近场对象数、后台滞后窗口、物理证据等待时间；
- 角色/区域公平性覆盖和 starvation age；
- replay digest、checkpoint+tail equivalence、零写拒绝。

性能超过设备预算时先减小精度/上下文/频率/近场数量，不得删除角色身份、记忆边界、owner 回执或公平性账。

## 7. 总体回滚点

- 所有新增派生图可从权威事件和角色 continuity 重建；回滚只撤下 consumer，不删除 authority history。
- B1 模块通过 registry policy 关闭或回退到 B0；不迁移/抹除已确认角色状态。
- Laya provider/admission 关闭时返回 continuity floor 或 requeue；不改角色模型身份或直接调用不受控 provider。
- Godot near activation 失败时保持已确认后端状态并隐藏未确认呈现；不伪造成功。
