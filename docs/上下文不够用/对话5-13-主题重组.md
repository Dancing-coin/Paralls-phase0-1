### C.4 第一条必须跑通的垂直样板

优先选择“火焰作用于橡木门”或“霜冻作用于农田”作为验收样板：

1. 创建实体档案并挂载类型、材料、物质、性质和状态。
2. 产生结构化意图或环境事件。
3. 查询源、目标和环境语义。
4. 匹配效应、抵抗和元规则。
5. 生成 `StateChangeBatch` 并由 authority 原子提交。
6. 写入实体档案和因果事件。
7. 让角色、经济、司命和 Godot 消费各自投影。
8. 验证成功、失败、回放、断线恢复和重复提交结果一致。

这条样板链没有跑通之前，不进入完整战斗、文明树、元素化学或大规模经济模拟。

### C.5 当前明确不优先做的事项

- 大而全的数据库重构；先稳定实体、事件、标签和结算 schema。
- 默认的元素/分子级化学模拟；只为明确的炼金或化学玩法提供局部模型。
- 司命直接执行正式规则或直接修改世界事实。
- 脱离统一结算链的通用 agent framework。
- 同时铺开完整经济、战斗、生产、政治和生态系统。

本清单的总体依据是：先完成事实、语义、效应、规则和结算底座，再把玩法作为内容包接入；这对应本文的 Phase A—E 建议：[12. 建议的建设优先级](#12-建议的建设优先级)。

## 0. 总体判断

这九份记录实际上围绕同一个问题逐步展开：

> 如何构建一个由程序、角色智能体和司命共同驱动的世界，使世界中的角色、物品、环境、经济和文明都能持续存在、相互作用、留下因果痕迹，并通过统一底座支持不同玩法。

讨论并不是从“经济系统”线性扩展到“战斗系统”，而是在反复寻找四个基础答案：

1. 世界中什么东西是可被记录、拥有和影响的实体。
2. 实体之间如何用通用语义表达“是什么、具有什么、正在经历什么”。
3. 一个动作或事件如何被转换成确定、可追溯、可扩展的状态结果。
4. 角色如何在大规模群体模拟和高精度智能体交互之间保持连续性。

最终形成的底座可以概括为：

```text
实体档案与事件档案
    -> 类型 / 材料 / 物质 / 性质 / 状态标签
    -> 效应模板与抵抗属性
    -> 元规则匹配与冲突仲裁
    -> 意图到结果的统一结算链
    -> 原子状态变更、事件记录和回放
    -> 角色记忆、社会关系、经济状态与视觉表现
```

司命和角色智能体不应替代这条确定性底座。它们主要负责选择、理解、创造、预测和赋予意义；程序负责状态计算、物理事实、规则结算和一致性维护。

## 1. 产品目标与世界运行方式

### 1.1 三种同时存在的产品目标

对话5首先提出了商业社会，但很快明确项目同时服务三种目标：

| 目标 | 需要的能力 | 主要来源 |
| --- | --- | --- |
| 可复用的世界/经济模板 | 配置化规则、文明树、智能体工厂、模块开关 | [D5] |
| 可玩的 AI 世界 | 玩家可进入经济、战斗、政治和社会关系；失败有后果但不应立即失去全部体验 | [D5]、[D9] |
| 可推演的社会模拟 | 真实数据接入、因果记录、统计投影、反事实分支、可解释结果 | [D5]、[D6]、[D8] |

这三个目标共享同一套状态和结算底座，但运行模式不同：

- 游戏模式强调即时反馈、玩家可参与和叙事高光。
- 世界模拟模式强调大规模并行、连续时间和个体状态不被平均化。
- 推演模式强调参数可控、数据可替换、过程可审计和结果可复现。

因此不应为三种用途复制三套系统，而应让同一事件、规则和档案拥有不同的消费视图。

### 1.2 世界不是简单的 NPC 统计模型

设定中的小镇由约 100 名玩家角色和 9900 名智能体角色组成。智能体在玩家附近或重大事件中被高精度唤醒，其他时间由群体模拟推进，但群体模拟不能把角色压缩成无个性的平均值。[D5]

每个角色都有多重身份：

- 消费者、劳动者、投资者、纳税人；
- 父母、子女、配偶、兄弟；
- 企业主、雇员、债务人、资产所有者；
- 某个组织的成员、某种文化或信仰的参与者。

同一角色的经济、家庭、关系和心理变化必须回写到同一个角色本体，而不是拆成互不相干的 NPC 副本。

### 1.3 司命、角色智能体和程序的边界

| 执行主体 | 负责 | 不应负责 |
| --- | --- | --- |
| 程序/规则引擎 | 数值更新、物理事实、批量结算、状态传播、事件写入 | 自由生成意义和人物内心叙事 |
| 角色智能体 | 感知理解、重大决策、社交回应、战术选择、内省和创造 | 直接写入世界真相、绕过权限或物理结算 |
| 司命 | 全局观察、叙事生成、规则候选、模式识别、关键事件标记和宏观调谐 | 直接代替物理引擎、直接修改任意状态、让叙事覆盖事实 |

对话中出现过“司命可以生成新字段、新规则和新资产”的设想。这个方向可以保留，但生成结果必须先经过 schema、权限、依赖、冲突和结算验证，不能让大模型输出直接成为 canonical truth。[D7]、[D8]、[D12]

## 2. 世界实体与档案本体

### 2.1 “万物有档”是整个系统的数据前提

对话6把视角从“角色中心”推进到“世界实体中心”。凡是能够被拥有、使用、损坏、生产、交易、继承或影响的对象，都应有独立档案。

核心档案类型：

| 档案 | 记录内容 | 主要作用 |
| --- | --- | --- |
| 角色档案 | 身份、人格、身体、能力、关系、所有物、心智和记忆引用 | 角色的持续本体 |
| 事物档案 | 类型、材料、属性、动态状态、位置、所有权、耐久、事件历史 | 物品、建筑、土地、作物、设施和环境对象的持续本体 |
| 事件档案 | 事件输入、参与实体、因果父子关系、影响、结算结果、来源 | 世界历史和因果链的客观记录 |
| 关系档案 | 双方关系、信任、怀疑、义务、情感、互惠和共享秘密 | 社会行为与记忆关联 |
| 文明/规则档案 | 文明阶段、已解锁机制、规则版本、世界参数 | 控制当前世界允许出现什么 |

档案之间通过实体 ID 和事件 ID 连接，而不是把所有数据嵌套复制到角色内部。例如，角色只持有土地的所有权引用，农田的肥力、作物和受灾历史仍属于农田档案。[D6]

### 2.2 事物档案不是静态配置，而是持续存在的对象

一个农田档案至少包括：

- 静态属性：面积、土壤、地形、灌溉条件。
- 动态状态：肥力、湿度、当前作物、生长阶段、病虫害、霜冻损伤。
- 所有权：当前所有者、历史转移、继承和交易来源。
- 事件历史：旱灾、霜冻、施肥、维修和产量变化。
- 叙事钩子：司命生成的关键历史意义，但不能取代事实字段。

这样，当土地转手、作物成熟、设施损坏或角色死亡时，事物的连续性仍然存在。

### 2.3 事件档案是因果链，不只是日志

事件档案要回答的不只是“发生过什么”，还要回答：

- 谁或什么触发了事件。
- 事件影响了哪些角色、事物和环境。
- 哪些状态变化由该事件产生。
- 它的父事件和后续事件是什么。
- 哪些角色感知到了它，哪些角色只通过传闻知道它。
- 如果没有这个事件，后续结果是否会不同。

因此事件应具有 `causal_parent`、`causal_children`、`affected_entities`、`observed_by`、`settlement_result` 等结构化字段。司命的新闻、传记和记忆应从事件链取材，而不是反向伪造事件。[D5]、[D6]、[D8]

### 2.4 统一实体模型与领域投影

角色、物品、建筑、农田和环境区域可以共享基础实体接口，但不应被强行做成相同的数据结构：

```text
Entity
  identity
  type_tags
  material/substance components
  properties
  statuses
  location
  ownership
  event_refs
  domain projections
```

经济系统读取所有权和价值投影，物理系统读取材料、质量和碰撞投影，角色系统读取感知和关系投影，视觉系统读取表现投影。每个领域拥有自己的读模型，但只能由明确的 authority 写回事实。

## 3. 标签、材料、物质、性质与状态

这一组概念是对话11—13逐步收敛出的语义底座。

### 3.1 五种概念必须分开

| 概念 | 回答的问题 | 示例 | 时间稳定性 |
| --- | --- | --- | --- |
| 类型标签 | “它是什么？” | 生物、人类、武器、门、建筑 | 通常稳定 |
| 材料 | “它属于哪类构成材料？” | 木材、金属、血肉、骨骼、液体 | 稳定或缓慢变化 |
| 物质 | “具体是哪一种材料实例？” | 橡木、铁、人类血肉、水、秘银 | 稳定，可被加工/转化 |
| 性质 | “它具有什么可参与规则的属性？” | 可燃、导电、硬度、韧性、耐久 | 可被修改 |
| 状态 | “它现在正在经历什么？” | 燃烧中、中毒、倒地、潮湿、受伤 | 高频变化 |

材料是通用分类，物质是具体实例。材料提供默认规则，物质提供精确参数并覆盖默认值。[D13]

例如：

```text
材料/木材
  默认：可燃、硬度范围、燃烧规则
物质/橡木
  继承木材规则，覆盖燃点、密度、硬度等参数
实体/橡木门
  类型：建筑部件、门
  材料：木材
  物质：橡木
  性质：结构耐久、可燃性
  状态：完好或燃烧中
```

### 3.2 多材料实体与部位结算

生物不是一种材料，而是由多个材料组件构成：血肉、骨骼、皮肤、毛发等。武器命中具体部位后，规则应使用被命中的材料组件计算结果：

- 金属剑命中血肉：穿刺/切割与血肉性质匹配。
- 金属剑命中骨骼：硬度、韧性和卡刃规则生效。
- 攻击命中护甲：先使用护甲材料和耐久结算，再决定是否穿透。

这让“攻击木桩”和“攻击人类”在底层上共享材料交互逻辑，同时保留部位和生物状态差异。[D13]

### 3.3 性质和状态的边界

性质不是状态，状态也不会自动变成性质：

- 性质是可被规则查询的相对稳定属性，例如可燃性、导电性和硬度。
- 状态是实体当前的时间性条件，例如燃烧中、中毒和倒地。
- 状态可以由性质决定能否施加，也可以在持续过程中修改性质。
- 只有经过明确规则，长期状态才可以转化为持久性质，例如腐蚀导致硬度永久下降。

典型链路：

```text
火焰效应 + 可燃性质
  -> 添加“燃烧中”状态
  -> 按时间结算火焰伤害和耐久损失
  -> 状态过期
  -> 若损伤达到阈值，永久修改结构耐久/脆弱性质
```

### 3.4 是否需要下沉到元素/分子级别

对话13形成的实用结论是：

- “物质”级别通常必要，因为铁、橡木、金、秘银的交互和经济价值不同。
- 化学元素或分子级别不应成为默认运行粒度，否则会造成组合爆炸和无意义的计算成本。
- 化学/炼金玩法可以使用专门的物质反应规则，但仍通过统一效应格式接入。
- 若未来有真正需要元素级模拟的玩法，可以为该领域增加局部高精度模型，不改变上层标签和结算接口。

## 4. 效应、抵抗与元规则

### 4.1 三者分工

对话11明确区分了三个经常被混用的概念：

| 层 | 作用 | 示例 |
| --- | --- | --- |
| 标签/性质 | 描述实体的语义和参数 | 火焰、木材、可燃、硬度250 |
| 效应 | 描述一次交互可能产生的作用类型 | 冲击波、燃烧、冻结、腐蚀、资源燃烧 |
| 元规则 | 根据条件、参数和世界状态决定最终结果 | 火焰温度高于燃点则点燃并持续扣减耐久 |

效应是可复用的中间语言，元规则是最终计算和仲裁机制。不能把每个技能、物品或玩法都写成独立结算代码。

### 4.2 效应—抵抗通用协议

任何环境或攻击影响都可以表示为：

```text
Effect
  source_entity
  target_entity
  effect_tags
  base_value
  duration
  area
  penetration
  source_refs
```

目标提供抵抗和承受能力：

```text
Resistance
  effect_tag
  resistance_value
  immunity/weakness
  location_modifier
  equipment_modifier
  environment_modifier
```

最终结果由效应、抵抗、目标性质、当前状态、环境和规则优先级共同计算。火焰、霜冻、毒素、爆炸、法力燃烧、舆论冲击甚至经济压力，都可以复用这一抽象。[D6]、[D9]、[D10]

### 4.3 元规则的八类职责

对话7和对话11把元规则从“战斗规则”提升为世界操作系统：

1. 因果传导：事件如何影响实体和下游事件。
2. 情绪心理：损失、不公、进展和社交评价如何改变情绪。
3. 社会行为：互惠、公平、权威、从众、谣言和群体极化。
4. 经济文明：生产、消费、价格、金融、产权和制度演进。
5. 物理元素：材料、能量、元素、环境效应和破坏。
6. 资源能量：生命、体力、法力、灵力、信仰和其他资源池。
7. 叙事触发：何时生成关键记忆、新闻、战报或世界事件。
8. 规则进化：发现未覆盖模式、提出临时规则并进入验证流程。

### 4.4 元规则的执行模型

元规则应采用声明式配置，而不是把流程硬编码在某个玩法脚本中：

```text
事件/状态变化
  -> 监听规则
  -> 条件匹配
  -> 优先级排序
  -> 冲突仲裁
  -> 执行效果
  -> 产生新的状态变化
  -> 继续链式触发
```

规则至少需要：

- `rule_id`、版本和来源；
- 条件、阈值、作用域和冷却；
- 效果与公式；
- 优先级、互斥和抑制列表；
- 可解释描述；
- 权限、持久化和回滚信息。

司命可以提出或调节规则，但规则必须经过验证、版本化和审计，不能在同步结算中直接凭自然语言改变世界。

## 5. 意图到结果的统一结算链

### 5.1 统一结算链是所有玩法的共同底座

对话9—12反复验证：战斗、生产、交易、建造、修炼、偷窃、暗杀、法术和炸山开矿，本质都是“一个主体对目标发起带条件的意图，并产生可验证后果”。

```text
Intent
  -> Preconditions
  -> Cost / Resource Check
  -> Skill / Stat Evaluation
  -> Physical or Logical Fact
  -> Semantic Tag Resolution
  -> Effect Resolution
  -> Meta-Rule Settlement
  -> Atomic State Changes
  -> Evidence / Event Trace
  -> Frontend and Narrative Projections
```

### 5.2 五层低耦合实现

对话11给出了可执行的分层：

1. 动作意图层：玩家或智能体想做什么。
2. 物理事实层：命中、位置、力道、范围、碰撞和材料接触。
3. 语义标签层：查询源、目标和环境的类型/材料/性质/状态。
4. 效应层：从标签组合得到可能效应模板。
5. 元规则层：结合世界快照执行最终状态变更。

每层只通过结构化数据通信：

```text
ActionIntent
  -> PhysicalResult
  -> SemanticEvent
  -> EffectTemplateList
  -> StateChangeBatch
```

结算器不直接修改数据库，而是生成 `StateChangeBatch`，由下游 authority 进行原子提交。这样可以支持正式结算和只读模拟两种模式。

### 5.3 统一底座覆盖非战斗玩法

“战斗结算链”应改名为“因果交互结算链”。例如用火药炸山：

- 意图：开矿或破坏山体。
- 物理事实：爆炸压力、冲击范围、破片和地形变化。
- 语义：火药、岩石、矿脉、矿工、可坍塌结构。
- 效应：冲击波、高温、破碎、坍塌、噪声。
- 元规则：地形耐久、矿脉暴露、矿工受伤、声誉和监管影响。
- 结果：山体状态、资源分布、角色伤势、事件档案和后续寻路全部更新。

同一套机制也可以处理暗杀、伪装、交易欺诈、建造、生产事故和法术对抗。[D9]、[D11]、[D12]

## 6. 角色智能体与大规模群体模拟

### 6.1 角色是“档案本体 + 可激活心智”

角色在休眠时不是不存在，而是以结构化档案持续被群体模拟更新；激活时也不是生成一个新 NPC，而是从同一个角色主记录组装运行上下文。[D5]

建议的角色运行结构：

```text
CharacterRecord
  identity / profile
  body / health
  attributes / abilities
  needs / motivation
  emotion / affect
  relationships
  knowledge / beliefs
  ownership / inventory
  current_action / schedule
  structured_state
  narrative_memory
  event_refs
```

### 6.2 结构化域与叙事域

| 域 | 负责内容 | 更新方式 |
| --- | --- | --- |
| 结构化域 | 生命、资源、资产、库存、技能、关系数值、目标、当前动作 | 程序批量计算、原子增量提交 |
| 叙事域 | 关键记忆、内心解释、人物弧线、人生里程碑、意义化摘要 | 触发式司命/智能体生成，异步追加 |

司命不能直接用一段故事替代结构化状态。叙事产出如“希望下降”只能作为受约束的影响提案，经规则引擎验证后写入结构化域。[D5]、[D8]

### 6.3 四层心智与实体世界的接合

1. 感知：程序根据空间、感官、注意力和当前状态过滤事件。
2. 理解：程序做基础因果归因，司命在模糊或矛盾处提供内在解释。
3. 决策：程序处理日常效用和重复行为，角色智能体处理重大选择、道德两难和战术决策。
4. 执行：动作、技能、社交协议和物理系统执行意图，并把结果反馈回感知和记忆。

属性、能力、情绪、需求和关系不是独立装饰，而是共同调制决策：

- 智力影响理解速度、学习和复杂因果识别。
- 体力、疲劳和伤势影响动作能力、情绪和恢复。
- 情商影响感知他人情绪、说服、安抚和冲突升级。
- 信任、义务、声望和互惠历史影响社会行动。
- 需求、目标和价值观决定哪些结果被角色视为重要。

### 6.4 群体模拟与激活协议

推荐运行节拍：

- 即时脉冲：玩家交互、战斗、关键环境变化。
- 日级结算：消费、工作、家庭库存、市场交易、情绪衰减和日程。
- 长周期结算：健康、技能成长、关系演化、文明和制度变化。

激活流程：

```text
玩家/事件触发 ACTIVATE(char_id)
  -> 加角色级激活锁
  -> 跳过或延迟该角色的并发批量写入
  -> 从主记录组装场景相关快照
  -> 初始化角色智能体
  -> 交互期间写入 pending_changes
  -> 结束时合并增量、追加记忆、释放锁
  -> 回到群体模拟队列
```

不应每次激活加载全部历史。应按场景读取当前状态、当前行动、附近关系、最近记忆和相关长期目标；完整历史用于回放和深度推演。[D5]、[D8]

### 6.5 司命介入的合理触发点

司命更适合在以下节点介入：

- 情绪、关系或目标跨越重要阈值。
- 连续事件形成需要总结的模式。
- 出现道德两难、人生转折或重大创新。
- 玩家互动形成不可替代的个人记忆。
- 群体模拟出现此前未定义但稳定重复的涌现模式。

日常买卖、移动、资源扣减和普通劳作不应调用大模型。

## 7. 创新、动态内容与文明演进

### 7.1 创新不是司命凭空生成，而是系统内生结果

对话7—8中的“苗棚”和“风车磨坊”案例可以抽象成：

```text
反复失败/需求压力
  -> 记忆和知识检索
  -> 材料与技能可用性检查
  -> 类比和组合假设
  -> 小规模尝试
  -> 统一结算验证
  -> 生成新实体/规则/工艺
  -> 司命命名、记录和传播
```

司命可以帮助角色生成假设和意义，但新事物必须具备可计算的数据模型：材料、性质、状态、成本、用途、风险、所有权和依赖关系。

### 7.2 动态字段的边界

“新字段”不能意味着随意向数据库写入不可解释的 JSON。应区分：

- 已注册 schema 字段：直接参与结算。
- 可扩展属性包：经类型、参数和版本验证后参与指定规则。
- 叙事字段：只供记忆和表达使用，不直接改写事实。
- 未识别候选字段：先进入 proposal 和审查队列，不能影响正式状态。

动态字段要有来源、类型、默认值、作用域、生命周期、版本和删除/迁移策略。[D7]、[D12]

### 7.3 文明树与六轴联动

经济系统不能脱离文明阶段。部落文明不应自动拥有股票市场；金融、制造、政府和科技机制应由文明树解锁。[D5]

六个相互传导的轴：

1. 物质与生态：资源、天气、农业、环境承载力。
2. 人口与社会：家庭、职业、人口结构、社会网络。
3. 政治与军事：权力、法律、战争、治理和秩序。
4. 文化与信仰：价值观、仪式、信仰和身份认同。
5. 知识与科技：技能、发明、教育和技术传播。
6. 司命与气运：全局观测、节奏调谐、关键事件和叙事意义。

轴之间通过带方向、衰减和阈值的因果边连接。例如技术突破可以改变生产率、劳动需求、财富分配、政治稳定和文化观念，但每一条传播都必须产生可追溯事件。[D5]

## 8. 经济、社会与玩法系统

### 8.1 经济社会的主体

商业社会至少包括：

- 家庭/消费者：需求、收入、储蓄、信用和消费偏好。
- 企业：生产、定价、雇佣、融资和产业链。
- 投资者：股票、债券、房地产、风险偏好和信息判断。
- 金融机构：存贷、清算、信用和风险传导。
- 政府：税收、福利、基建、债务和货币政策。
- 监管者：市场操纵、内幕交易、许可和处罚。
- 玩家：可以创业、就业、投资、消费、治理或参与政治，但不能无条件绕过世界规则。

经济行为应由角色的多重身份、需求、资产、关系和知识共同驱动，而不是生成独立的“消费者 NPC”和“投资者 NPC”。

### 8.2 玩法领域不是一组孤立系统

对话10和对话12共同指向一种可组合玩法架构：

| 玩法域 | 复用的底座 | 领域特有内容 |
| --- | --- | --- |
| 战斗 | 动作、效应、抵抗、资源、状态、结算 | 武器、部位、伤害、士气、战术 |
| 生产/建造 | 物品、材料、技能、时间、所有权、事件 | 配方、蓝图、施工、维护、产能 |
| 经济 | 所有权、价值、契约、时间、事件 | 货币、账户、债务、税收、市场 |
| 修炼/成长 | 资源、技能、记忆、状态、突破规则 | 功法、境界、灵力、瓶颈、法宝 |
| 社交/剧情 | 关系、知识、记忆、目标、身份 | 对话、秘密、任务、证据、声望 |
| 生存/环境 | 资源、材料、效应、时间、身体状态 | 饥饿、疾病、温度、生态和灾害 |
| 潜行/暗杀 | 感知、动作、伪装、信息、社会后果 | 破绽、痕迹、调查和嫌疑 |

新增玩法首先应声明它需要哪些状态、标签、效应、规则、表现和验证，而不是直接修改多个核心模块。

### 8.3 战斗是统一底座的压力测试，不是特殊例外

动作系统提供移动、持握、挥动、刺出、投掷、格挡、闪避和交互等基元。战斗只是这些基元叠加了目标、时间压力、效应和伤害规则。

战斗系统还应连接：

- 体力、耐力、生命、法力、灵力、信仰等资源。
- 部位、护甲、材料、抗性和状态异常。
- 士气、恐惧、忠诚、关系和撤退意愿。
- 战术计划、语音指挥、AI代打和玩家接管。
- 战后伤势、财富、声望、政治和记忆后果。

因此战斗不能只做“攻击力减防御力”，也不应拥有一套与生产/建造完全不同的结算逻辑。[D9]、[D10]

## 9. 《开本》v3.0 的架构回接

### 9.1 原有六层架构

对话12提供的现有架构可整理为：

| 层 | 定位 | 关键内容 |
| --- | --- | --- |
| L1 | 确定性空间层 | 场景、物理、环境、音频、客户端交互 |
| L2 | 智能体交互层 | 角色智能体、司命、对话、玩法、目标、叙事 |
| L3 | 视觉增强层 | 生成渲染、点云、镜头、高光和视觉障眼法 |
| L4 | 商业运营层 | 大玩家经营、资产经济、创作者经济 |
| L5 | 平台治理层 | 安全、合规、用户、生态和创作工具 |
| L6 | 跨层基础设施 | 通信、房间、存档、事件总线、证据链和测试 |

现有架构的主要缺口不是“少一个战斗模块”，而是 L1 的物理事实与 L2 的智能体/玩法逻辑之间缺少通用的语义和因果结算层。[D12]

### 9.2 建议增加的四个通用基座

1. 意图—结果统一结算链：连接动作、物理、逻辑意图和状态变化。
2. 万物档案系统：在 L6 的持久化、事件和证据基础上统一实体本体。
3. 标签/材料/物质/性质/状态语义网络：为所有实体和效应提供通用语言。
4. 深层角色运行时：把角色档案、心智、需求、能力、社会和玩法状态合并为可激活运行体。

### 9.3 ESM 的合理位置

现有 ESM 可以复用，但不能单独承担完整元规则引擎。它适合：

- 管理环境状态、物理结果和场景同步。
- 维护确定性环境规则和状态机。
- 作为 L1 的世界状态适配器。

需要新增或外置的部分：

- 标签查询和实体语义解析。
- 效应模板查询。
- 跨角色、物品、经济和社会的元规则。
- 原子状态变更批文。
- 事件证据和叙事触发标记。

推荐把 ESM 逐步接入“因果交互总线”，而不是把所有角色心智、经济和司命职责继续塞进 ESM。[D12]

### 9.4 计算与表现必须分离

状态变化通过事件总线广播：

```text
StateChangeBatch
  -> 角色状态/情绪/关系
  -> 事物耐久/环境/寻路
  -> 经济/文明/任务
  -> L1音频、粒子、动画、HUD
  -> L3镜头、高光和视觉增强
  -> 司命叙事与记忆
```

L1/L3 只消费已经结算的结构化结果，不能通过播放特效确认世界变化。木屋倒塌、角色受伤和矿脉暴露都必须先由 authority 结算，再由表现层呈现。[D12]

## 10. 性能、缓存与预加载

### 10.1 性能原则

高规模世界需要分层处理：

- 规则、小模型和纯函数负责高频、重复、低叙事价值行为。
- 角色智能体处理玩家交互、复杂社交、重大抉择和创造。
- 司命处理关键叙事、模式识别、规则候选和宏观调谐。

不能为了“每个角色都活着”而让每个角色每秒调用大模型，也不能通过简单平均抹掉个体差异。

### 10.2 规则索引与缓存

标签系统可以通过以下方式优化：

1. 启动时扁平化标签继承树。
2. 为实体缓存完整标签快照和参数。
3. 为源标签、目标标签和环境标签预编译匹配键。
4. 对场景中新增实体或标签做增量预加载。
5. 使用带版本和失效时间的热点缓存。

### 10.3 司命预测性预加载

对话12提出司命可以预测可能的规则和资源需求，例如检测到火焰剑战士与冰霜法师在木屋附近对峙时，提前加载冲击波、燃烧、冻裂、木屋耐久和相关表现资源。

但预测只能优化缓存，不能预先提交世界结果。预测错误时必须可清理，不得产生幽灵事件或污染正式状态。

### 10.4 快速路径与通用路径

可以保留少量高频快速路径，例如普通移动、基础命中和简单资源扣减；遇到特殊标签、环境交互、稀有状态、高叙事价值或跨域影响时回退到通用结算链。

两条路径必须输出相同的结构化结果格式，并接受同一套回放和验证，避免形成两套世界真相。[D12]

## 11. 权威、回放与一致性原则

从全部对话可以提炼出以下不变量：

1. 每类事实只有一个 canonical owner。
2. 客户端表现不能确认世界真相。
3. 司命叙事不能覆盖确定性结算结果。
4. 角色智能体不能直接写入正式库存、财富、生命、地形或事件历史。
5. 所有状态变化必须带来源、时间、规则版本和事件引用。
6. 结构化状态变化必须原子提交，跨域结果必须可回滚或可补偿。
7. 事件记录不可被叙事重写，叙事只能引用或解释事实。
8. 规则、标签、效应和 schema 必须版本化，旧存档需要明确迁移策略。
9. 预览、推演和正式运行必须隔离事件存储和权限。
10. 任何新字段、新规则、新资产和新玩法都必须经过验证后才能进入正式运行。

## 12. 建议的建设优先级

### Phase A：语义与事实底座

- Entity/Character/Thing/Event 基础档案。
- 类型、材料、物质、性质、状态标签。
- 参数化标签、继承、版本和查询缓存。
- 事件因果链、来源和状态变更批文。

### Phase B：统一因果结算

- `ActionIntent`、`PhysicalResult`、`SemanticEvent`、`EffectTemplate`、`StateChangeBatch`。
- 效应—抵抗协议。
- 元规则匹配、优先级、冲突和抑制。
- 正式结算、模拟结算和回放模式。

### Phase C：角色完整运行时

- 角色结构化域和叙事域。
- 属性、能力、需求、情绪、关系、所有权和记忆。
- 群体模拟节拍。
- 角色激活锁、上下文快照、pending changes 和回写。

### Phase D：具身与玩法接入

- 动作基元、物理适配器、身体状态和资源池。
- 战斗、生产、建造、交易、修炼等作为规则/内容包接入。
- Godot 表现订阅状态变更。
- 玩家指挥、角色自主和接管协议。

### Phase E：文明、创新与平台化

- 经济社会和文明树。
- 六轴联动、群体涌现和反事实推演。
- 创新提案、动态内容、资产生成和规则演进。
- 真实数据校准、创作者工具、审核、版本、回滚和生态治理。

## 13. 仍需明确的设计决策

这些内容在对话中已有方向，但还没有完全冻结：

### 13.1 司命能否生成正式规则

已有两种倾向：司命可以动态提出规则；元规则又必须是稳定的世界宪法。建议区分“规则提案”和“已激活规则”，后者必须经过验证、版本化和权限批准。

### 13.2 动态字段的存储边界

需要确定哪些字段进入核心 schema，哪些进入扩展属性包，哪些只能停留在叙事域。否则动态创造会变成不可测试的自由 JSON。

### 13.3 物理、逻辑和超自然规则的优先级

已有“自然规则为基线、超自然规则为覆盖或增强层”的方向，但需要正式定义：覆盖、叠加、抑制、免疫、穿透和世界区域禁用的优先级。

### 13.4 材料、物质与化学模型的边界

默认建议停在物质级别；化学和炼金作为局部领域模型；元素/分子模拟只在明确玩法需要时启用。

### 13.5 游戏、模拟和推演的真实性等级

三种模式应共享事实模型，但可以有不同的时间粒度、智能体唤醒策略、数据源和输出报告。需要进一步定义模式切换时哪些状态可以复用，哪些必须重新计算。

## 14. 最终主题归纳

这组对话最终并不是要分别实现“经济系统、战斗系统、司命系统和标签系统”，而是在形成以下统一判断：

> 世界的基本单位是有档案的实体；实体通过类型、材料、物质、性质和状态被描述；交互通过效应和元规则被计算；结果通过事件和原子状态变更被记录；角色通过结构化状态和叙事记忆持续存在；不同玩法只是对同一结算底座的不同内容化和表现化。

对应到《开本》现有架构，最关键的增强不是继续增加孤立的玩法模块，而是优先补齐：

```text
万物档案
  + 标签/材料/物质/性质/状态
  + 效应与抵抗
  + 元规则引擎
  + 意图—结果统一结算链
  + 角色完整运行时与群体模拟
  + 事件回放和表现投影
```

这几个基座一旦稳定，经济、战斗、建造、修炼、社交、暗杀、政治、生态和创作者玩法才能以脚本、配置和内容包的形式持续扩展，而不必为每个新玩法重新制造一套世界逻辑。
