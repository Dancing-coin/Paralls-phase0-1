> 两者有什么区别

区别在“谁拥有移动真相”。

**方案 A：移动也经过 backend authority**
角色智能体想移动时，不是直接在 Godot 里走，而是：

```text
Agent decides goal
-> backend validates / authorizes movement intent
-> Godot receives approved movement command
-> CharacterActor moves and presents result
```

优点是边界最干净：backend 是世界真相，角色不能穿墙、越权、绕过规则，后续多人/审计/因果链更稳。缺点是 Phase 0 会更重：要定义移动 intent、空间约束、失败结果、同步频率，否则移动会慢或僵。

适合：重要剧情移动、对象接近、进入禁区、追逐、空间规则、需要可追责的行动。

**方案 B：backend 给高层目标，Godot 本地移动**
backend/Agent 只说“去桌边”“靠近玩家”“面向信件”，Godot 本地 actor 自己寻路/移动：

```text
Agent decides goal
-> backend emits high-level goal
-> Godot local controller turns goal into movement
-> backend only在关键交互时裁决成功/失败
```

优点是 Phase 0 更快、更顺，移动表现可以本地高频运行，不需要后端每步批准。缺点是世界真相边界弱一点：如果没有额外约束，Godot 可能本地走到了一个 backend 不认可的位置。

适合：闲逛、走位、面向、靠近、表演性移动、Phase 0 demo。

我的建议：**Phase 0 用 B，但只允许“表现性/导航性移动”本地化；所有会改变世界状态的动作必须走 A。**

也就是：

```text
走到桌边：Godot 本地执行
拿起信件：backend authority
打开门：backend authority
进入禁区：backend authority
对话承诺/关系变化：backend authority
```

这样玩家和智能体可以共享同一个 `CharacterActor` 底层，同时不把 Phase 0 做得过重。

> 鼠标也应该转玩家身体，保证身体朝向和镜头朝向一致才好，这属于哪个方案？

> A/D 是相对身体/相机的左右平移？ 怎么理解，A、D对镜头和身体朝向没有决定权对吗

对，按这个方案，`A/D` **不决定镜头朝向，也不决定身体朝向**。

它们只是在当前身体/镜头朝向的基础上，生成一个“侧向移动向量”。

如果当前角色面朝北：

```text
鼠标决定朝向：北
W = 向北走
S = 向南倒退
A = 向西左移
D = 向东右移
```

此时按 `A`：

```text
身体仍然朝北
镜头仍然朝北
角色向左平移
```

这就是 FPS 里的 strafing，中文常说“横移”。

所以控制权可以拆成：

```text
鼠标 X：决定身体 yaw + 镜头 yaw
鼠标 Y：决定镜头 pitch
W/S：沿身体 forward/backward 移动
A/D：沿身体 right/left 横移
```

更准确的运动公式是：

```text
forward = -actor.global_basis.z
right = actor.global_basis.x

move_world =
  forward * input_y
  + right * input_x
```

其中：

```text
W: input_y =  1
S: input_y = -1
D: input_x =  1
A: input_x = -1
```

但 `actor.global_basis` 本身由鼠标 yaw 决定，不由 WASD 决定。

这会产生一个重要要求：动画不能只播放“向前走”。需要至少支持：

```text
W：forward walk/run
S：backpedal
A：strafe left
D：strafe right
W+A / W+D：diagonal forward strafe
S+A / S+D：diagonal backward strafe
```

如果 Phase 0.5 暂时没有完整 strafe 动画，可以先用 forward 动画 + root motion 投影，但 spec 应该明确：目标形态是 camera/body locked + local-space locomotion blend。

> strafe 动画？

`strafe 动画`就是“身体/视线仍朝一个方向，但角色往侧边移动”的动画。

比如角色面朝北，镜头也朝北：

```text
W：面朝北，向北走
A：面朝北，向西横移
D：面朝北，向东横移
S：面朝北，向南后退
```

这里 `A/D` 需要的就不是普通“转身往左走”的动画，而是：

```text
strafe_left：身体朝前，脚步横向往左挪
strafe_right：身体朝前，脚步横向往右挪
backpedal：身体朝前，脚步往后退
```

在 FPS / 第三人称射击里这很常见，因为准星、身体、枪口/视线要保持朝向目标，但角色还要能左右移动躲避。

和普通走路的区别：

```text
普通左转走：
身体转向左边，然后往左走。

strafe left：
身体不转向左边，仍然朝前，只是横向左移。
```

对你的 Character Actor 设计来说，这意味着动画系统最好不是只有：

```text
idle
walk_forward
run_forward
jump
```

而是至少有一个二维 locomotion blend：

```text
move_x = -1 左横移
move_x =  0 无横向
move_x =  1 右横移

move_y = -1 后退
move_y =  0 原地
move_y =  1 前进
```

组合起来：

```text
(0, 1)   forward
(0, -1)  backward
(-1, 0)  strafe left
(1, 0)   strafe right
(-1, 1)  forward-left
(1, 1)   forward-right
(-1,-1)  backward-left
(1,-1)   backward-right
```

如果现在没有这些动画，Phase 0.5 可以先做“技术正确但动画不完美”的版本：

```text
身体和镜头锁定同向
WASD 产生本地二维移动向量
物理移动正确
临时用 forward walk/run 动画表现所有移动
后续替换为 strafe/backpedal blend 动画
```

但 spec 里要写清楚：**最终正确目标需要 strafe/backpedal/diagonal locomotion 动画或 blend tree。**

> 这样能保证游戏体验真实合理吗

**1. 感知真实**
智能体不能天然知道世界状态，只能基于：

```text
当前可见
当前可听
刚刚接触过
可信记忆
他人告知
司命催化但不强制真值
```

并且每条感知要有：

```text

certainty
last_seen_time
source
occlusion / distance / lighting / noise
```

否则 AI 还是会像全知 NPC。

**2. 具身真实**
知道目标不代表能执行动作。必须还满足：

```text
距离够近
有路径可达
身体朝向合理
手/视线/交互点可达
没有被碰撞或状态限制
动作耗时
可被打断
```

比如角色知道信在桌上，但它必须走过去、看向它、伸手/调查，不能瞬间完成。

**3. 决策真实**
智能体不应该每次都做最优动作，而应该受角色状态影响：

```text
性格
当前目标
恐惧/犹豫/疲劳
关系
风险判断
注意力
信息不完整
误判
```

否则即使不作弊，也会像机器导航。

所以 spec 里应该把真实感写成一个三门系统：

```text
Perception Gate:
Can this actor plausibly know or notice the target?

Embodiment Gate:
Can this actor physically perform the action now?

Character Gate:
Would this actor choose to do this, given personality, context, and uncertainty?
```

执行流程：

```text
Agent wants interact(obj_letter)
        ↓

  fail -> search/look_around/ask/ignore
        ↓
Embodiment Gate
  fail -> approach/reposition/wait/fail
        ↓
Character Gate
  fail -> hesitate/refuse/comment/choose alternative
        ↓

  fail -> constraint result
        ↓

```

对玩家也类似，只是 `Character Gate` 对玩家通常不限制选择，除非是剧情/状态约束。

这能把体验从“脚本 NPC”推进到“可信 AI 玩家”。后续再增强记忆、误判、社交动机，真实感才会继续提升。
