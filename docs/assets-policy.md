# Repository Asset Policy

这份文档定义 `paralls-phase-0-demo` 当前阶段的资产入库边界，目标是让仓库继续适合开发、验证和联调，而不是逐步变成不可维护的 DCC 素材仓。

## 目标

- 保持 `Phase 0` Godot + backend 可直接拉取、打开、运行。
- 保留运行时真正依赖的资产。
- 限制制作源文件无限堆积到主仓库。
- 给后续资产迁移到独立资产仓留下明确边界。

## 结论先行

主仓库保留：

- Godot 运行时直接消费的资产和场景。
- 为当前演示必需的导出结果。
- 为当前导入链路必需的 `.import` 和配套元数据。
- 小体积、对运行时不可替代的源文件。

主仓库不应长期积累：

- 大体积 Blender 源文件
- 高精度环境源贴图
- 只用于编辑器/DCC 的中间产物
- 本地调试产物、截图、日志、scratch 脚本

## 资产分类

### 1. Runtime Assets

定义：Godot 运行时或编辑器打开项目时会直接依赖的文件。

默认允许留在主仓库：

- `.tscn`
- `.tres`
- `.res`
- `.gdshader`
- `.glb`
- `.gltf`
- `.bin`
- 运行时实际引用的贴图
- 对应 `.import`

规则：

- 优先放在 `assets/` 作为正式运行时入口。
- 如果临时落在 `addons/`，也要能说明它是当前 demo 运行必需，而不是仅供 DCC 编辑。
- 大文件一律走 Git LFS。

### 2. Source Assets

定义：用于 Blender、贴图制作、材质编辑、场景重建的源文件。

典型类型：

- `.blend`
- 大体积 `.exr`
- 大体积 `.hdr`
- 高分辨率贴图母版
- 未来可能出现的 `.psd`、`.kra` 等

规则：

- 短期允许为了当前里程碑验证临时留在主仓库。
- 一旦确认运行时导出结果稳定，应优先迁移到独立资产仓或对象存储。
- 如果必须暂留主仓库，必须走 Git LFS。

### 3. Local Working Artifacts

定义：本地工具链、联调、截图、日志、scratch 文件。

典型类型：

- `.codex/tmp/*`
- `goblend.log`
- `push-*.log`
- 本地验证截图
- 临时导出报告

规则：

- 不提交。
- 通过 `.gitignore` 忽略。

## 目录边界

### `assets/`

用途：

- 正式运行时资产入口
- 角色、环境、道具导出结果

这是默认推荐入口。新资产优先从这里进入项目。

### `addons/`

用途：

- 外部插件
- 插件自带示例资源
- 为插件工作流临时保留的补充资产

限制：

- 不应把它当成长期环境主资产仓。
- 如果某个 `addons/` 目录开始承载项目级正式环境资源，应规划迁移到 `assets/`。

### `goblend/`

用途：

- `.blend` 试验资源
- `goblend` 路径验证

限制：

- 不作为默认运行时交付入口。

## LFS 规则

以下类型默认应走 Git LFS：

- `*.blend`
- `*.glb`
- `*.gltf`
- `*.bin`
- `*.png`
- `*.hdr`
- `*.exr`

原因：

- 避免主 Git 对象库膨胀。
- 保持大文件传输与普通文本历史隔离。

## 新资产入库准入规则

在把一批新资产提交到主仓库前，至少回答这 4 个问题：

1. 这个文件是否被当前 Godot 项目直接运行时消费？
2. 是否已经有更小的导出结果可以替代它？
3. 是否已经走 Git LFS？
4. 这个文件是否更适合留在资产源仓而不是代码主仓？

如果第 1 个问题回答是否定的，第 4 个问题通常应当回答是。

## 当前默认策略

### 允许直接进主仓库

- 当前 demo 必需的运行时导出结果
- 当前 Godot 项目打开和导入必需的配套文件
- 小体积插件资源

### 允许临时进主仓库，但需要后续迁移

- 单个超大 `.blend`
- 环境源贴图
- 只服务于资产生产而非运行时的源文件

### 不允许进主仓库

- 本地日志
- 临时截图
- scratch 脚本
- 调试报告

## 建议的后续迁移路径

对于已经在主仓库中的大体积源文件，推荐按下面顺序迁移：

1. 先确认 Godot 运行时真正依赖哪些导出结果。
2. 把 Blender/贴图源文件复制到独立资产仓。
3. 在主仓库保留：
   - 导出结果
   - 必要 `.import`
   - 一份资产追溯文档
4. 等团队确认追溯链稳定后，再从主仓库移除超大源文件。
