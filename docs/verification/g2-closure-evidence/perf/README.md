## 方法与可比性边界

- 真实 TCP 回环 WebSocket，经当前 `component_app` 的 `/ws`、绑定协议、pull 分发、投影构造和实际 socket 发送前复核。后台签发的本地启动凭证绑定发起者角色；pull 及发送前的绑定/租约/资格检查均执行。所有采样断言收到正向 session 事件；当前路径另检查 `known_time=481` 和禁止披露字段未出现。
- 同一进程、同一 fixture、同一已绑定连接内，交错切换当前 handler 与从 detached worktree AST 加载的历史 handler；每对样本轮换先后顺序。每轮每档每路径先预热 10 次（保留但不计入统计），再采样 60 次。两轮共保留 480 个计时样本及 80 个预热样本；没有删样本或选择较好轮次。
- 两档分别为同一目标流 100 / 4,096 事件：一个由真实 session Owner 提交的 v2 proposal，加上经真实 Store `append_batch` 提交的合成生命周期形状历史。后者用于固定读取/深复制规模，不证明这些重复 lifecycle 事件符合 Owner 状态机，也不代表真实生产事件分布。所有请求从 cursor 0 读取同一 proposal，而非排空历史事件。
- 历史 handler 和当前 handler 共享当前内存 Store、v2 fixture、绑定与发送门；历史 helper 使用其原字段投影和 outbox/bus 查找流程。这是**局部历史 handler 对照**，不是完整旧服务器的复跑。旧服务器无主体绑定、协议字段及 v1/outbox 行为也不同；因此**完整授权等价旧路径无可比基线**。下表比例只作诊断，不能据此声称完整改动的相对开销不超过 10%。
- 计时覆盖同步客户端发送、服务器读取与投影、发送前复核、回环传输及客户端 JSON 解码；绑定握手在计时之前。单进程内存 Store 不等于 Durable SQLite、生产 spawn host、跨机器网络或 Godot 渲染；未测持久库竞争、远程身份、真实客户端呈现及响应时序不可区分性。
- GC 保持启用，阈值为 `(700,10,10)`，未手动调 GC。记录每个样本内的 GC start；进程总计 19,310 次，含 fixture 构造/预热/采样。GC 可能影响长尾，本次不凭此推断根因。
- 准备阶段曾因错误使用生产包装 app（fixture 在 component app 内）及摘要路径拼写而退出，均发生在首个有效计时样本前；没有完成或删除额外测量轮次。随后一次脚本执行完成以下两轮，未发现正向响应断言失败。
