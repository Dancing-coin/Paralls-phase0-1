## B2 PRD 范围

结论：**PRD 未要求县城守城 Demo 必须实现两个角色之间的 session 交互（例如握手），也未要求以 session 机制提供交互。** PRD 有更一般的命令传达和面对面交互要求，但没有把它规定为 session 正向投影的验收项。

- `docs/PRD/05-阶段与可玩切片/县城守城Demo/可玩切片与需求覆盖.md`，切片 V1：“玩家发出 `defend_city`、`hold_gate`、`patrol_wall`，能看到传令兵移动、命令送达、理解/接受/拒绝和队伍不同响应。”这里要求军情—命令—传令—队伍响应，没有规定两个角色通过 session 握手。
- `docs/PRD/05-阶段与可玩切片/县城守城Demo/验收标准.md`，命令行：“传令、失效、拒绝、过期”；玩家需看到节点、状态和原因。未规定 session 协议或参与者投影。
- `docs/PRD/01-全局规则/信息可见性与认知边界.md`，6.1 清单引言：“下表保留原玩法案的完整界面职责，作为四类界面的下钻方向；它是设计清单，不代表十二套界面已制作、版式或键位已定。”其“世界内传达/会议界面”列举面对面交互与媒介；这是通用设计清单，不能单独当作该 Demo 的 session 握手要求。
- `docs/PRD/02-玩法模块/社交、关系与情报.md`：“语音、书信、手势、口令、旗语、传令、会议、沙盘和舆图共同承载观察、表达意图、传达与核查，不能默认为瞬时全域遥控。”同样是通用信息传达边界，没有指定 session 切片。

据此，参与者正向 session 路径不列为当前 Demo 的明确必需项；这不改变 G2 技术切片自身约定的限制和未完成项，也不替项目负责人宣布 G2 通过。
