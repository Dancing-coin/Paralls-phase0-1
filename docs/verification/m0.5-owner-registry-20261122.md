# M0.5 Owner registry expansion

Date: 2026-11-22

## Canonical identifiers

Owner IDs in rule-pack manifests use the short names below. The 22 Architecture v2 Owners are the canonical domain set. `Credential` remains as one additional legacy identifier because existing compatibility tests and historical packages use it. It is not an Architecture v2 Owner declaration. `Combat` remains excluded pending S-1.

The validator accepts only the canonical IDs in this table. It rejects `Economy / Market`, `Production / Facility`, `Morale / Formation`, `ProductionFacility`, and unregistered names. No alias normalization is performed.

## Economy / Market compatibility check

Repository search for the literal `Economy / Market` found only:

- the previous `REGISTERED_OWNER_IDS` declaration;
- temporary-package substitutions and an assertion in `backend/tests/test_rule_pack_validator.py`.

Search covered tracked and untracked source, test, pack, and script paths. No persisted event payload, receipt, checkpoint fixture, or golden runtime data contains this Owner string. The only code-side occurrences were test fixtures generated under pytest temporary directories. Therefore `Economy` is the canonical ID; the former spelling is rejected.

## Credential disposition

The Architecture v2 Owner definition lists 22 domain Owners and does not list `Credential`. The production `credential_reference` pack declares `Ownership`; however, `test_legacy_credential_owner_pack_remains_loadable` explicitly preserves support for old packs declaring `Credential`. `Credential` is retained as a compatibility allowlist entry only. Its presence in the allowlist does not declare a new Owner or grant authority.
