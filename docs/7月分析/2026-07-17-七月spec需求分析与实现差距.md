## 2. 需求总体解读

五个 spec 拼出一条主线：**把角色从"有骨架的心智"深化为"完整的人"**。

- 07-08：结构化需求（马斯洛五层）、细粒度性格反应层、三时间尺度情绪（即时/中期张力/长期沉淀）；
- 07-10：档案能力变成可检查的技能状态，技能-动作绑定并参与结算，学习证据驱动、默认关闭；
- 07-11：心智因子分层（authored truth / 记忆证据 / 运行态 / affordances / 认知工作区 / 写回账本），分层投影给 L2/L3/L4；
- 07-13 dossier：Profile 之上加完整档案外壳（多身份、具身静态基线、私密真相可见性治理、关系种子、能力种子）；
- 07-13 人格重构：Big Five+facets 取代旧五维 trait 作为行为输入，去重人格投影成为唯一行为偏置面。

贯穿所有 spec 的两条铁律（比功能本身更能说明意图）：

1. **authored truth 与运行时演化严格分离**——短期状态永不改写档案；长期变化（人格漂移、技能学习）必须证据驱动+闸门晋升，默认关闭；
2. **一切新能力 shadow/additive 起步**——不替换 L1→L4 主链、不改变现有行为、不破坏冒烟路径。

## 4. 问题定义

### P1：技能系统已完成 bounded 行为消费、结算与受治理扩展

- 已完成：runtime 将压缩 affordance 传入 L3 的模型上下文；L4 保留 `source_intent` 与 legacy bundle，仅对少量既有语义映射 composite action；runtime 调用 `CharacterSkillService.evaluate_action()`，记录 selected / blocked / unregistered advisory guardrail，并只对可行 binding 输出 primitive plan。
- 保持边界：skill 层不改写 L3 选择、不阻断 legacy command、不参与 ESM 或物理结算真值。
- 已完成：编排服务只在包装层保留 `ActionSettlementResult`，并在 policy 允许时写入 actor-scoped `SkillEvidenceStore`；候选、晋升审查、learned overlay、观察 belief、玩家 hints 和 realization metadata 均保持独立投影。默认不晋升，`authority`/`special` 不自动晋升，Kimodo 不能写 world truth。
- 仍非范围：持久化学习、自动晋升、完整 AbilityGraph、广泛 action-library 替换，以及把 advisory guardrail 变成执行拦截。

### P2：dossier 数据面只有 char_a（仍开放，但 char_c 需按角色边界确认）

- 现象：`assets/characters/dossiers/` 只有 `char_a.yaml`；`char_b` 没有 dossier 文件；`char_c` 是否应补完整 dossier 需要按“玩家壳 vs 角色智能体”边界决定。
- 影响：dossier 机制（可见性过滤、mind frame dossier card、热加载）目前只在单角色数据面得到证明；若 `char_b` 作为 agent 角色继续参与主线，应补 dossier。
- 定性：**数据缺口**，机制本身合规。

### P3：需求进料只有两层且靠文本巧合（已修复，保留历史）

- 原 2026-07-17 现象：五层需求只有 safety/esteem 可非零；标签来自 `perceived_summary` 英文子串匹配。
- 当前 2026-07-21 状态：已修复。
- 当前证据：`need_tension_engine.py` 已有 `TAG_TO_NEEDS` 映射，覆盖 `spatial_uncertainty`、`public_dismissal`、`goal_blocked`、`social_isolation`、`resource_scarcity` 等标签；`runtime_loop._derived_need_tension_event_tags()` 从 clarity/certainty、recent constraint results、Siming pressure marker、社交感知通道等结构化字段推导标签。
- 验证证据：聚焦测试已覆盖 `test_need_tension_engine.py`、`test_character_runtime_needs_affect_flow.py`；《断点分析》相关对话/需求测试也已通过。
- 定性：**原实现缩水项已关闭**。

### P4：prompt 同时携带原始 traits 与去重投影（仍开放）

- 现象：`prompt_policy.py` 在 profile summary 中并列输出 `traits=`（旧五维原始值）与 `personality_projection=`（去重投影）。
- 影响：不构成验收红线“重复计分”（无引擎评分消费），但对模型是双重人格信号，与 07-13 人格重构“单一去重行为偏置面”的目标相悖；投影尚未成为 prompt 侧唯一人格面。
- 定性：**过渡态残留**，shadow 期可容忍，行为消费期必须收口。

### P5：spec 状态头与实际完成度漂移（仍开放）

- 现象：07-08 spec 状态头为 `proposal`、两个 07-13 spec 为 `proposed`，但 `docs/character/character-mind-core-status.md` 和主线文档已将相关成果作为“已完成仓库事实”引用。
- 影响：文档真值层级（AGENTS.md §2）的可信度被稀释；后续 agent 按状态头筛选“活跃设计”时会误判。
- 定性：**文档纪律问题**，一行改动即可修复，但应与项目现行状态词体系对齐。

### P6（元问题）：深度优先于接缝，心智核心“有深度、缺输入”（部分已解决）

- 原 2026-07-17 现象：七月全部 spec 在深化心智核心内部，而《断点分析》证实的三处外部接缝（对话不进心智、角色互相听不见、感知→需求断）仍在核心之外开着。
- 当前 2026-07-21 状态：外部接缝主问题已修复。玩家对话会进入心智核心；角色言语会后端语义回灌给听者；需求标签不再靠自由文本子串。
- 仍开放的问题：技能系统、dossier 数据面、prompt 人格面仍属于“深度组件建成后接线未到底”的收尾项。
- 定性：**路线风险已显著降低，但内部接线收尾仍需要继续推进**。

## 5. 解决方案

### P1：给技能运行时收尾定义完成标准（优先）

按 07-10 spec 的 shadow 原则，分两级定义“接线完成”：

- 一级（shadow 完成）：`CharacterSkillService` 被 `runtime_loop` 真实调用。每轮 L3 决策后生成 `SkillAffordanceSummary`，写入 mind frame / `MindDeltaLedger` 或等价 observability surface，只记录、不改评分；observatory 可观察技能评估轨迹。
- 二级（行为消费）：affordance 结果进入 L3/L4 候选可行性护栏。不替代模型仲裁，只做契约、权限、可行性过滤，符合 spec“本地只做护栏”的 model-led 纪律；`CompositeActionProposal` 携带真实 `selected_skill_path` / binding path，而非 intent 直译。
- 验证：新增测试“L3 选定意图后 affordance summary 落账本/观测面”；跑 `python -m pytest -q backend/tests -k "skill or mind_frame"` 的聚焦子集。

### P2：补齐 char_b dossier，并明确 char_c 边界

- 参照 `assets/characters/dossiers/char_a.yaml` 的结构与 `char_b` profile 内容，为 `char_b` 编写 dossier YAML。
- 对 `char_c` 先做边界判断：若它只是玩家壳，完整 dossier 可不作为 agent 完成条件；若它也要作为角色智能体参与同等心智链路，则补 dossier。
- 加 loader 测试：目标角色 dossier 均可加载、actor_id 一致性校验通过、visibility 投影输出非空。

### P3：已关闭，只需保持回归

- 保持 `TAG_TO_NEEDS` 映射与结构化标签推导。
- 回归测试继续覆盖：低 clarity/certainty → `spatial_uncertainty` / safety；recent constraint results → `goal_blocked` / esteem+self_actualization；社交通道 → `social_engagement`。

### P4：prompt 人格面收口

- 第一步（低风险）：将 profile summary 中 `traits=` 改名为 `legacy_traits=`，或从主 prompt summary 移入迁移/debug 细节；主人格面只保留 `personality_projection=`。
- 第二步（随行为消费期到来）：按 07-13 spec 验收要求补回归测试“评分路径只消费投影”。
- 注意保持 shadow 期行为不变：本改动只影响 prompt 文本，不动任何评分逻辑，需跑 `test_character_model_gateway.py` 确认 prompt 契约测试同步更新。

### P5：对齐 spec 状态头

- 把 07-08 与两个 07-13 spec 的状态头更新为实际状态（例如 `implemented-and-verified`、`implemented`、`completed`，具体措辞应与本仓库 docs 体系一致）。
- 改后跑 `python scripts/verification/harness.py --profile docs`。

### P6：路线排序建议（更新后）

建议顺序：**先技能接线，再收口数据和文档**。

1. P1：技能运行时 shadow 接线。现在外部对话/社交/需求进料已经修复，技能评估有真实上下文可落账。
2. P4：prompt 人格面收口。改动小，但能降低模型侧双重人格信号。
3. P2：补 `char_b` dossier，并明确 `char_c` 是否需要完整 dossier。
4. P5：spec 状态头同步。完成后用 docs harness 防止文档真值继续漂移。
