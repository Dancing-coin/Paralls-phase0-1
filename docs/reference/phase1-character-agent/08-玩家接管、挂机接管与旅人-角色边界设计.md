# 08-玩家接管、挂机接管与旅人-角色边界设计

## 1. 文档目标

本文档冻结玩家、旅人、剧中角色和角色智能体之间的关系，以及玩家接管和挂机接管的边界。

## 2. 三个对象的严格定义

### 玩家
现实中的操作者，拥有真实判断和选择，不属于世界内对象。

### 旅人
玩家在 Paralls 中的 Meta 身份，拥有跨世界连续性、穿梭、凝神和带走等能力，但不等于某一局剧本中的角色。

### 剧中角色
世界内的具体存在，拥有世界内身体、身份、关系和角色智能体底层。角色智能体承载的是剧中角色，而不是旅人。

## 3. 正确关系

`玩家 -> 旅人 -> 剧中角色 -> 角色智能体`

## 4. 双回路模型

玩家角色采用：

- 真实玩家认知回路（系统外）
- 剧中角色补全回路（系统内）

玩家负责真实判断和高层选择；系统负责角色人格连续性、自动微表现、挂机保守承接和主观补全。

## 5. 接管边界

玩家不直接接管：

- 静态人格档案
- 角色补全型 `L1/L2`
- 自动生理和微表现层
- 挂机保守接管机制

玩家主要接管：

- `L3` 主动规划权
- `L4` 主动执行权

## 6. 自动补全层

即使玩家主动控制，高层输入仍要经过角色化补全：

- 微表情
- 小动作
- 社交距离微调
- 眼神行为
- 呼吸、紧绷、颤抖
- 内心独白提示
- 决策建议
- 冲动提示

## 7. 挂机接管

挂机接管不是停机，也不是代打。它只允许：

- 原地观察
- 轻微移动与转身
- 被动回应
- 回避危险
- 维持社交连续性
- 保持微表情与生理自动层

禁止：

- 推进关键对话
- 公开重要信息
- 主动使用关键证据
- 完成不可逆高风险行为

## 8. 回归同步

玩家回归后必须：

- 交还主动控制权
- 生成挂机摘要
- 把挂机期间结果写入记忆
- 保留情绪/身体/会话连续性

## 9. 小世界承接

被带回小世界的角色不是新建陪伴壳，而是同一剧中角色底层的压缩承接版本；旅人负责跨世界 Meta 连续性，角色负责世界内人格延续。

## 10. Phase 1 范围

Phase 1 必须冻结：

- 玩家/旅人/剧中角色三层定义
- 双回路模型
- 玩家接管 `L3/L4` 主动部分
- 自动补全层常驻
- OOC 自然泄露机制
- 挂机保守接管
- 回归同步
- 小世界同一角色底层延续

## 11. 一句话收束

玩家角色的正确模型不是“我就是这个角色”，也不是“系统替我演这个角色”，而是“我以旅人的身份投射意志，驾驶一个始终保有自己人格、身体和潜意识层连续性的剧中角色”。
