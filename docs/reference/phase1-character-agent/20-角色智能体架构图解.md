### 2.2 工程重点

- 角色智能体不是一次 `LLM` 调用，而是连续状态链
- `Godot` 本地只做高频具身执行与视觉事实抽取，不做认知真值判断
- `VisualFactEvent` 是角色表达层与感知上游的桥

## 3. 策划视图

```text
┌────────────────────────────────────────────┐
│          角色行为生命周期（策划版）        │
└────────────────────────────────────────────┘

世界里发生一件事
  -> 这个角色有没有机会看到/听到/闻到？
  -> 看到了多少？是轮廓、姿态，还是细节？
  -> 角色把这件事记到哪里？
     - 事件
     - 观察
     - 知识
     - 社交
     - 高阶知识
  -> 角色怎么理解？
     - 觉得发生了什么
     - 相信了什么
     - 怀疑了谁
     - 情绪/压力怎么变
  -> 角色此刻想做什么？
     - 目标被激活
     - 候选行动出现
     - 三重过滤器筛掉不该做的
  -> 角色最后选了什么？
     - AI 角色自动选
     - 玩家角色给建议，由玩家定
  -> 角色怎么露出来？
     - 说什么
     - 脸怎么变
     - 身体怎么动
     - 和别人保持什么距离
     - 生理层有没有泄露
  -> 别的角色又感知到这一切
  -> 新一轮博弈开始
```

### 3.1 策划最该检查的 5 个点

1. 角色有没有看到不该看到的东西
2. 角色有没有跳过理解直接行动
3. 行动是不是符合人格
4. 表现是不是和内在状态一致
5. 玩家有没有被抢控制权

### 3.2 这个视图回答的问题

- 角色为什么会像“一个人”而不是“一个会说话的 NPC”
- 玩家为什么不会感觉自己只是控制一个空壳
- 为什么角色的身体和表情会出卖他

### 4.1 Phase 1 最小闭环建议

先打通：

`看见 -> 理解 -> 选一个动作 -> 播出来 -> 别人看见`

最小样板优先：

1. `fixed_gaze_on_target`
2. `object_removed_from_surface`
3. `door_opened_partial`
4. `light_level_drop`
