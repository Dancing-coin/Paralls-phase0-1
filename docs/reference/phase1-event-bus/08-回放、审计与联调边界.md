## 1. 文档定位

本文件负责冻结：

- replay 真源边界
- audit 真源边界
- 最小可重放链
- 联调时最先验证的因果链

它不负责：

- 具体存储引擎与库表结构
- 具体调试 UI
- 具体回放播放器实现

## 2. replay / audit 的真源

当前真源必须来自后端权威叙事/事实总线，而不是 Godot 本地表现总线。

因此 replay / audit 至少应覆盖：

- 原始世界事实
- 视觉事实
- 候选感知与角色感知相关关键事件
- 六件套会话确认事件
- 角色行为回写
- `ESM` 结果
- 司命高层消息

当前不要求进入 replay 真源的内容：

- 原始骨骼 `(x,y,z)` 高频流
- 全 `AU` 高频流
- `AnimationTree` 中间态
- `SkeletonModifier3D` 中间修正量
- 纯本地 UI 层提示

## 3. 最小可重放链

当前角色相关最小可重放链至少应为：

`CharacterPerceivedEvent -> BeliefUpdateDelta -> IntentCommitted -> ActionRequestIssued / SpeechActPublished -> ESM Result / Social Consequence`

当前会话机制相关最小可重放链至少应为：

`Raw World Fact / Visual Fact / Audio Fact -> AccessResolution -> AwarenessResolution -> MembershipResolution -> KnowledgeResolution -> Character Local State Update -> SpeechActPublished / SocialSignalPublished`

边界强调：

- replay 的目标是重建“当时系统依据什么做出判断”
- 不是重建 Godot 本地骨骼中间态

## 4. 审计边界

审计至少应能回答：

- 某条世界事实何时进入总线
- 某角色何时接入了某场会话
- 某角色何时成为 `passive_member / active_member / excluded`
- 某条知识状态依据什么来源形成
- 某次风险判断为何成立

因此审计链至少需要索引：

- `event_id`
- `producer_ts`
- `room_id`
- `scene_id`
- `zone_id`
- `causation_id`
- `correlation_id`
- 关键确认事件的 payload 摘要

## 5. 联调优先顺序

联调时不应一开始就追求“大而全回放”，而应按最小闭环推进：

### 第一批

- 原始世界事实进入总线
- `AccessResolution`
- `MembershipResolution`
- `KnowledgeResolution`

### 第二批

- `AwarenessResolution`
- `ConversationBoundaryChange`
- `PrivacyRiskResolution`

### 第三批

- 角色本地状态更新
- 角色记忆沉淀
- `ESM` 结果回写
- 司命高层消息联动

## 6. 联调检查表

### 6.1 事实链

- `L1/ESM` 是否产出了足够原始事实
- 原始事实是否都带有足够的 `room / scene / zone` 上下文

### 6.2 确认事件链

- 是否先有 `AccessResolution`
- 是否在接入后才出现 `AwarenessResolution`
- 是否在知晓关系成立后才出现 `MembershipResolution`
- 是否在接入成立后才出现 `KnowledgeResolution`

### 6.3 角色承接链

- 角色本地会话运行态是否只保存本地态
- 记忆系统是否按五类拆写
- `L2/L3/L4` 是否通过确认事件驱动，而不是直接绕过总线硬编码

## 7. Phase 1 当前冻结边界

当前先冻结：

- replay / audit 真源属于后端权威总线
- 最小可重放链
- 会话确认事件至少纳入可审计链
- 原始骨骼 / AU 高频流不进入 replay 真源

当前不冻结：

- 完整回放播放器形态
- 跨局回放能力
- 全量性能压测体系

## 8. 一句话收束

回放、审计与联调边界的正确口径不是“什么都录下来”，而是：

> 只记录那些足以重建系统判断依据、角色接入边界和关键行为后果的权威事件链，而把本地表现中间态留在 Godot 本地。
