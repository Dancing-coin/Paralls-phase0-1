## 1. 文档定位

本文件负责冻结后端权威叙事/事实总线的职责和治理边界。

它负责：

- 实时 / 可靠通道拆分
- replay / audit 真源边界
- 业务总线订阅者与生产者边界
- 哪些消息属于后端权威层

它不负责：

- Godot 本地表现总线执行细节
- 角色本地状态字段
- 六件套确认事件的完整字段表
- 视觉事实系统内部特征与模板

## 2. 统一定义

后端权威叙事/事实总线是《开本》中真正承载世界事实、司命判断、角色回写和 replay / audit 真源的跨服务总线。

一句话：

> 只要一条消息需要参与世界真值、跨服务协作、审计或回放，它就应首先被视为后端权威叙事/事实总线的对象。

## 3. 业务总线承载内容

当前至少承载：

- 原始 / 结构化世界事实
- 候选感知事件
- 角色感知事件
- 司命高层消息
- `ESM` 结果事件
- 视觉事实事件
- 六件套会话确认事件
- 角色行为回写
- replay / audit 所需事件日志

当前不承载：

- 原始骨骼 `(x,y,z)` 高频流
- 全 `AU` 高频流
- `AnimationTree` 内部瞬时参数抖动
- 本地 `SkeletonModifier3D` 精修中间态
- 纯客户端 UI 层本地提示

## 4. 通道拆分

### 4.1 实时通道

负责：

- 客户端实时交互
- `P0 / P1` 控制消息
- 高频状态同步
- 感知心跳与高频流式更新

当前技术方向：

- 客户端 ↔ 服务端：`WebSocket`
- 服务端内部超低延迟分发：`内存队列 / 本地直连`

### 4.2 可靠通道

负责：

- 异步 AI 推理请求
- 跨服务解耦
- 事件持久化入口
- 审计、复盘和重放数据

当前技术方向：

- `NATS / JetStream`

## 5. 业务订阅者与消费者

当前主要订阅 / 消费方包括：

- 司命
- `ESM`
- 可感知信息编译层
- 角色感知入口
- 证据链相关系统
- 持久化 / audit
- replay / 调试回放链

这意味着：

- 角色智能体不是全量订阅者
- Godot 本地表现总线不是业务总线的直接替身
- replay / audit 不应依赖本地表现总线回放中间态

## 6. replay / audit 真源边界

后端权威叙事/事实总线是 replay / audit 真源。

当前必须至少保留：

- 原始世界事实
- 视觉事实
- 会话确认事件
- 角色行为回写
- `ESM` 结果
- 司命高层消息

当前不要求把以下内容作为 replay 真源：

- 原始骨骼 / AU 高频流
- `AnimationTree` 中间混合态
- `SkeletonModifier3D` 中间修正量

## 7. 事件分类与优先级

当前至少分为：

- 玩家行为事件
- AI 行为事件
- 环境与物理事件
- 视觉事实事件
- 感知结果事件
- 司命叙事事件
- 系统状态事件
- `L3` 视觉增强请求事件

当前采用四级优先级：

- `P0`
- `P1`
- `P2`
- `P3`

其中：

- `P0/P1` 走最短实时路径
- `P2` 允许正常排队
- `P3` 允许延后或异步处理

## 8. 背压、TTL 与降级

当前必须支持：

- 高时效低价值消息超时丢弃
- 低频关键消息不可过期丢弃
- 高频感知更新批处理
- 客户端或角色侧积压过高时，优先保留关键事件
- 从实时细粒度更新降为心跳补全

## 9. Phase 1 当前冻结边界

当前先冻结：

- `WebSocket` 主链路
- 实时 / 可靠通道拆分
- 视觉事实 + 听觉事实的结构化事件
- 精确空间事件最小字段集
- 六件套确认事件进入业务总线
- replay / audit 作为业务总线真源

当前不冻结：

- 最终中间件部署拓扑
- 序列化格式
- 跨服或持续世界级的完整总线扩展

## 10. 一句话收束

后端权威叙事/事实总线的正确定位不是“所有消息的大管道”，而是：

> 只承载那些需要参与世界真值、跨服务协作、司命判断和 replay / audit 的权威事件流。
