# 13-司命调试工作台设计

## 1. 文档目标

本文档冻结工程师、策划、QA 和运营如何实际观察、解释、定位、回放司命的运行过程。

## 2. 核心定位

司命工作台不是日志页，而是“全局公平判断与干预链路的可视化解释台”。

它必须能回答：

- 司命刚才看见了哪些高价值事实
- 它为什么判断当前局势失衡
- 它为什么选择这条最小干预
- 这次干预是否真的生效
- 它有没有越权或过度导演

## 3. 用户角色

至少服务：

- 工程师
- 策划 / 叙事设计师
- QA / 验收人员
- 运营 / 大玩家控制台使用者

## 4. 七个主面板

1. 房间总览面板
2. 公平快照面板
3. 干预候选与决策面板
4. 视觉事实与证据输入面板
5. 角色承接反馈面板
6. `ESM / Godot` 可执行与回流面板
7. 回放与对比面板

## 5. 三种视图模式

- `Engineering View`
- `Design View`
- `Operations View`

### 5.1 `Engineering View`

重点看：

- event ingest
- snapshot 构建
- candidate 生成
- decision 路径
- replay / audit 主键链

### 5.2 `Design View`

重点看：

- 局势是否失衡
- 这次干预是否公平
- 干预是不是过重
- 角色有没有真正接住

### 5.3 `Operations View`

重点看：

- 当前房间热度
- 最近关键干预
- 连续失衡与失败干预
- 是否需要人工观察

## 6. 必须能追踪的链路

司命工作台最小必须能追踪：

```text
World / Visual / Conversation Input
-> Auditor Result
-> FairnessStateSnapshot
-> InterventionCandidate
-> InterventionDecision
-> Dispatch Event
-> Character / ESM Observed Effect
-> FairnessStateSnapshot After
-> InterventionAuditRecord
```

## 7. 各面板最小字段

### 7.1 房间总览面板

最少展示：

- `room_id`
- `world_ts`
- `phase_marker`
- `dominant_imbalance_type`
- `global_imbalance_score`
- `intervention_urgency`
- `latest_result_status`

### 7.2 公平快照面板

最少展示五大维度：

- `information_distribution`
- `participation_distribution`
- `conversation_access_fairness`
- `suspicion_heat_distribution`
- `evidence_visibility_distribution`

同时展示：

- `affected_actor_ids`
- `imbalance_reasons`
- `candidate_relief_paths`

### 7.3 干预候选与决策面板

最少展示：

- `candidate_id`
- `band`
- `strength`
- `goal`
- `target_actor_ids`
- `selected_path`
- `fallback_path`
- `decision`
- `decision_reason`

### 7.4 视觉事实与证据输入面板

最少展示：

- 最近高价值 `VisualFactEvent`
- 最近 `visual_evidence_projection`
- 它们分别推高了哪个公平维度

### 7.5 角色承接反馈面板

最少展示：

- 哪个角色收到了哪条司命消息
- 是否进入 `L2`
- 是否改变候选行为空间
- 是否形成 `IntentCommitted`
- 是否被三重过滤器拦下

### 7.6 `ESM / Godot` 回流面板

最少展示：

- 哪些干预走了 `environment_change_path`
- 哪些被 `ESM` 批准 / 拒绝 / 降级
- 哪些走了 `visual_fact_path` / `l3_highlight_path`

### 7.7 回放与对比面板

最少展示：

- `before / after snapshot`
- 相同房间不同时间点对比
- 同类失衡的多次干预对比

## 8. 高亮规则

工作台必须能高亮以下风险：

1. `over_intervention`
2. `under_intervention`
3. `autonomy_risk`
4. `unreplayable_path`
5. `repeated_ineffective_intervention`
6. `private_channel_lock_persisting`

## 9. 关键联跳能力

工作台必须支持从司命侧跳到：

- 角色工作台
- 事件总线回放
- 视觉事实工作台
- `ESM` 结果记录

最小联跳字段：

- `snapshot_id`
- `candidate_id`
- `decision_id`
- `audit_id`
- `message_id`
- `correlation_id`
- `causation_id`

## 10. 人类可读解释摘要

`Phase 1` 工作台必须自动生成简短解释：

- 当前为什么失衡
- 为什么选了这条干预
- 为什么没有选另一条
- 结果是变好、无效还是变坏

解释摘要必须是结构化可复核的，不允许只有模糊自然语言。

## 11. `Phase 1` 最小实现要求

必做：

1. 房间总览
2. 公平快照
3. 候选与决策
4. 视觉输入
5. 角色承接反馈
6. 单周期回放
7. `before / after` 对比
8. 人类可读解释摘要

后补：

- 多房间并排观察
- 干预策略统计报表
- 运营级聚合分析面板

## 12. 一句话收束

司命调试工作台不是把司命日志摊出来，而是把“它看到了什么、为何认定失衡、为何这样干预、结果有没有真的改善局势”这条全局裁判链翻译成工程、策划、QA 和运营都能共同使用的解释界面。
