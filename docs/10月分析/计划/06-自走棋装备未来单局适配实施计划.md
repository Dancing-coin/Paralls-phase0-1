- 当前可复核底座：`backend/app/gameplay/equipment_runtime.py`、`inventory_runtime.py`、`patch_runtime.py`、`patch_lifecycle_authority.py`、`production_package_registry.py`、`resource_body_runtime.py`、`event_store.py`，以及角色16/规格09所接入的时间窗口合同（以计划04实际实现为准）。这些现有模块**没有**自走棋 board/roster/trait/round/reward authority 的证明。

- 不更改通用 equipment/resource/status/time/action API 来加入“最多三件”、board slot、round、trait、offer 特例。不将棋盘格/三件上限放进通用目标或 equipment schema。

**最终断言**

- AC01：任一前置 evidence stale/static-only/owner 缺失时 gate 阻断；此为合法结果，不算自走棋实现完成。
- AC02–AC08：各对象由对应 admitted owner 提交事实、receipt 与 privacy-filtered projection；failures 按各 owner recovery contract 收敛，不强求跨 owner atomicity。
- AC09：非自走棋 profile 不受 loadout/board/trait/phase/offer policy 污染；generic equipment/time/action schema 不含“三件”、棋盘格或 trait 特殊分支；历史 revisions/replay 保留。

**回滚点**：任一隔离断言失败，disable 新 auto-chess package revision/adapter，并保留既有通用 owner facts。只通过 package lifecycle 的受信新 revision rollback policy 处理后续应用；不回写/删除已经提交的棋盘、库存或奖励历史。
