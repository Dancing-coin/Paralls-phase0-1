# 角色心智运行时基础实施计划

状态：`analysis/planned/non-authorizing`。本轮交付规格与计划文档，任务复选框表示未来实施，不是已执行记录。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 CharacterAgent 代码上形成一条可重放的 `CharacterTurnContext -> MindFrame -> L1/L2/L3/L4 -> authority receipt -> writeback` 主链。

**Architecture:** 复用现有 turn lifecycle、MindFrameBuilder、memory stores、model gateway 和 L4 contract；新增的是冻结 frame/policy/provenance 的编排层和兼容适配，不是第二套角色脑。

**Tech Stack:** Python 3、Pydantic、pytest、现有 CharacterAgent services/storage/gateway。

**Spec:** [../规格/01-角色智能体心智运行时重构总规格.md](../规格/01-角色智能体心智运行时重构总规格.md)、[../规格/02-角色回合编排与L1-L4生命周期规格.md](../规格/02-角色回合编排与L1-L4生命周期规格.md)、[../规格/03-角色心智帧、感知边界与ThoughtMode规格.md](../规格/03-角色心智帧、感知边界与ThoughtMode规格.md)、[../规格/04-角色记忆分层、召回与写回规格.md](../规格/04-角色记忆分层、召回与写回规格.md)

## Global Constraints

- 复用 `CharacterTurnContext` 和现有 stage order。
- `MindFrameBuilder` 是唯一心智输入编译入口。
- memory writeback 必须携带 source refs、privacy、revision 和 owner receipt。
- model output 必须通过 schema/evidence/admission gate。
- L4 仍只能产生 `CharacterExecutionContract`。

## Review Focus

- 新旧 context 同时存在：必须在 coordinator 边界合并并固定 digest。
- 缺失 required memory evidence：必须返回结构化缺失，不准模型猜测。
- 模型 provider 不可用：调用失败经现有 runtime/coordinator continuity floor 处理并记录降级；被取消/过期的 turn 不得用旧 frame 写入 fallback。
- recovery 从中间 stage 重启：必须保持同一 turn/revision/idempotency。
- writeback 冲突：必须 zero-write 或 canonical correction，不覆盖旧历史。

## Dependency order

执行顺序固定为：Task 1（现状与生命周期基线）→ Task 2/2A（冻结回合并先建立 self/external/action execution 投影）→ Task 3（ThoughtMode 注册与 MindFrame）→ Task 4/5（L2/L3 admission 与主动感知/记忆）→ Task 1B（真实 Laya checkpoint/provider 先验验证）→ Task 1A/6A（冻结 Laya adapter、异步重规划与 continuity floor）→ Task 6/7（恢复与证据门）。文件编号保留以便与既有草案交叉引用；不能跳过 2A 或 1B 直接发明 Laya schema。

Task 1C 启动前先阅读并遵循 [审查04：第二项实施准入包与静态映射](../审查/04-第二项实施准入包与静态映射.md)。该包固定来源映射、离线 fixture、U/P 合同和评估隔离准备。用户于2026-10-11确认允许执行本计划时按证据逐项解锁：Task1A/1B接入后验证真实gateway/admission；Task1C开发阶段确定预算/质量/延迟及微调触发标准、独立校准方案，在final前冻结；必要微调按条件触发，独立final后判定Laya质量。不得要求这些尚待实施的验收结果先全部通过才开工；本次确认不等于已开始runtime实施。

本计划的能力限制先复用现有skill/affordance、gateway budget和output/execution validator；完整 `CapabilityEnvelope`/`CognitionPolicy` 是计划02 Task1–3的产物。本计划Task7只释放“心智基础已验收”，不能释放“角色重构全部完成”。计划02接入包络后必须回验Task1A/6A/6，记录同一policy/envelope来源、privacy/能力限制和取消/恢复行为。冻结输入的digest是当前对象的派生校验值；原文与现有模型未提供的wire字段不能未经合同修订加入模型或provider请求。

[已收敛决策 D01–D11](../审查/03-实施待决收敛与验证闸门.md)与规格01 §3.1、规格05 §4.2共同约束本计划：本地独立 multilingual 服务、专用 adapter、完整候选一次选择、按情境升级、API 慢/Deep、官方基线及实测触发微调。Task1C的数据与官方基线准备可随Task1B开始；实时选择质量在Task1A/6A后测，计划02完整包络接入后再冻结A阶段正式质量结果。B连续Boss和C双角色协同由总计划Task6A、计划03 Task6A随后验收，不是本计划Task7的开工前置。
