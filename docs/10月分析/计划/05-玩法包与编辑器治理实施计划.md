## 共用 API / 安全边界

- 复用 `GameplayPatchManifest`、`GameplayPatchRegistry`、`GameplayPatchLifecycleAuthorityService`、production manifest whitelist、现有 `GameplayEventStore` 与 revision。现有 active-set lifecycle 是可参考的 narrow base，不等于外部 catalog、generic editor 或完整安装/预览系统。
- `discover` 只读；`configure` 只产生 pinned draft；`preview` 在授权、隔离的 view/sandbox 执行；`apply` 发带 target scope、requested revision pins、expected current revision、activation boundary/migration/idempotency/payload digest 的 owner-bound lifecycle request。实际命令字段映射必须读取当前 `PatchCandidateInstallCommand`、`PatchActiveSetCommand` 后再审查，不能照抄规格中的示意合同并声称已实现。
- owner route 从受信 descriptor/schema 推导，调用方不能自由提供 stream/owner 坐标。package 作者/hidden owner/arbitrary script 不可执行；manifest dependency 和 requested capability 不自动授予权限。
- PackageRevisionView 与 per-scope PackageApplication 分开；当前 registry 中的 immutable manifest 不代表世界 application 实例、usage counters、cooldowns/config 已实现。
- Preview 只有静态检查/明确准入的 projection/replay/sandbox 形态。sandbox 若未来获准可有临时隔离 ledger，但正式 `GameplayEventStore` append 必须为零。当前没有可证明的通用 sandbox API 时，不把 `branch_preview.py` 写成已有能力。
- 发布 revision 不等于 active。activation boundary 由 owner 重新读取当前 revisions/capabilities/migration/privacy 后决定；事件/receipt 先于 registry/cache cutover。rollback 发新反向 revision，不能删除历史。
