# 十月分析规格目录规则

本目录只保存按主题收敛后的分析规格，状态统一为 `analysis/planned/non-authorizing`。规格必须从仓库现有代码、测试和架构文档出发，不能把分析建议写成已实现能力。

命名规则：`NN-主题规格.md`，`00` 为跨域总规格，后续编号按依赖顺序排列。规格文件不写实现计划步骤；实现计划统一放在同级 `../计划/` 目录。

每份实质规格必须包含 `[current]`、`[planned]`、`[deferred]`，并提供架构图、主流程时序图、数据流图、现有实现映射、边界、验收条件和后续 plan 引用。没有原文允许延期的能力时，明确写 `[deferred] 本主题无另行延期项`，不得为了凑状态虚构能力。永久禁止项单独标记；即使分析原文将越权项列入暂缓，规格也必须按根 AGENTS 的 authority/隐私边界保留禁止。图中的 `authority commit` 必须与 proposal、preview、模型输出和 Godot 表现边界分开。

角色规格优先引用 `backend/app/character_agent/` 与 `docs/character/` 的现状；战斗、玩法包和编辑器只能通过已定义的 owner 合同接入。禁止引入第二套 event store、clock、scheduler、tag registry、模型直写或任意脚本规则。

如果收敛规格相对原始分析设计改变了实施顺序、候选协议、范围或 owner 边界，必须同时在对应原始设计文档末尾增加“本批规格与计划回写”小节，并登记到 `../回写/README.md`。覆盖矩阵不能替代设计回写；没有回写的偏离不得作为已审阅设计进入代码执行。
