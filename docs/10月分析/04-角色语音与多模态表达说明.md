# 04 角色语音与多模态表达说明

本说明对应 [04 设计](04-角色语音与多模态表达设计.md)。

## 表达上下文的最小字段

```text
speaker_id
voice_id
audience
speech_goal / speech_act
allowed_claims
forbidden_claims
style_snapshot
allowed_fillers
max_duration_ms
context_version
expires_at
fallback_clip
```

不要把完整 `CharacterMindFrame` 原样发送给表达模型；上下文控制器应投影当前表达所需的最小信息。

## 对话实时性策略

- 紧急战斗信息走预设音频。
- 迟疑或等待走口癖填充，动态内容后台生成。
- 普通对话使用流式文本和流式 TTS。
- 动态语音必须可取消；上下文版本失效时丢弃后续片段。
- 动态音频返回太晚时回退到预设语音或沉默。

## 当前不应宣称的能力

仓库现有 `.env.tts` 等配置不等于已完成角色级流式语音闭环。只有真实语音服务、音色绑定、播放回传和队友 L1 接收证据齐全后，才能宣称实时语音交互已验证。

## 验证重点

1. 口癖是否按角色档案和上下文选择，而不是每句机械追加。
2. 动态语音是否只表达 L1 已知内容。
3. 局势变化后能否取消过期语音。
4. TTS 延迟期间快循环是否仍然运行。
5. 队友是否通过听觉边界接收，而不是直接获得文本真相。
