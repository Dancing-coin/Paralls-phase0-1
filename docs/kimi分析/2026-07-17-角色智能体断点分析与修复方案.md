# 角色智能体断点分析与修复方案

- 日期：2026-07-17
- 状态：已被取代（文中三处核心外部接缝已落地修复）
- 作者：Kimi
- 证据基准：原始 `文件:行号` 引用核对于 2026-07-17；2026-07-29 已按当前工作区代码、测试与主状态文档复核总状态
- 性质：问题分析与修复建议，不作为仓库当前实现事实声明
- 治理说明：正文保留 2026-07-17 的历史问题快照；当前事实以 `docs/character/character-mind-core-status.md`、相关正式 spec/plan 与 runtime/harness 证据为准

## 1. 背景

后端心智核心（`backend/app/character_agent/`，L1→L2→L3→L4、五池记忆、需求/情绪/漂移、四种控制模式）已按 `docs/character/character-mind-core-status.md` 声明建成，测试全绿。

但代码核实发现：心智核心与 Phase 0 冒烟路径是两套平行系统，之间有三处接缝没有焊接。心智核心的"上层建筑"都在，**进料管是断的或糊的**。测试发现不了这些断点，因为测试按模块契约构造理想输入，而断点全在模块之间的真实数据流上；`*_static.py` 守护测试锁的是文件边界，没有测试守端到端语义（如"玩家说一句话 → 角色记忆多出一条记录"）。

## 2. 断点一：玩家对话完全绕过心智核心

### 证据

`backend/app/main.py:638-652`：`dialogue_submit` 路由到 `character_service` 后，整个处理为：

```python
response = character_service.handle_dialogue(event)   # main.py:649
event_trace.record(response.output_type)
messages.append(_as_envelope("dialogue_response", response.model_dump()))
return _finalize_outbound_messages(messages)
```

全程没有一次 `character_agent_runtime.ingest_*` 调用——玩家的话从未进入目标角色的 L1 感知。

`backend/app/services/dialogue_service.py:13-27`：生成回复时传给 LLM 网关的 context 为：

```python
"snapshot": {},
"memory": {"working_memory": [], "episodic_memories": [], "relational_memories": []},
```

profile 不在 context 键里。

### 影响

断裂链：玩家的话 → 不进 L1 快照 → L2 不产生 belief/social/higher-order deltas → 五池记忆不记录对话 → L3 目标与意图不受对话影响 → 需求/情绪/漂移无输入。

- 在线模式：回复是无人格、无记忆的裸 LLM completion；
- 默认 stub 模式：回复是关键词匹配固定句（`backend/app/character_agent/gateway/model_provider.py:210-224`）；
- 设计文档中 L2/social memory/higher-order memory 的核心场景（记得玩家说过什么、因被羞辱改变态度）在对话路径上不可能发生。

## 3. 断点二：角色对角色说话，对方收不到

### 证据

`backend/app/main.py:416-444`：`speak_public/speak_private/share_info/withhold` 动作的处理为：

1. `record_execution_request`（记在**说话者**自己的 runtime）；
2. 合成 `DialogueSubmit(player_id="character_agent")`，走断点一的空 context 管线；
3. `record_dialogue_response`（仍记在说话者的 runtime）；
4. `dialogue_response` 发 Godot。

目标角色的 runtime 没有收到任何 ingest 调用。

唯一反馈回路绕经 Godot 且无内容：`scripts/audio/SpatialVoiceController.gd:28-36` 发射的 `speaker_active` 听觉 fact 只携带由 tone 推导的 `speech_mode`/`loudness_band`，**不带 content**。且 `backend/app/services/candidate_percept_service.py:4,11-12` 的听觉候选策略为 `targeted_actor_only` 并要求 `targets.actor_id` 非空——`speak_public` 广播连候选都不产生。

附加问题：`main.py:433` 的 agent 自发言语被 `generate_utterance` 用空 context 重新生成，等于把 L3 已决定的发言内容覆盖（stub 模式下直接替换成关键词固定句）。

### 影响

- 两个 agent 分身只能互相"看见"移动（visual fact 链是通的），永远"听见不知内容"；
- `share_info` 语义上无效：情报不进入任何其他角色的知识池；
- social memory / higher-order memory 最重要的进料管是断的。

## 4. 断点三：需求压力触发靠文本巧合

### 证据

`backend/app/character_agent/logic/need_tension_engine.py:31-35`：五层需求中只有 `safety` 和 `esteem` 有触发逻辑，各认一个事件标签。标签来源是 `backend/app/character_agent/runtime/runtime_loop.py:2964-2978` 对 `perceived_summary` 等自由文本做英文子串匹配：

```python
if "spatial_uncertainty" in normalized or "unstable doorway" in normalized:
    tags.append("spatial_uncertainty")
if "public_dismissal" in normalized or "public dismissal" in normalized:
    tags.append("public_dismissal")
```

### 影响

- profile 里完整建模的五层需求权重（`assets/characters/profiles/char_a.yaml:102-108`）只有两层可能非零；
- 触发条件是"感知摘要里恰好出现 `unstable doorway` 这类字面短语"——文本巧合，不是语义识别；
- 下游 motivation_stack、AffectEngine、人格漂移观察建立在空地基上；测试全绿只因测试直接构造了含这些短语的 summary（如 `backend/tests/test_character_runtime_needs_affect_flow.py:364`）。

## 5. 共同根源

三个断点同形：心智核心作为与 Phase 0 冒烟路径平行的系统建成，接缝未焊——对话入口（玩家→角色）走旧 `CharacterService` 门面，对话出口（角色→角色）走旧 `dialogue_response` 直发 Godot，事件分类（感知→需求）没有真正的分类器。

附带小断点（配置层）：`backend/app/config.py` 默认 `character_model_provider_kind="qwen"`，但 `backend/app/character_agent/gateway/model_router.py:13` 默认路由硬编码 `deepseek`，settings 里的 `character_model_*` 配置实际不生效。

## 6. 修复方案

共同前提：全部为后端改动，Godot 侧不动（它已会渲染 `dialogue_response`）；遵守 model-led 纪律——模型不可用时走 continuity_floor 诚实降级，不用本地规则伪造。

### 6.1 断点一：玩家对话接入心智核心

分两半修，缺一不可。

**入口（ingress）——让角色听到**：在 `main.py:649` 处理 `dialogue_submit` 时构造 `CharacterPerceivedEvent` 调 `character_agent_runtime.ingest_character_perceived_event()`。现有 schema 够用，不改模型：

- `percept_channel="auditory"`，`source_actor_id=char_c`（玩家壳），`target_actor_id=目标角色`
- `perceived_summary` 承载言语内容，如 `char_c对你说："…"`

`ingest`（`runtime_loop.py:122-361`）是现成全链路：L1 快照 → 需求/情绪 → L2 认知写回（belief/social/higher-order deltas + 记忆落池）→ L3 选意图。

**出口（reply）——让回复带人格**，两个候选走法：

- 方案 A（小改，保冒烟契约）：仍走 `DialogueService.generate_reply`，但接入 context provider，从 runtime 现有 getter 取真值（`_effective_profile_payload`、snapshot、`get_memory_record_bundle`、need_tension_state）。网关 prompt 组装（`backend/app/character_agent/gateway/prompt_policy.py`）本来就序列化这些键，契约不动，只是 `dialogue_service.py:13-27` 不再填空。
- 方案 B（架构正确）：消费 `ingest` 返回的 L4 commands——L3 选中 `speak_*` 时，用角色自己决定的内容作回复，跳过 `generate_reply`。"回不回话、怎么回"由人格和三重过滤决定。

**建议 A+B 混合**：优先消费 L3 的 `speak_*`；L3 未选言语动作或 continuity_floor 期间回落方案 A。冒烟契约"必有 `dialogue_response`"始终成立。

**顺手修**：`main.py:416-444` 中 agent 自发言语改为 L3 产出的 content 直接透传，`tone` 缺省，不再被空 context 重新生成覆盖。

**风险**：L2+L3 两次模型调用替代原来一次，延迟和成本上升，但只发生在对话提交时，频率低；离线时 continuity_floor 保证链路不断。

### 6.2 断点二：角色言语回灌感知

在 `main.py:416-444` 的 `speak_*` 分支，发言生成后由**后端直接**为每个听者构造感知事件 ingest，不再依赖 Godot 无内容听觉 fact 回路（该回路保留做具身表现，不再承担语义）：

- `speak_private`：听者 = `target_actor_id`，事件带 content + tone，`clarity_score=1.0`；
- `speak_public`：听者 = 同房间所有注册角色（`runtime.supports_actor` + 房间成员记录）减去说话者，含玩家壳 char_c；距离远时降 `certainty_score`。`candidate_percept_service.py` 的 `targeted_actor_only` 策略不动，因为语义不再走那条路。

收益自动兑现：听者收到的内容经 L2 后，social memory、higher-order memory（"X 告诉了 Y 什么"）开始积累，`share_info` 第一次有语义。

**必须加的防护**：听者角色的 L3 可能因此也选 `speak_*` → 再回灌 → 同步递归。这是期望中的"对话涌现"，但要在同一请求链里加**级联深度上限**（如 depth≥3 的事件只记录不再触发认知），或改为排队到后续 tick 处理。没有守卫，两个 agent 能在一次请求里无限对话。

### 6.3 断点三：需求触发改成结构化分类

两处小改，互相独立：

**杀掉子串匹配**（`runtime_loop.py:2964-2978`）：`_derived_need_tension_event_tags` 改为只从结构化字段推导标签，不碰自由文本。现成来源：`clarity/certainty < 阈值` → `spatial_uncertainty`；快照里的 `recent_constraint_results` → `goal_blocked`；`siming_pressure` → `supervision_pressure`；社交言语事件 → `social_engagement`。

**引擎泛化**（`need_tension_engine.py:31-35`）：两个硬编码 if 换成模块级映射表遍历求压：

```python
TAG_TO_NEEDS = {
    "spatial_uncertainty": ["safety"],
    "public_dismissal": ["esteem"],
    "goal_blocked": ["esteem", "self_actualization"],
    "social_isolation": ["belonging"],
    "resource_scarcity": ["physiological"],
}
```

profile 的五层 `base_weights`/`deprivation_sensitivity` 已齐全（`char_a.yaml:102-108`），**不需要动 profile schema**。语义层面的压力（"这句话让我受辱"）按 model-led 原则仍归 L2 的 `dynamic_state_delta` 负责；规则映射只做确定性地板，不越权。

## 7. 实施顺序与验证

| 顺序 | 断点 | 改动面 | 预估 |
| --- | --- | --- | --- |
| 1 | 三 | `need_tension_engine.py` + `runtime_loop.py` 一个方法 | 最小，纯后端逻辑 |
| 2 | 二 | `main.py` 一个分支 + 事件构造 + 级联守卫 | 中，不改变现有出口 |
| 3 | 一 | `main.py:649` ingress + `DialogueService` context 接线 + 混合回复 | 最大，动对话行为 |

每个断点配一条端到端语义测试（现有测试体系缺的那层）：

- 断点一：玩家说一句话 → 目标角色 episodic/social memory 出现对应记录，且在线回复 prompt 含 profile 字段；
- 断点二：char_a `speak_private` → char_b 的 L1 快照和 L2 解释出现该内容，级联深度守卫生效；
- 断点三：注入 constraint 失败事件 → `NeedTensionState.esteem` 非零；低 clarity 事件 → `safety` 非零。

确认冒烟路径无回归。
