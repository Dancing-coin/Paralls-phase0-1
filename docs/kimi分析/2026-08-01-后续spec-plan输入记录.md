## 2. 已明确的产品方向

### 2.1 总目标

目标不是继续堆局部 demo 能力，而是让项目逐步具备：

- 更一致的智能体自由度
- 更强的具身交互可信度
- 更自然的说话与发声体验
- 更清晰的玩法状态底座

大白话说：

- 不能只让智能体在少数热点对象上“很聪明”
- 要让它在越来越多默认对象、默认动作和默认交互里都遵守同一套规则

### 2.2 VLA 当前产品决策

已明确：

- `VLA deep` 当前**暂时搁置**
- 原因：`plus` 模型推理速度偏慢，不适合当前阶段的在线反应目标
- 当前阶段应把 VLA 视为：
  - `fast-only online advisory`
  - 以较快反应优先
  - 不把 `deep` 当当前 blocker

VLA 的角色仍然必须保持：

- advisory provider
- 不写 `world truth`
- 不写 `ESM authority`
- 不直接控制角色动作
- 已知场景真值优先来自 Godot scene/entity/collider/anchor/registry

### 2.3 VLA 模型选择方向

对当前项目的在线 VLA 路线，当前讨论已明确建议：

- 默认优先：`qwen3.7-flash`
- `qwen3.7-plus` 作为未来可恢复的更慢更深层路线，而不是当前默认目标

如果后续正式 spec / plan 仍保留 `deep` 概念，必须明确写成：

- deferred
- parked
- non-blocking

而不是继续把它写成当前阶段必须收口的硬要求。

### 2.4 TTS 当前产品方向

已明确：

- TTS 是表现层，不是文本模型替代物
- TTS 的目标是让角色“像活着一样开口说话”
- 它应与 `dialogue streaming` 联动

接入策略优先级：

1. 真实 TTS provider
2. 句子级 / 分段流式语音
3. 真流式音频作为后续增强

### 2.5 动作库 / 原子动作方向

已明确不采用纯一边倒路线。

推荐正式方向：

- **控制器主导，动作库供给**

具体边界：

- 控制器负责：
  - 去哪里
  - 站在哪里
  - 什么时候接触
  - 是否中断
  - 如何恢复
- 动作库负责：
  - 原子动作资产
  - root motion profile
  - modifier / overlay
  - equipment override
  - 可组合的表现性动作片段

### 2.6 root motion 使用原则

已明确：

- root motion 不拥有整段空间真相
- 大位移由控制器 / navigation / stance reservation 决定
- root motion 主要负责：
  - 局部位移
  - 身体节奏
  - 接触前后表达
- IK / motion warping 用于贴合目标
- authority 决定最终结果

## 3. 动作库正式设计应保留的结构

### 3.1 三层结构

后续正式 spec / plan 应优先延续这三层：

1. **语义动作层**
   - 例如：`approach`、`align`、`kick`、`grab`、`place`、`handoff`
2. **原子动作层**
   - 例如：起步、停步、转身、伸手、握持、踢击、收手、恢复
3. **本地执行层**
   - `EmbodiedActionController` / `CharacterMotor` / IK / motion warping / local observation

### 3.2 原子动作分类建议

后续正式动作库至少要按以下类别组织：

- 位移动作原子
  - `start_move`
  - `stop_move`
  - `turn_to_target`
  - `step_left`
  - `step_right`
  - `backstep`
- 上肢原子
  - `raise_hand`
  - `reach_forward`
  - `grip`
  - `release`
  - `offer_item`
  - `receive_item`
- 接触原子
  - `kick_contact`
  - `push_contact`
  - `tap_contact`
  - `brace_contact`
- 恢复原子
  - `recover_balance`
  - `reset_guard`
  - `return_idle`
  - `abort_contact`

### 3.3 资产 contract

动作资产 contract 继续沿用当前方向：

- `CharacterActionAssetDescriptor`
- `CharacterEmbodimentAssetRegistry`
- `selected_skill_path`
- `primitive_action_tags`
- `primitive_realization_keys`

不要新造第二套并行资产 contract。

## 5. 后续 spec / plan 不应再重复犯的错误

后续新线程写正式 spec / plan 时，不应再：

- 把 `VLA deep` 继续写成当前阶段硬 blocker
- 把 TTS 当成文本模型替代物
- 把 root motion 写成空间真相拥有者
- 把动作库写成执行控制器
- 把控制器写成动作库替代物
- 把 `CharacterGameRuntimeState` 描述成已实现事实
- 把已经有正式 spec / plan 的主题重新塞回 `docs/kimi分析`

## 6. 后续正式 spec / plan 应优先处理的主题

按当前讨论，后续应优先整理或推进：

1. 原子动作库与本地控制器协同设计
2. VLA `fast-only` 当前阶段正式化
3. TTS / dialogue streaming / voice profile 协同边界
4. 默认主场景对象的具身交互覆盖路线
5. `CharacterGameRuntimeState` 最小可执行核心，而不是一次性全量玩法底座
