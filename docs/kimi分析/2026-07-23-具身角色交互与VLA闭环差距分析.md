# 具身角色交互与 VLA 闭环差距分析

- 日期：2026-07-23
- 状态：分析完成，待转化为实施计划
- 作者：Codex
- 性质：基于当前运行证据与代码边界的问题定义和解决建议；不替代主线 spec、实施计划或 Godot editor 验证。
- 范围：角色与角色、角色与物体、角色与世界的开放式具身交互；包括 VLA 的作用和边界。

## 1. 结论摘要

当前仓库已经验证了一个真实的智能体驱动 3D 垂直切片：Godot 场景可加载，角色可接收后端执行计划，玩家可发起对话和交互，后端可返回成功或结构化约束失败，世界状态和 Siming 输出可回到场景。

这证明了“角色智能体 - 后端 authority - Godot 表现”的基础链路已通，但尚不能证明通用具身闭环。例如，当前不能可靠地让角色看见右侧一米的椅子后，自行走到正确踢击站位、踢中椅子、确认椅子倒下并据此重规划。

接入大模型或 VLA 都是必要增强，但都不是充分条件：

- 大模型负责高层目标、策略、对话和重规划，不应逐帧控制骨骼或物理。
- VLA 负责从视觉中识别未知物体、状态与潜在可供性，不应直接写 world truth 或施加物理效果。
- Godot 本地具身控制、碰撞、IK、导航和刚体物理负责“是否做得到、是否真的做成”。

目标应表述为：**开放式语义交互，受角色设定、能力、关系、空间、物体状态、物理与后端 authority 约束。** 这比没有约束的“无限制交互”更真实、可验证，也避免模型幻觉直接改写世界。

## 2. 当前已具备的能力

### 2.1 角色心智和设定注入

仓库已有 profile 与 dossier 输入层，能够承载身份、经历、价值观、人格、需求、表达、关系种子、技能、权力边界和私密真相的可见性。现有资源位于：

- `assets/characters/profiles/`
- `assets/characters/dossiers/`

运行时已具备私有感知、工作/情节/关系记忆、needs/affect、L2 理解、L3 规划、L4 执行语义与写回路径。角色的执行计划可携带 speech、face、body、social-spatial、physiology、focus 与动作状态。

### 2.2 Godot 表现与 authority 闭环

当前已验证的 Phase 0 路径包括：

- 主 3D 场景加载和后端 WebSocket 连通；
- 结构化对话与角色表现回写；
- 权威成功交互与结构化失败交互；
- 物体/环境状态变化与 Siming 反应；
- `character_agent_execution` 到 `CharacterReplica` 本地表现入口；
- 玩家和 NPC 的局部 root motion 验证。

最近一次证据为 `.harness/verification/harness-run-report.md`，其中 `phase0` profile 的 exit code 为 `0`。

### 2.3 已有但尚未完成产品化的感知/物理接缝

仓库已有 L1 事实、空间、provider、ESM 物理通道和 VLA advisory 合约。这些是正确的边界基础，但不等于现有主场景已实现任意物体的碰撞、抓取、推踢或双人协同动作。

## 3. 主要问题

### P0：没有通用的感知到动作闭环

当前角色可获得目标 ID、关注、距离/空间关系和世界结果，但缺少统一控制器将高层意图拆为连续阶段：

```text
目标识别
-> 计算合适站位
-> 导航接近
-> 面向和姿态对齐
-> 接触或抓取
-> 验证结果
-> 恢复、重试或放弃
```

后果是角色可以“想踢椅子”，但无法保证在合理距离、正确朝向和无阻挡条件下踢中椅子。

### P1：场景对象缺少可执行的 affordance 数据

当前交互对象与环境状态有协议壳，但开放式交互要求每个可交互实体暴露更完整的数据：

- 精确 transform、边界、碰撞体、动态/固定状态；
- `kick`、`push`、`grab`、`sit`、`open`、`pour` 等 affordance；
- 可达站位、抓取点、踢击点、放置面、使用点；
- 质量、摩擦、约束、破坏阈值、状态机；
- 支持的 authority action 与结果观察方式。

没有这些数据，模型只能提出意图，无法安全且可重复地执行。

### P2：缺少多角色 interaction session

拥抱、握手、递杯子、搀扶等不能被建模为两个互不相关的单人动作。它们需要共享的 session：

- 发起、接受、拒绝、犹豫、取消和中断；
- 双方站位槽、朝向、时间轴和动作所有权；
- 同步进入、进行和退出；
- 对关系、记忆、同意/权限和世界事实的写回。

当前执行计划可以表达角色动作语义，但尚未构成这一层通用双人协议。

### P3：本地运动控制、IK 与物理结果验证未收敛

现有角色壳和骨架表现支持动作、姿态和 root motion，但还缺少面向语义动作的本地执行器：

- NavMesh 路径、局部避障和站位 reservation；
- 运动状态机或行为树；
- 头部/躯干/手/脚 IK、motion warping 和接触窗口；
- 手持 attachment、脱手、掉落和约束；
- `RigidBody3D` 物理作用、接触事件、冲量和最终姿态验证；
- 失败后的恢复姿态和重新规划输入。

仅播放动画不能解决目标位置、身高、障碍物、移动目标和中断；只用程序化运动则无法得到拥抱等高精度情感表现。

### P4：真实模型与 VLA 尚未成为已验证的在线能力

当前 provider readiness 记录中，character text provider 缺凭据、Siming LLM 默认 disabled、VLA spatial provider 为 blocked。无模型时角色会走 `local_only_stub` 或 continuity fallback。

因此，当前成功的运行时验证证明的是协议、结构化回退和 authority 链路，而不是长期开放式模型驱动的社会互动质量。

### P5：动作资源、声音和面部表现不足

当前角色动作集有限，部分高级语义存在 idle fallback；语音是 stub；没有完成的 viseme、面部 blendshape 与情感表现链。这样会削弱“角色真的理解并做出反应”的可读性，即使后端决策正确。

## 4. 目标架构

### 4.1 分层职责

```text
角色智能体 / LLM
  目标、动机、关系判断、对话、策略、重试或放弃
        |
具身动作规划器
  affordance 选择、站位、动作阶段、接触点、预条件、失败恢复
        |
Godot 本地执行器
  导航、避障、AnimationTree、IK、attachment、碰撞、刚体、接触检测
        |
Backend authority
  权限、约束、结算、世界事实、审计、记忆/关系/状态写回
        |
感知回流
  真实接触、物体最终状态、可见/可听结果、置信度与异常
```

LLM 和 VLA 均不得绕过 Godot 本地执行与 backend authority。

### 4.2 VLA 的正确位置

VLA 应作为场景理解和未知资源补全能力：识别“疑似椅子”、估计状态、识别可供性、发现异常和提供空间建议。它输出的是带置信度的 advisory 结果。

对于已知 Godot 资源，精确位置、碰撞体、质量、状态和 anchor 应优先来自场景实体数据，不应由 VLA 估算。VLA 结果需要和 scene entity / collider / affordance registry 融合后，才能进入动作规划。

### 4.3 三类表现策略

| 策略 | 适用交互 | 实现 |
| --- | --- | --- |
| 物理主导 | 推、踢、拉、摔、掉落 | 程序化动作 + IK + 刚体/约束 |
| 原子组合 | 观察、指向、递交、拿杯子、回避 | locomotion + additive posture + IK + attachment |
| 专用同步片段 | 拥抱、握手、扭打、跳舞、急救 | 双人动画 + 站位对齐 + IK 微调 + 中断规则 |

专用动画用于关键情感或高精度接触时刻；通用系统负责接近、对齐、进入、退出、失败和世界反馈。

## 5. 最小实现方案

### 5.1 实现 `EmbodiedActionController`

为每个 agent-controlled 角色创建本地控制器，输入为已授权的结构化 action request，输出为动作状态、接触观察和执行结果。

建议的通用状态机：

```text
AcquireTarget -> PlanApproach -> Navigate -> Align -> Prepare
-> ExecuteContact -> Verify -> Recover
                         |          |
                         +-> Abort -+
```

控制器必须以本地帧率运行；LLM 只在目标、策略和失败恢复层参与，不能输出单帧骨骼变换。

### 5.2 建立 `SceneAffordanceRegistry`

每个角色、物体和环境实体注册：

- stable ID 与 scene node；
- transform、collider、navigation footprint；
- semantic type、state、affordance 与限制；
- interaction anchors；
- 物理属性与 authority policy；
- 可被 VLA 建议绑定的语义标签。

例如 `chair_01` 至少要有 `kick_contact_anchor`、`push_anchor`、质量、是否固定、可踢站位和倒地状态判定规则。

### 5.3 定义 `InteractionSession`

为多角色或角色-物体操作提供统一协议。最小字段应包括：

- `session_id`、initiator、target、action semantic、阶段；
- participants 的 accepted/rejected/cancelled 状态；
- 各角色站位与朝向槽；
- 所需的 animation profile 或原子动作组合；
- authority request、causation/correlation ID；
- 接触/物理观察和完成、失败、中断结果。

### 5.4 扩展本地表现层

先建立少量可组合原子，而非大量专用动画：

- locomotion：idle、walk、run、turn、stop、backstep；
- 姿态：relaxed、guarded、hesitant、alert；
- 上身：reach、grip、release、point、wave、reject；
- 感知：look-at、head/torso orient、breathing；
- 下身：generic kick / shove；
- 物体：attach / detach / drop。

拥抱、握手等再作为少量高价值双人 clip 接入，并通过 IK 处理身高差和小幅误差。

### 5.5 感知与物理回流

执行器不应以“动画播放结束”当作成功。它需要上报：

- 是否抵达站位、路径是否阻断；
- 是否处于有效朝向和接触距离；
- 是否发生真实 collider contact；
- 目标是否移动、掉落、倒下、损坏或被其他角色拿走；
- 场景中其他角色可感知到的视觉、听觉和空间事实。

后端依据这些观察确认或拒绝结算，并将结果写入角色记忆、关系和世界状态。

## 6. 验证路线

不要直接从拥抱开始。按以下顺序建立可重复的端到端证明：

1. **接近与对齐**：角色选择目标，走到可交互站位，面向目标；目标移动或被阻挡时中止。
2. **推/踢椅子**：角色进入踢击站位，触发通用腿部原子和 IK；椅子由 `RigidBody3D` 倒下；未命中、距离不足、椅子固定时返回不同结果。
3. **拿起并递交杯子**：手部对准 grip anchor、attach、移动、对方接受或拒绝、detach、掉落恢复。
4. **握手**：双方 interaction session、站位同步、接受/拒绝/中断和关系写回。
5. **拥抱**：在前述共享协议上接入双人专用 clip，验证关系、同意、空间、取消和退出。
6. **长时自主测试**：2-4 名角色在包含门、椅子、杯子、桌子和私密区域的场景中运行 30-60 分钟，检查自主对话、关系演化、记忆、物理结果、失败恢复和无玩家输入行为。

每项应同时验证：Godot 画面、后端 authority 结果、角色记忆/关系写回和可重放 trace。静态测试不能替代这些运行时证据。

## 7. 验收标准

“角色看见右侧一米的椅子并主动踢开”可作为首个完整验收：

1. 角色从场景或 VLA 融合结果得到带置信度的 `chair_01`、位置和 `kick` affordance。
2. 角色智能体基于目标、设定和约束选择 `kick(chair_01)`。
3. action controller 计算并抵达踢击站位，必要时避开障碍物。
4. 接触前再次检查距离、朝向、碰撞和椅子状态。
5. 本地骨骼控制器完成通用踢击原子，脚部在接触窗口抵达 anchor。
6. 物理引擎验证接触并施加已授权的冲量；椅子最终姿态满足倒地阈值。
7. Godot 上报 `chair_tipped` 或 `missed_contact` 等观察；后端据此结算世界事实。
8. 相关角色将结果写入私有感知、记忆和关系/情绪输入，并可作出后续反应。

## 8. 实施优先级与风险

### P0：先完成的通用能力

1. `SceneAffordanceRegistry` 与一个动态椅子资源。
2. `EmbodiedActionController` 的接近、对齐、踢击、验证、恢复路径。
3. Godot 物理观察回传与后端 authority 结算。
4. 一套 `generic kick` 原子、脚 IK 与最小 motion warping。
5. 上述端到端 harness 场景。

### P1：扩展至可组合社交交互

1. 手部 IK、attachment、grip/release。
2. 拿杯子、递杯子、拒绝接收。
3. `InteractionSession` 与握手。
4. 真实角色模型 provider、对话 provider 与持久会话配置。

### P2：高情感与开放场景能力

1. 拥抱等双人同步动画和面部/语音表现。
2. VLA 与场景实体融合、未知资产识别和置信度治理。
3. 长时间多角色自主运行、性能预算、回放和回归测试。

### 主要风险

- 直接让 LLM 或 VLA 控制骨骼/刚体会导致不稳定、不可重放和 authority 越界。
- 只为每种交互制作专用动画会使内容成本随角色和物品组合爆炸。
- 只用程序化骨骼会使拥抱等高情感接触显得不自然。
- 没有明确 affordance、anchor 和物理结果验证时，角色会产生“看似执行、实际未命中”的假象。
- 当前模型/VLA readiness 不等于在线质量、延迟、安全性和长时稳定性已经验证。

## 9. 建议的下一步

将 P0 的“踢椅子”闭环写成主线 implementation plan，并先完成一条可回放、可失败、可恢复的真实 Godot 场景路径。该路径完成后，再用同一套 affordance、动作控制和观察回流机制扩展至拿杯子、递交、握手与拥抱。
