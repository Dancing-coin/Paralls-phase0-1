# 活跃 plan 与 spec 进度分析

- 日期：2026-08-03
- 状态：已复核更新
- 作者：Codex
- 证据基准：对照当前工作区代码、`docs/INDEX.md`、活跃 `docs/superpowers/specs/` 与 `docs/superpowers/plans/`、以及 2026-08-03 的 `.harness/verification/` 产物
- 性质：活跃规格与实施计划的进度分析，不替代正式 spec / plan
- 治理说明：本文只记录当前复核结论；正式架构边界以 `AGENTS.md` 和正式 spec / plan 为准，运行时完成声明必须以新鲜 Harness 证据为准

## 1. 判断口径

本文把文档明确标为 `execution-active`、`implementation-active`、
`partially-implemented`，或被 `docs/INDEX.md` 列为活跃入口的计划视为活跃。
标为 `completed`、`implemented-and-verified` 的历史 plan 不作为当前未完成
执行线，但会作为依赖和证据来源保留。

当前主线入口是：

- `world-character-siming-authority unified runtime`
- gameplay foundation
- embodied interaction product foundation
- current-project intelligence upgrade 的 provider/VLA 增量线

## 2. 总体结论

当前项目已经越过“只有 demo 和局部协议”的阶段，进入基础运行时和玩法底座
逐步闭合阶段。现状应表述为：

> authority、event spine、具身交互基础和多个 Godot/Backend 切片已被验证；
> mirror live delivery、通用玩法 domain、完整默认场景覆盖和新鲜 LLM closure
> 仍未完成。

最新记录的 Harness 聚合报告为 `overall_harness_passed: true`，主线 unified
runtime、Phase 0、gameplay foundation、embodied foundation、Godot mirror、
TTS profile 和 VLA backend 等已注册 profile 均有通过产物。这个结论只覆盖
已注册的 bounded profile，不应被扩大解释为产品级全量完成。

## 3. 活跃 plan / spec 状态

### 3.1 WebSocket session identity 与 gameplay mirror

- Plan：`2026-08-03-websocket-session-identity-and-mirror-scope-plan.md`
- Spec：`2026-08-03-websocket-session-identity-and-mirror-scope-design.md`
- 状态：plan 为 `execution-active-for-foundation-core`；spec 为
  `implemented-foundation; live-mirror-delivery-planned`
- 已完成：一次性 loopback enrollment、opaque session、multi-actor read scope、
  peer-host propagation、session-scoped bind/subscribe/snapshot/unsubscribe、
  configured backend source、after-commit bounded fanout、Godot disconnect 清理。
- 证据：`godot-gameplay-mirror` profile 通过；事件脊柱和 mirror static/local
  bridge 证据通过。
- 未完成：端到端 reconnect/resync、重新 enrollment 流程、真实 Godot WebSocket
  live mirror deployment proof、backpressure/capability negotiation 的完整闭合。

这是当前最明确的下一阶段主线，因为它把已经存在的 backend authority state
真正送到受 session 约束的 Godot live presentation。

### 3.2 Gameplay foundation shared spine

- Plan：`2026-07-31-coupled-event-store-and-authority-bus-plan.md`
- Spec：`2026-07-31-coupled-event-store-and-authority-bus-design.md`
- 状态：shared spine 已实现并 focused-test 验证；plan 保持 active 是为了维护
  和承接下游 domain，不代表 event store 核心仍未实现。
- 已完成：atomic event batch、stream/global sequence、idempotency、replay、
  committed outbox、after-commit authority bus dispatch、sequence/gap 相关基础。
- 未完成：更广泛的 domain closure、持久化生产实现、完整 gameplay mirror delivery
  和各领域之间的全面 settlement。

### 3.3 Stateful Patch data migration

- Plan：`2026-08-02-stateful-patch-data-migration-plan.md`
- 对应 spec：`persistence-replay-migration-and-hot-reload` 与 Patch Rule IR spec
- 状态：首个 typed resource slice 已实现；broader migration planned。
- 已完成：immutable manifest、active-set lifecycle、explicit actor state-group
  lifecycle、compatible identity rebind，以及 `core.resources` maximum-reduction
  typed migration 的原子提交和 replay 证明。
- 未完成：通用 domain-owned migrator、跨 domain batch、历史 reader/rollback
  compatibility、补偿策略和生产级 Patch registry。

### 3.4 Atomic action library 与默认主场景覆盖

- Plan：`2026-08-01-atomic-action-library-and-default-scene-coverage-plan.md`
- Spec：`2026-08-01-atomic-action-library-and-default-scene-coverage-design.md`
- 状态：`partially-implemented; waves-1-to-3-planned`。
- 已完成：既有 action descriptor/registry 解析、typed
  `action_assets_unavailable`、controller phase binding，以及少量 reviewed
  default-scene fixtures 的 authority success/rejection 和 Godot 证据。
- 未完成：全对象族覆盖、真实 clip playback、CharacterMotor/IK/motion-warping
  接线、Wave 2/3、通用 pickup/container/social interaction。

这里的正确理解是“按 reviewed affordance 逐个扩展”，不是把所有 Godot node
自动变成可交互对象。

### 3.5 Dialogue、TTS 与 voice profile

- Dialogue streaming plan/spec 已分别是 `completed` / `implemented`，不属于当前
  未完成 implementation lane。
- TTS voice profile adapter 的 catalog importer、binding validation、enrollment
  boundary 和 focused profile 已实现；spec/plan 仍为 `implementation-active`，
  因为 operator voice approval、最终 actor mapping 和后续 guarded live synthesis
  仍有外部决策门槛。
- 已有真实 TTS provider 与 Godot 播放证据，但这不等于句级 audio clip queue、
  token/audio streaming 或认知驱动 expressive instruction 已完成。

### 3.6 VLA / intelligence upgrade

- `2026-07-29-vla-real-provider-adapter` 的 adapter 和 backend contract 已实现，
  但默认 profile 的 readiness 仍可以是 `blocked_missing_credentials`；显式 live
  proof 与默认 harness readiness 是两类证据，不能混用。
- `2026-07-30-advisory-vla-routing-and-tts-convergence` 已把生产路线固定为
  `advisory-fast`，`qwen3.7-plus` 的 `advisory-deep` parked、non-blocking。
- fast route 的 Godot capture/live proof 已有证据；deep route 不应重新成为当前
  blocker。
- 未完成：20 个多场景样本的人工 truth review、稳定的质量/准确率评估门槛和
  句级 TTS queue。

## 4. LLM closure 的证据风险

`Complete LLM Integration Closure` 的 plan 文档标记为 completed，且旧的
character live report 曾记录 dialogue/L2/L3 通过。但当前 closure 不能只看旧
报告：

- 旧 closure/character live 产物来自 2026-07-23；
- 当前 2026-08-03 readiness report 的 run ID 为空；
- 当前 Siming backend-chain report 为 `Overall: False`，失败在 provider
  credential check；
- 正式 closure 要求 readiness、Character live proof、Siming proof 使用同一个
  新鲜 `LLM_CLOSURE_RUN_ID`。

因此当前准确状态是：

> LLM closure 的实现代码已完成，历史 live proof 存在；当前新鲜 closure
> 证据未重新收口，不能宣称当前 live closure 已完成。

## 5. 推荐下一步顺序

1. 完成 WebSocket reconnect/resync 和真实 Godot mirror live proof。
2. 以已有 gameplay event spine 为依赖，继续补 gameplay facade 和跨 domain
   settlement，但保持每个 domain 的独立 authority ownership。
3. 按 reviewed affordance 扩展默认主场景 Wave 1，再进入 Wave 2/3；不要做 node-name
   推断式全场景交互化。
4. 重新执行同一 `LLM_CLOSURE_RUN_ID` 下的 Character + Siming live proof，修正
   readiness 与 live evidence 的新鲜度问题。
5. 最后再推进句级 TTS queue 和 VLA deep re-admission/annotation review。
