# 创作者工具、Codex 控制与生态商业化

## 1. 创作者真正需要的不是裸引擎

创作者需要的是“内容生产控制面”，至少包括：

- 世界设定、角色档案、关系和秘密编辑；
- 剧本、事件、任务目标和证据结构化；
- 玩法规则、资产、音频、UI 和动作绑定；
- 角色技能、需求、组织、经济和权限配置；
- 运行、调试、回放、分支、重置和版本发布；
- 资产缺失、规则冲突、隐私泄漏和玩法不可达检测；
- 成本预算、模型路由、算力额度和缓存命中分析。

## 2. Codex 可控制的接口

底座应提供三种相互复用的接口：

### CLI

适合本地项目、CI 和 Codex 直接调用：

```text
project create / validate / build / test
profile validate / install / activate / retire
world add / inspect / replay
character create / bind / inspect / reset
rule enable / disable / verify
asset import / bind / check
run start / stop / snapshot / replay
```

### MCP 或结构化工具 API

适合 Codex、其他智能体和在线工作台：

- 读取项目结构和当前状态；
- 修改允许的内容文件；
- 生成规则/资产绑定提案；
- 运行验证和回放；
- 获取失败原因和修复建议；
- 提交版本发布申请。

### 在线创作工作台

适合非程序创作者：

- 档案、剧本、任务、关系、资产和测试的可视化编辑；
- 统一预览和多人协作；
- 版本、审阅、回滚和分润记录。

## 3. 下载版与在线一键生成

两者不是完全互斥的产品：

### 下载版闭源底座

适合专业开发者、企业、私有数据和高频迭代。优点是可控、可离线、可接入自有工具；缺点是安装、升级、算力和闭源保护更复杂。

### 在线一键生成

适合低门槛创作者。优点是版本统一、算力统一、资产和规则可以自动校验；缺点是隐私、成本、平台依赖和复杂项目可控性较弱。

### 推荐组合

```text
在线工作台：低门槛创作、资产生成、协作和发布
下载版 CLI/SDK：专业创作、Codex 开发、本地测试
远程闭源 Core：角色心智、权威结算、核心状态和关键算法
```

如果完整 Python 核心随下载版交付，就无法绝对阻止创作者修改或反编译。闭源保护应依靠远程核心、签名包、能力白名单和审计，而不是只依靠“不提供源码”。

## 4. 资产商店、生成站和交易市场

建议分成三个产品，不要混成一个“素材商城”：

- 资产生成站：生成模型、场景、动画、声音、UI 和绑定候选；
- 资产商店：经过 schema、版权、性能和运行时适配验证的可用资产；
- 资产/故事结果市场：出售资产授权、规则包、故事方案、角色包和可复用结果。

每份资产和结果至少需要：

- 来源和版本；
- 版权/授权范围；
- 依赖的模型、规则和运行时版本；
- 贡献者和权利人；
- 使用次数、衍生关系和收益分配；
- 可撤销或下架策略。

## 5. IP 共创与分红

本线程中的“创作权和分红权共享”需要比资产交易更完整的权益账本：

- 角色、世界、剧情、资产、规则、模型结果的贡献归因；
- 版本和衍生关系；
- 参与者的创作权、署名权、收益权和治理权；
- 服务器、模型、资产和运营成本扣除规则；
- 争议、撤稿、侵权和下架处理；
- 链上权利凭证与链下内容交付的对应关系。

当前项目没有完成链上确权和分账；现有产权/经济模块不能直接等价为创作者收益系统。
