# 多角色面包店参考包与验证门禁

状态：`historical P2D sample invalidated; P2D-R fixed owner re-closure verified; full three-role/Godot close remains incomplete`

`bakery-authored-agents` 是 `bakery-single-owner` 的多角色增量配置。它验证三个已经
存在的角色能否在一个商业组织内完成不同工作并共享同一条 authority/replay/mirror 事实链，
不验证 NPC 生态或群体模拟。

## 1. 参考包配置

正式内容包需显式声明以下资源，并通过现有 `GameplayPackageManifest` 兼容性检查：

| 内容 | 本阶段要求 |
| --- | --- |
| actor refs | 3 个已在 profile registry 存在且获得内容授权的 `character:<profile_id>` |
| Organization | 一个 bakery organization、一个 owner、一个 jurisdiction、一个 permit |
| roles | `operator`、`baker/production`、`counter/procurement`；岗位关系不改写 authored profile |
| facility | 一个 bakery facility、一个共享 production slot、一个 stock container |
| economy | 既有 bakery accounts、一个固定 supplier quote、聚合 customer demand、工资 policy |
| policy | 一个 survival profile、permit/tax/inspection policy、一个 operating-window policy |
| presentation | 一个 committed-only 管理观察镜像；角色视图按 actor scope 过滤 |

当前 `char_a`、`char_b`、`char_c` 只可作为 contract harness actor。若没有内容授权包，
不能把它们命名为面包师、采购员或店员；不能通过测试 fixture 覆盖它们的 identity、
occupation、记忆或状态。

## 2. 一个经营窗口的可观察脚本

```text
open window W1
-> operator publishes two offers
-> baker accepts production shift
-> counter accepts procurement/counter shift
-> counter uses fixed supplier quote and organization-authorized inventory flow
-> baker submits start_work; skill + survival capability + slot are checked
-> production run finishes with worker contribution evidence
-> output receipt enters stock, aggregate demand consumes one bread
-> economy records sale and wage accrual from evidence
-> operator closes W1; wage paid or overdue obligation is recorded
-> scoped projections and Godot mirror show committed result
```

第二个窗口应覆盖一次可恢复失败：例如 baker 缺席、counter 与 operator 争用同一 slot，
或组织现金不足导致工资逾期。恢复必须通过新窗口/新命令完成，不能编辑旧事件。

## 3. 验证矩阵

### 3.1 成功路径

| 证明 | 证据要求 |
| --- | --- |
| profile-backed actors | 三个 actor ref 均可回查 registry；未知 ref 无事件 |
| 独立协作 | 至少两个角色各有 assignment、accepted shift 和独立 work evidence |
| 生产链 | `reservation -> run_ref -> consume -> output` 顺序可由事件重放重建 |
| 销售链 | 售出数量从 inventory 消失/减少后才出现 sale posting 和 account transfer |
| 工资链 | wage accrual 只引用 completed evidence；payment/overdue 状态可重放 |
| 经营窗口 | open/close、due evaluation、period summary 均为 committed facts |
| projection | actor、manager、Godot 视图字段按 scope 过滤并带 source revision/digest |

### 3.2 失败与恢复

| 场景 | 期望结构化结果 | 应保持不变的 owner 事实 |
| --- | --- | --- |
| synthetic/unknown actor | `character_record_required` | 组织、角色、经济均零写入 |
| 未授权岗位或过期 offer | `work_authorization_denied` / `shift_offer_stale` | 不产生 attendance/work evidence |
| insufficient skill | `insufficient_skill` | 不创建 production run，不预扣工资 |
| Survival 阻断 | `labor_unavailable` | 不修改 need/body；disabled/narrative 遵循 policy |
| 共享炉位争用 | `facility_slot_conflict` | 只有先提交者拥有 slot/run |
| 材料预留争用 | `reservation_conflict` | 失败者不消耗材料 |
| 窗口外提交 | `operating_window_closed` | 原窗口事实不变 |
| 完成证据无效 | `work_evidence_invalid` | 不产生 completed wage accrual |
| 现金不足 | `wage_payment_insufficient_funds` | wage obligation 转 overdue，不伪造付款 |
| stale/duplicate | `revision_conflict` / `duplicate_replayed` | 无第二份事实或部分写入 |
| 隐私越权 | `projection_scope_denied` | 不泄露其他角色私有状态/工资明细 |

## 4. 回放、镜像与 Harness 门禁

历史 `phase2-bakery-authored-agents` profile 不能再作为此门禁证据：它绕过 authority 直接
append synthetic batch，并以合成布尔值汇总能力。P2D-R 改用 focused profile
`p2dr-authored-bakery-authority-reclosure`，
并要求：

1. 先通过 P1B、P1C、P1D 和四个 Econ-1 子 profile；若 P1D 证据链未 fresh-green，P2D
   只能标记 `blocked-by-p1-evidence`，不能以静态文档代替；
2. 运行两条至少包含两个角色的成功/失败场景，并记录 owner/event diff；
3. full replay 与 checkpoint + tail replay 的 organization、production、inventory、
   economy、survival 和 scoped projections digest 相同；
4. 检查所有命令的 idempotency、causation/correlation、expected/pinned revisions 和
   零部分写入；
5. 检查 manager mirror 与 actor mirror 不越过 `GameplayMirrorSubscriptionRegistry` 的
   backend-granted scope；Godot 只消费 committed snapshot/delta；
6. 检查仓库中不存在 `NpcState`、Population authority、动态 order book、第二个 event store
   或 CharacterAgent 直写 store 的新增路径。

## 5. P2 完成声明

只有 P2D-R 继续扩展为真正三角色、scope-filtered Godot mirror 并完成本节所有门禁后，以下
文字才可以在阶段完成后使用：

> 已有角色的多智能体组织协作已在 `bakery-authored-agents` 参考包中通过权威结算、
> 回放、权限投影和 Godot committed mirror 门禁。

同时必须保留以下限制：

- 顾客仍是 `CustomerDemandAggregate`，供应商仍是固定 quote，竞争对手仍是公开 profile；
- 没有员工/顾客/供应商/竞争对手/监管人员的 Population Simulation 连续生活；
- 没有动态市场、自动招聘、金融信用或全局时间调度；
- 自动角色意图默认关闭，除非 P2A/P2C 的正式 spec 与 evidence 明确开启。

## 6. Population Simulation 后续接入门槛

从本参考包进入人口生态前，必须先证明：

1. Population authority 能把角色物化/激活到既有 CharacterProfile/CharacterRecord，而不是
   创建副本；
2. 家庭、职业、预算、知识和连续性 projection 有明确 owner 与权限过滤；
3. 批量计划生成同样的 `GameplayCommandEnvelope`，使用同一 idempotency、revision 和
   append batch；
4. 批量 catch-up、暂停、恢复和失败补偿经过 Harness；
5. 顾客、供应商、竞争对手和监管人员的私有账户/库存/需求在获得授权后才可 materialize。

在这些门槛关闭前，`bakery-authored-agents` 是本阶段的终点，而不是人口模拟的暗门。
