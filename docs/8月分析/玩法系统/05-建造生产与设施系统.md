# 建造、生产与设施系统

状态：`bounded construction/production slice implemented; generic construction and facility lifecycle remain planned`

## 1. 领域职责

建造 authority 维护地块、蓝图、施工阶段、设施状态、产能、维护和产权引用。
经济域只负责工程款、材料价格、贷款、押金和维护账目。

## 2. 核心模型

```text
Plot(plot_id, jurisdiction_ref, ownership_right_ref, zoning_policy_ref)
Blueprint(blueprint_ref, materials, labor, duration, capabilities)
ConstructionJob(job_id, plot_ref, blueprint_ref, progress, worker_refs, status)
Facility(facility_id, ownership_right_ref, capabilities, condition, throughput)
Recipe(recipe_ref, inputs, tools, skills, duration, outputs, byproducts)
ProductionRun(run_id, facility_ref, recipe_ref, inventory_reservation_refs,
  facility_slot_reservation_ref, labor_obligation_refs, finish_tick)
```

生产启动向 Inventory Authority 请求材料/工具预留，向设施 owner 请求时段预留，向
Organization/Economy Authority 提交劳动义务或工资 hold proposal；建造域只保存这些
已提交预留/义务的引用。完成 tick 再验证条件并原子提交产物、磨损、工资应付和
副产物。建造失败不能只退钱而不恢复材料，必须由规则决定释放、损耗或形成返工 job。

`ownership_right_ref` 由产权域解释，`zoning_policy_ref` 由政府域解释；组织的
`OperatingPlan` 只安排工人、预算和生产目标，不能复制 `ConstructionJob` 或
`ProductionRun` 的进度事实。

设施和建筑的静态材料、部位、性质与高频状态必须分开。蓝图可声明墙体、门、
屋顶、基础等 component；语义因果层再根据橡木、石材、金属等物质参数处理
火焰、霜冻、冲击、腐蚀和长期耐久变化。建造域消费最终的设施/部件状态，而
不维护第二套专用火灾或伤害规则。

## 3. 与其他系统

技能提供施工/生产资格和质量；背包提供材料和工具；生存影响工人可用时间和
身体能力；商业组织拥有工坊并安排工作；政府提供 zoning、permit、检查和税费；
任务系统可引用完工证据。

## 4. 当前与新增

- `implemented`：通用 authority event spine、对象状态、产权、库存和能力 gate；
- `reusable`：revision pinning、scheduled hints、replay、Godot presentation；
- `implemented bounded`：P1 Econ-1 的 facility/recipe/production run、材料 reservation、
  completion evidence、output 和失败恢复；
- `planned`：通用 blueprint、plot、设施生命周期、维护、产能和批次质量。

创作者可编辑蓝图、配方、工期、材料需求、视觉绑定和维护参数；设施状态、
材料扣除、产物生成和产权结算必须留在闭源 authority。
