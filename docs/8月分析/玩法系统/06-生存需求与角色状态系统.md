# 生存需求与角色状态系统

状态：`bounded survival/profile and obligation slices implemented; full survival simulation remains planned`

角色心智的 `NeedTensionEngine` 只计算叙事/心理张力，不能替代饥饿、口渴、睡眠、疾病等可结算的 Survival Authority。现有 resources、body、status 与 effective stats 是本领域的复用基础，不是周期性生存模拟。

## 1. 可调整、可关闭的核心模块

生存系统与角色状态强关联，因此属于核心系统；同时必须支持按项目、世界、
角色群组启停和分级模拟：

| 模式 | 结果 |
| --- | --- |
| `disabled` | 不产生需求衰减、消费和身体惩罚 |
| `narrative` | 只产生可供剧情读取的张力标签 |
| `lightweight` | 低频数值更新，提供软惩罚和恢复 |
| `simulation` | 完整需求、消费、身体后果、劳动能力和失败处理 |

模式切换必须是新 ruleset revision，不能直接重写正式角色状态。

## 2. 数据模型

```text
NeedDefinition(need_ref, decay_curve, satisfaction_sources, thresholds)
NeedState(actor_ref, need_ref, tension, last_tick, source_revision)
BodyResource(actor_ref, resource_ref, current, maximum, reservations)
SurvivalPolicy(enabled_mode, tick_interval, failure_policy, recovery_policy)
ConsumptionPlan(actor_ref, need_ref, satisfaction_source_refs, due_tick)
```

Survival Authority 在 tick 中更新需求张力，并只提出“满足哪个需求、何种来源可满足、
何时到期”的消费需求。Inventory Authority 决定 custody 与物品消耗，Economy
Authority 决定 quote、付款方与扣款，Ownership Authority 验证使用权；生存域不能
选择账户或自行扣款。需求满足后才写回状态，并影响有效技能、行动成本、情绪和角色决策。

环境压力必须先由语义因果层表达为可验证 effect，例如寒冷、热量、毒性、潮湿、
疾病媒介或社会压力；生存域负责把 effect 作用到需求、身体资源和恢复策略。
这样霜冻既能影响农田，也能影响无保暖装备的角色，而不复制两套气候规则。

## 3. 玩法闭环

```text
时间衰减 -> 饥饿/疲劳/住房张力
-> 休息、购买、采集、工作或求助
-> 物品/经济/组织结算 -> 身体和状态写回
-> 技能、关系、任务和经营结果变化
```

## 4. 当前与新增

- `implemented`：resources、body、status、effective stats、state groups，以及角色
  needs/affect 运行态；
- `reusable`：状态组启停、事件重建、policy-filtered view、reservation 和 replay；
- `implemented bounded`：Survival profiles、need/consumption proposals、body/status gates、
  obligation expiry/overdue handling and replay；
- `planned`：完整 Survival Authority、需求衰减调度、四档长期模拟、身体后果与劳动能力反馈。

创作者可调整需求列表、曲线、物品映射、阈值、难度和启停；不能直接写 hunger、
health、stamina 或隐藏身体 workspace。
