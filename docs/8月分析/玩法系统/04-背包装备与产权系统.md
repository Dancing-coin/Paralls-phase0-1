# 背包、装备与产权系统

状态：`通用 Inventory Platform implemented-and-verified；既有 item/container/custody 窄行保持兼容基线；August INF A-D not complete`

状态：`implemented/reusable foundation guidance; advanced logistics and rights remain planned`

## 1. 三种事实

必须区分：

- `custody`：物品当前在谁的哪个容器；
- `equipment`：物品是否激活并占用角色槽位；
- `ownership`：谁拥有法律权利，是否有凭证、抵押或租赁限制。

“拿在手里”不等于拥有，“拥有地契”也不等于当前站在那块地上。

## 2. 数据模型

```text
ItemDefinition / ItemInstance / ItemLot
ContainerSpec / ContainerState
CustodyRecord(item_ref, container_ref, holder_ref)
EquipmentActivation(item_ref, slots, modifier_refs, grant_refs)
OwnershipRight(asset_ref, holder_ref, right_kind, revision)
```

库存 authority 保证单一位置、容量、密封、负重、转移和幂等；装备 authority
在同一批中处理卸装、槽位冲突、modifier 激活和能力路径 grant；产权 authority
独立处理 title transfer、credential issue/revoke。

## 3. 与玩法协作

技能读取装备 modifier 和工具可用性；建造读取材料与工具 custody；生存读取
食物、衣物和住房物品；经济购买导致 payment、custody 和 ownership 的联合
结算；任务读取证物的存在与持有者，但按隐私规则过滤。

## 4. 当前与新增

- `implemented`：item/container、单一位置、容量/负重、装备槽、产权转移和凭证；
- `reusable`：event-derived projection、原子 batch、filtered mirror、replay；
- `planned`：可替代 lot 堆叠/拆分、耐久和质量、腐败、仓储/物流、租赁/抵押/没收、
  复杂容器嵌套与经济成本。

创作者可以定义物品、槽位、容量、标签和权利类型，不能直接移动正式库存或
伪造 title。
