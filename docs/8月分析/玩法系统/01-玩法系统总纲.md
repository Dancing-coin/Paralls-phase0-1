# 玩法系统总纲

状态：`incremental gameplay guidance; existing authority slices are reusable and new gameplay domains are planned`

## 1. 目标

玩法系统要让角色的能力、物品、身体、目标、关系、组织和环境形成持续可玩的
闭环。它包含即时具身、个体生活、生产交换、社会制度和世界演进等不同层级；
“能在后台自主推进”不是把经济或政府排除出玩法的理由。闭环必须满足：可组合、
可关闭、可调参、可回放、可解释、可多人并发，且最终真相由闭源 authority 维护。

领域拆分不等于每个领域各造一套世界。所有玩法必须共同依赖三个前提：

1. **万物档案**：角色、物品、农田、建筑、环境和事件拥有独立连续本体；
2. **语义因果层**：类型、材料、物质、性质、状态、效应、抵抗和元规则可以
   被不同玩法复用；
3. **因果结算链**：所有动作先产生事实，再解析语义和效应，最后由 authority
   原子提交状态变更。

其中标签体系和元规则引擎是对既有 `world_runtime` / ESM / Gameplay authority 路径的增量扩展，
不是并列 runtime。其具体 contract 以
[00-标签体系与元规则引擎.md](../世界基础设施增量指导/00-标签体系与元规则引擎.md) 为准；各玩法域
不能自行发明自由字符串标签、未注册属性或私有规则解释器。

```text
角色档案/状态
  -> 意图与行动资格
  -> 技能、物品、设施、关系和环境约束
  -> authority settlement
  -> 事件、投影、任务进度、经济和呈现镜像
  -> 新状态与新选择
```

## 2. 在全域架构中的位置

```text
Existing world_runtime / ESM extension path
  -> Entity/Thing/Environment records、语义、规则、因果、调度与生态
  -> Character Core + Social Projection Guidance：角色意图、感知、知识与关系的受限投影
  -> Layered Gameplay
       L1 行动/感知/冲突
       L2 技能/物品/生存/任务
       L3 建造/生产/交易
       L4 组织/监管/金融/公共秩序
       L5 文明能力与长期世界选择
  -> Presentation：Godot、音频、UI、调试和回放视图
```

世界事实层不强迫角色、土地和武器使用相同字段；它们共享 identity、类型标签、
位置、事件引用和领域 projection 的连接方式。每个领域只拥有自己那部分事实，
既有世界运行时扩展不直接越权写入领域 stream。全局 owner 以
[系统边界与责任矩阵](../全域架构/00-系统边界与责任矩阵.md) 为准。

## 3. 领域边界

| 领域 | Canonical owner | 典型事件 |
| --- | --- | --- |
| 技能成长 | Skill Authority | learned、training、action_resolved、promotion |
| 背包装备产权 | Inventory/Ownership Authority | item_created、moved、equipped、custody_changed、right_transferred |
| 建造生产 | Construction Authority | work_started、material_consumed、facility_completed、maintenance_due |
| 生存状态 | Survival Authority | need_decayed、consumed、body_changed、recovery_applied |
| 任务剧情 | Quest/Story Authority | objective_activated、evidence_added、stage_advanced、quest_completed |
| 战斗冲突 | Conflict Authority | encounter_started、hit_resolved、damage_applied、retreat_settled |
| 行动与潜行扩展 | Action/Perception + Conflict Authority | action_resolved、trace_generated、exposure_resolved |
| 修炼与超自然 | Cultivation Authority | resource_circulated、technique_resolved、breakthrough_settled |
| 社会与制度玩法 | Economy/Organization/Governance/Polity Authorities | quote_resolved、wage_settled、permit_issued、tax_assessed、policy_effective |

一个领域可以读取其他领域的 pinned projection，但不得直接写入其他领域的
canonical stream。L4/L5 域具有独立 authority，并不削弱它们作为玩法层的地位。已经
落地的领域 authority 继续按当前方式直接构造事件并调用既有 `GameplayEventStore.append_batch`。
只有当“新增语义/因果/跨域 adapter”尚未收口为单一领域事件映射时，才由 `planned` 的
`GameplaySettlementCoordinator` 生成和验证预提交 `SettlementPlan`，随后仍落回既有
`append_batch` 原子提交。

## 4. 创作者运行边界

玩法包只包含声明式定义、参数、资产引用、依赖和 capability 声明。编辑者可
在 Workbench 中修改草案和模拟世界，管理员通过签名 revision、staging/canary
和 world tick 激活；正式运行时的真实玩家状态不接受直接写入。

创作者调节生存模块、战斗伤害、技能门槛或市场参数时，实际修改的是新的
`ruleset revision`。当前 session 固定自己的 revision，迁移由闭源 migrator
执行，保证旧局可回放。

## 5. 统一因果交互协议

```text
ActionIntent
  command_id, actor_ref, intent_kind, target_refs
  expected_revision_vector, requested_capabilities, idempotency_key

PhysicalFact | LogicalFact
  fact_id, source_refs, target_refs, spatial_or_domain_measurements, evidence_refs

SemanticEvaluationInput
  semantic_snapshot_digests, effect_refs, resistance_inputs, policy_context_refs

SettlementPlan
  proposal_id, typed_domain_changes, pinned_revisions, policy_refs
  causal_parent_refs, explanation_digest, no_persistence_yet

SettlementReceipt
  transaction_id, committed_event_ids, projection_digests
  rejected_effects, audit_refs
```

普通移动、简单资源扣减可以走快速路径，但它仍必须输出同样的结构化事实。对已经
落地的领域 slice，这些事实可以直接进入其现有 authority 校验和事件映射；不要求
先物化一个独立 `SettlementPlan`。只有新增语义/跨域 adapter 才需要显式预提交
`SettlementPlan`。无论走哪条路径，每项 proposed change 都必须由 owning domain
映射成事件 schema；任何一项验证失败时，`append_batch` 零提交。模型、NPC、Godot
和创作者工具只能提交 intent/proposal 或读取过滤后的 view；不能成为世界真相写入端。

## 6. 分阶段增量路线

本节是与 mainline plan tree 对齐的分析层 backlog，不表示这些阶段已经同步为正式执行授权。

1. 先完成实体档案、语义标签、效应/抵抗、元规则，以及仅供新增 adapter 使用的预提交 `SettlementPlan`；
2. 用“霜冻农田”或“火焰橡木门”跑通首条跨域垂直样板；
3. 再以经济、库存、技能、生产、生存组成 Econ-1 跨层生活与经营循环；
4. 接入任务、社交、潜行和冲突，形成 RPG/剧本杀可玩闭环；
5. 扩展组织经营、政府监管、动态市场、公共秩序和持久世界经营；
6. 最后增加文明能力、跨辖区、多世界、群体模拟和反事实推演。
