# 行动基元与具身交互

状态：`implemented/reusable interaction foundation; generic ActionPrimitive registry and physical-fact contract are planned`

## 1. 领域职责

行动层是玩法的共同输入面：它把角色、玩家或 NPC 的语义意图接到现有具身互动和
领域 authority。它不拥有世界事实，也不把本地动画、VLA 建议或控制器完成信号当作
结算成功。

当前已有的正式依据是 [原子行动库与默认场景覆盖设计](../../superpowers/specs/world-character-siming-authority-mainline/embodied-interaction-product-foundation/2026-08-01-atomic-action-library-and-default-scene-coverage-design.md)：
语义 action、行动资产、`EmbodiedActionController`、审阅 affordance 和后端 authority
仍是分工协作，而不是第二套动作或世界状态系统。

```text
角色/玩家/NPC 的 structured intent
-> 已审阅 affordance 与后端 preflight
-> 本地导航、对齐、接触观测与恢复
-> authority accept/reject
-> committed event + filtered presentation
```

## 2. 当前基础与计划性收口

| 层 | 当前状态 | 边界 |
| --- | --- | --- |
| 语义行动与动作资产 | `implemented/reusable` | `selected_skill_path`、primitive tags/realization keys 与现有 action-asset registry 可复用；它们不是完整战斗动作库 |
| 本地具身执行 | `implemented/reusable` | `EmbodiedActionController` 负责导航、对齐、接触窗口、取消和恢复；不结算世界结果 |
| 场景 affordance | `implemented/reusable` | 已审阅对象可返回成功或结构化约束；未注册对象不因“看起来可达”而获得交互权限 |
| 通用行动语义 | `planned` | 统一 `ActionPrimitive` registry、可组合的 `ActionIntent` 和物理/逻辑事实 envelope |
| 玩法专属判定 | `planned` 或领域已有 | 技能、背包、建造、生存、冲突等各自拥有资格、成本和后果事件 |

当前 Harness 的边界证据见 [embodied-affordance-registry report](../../../.harness/verification/embodied-affordance-registry-report.md)。它只证明审阅的门、工作台、座椅、令牌等窄场景切片；不证明泛化物理、所有物体可交互、战斗命中或完整动作游戏。

## 3. 统一结算中的位置

后续通用 `ActionPrimitive` 至少应描述语义动作、所需 capability、目标种类和本地
观测要求。`PhysicalFact` 描述接触、位置、遮挡或作用力等可验证证据；交易、对话、
建造计划等不依赖物理接触的情况则形成 `LogicalFact`。二者都必须由对应 authority
映射成领域事件。

```text
ActionIntent
-> PhysicalFact | LogicalFact
-> 领域资格/资源/语义检查
-> 直接事件映射，或新增跨域 adapter 的预提交 SettlementPlan
-> GameplayEventStore.append_batch
```

这不是要求现有 inventory、economy、body 或 interaction slice 迁到新 coordinator；
它们继续保留当前的“校验 -> 构造事件 -> `append_batch`”路径。

## 4. 与感知、技能和表现的边界

- 感知决定行动者或观察者能知道什么，潜行/调查由
  [行动、感知与潜行系统](../角色与社会投影增量指导/16-行动感知与潜行系统.md) 扩展；
- 技能、身体资源、装备和状态只提供资格、成本、修正或失败原因，不由行动控制器写入；
- 建造、生产、冲突、交易等玩法只声明自己的 domain intent 和结果事件，不再复制本地动作资产契约；
- Godot、动画、音频和 VLA 只消费 authority 结果或提供 advisory，不能提交世界成功。

## 5. 后续验收

通用行动层进入正式计划后，首个新增动作必须证明：已审阅的 intent；前置拒绝；
本地中断/恢复；后端唯一结算；重复 command 不重复写入；断线重连后只按 committed
结果更新呈现。战斗、潜行和建造必须在此基础上增加各自的领域验收，不能借用本文件
宣称已完成。
