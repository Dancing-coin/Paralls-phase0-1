# 经济系统底座

状态：`bounded fixed-offer, debt, dynamic-quote and credit slices implemented; macro finance remains planned`

下列 `EconomicSubject`、currency、posting、hold、market 和组织模型是基于现有账户、库存、产权和事件脊柱的后续领域扩展。经济是 L3 生产与交换、L4 社会与制度玩法的共同核心：角色可以劳动、消费、交易、创业或投资，NPC/组织也可按日程推进相同的受限意图。当前实现只覆盖账户投影、同币种转账、固定报价购买、赠与、产权、简单债务、受限合同和后端查询过滤；它不构成动态市场、企业经营或税收监管运行时。

## 1. 定位

经济 authority 负责价值的计量、持有、预留、转移和义务结算；不负责角色技能事实、
物品位置、设施状态或需求张力。玩法层则把这些不同 authority 的受限投影组合为劳动、
交易、经营和投资选择；两者不能混为同一个 writer。

## 2. 核心模型

```text
EconomicSubject
  subject_id, kind(character|npc|organization|government), jurisdiction_ref

Currency
  currency_ref, scale, issuer_ref, monetary_policy_ref

Account
  account_id, owner_ref, currency_ref, balance_projection, status

EconomicTransaction
  transaction_id, kind, initiator_ref, counterparties
  quote_ref, policy_revision, idempotency_key

JournalEntry / Posting
  entry_id, account_id, direction, amount, reason_code, effective_tick

Hold
  hold_id, account_id, amount, purpose_ref, expires_at, status

Debt / Contract
  principal, outstanding, due_tick / terms_ref, evidence_kind, status
```

余额和债务余额都是事件投影，不能接受客户端传入的新值。转账、购买、工资、
税费和偿还必须在一个 atomic batch 中保持金额守恒；重复命令由 idempotency
key 返回原结算结果。

## 3. 与其他玩法的协作

| 协作者 | 经济读取 | 经济产生 |
| --- | --- | --- |
| 技能 | 工作资格、完成证据、效率/质量 | 工资、培训费、服务收入 |
| 背包/产权 | item lot、custody、title | 购买付款、资产转移记录 |
| 建造 | 设施所有者、施工证据、维护成本 | 工程款、材料成本、贷款/押金 |
| 生存 | 消费计划、住房/医疗价格 | 商品消费、生活支出 |
| 商业组织 | 预算、库存目标、经营周期 | 收入、成本、工资、利润和债务 |
| 政府监管 | 辖区和有效政策 revision | 许可费、销售税、财产税、罚款 |

## 4. 动态市场

第一阶段采用周期性权威报价：`MarketQuote` 固定商品、买卖价、数量上限、
有效 tick、政策版本和解释摘要。购买必须引用未过期 quote，不能自行传单价。

报价依据库存覆盖天数、基础需求张力、生产成本、运输和税费计算。订单簿、
拍卖、做市、跨区贸易、汇率和通胀属于后续阶段，不能削弱第一阶段的 authority
和回放约束。

## 5. 经济不是脱离世界本体的数字表

商品、土地、作物、设施和货币凭证必须引用独立实体档案与事件链。经济只保存
价值、账户、义务和权利投影；农田的肥力、作物状态、霜冻损伤和产量仍属于其
自身的 `Thing/Environment` 档案。这样一次霜冻可以由语义因果层产生统一的
`SettlementPlan`，再分别影响作物产量、面包店原料成本、土地资产价值、
所有者情绪和政府救济资格。

金融、制造、公司制或股票等机制必须由 `CivilizationCapability` 解锁。不同
世界可以只启用以物易物或单货币商店，不允许低文明模板自动获得完整金融市场。
消费和劳动计划还应由家庭义务、角色知识与信用条件共同调制；银行、证券和
系统性信用风险属于 [21-金融信用与投资系统.md](21-金融信用与投资系统.md) 的后置领域，
不能被误实现为普通账户余额的自由乘数。

## 6. 创作者开放边界

可编辑：货币显示、商品定义、商店报价规则、税率档位、工资策略、市场周期、
组织经营目标。

必须闭源：分录生成、金额守恒、冻结/解冻、产权结算、债务状态迁移、跨域原子
提交、回放和隐私投影。创作者只能调用 `economy.quote.resolve`、
`economy.settlement.commit` 等已注册 capability。

## 7. Econ-1

Econ-1 的前置验收是语义因果垂直样板，而不是直接开始做商店。随后实现单币种、
单辖区、一个面包店、一个政府组织、三类商品、一个生产配方、一个技能工作单、
一个食物需求、每日报价、销售税和许可证。验收必须覆盖生产、购买、消费、工资、
税费、资金不足、材料不足、许可证过期和重复 tick replay。

## 8. 状态矩阵

- `implemented`：账户投影、同币种转账、固定报价购买、gift、债务、简单合同、
  产权和事件回放基础；
- `reusable`：Gameplay event store、原子 `append_batch`、幂等、隐私投影、
  ownership/custody 分离、Patch capability 边界；
- `implemented bounded`：currency/account projection、fixed/dynamic quote、journal-like
  settlement、production/wage/tax、debt/credit、replay and zero-write rejection；
- `planned`：通用 currency registry、lot/hold 扩展、CivilizationCapability、完整
  SimulationClock 和跨域 settlement coordinator。
