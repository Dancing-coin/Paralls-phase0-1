# 政府组织与监管系统

状态：`bounded permit/tax/inspection/credit slices implemented; general policy activation remains planned`

## 1. 定位

政府组织是 L4 的制度玩法主体，不拥有“万能管理员”权限。玩家可作为居民、经营者、
官员或利益相关方处理许可、税则、检查、申诉、补贴和公共建设；政府通过这些注册
capability 影响其他组织和角色。

## 2. 数据模型

```text
Jurisdiction(jurisdiction_ref, parent_ref, calendar_ref, currency_ref)
PermitDefinition(permit_ref, activity_tags, fee_policy, validity_period)
Permit(subject_ref, permit_ref, issued_at, expires_at, status)
TaxPolicy(policy_ref, tax_base, rate, allowance, effective_tick, sunset_tick)
TaxLiability(subject_ref, assessed_base, amount_due, due_tick, status)
Inspection(subject_ref, rule_ref, evidence_refs, result, penalty_ref)
```

政府域决定政策和管辖权；经济 authority 负责许可费、销售税、工资税、财产税、
罚款和补贴的账户分录。税务评估保存基数、政策版本和舍入方式，历史政策不能
被覆盖。

## 3. 监管流程

```text
活动申请 -> 资格/辖区校验 -> fee hold/payment -> permit issued
-> 经营或交易形成 tax base -> liability assessed
-> 到期扣款/转债务 -> inspection evidence -> penalty/appeal
```

没收、冻结和停业必须是有原因、可申诉、可回放的状态变更；政府不能直接从
库存或账户删除资产。政策启停采用 signed revision + scheduled activation（两者均为待建设能力）。
税务监管只是公共权力的一部分；授权正当性、公共预算、执法、领土和军事冲突
由 [22-政治军事与公共秩序系统.md](22-政治军事与公共秩序系统.md) 继续展开。

## 4. 当前与新增

- `implemented`：ownership/economy 原语、append-only event、审计和 Patch capability
  边界；
- `reusable`：revision pinning、privacy view 与 replay/migration 脊柱；
- `implemented bounded`：permit verification/expiry、inspection/tax、公用义务、credit 和
  stale-policy/zero-write/replay boundaries；
- `planned`：通用 policy authority、signed scheduled activation、jurisdiction 扩展、appeal、
  penalty、补贴和公共建设预算。

创作者可编辑税率、许可类型、检查规则、辖区内容和政策生效时间；不能提供
任意监管脚本、读取所有居民隐私或直接覆盖经济账本。
