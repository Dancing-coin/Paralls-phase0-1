# F1C 玩法包版本激活与闭源边界

状态：`partial-foundation verified; creator control plane remains planned`

## 大白话

P6 真正缺的不是一个漂亮 UI，而是“一个玩法包从草案到正式启用时，谁能做什么、版本是否可信、出问题怎么回滚”。F1C 把这条链写成合同。

## 必须定义

- immutable manifest、digest、schema、依赖、capability allowlist；
- `draft -> preview -> staging -> active` 以及 rejected/withdrawn/rolled-back；
- reader/editor/admin 在 UI、CLI、MCP 上一致的授权结果；
- 激活、回滚、审计如何进入既有 authority batch。

## 验收

focused tests 要覆盖签名/digest、权限拒绝、三种入口一致性、过期激活、原子激活/回滚、migration failure、audit completeness、replay 和拒绝零写入。没有闭源 core owner 和 rollback target，P6C/P6D 继续 `planned/blocked`。
