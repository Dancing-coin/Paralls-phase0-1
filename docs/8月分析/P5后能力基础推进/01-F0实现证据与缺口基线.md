# F0 实现证据与缺口基线

状态：`implemented-and-verified; evidence baseline only`

## 大白话

先把账算清楚：哪些已经真的有代码和测试，哪些只是八月分析里写过，哪些只有一个窄样板，哪些被 blocker 卡住。没有这张账，P6/P7 很容易把“设计过”误说成“已经有底座”。

## 五条盘点线

| 线 | 必查内容 | 主要证据入口 |
| --- | --- | --- |
| 具身/呈现 | action library、默认场景、Godot mirror、TTS/对话/资产排除项 | embodied foundation、Godot profiles |
| 玩法 | action、skill、inventory、ownership、combat、survival、supernatural | Gameplay authority、P1/P4/P5 reports |
| 角色/社会 | relationship、identity、family、knowledge、perception、privacy | Character Core、P5B、scoped projections |
| 世界/司命 | entity、semantic、causal、time、world mode、Siming proposal | world_runtime、ESM、Siming event path |
| 创作/运营 | package、revision、permission、preview、activation、rollback、audit | 创作分析、Patch/runtime、P6 design |

## 交付物

逐文件账见 [F0 八月分析逐文件覆盖台账](07-F0八月分析逐文件覆盖台账.md)。它以 `verified/partial/planned/blocked/not-applicable` 记录状态；`f0-owner-map` 指向已有 owner；`f0-gap-register` 指向 F1A/F1B/F1C/F2；`f0-claim-ledger` 记录不能宣称的范围。

## 停机条件

找不到 owner、证据互相矛盾或只有未来日期的文档时，标为 `blocked`，不能自动判绿。
