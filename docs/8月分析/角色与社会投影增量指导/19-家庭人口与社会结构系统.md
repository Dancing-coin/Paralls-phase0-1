# 家庭、人口与社会结构系统

状态：`planned household/population extension; it must not create a second character or economy store`

## 1. 为什么不能把家庭当作普通组织或一组关系标签

一个角色可以同时是消费者、照护者、子女、配偶、雇员、债务人、资产所有者和
纳税人。家庭不是“家庭组织 NPC”，而是人口、亲属、居住、照护、共同消费和
继承义务的持续事实；它会改变经济计划、日程、情绪、任务和社会稳定。

## 2. 核心模型

```text
Household
  household_id, residence_ref, member_refs, shared_inventory_ref, budget_ref

KinshipEdge
  subject_ref, relative_ref, relation_kind, legal_or_cultural_status, visibility

CareObligation
  obligation_id, provider_ref, dependent_ref, kind, schedule, priority, status

DemographicProfile
  character_ref, life_stage, health_band, occupation_refs, migration_status

InheritancePlan
  estate_ref, beneficiary_refs, policy_ref, evidence_refs, status
```

亲属、婚姻、监护、收养、共同居住和继承不是同一种 relation；文化规则可以
定义可用关系类型，但每个关系都必须有 source event、有效时间、可见性和法律/
社会语义。家庭共享库存或预算仍由 inventory/economy authority 维护，不创建
第二套物品和账户真相。

## 3. 生命周期与跨域影响

```text
出生/迁入/结伴/分居/死亡/继承
-> household membership 与 care obligations
-> 消费、工作时段、教育、医疗、住房与资产变化
-> 情绪、关系、声望、任务、税务与人口统计投影
```

日级模拟处理照护、家务、消费和日程冲突；长周期处理生命阶段、健康、教育、
迁徙、继承和人口结构。高精度角色激活只能对同一 `CharacterRecord` 的 pending
changes 做 revision-checked merge，不能把家庭成员替换成统计平均值。

## 4. 隐私、权限与创作者边界

亲缘、监护、家庭秘密、收入、居住和遗嘱均可能是 `project_private` 或
`runtime_private`。玩家/角色看到的是 Perception/Knowledge Authority 裁剪后的
视图，不因其在同一场景就获得完整家庭档案。创作者可定义家庭制度、文化关系、
照护与继承政策；正式成员、资产、亲属状态和遗产结算仍由 authority 管理。

## 5. 当前与新增

- `implemented`：角色档案、关系种子、需求/情绪、账户/产权/合同、事件与隐私投影；
- `reusable`：Organization/EconomicSubject、时间调度、关系记录、ownership、
  Creator Control Plane 和 replay；
- `planned`：Household/Kinship/Care/Demographic/Inheritance authority、共享预算与
  库存规则、生命周期事件、家庭日程、人口统计 projection 和隐私策略。
