# 玩法包契约

状态：`planned package contract; current Patch runtime is a narrower trusted internal slice`

玩法包是玩法内容和声明式规则的交付单元，不是新的 world store、authority 或可执行
脚本容器。它的任务是说明“这个玩法依赖什么、能产生什么、怎样兼容和验证”；谁能
创建/发布它由 [创作者权限与闭源控制面](../10-创作者权限与闭源控制面方案.md) 决定，
如何跑垂直样板见 [17-垂直样板与验收矩阵.md](17-垂直样板与验收矩阵.md)。

```text
GameplayPackageManifest
  package_id, revision, required_core_version
  entity_kinds, semantic_tags, fields, effects, rules
  capabilities, presentations, schema_versions, compatibility_range
  migration_ref, test_scenarios, declared_dependencies
  content_digest, signature
```

每个包必须声明读取哪些实体/字段、产生哪些 effect/状态变更、需要哪些已注册
capability，以及其表现、测试和迁移引用。`migration_ref` 只引用闭源核心已注册、
签名且可测试的 migrator；包本身不得附带可执行 migration、Python/GDScript、事件删除
指令或 authority handler。未注册字段、能力、解释器或依赖一律 fail closed。

标签、字段、effect 与规则必须引用
[标签体系与元规则引擎](../世界基础设施增量指导/00-标签体系与元规则引擎.md) 的已发布 revision。
包可以声明新定义草案，但不得私带解释器或绕过冲突、循环、预算与优先级验证。

## 当前与新增

- `implemented`：Patch/Rule IR、manifest/digest/依赖 gate、authority capability 与 event/replay；
- `reusable`：schema registry、trusted manifest、revision pinning、outbox、audit 与 Godot mirror；
- `planned`：面向创作者的玩法包 schema、effect/rule dependency validator、签名发布、
  package compatibility/migration gate 和独立的 package Harness。
