# 创作者草案、预览与发布流程

状态：`planned creator workflow; this file does not define a currently available external API`

本文件只描述玩法包从草案到可激活 revision 的流程。权限、数据分级和 command/query
contract 由 [10-创作者权限与闭源控制面方案.md](../10-创作者权限与闭源控制面方案.md)
拥有；跨领域闭源保护由 [11](../11-全面闭源核心保护与创作者控制面方案.md) 拥有。

```text
draft -> schema/dependency/privacy validation -> preview simulation
-> effect/rule conflict report -> replay oracle -> review
-> signed revision -> staging/canary -> scheduled activation -> audit
```

`editor` 可创建草案、校验、模拟、查看 diff 并提交审核；`admin` 才可发布、启用、
迁移或回滚。UI、CLI、MCP 必须调用同一个未来 control-plane contract，均不能导入
内部结算函数、追加 production event 或上传可执行 authority 脚本。

预览只使用隔离世界、合成主体和可重置事件。它能执行规则，但其账户、库存、产权和
事件绝不能成为 Production 的真相来源。任何 activation 都必须固定 content/core/schema/
semantic/policy 等 revision，旧 session 的迁移由闭源 migrator 和正式 plan 决定。

当前 Patch 生命周期只是可复用的内部基础，不能据此宣称已有对外 Workbench、发布服务、
Preview 产品或 `reader/editor/admin` grant。
