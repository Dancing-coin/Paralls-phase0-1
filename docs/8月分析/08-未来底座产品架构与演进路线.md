# 未来底座产品架构与演进路线

## 1. 不应维护多套智能体核心

未来需要多个底座，但差异应主要在“形态适配、玩法域和工具面”，不应复制多套角色心智：

```text
共享核心：档案、心智、记忆、目标、权限、事件、回放、authority
        ↓
玩法域：RPG、战斗、任务、经济、生存、组织、建造
        ↓
形态层：3D、VRM、2D、Live2D、像素、VR、机器人仿真
        ↓
创作控制面：CLI、MCP、在线工作台、资产市场
```

## 2. 建议的底座产品族

### A. 剧本杀/调查 RPG 底座

第一优先级。重点是：

- 角色秘密、关系、记忆和信息可见性；
- 调查、对话、证据、任务目标；
- 物品、场景交互、简单交易和契约；
- 司命节奏、公平性和结果复用；
- Godot/2.5D/网页等轻量呈现。

### B. 通用 3D RPG 底座

在 A 的基础上补充：

- 任务和剧情目标系统；
- 完整技能和成长；
- 战斗、伤害、敌人 AI、掉落；
- 建造、生存和更完整经济；
- 多场景和持久世界。

### C. 2D/Live2D/箱庭底座

复用角色心智与剧情，但替换：

- 2D 感知；
- 2D affordance；
- 2D 运动与碰撞；
- Live2D/像素/视频图文表现。

### D. VR/沉浸式陪伴底座

重点是：

- 第一视角空间感知；
- 注视、触碰、手势和手套；
- 角色同意、边界、距离和情绪反馈；
- 低延迟 embodiment 与安全接管。

### E. 世界模型实验与机器人沙盒底座

重点是：

- world model prediction；
- world action model；
- 物理仿真、轨迹预演和安全验证；
- 传感器延迟、动力学和 sim-to-real；
- 与游戏世界共享状态、动作和回放协议，但不共享全部产品规则。

## 3. 推荐演进顺序

```text
当前
角色心智 + authority + 具身交互 + RPG 基础玩法
  ↓
第一阶段
剧本杀创作工具、CLI/MCP、任务/证据/关系/剧情包
  ↓
第二阶段
战斗、成长、生存、建造、商业组织和完整经济
  ↓
第三阶段
2D/Live2D/VRM/VR 形态适配器与多端发布
  ↓
第四阶段
世界模型预测、结果复用、可交互生成资产
  ↓
第五阶段
机器人沙盒、脑内预演和现实动作安全闭环
```

## 4. 关键工程原则

- Godot、2D 客户端和机器人仿真都不是世界真相源；
- 角色模型不直接写低层运动或玩法状态；
- 世界模型不直接确认世界变化；
- 经济不直接修改背包、技能、建筑和生存状态；
- 每个状态只有一个 canonical owner；
- 任何跨域结果都通过 typed proposal 和 atomic settlement；
- 所有内容包和模型结果必须版本化、可回放、可审计；
- 创作者配置和闭源核心实现必须严格分离。

## 5. 第一版产品的合理完成线

第一版不需要完成“所有 RPG”，但应做到：

1. 创作者能用 CLI/工作台导入世界、角色、剧本和资产；
2. 系统能自动验证档案、关系、秘密、动作和资产绑定；
3. 角色能感知、记忆、理解、规划并完成结构化行动；
4. 调查、对话、物品、证据和简单任务形成闭环；
5. 失败有约束原因，状态可回放，Godot/2D 表现可替换；
6. 作品能打包、发布、复用和记录贡献/收益；
7. 闭源 core 不被创作者内容包直接删改。
