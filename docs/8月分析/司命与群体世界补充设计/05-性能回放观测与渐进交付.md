# 性能、回放、观测与渐进交付

状态：`proposed; existing Harness/replay substrate is reusable, no end-to-end capacity claim`

对应母规格：[Character Simulation Memory Seed And Continuity Design](../../superpowers/specs/world-character-siming-authority-mainline/2026-08-22-character-simulation-memory-seed-continuity-design.md)，映射范围：budget、replay、evidence 和 staged delivery。

## 为什么

owner-only 结算不应拖慢本地 3D 表现；反过来，群体/图谱/表现也不能以高频写入淹没事件脊柱。性能必须与 replay 和审计同时设计，而不是等世界规模扩大后补救。

## 运行预算

| 时间尺度 | 责任 | 写入策略 |
| --- | --- | --- |
| 毫秒级 | Godot 本地动画、移动、镜头、音效 | 不逐帧生产 append |
| 秒/分钟级 | 中场角色壳、局部社交、近场候选 | 读 projection；只有业务后果提交 intent |
| 小时/天级 | 远场群体、经济、生产、生态 | 批量、合并、owner-specific settlement |

## 必需证据

- 每个 vertical：success、zero-write rejection、privacy、revision、idempotency、receipt、full/tail replay；
- 图谱：来源修正后派生结果重建等价；
- 表现：同一 projection digest 的 deterministic mapping 或明确 asset fallback；
- 性能：plan size、owner append count、projection latency、agent activation count、replay time 的可重复 profile；
- 降级：过载时保留事实结算和近场安全路径，降低图谱分析、远场精度与非关键表现。

## 调研驱动的性能边界

OASIS 说明大量 agent 必须有离散 action、批量调度和预算控制；其“百万 agent”不是 Paralls 的完成标准。Paralls 的指标是每一层在固定输入、seed 和 revision 下可重演、可降级、不会写出无 owner 的事实。KurrentDB 的 event-native 经验支持 expected revision、append 和订阅投影，但 Paralls 必须继续使用既有 `GameplayEventStore`，不能为规模另建 event database。Sotopia 的 sampler/evaluation 可启发社交模拟测试集：应把高成本 agent 的启动数、每 batch token/模型预算和行为质量作为 profile 指标，而不将生产数据库或隐私记忆暴露给 benchmark。

## 执行状态

先为一个完整群体到近场 vertical 建立 Harness profile 和基线指标；没有实测证据前，本包不得使用“可扩展”“实时”或“高并发已验证”的完成声明。

## 可复现的性能 profile

性能验证不是一次机器上的帧率截图。每个 profile 固定 world mode、source event vector、policy/mapping revision、seed、cohort selector、设备等级和预算，再记录输入规模及结果。第一个正式 vertical 至少应提供下列 profile：

| Profile | 固定场景 | 必须测量 | 通过含义 |
| --- | --- | --- | --- |
| `population-batch-baseline` | 一组有限区域/组织桶的远场批量计划 | cohort 数、计划耗时、candidate 数、owner append 数、预算剩余 | 远场不会按帧写入，输出在同 seed 下可重演 |
| `activation-handoff` | 远场计划进入玩家邻域并预热/激活一个角色 | prewarm 数、activation lock 冲突、激活耗时、requeue 数 | 三档切换没有双身份、双记忆或重复 intent |
| `presentation-tail-replay` | 一个已结算状态映射到局部场景 | projection latency、view digest、asset fallback、full/tail replay 时间 | 同一范围与 revision 产出相同语义表现 |
| `privacy-load-shed` | scope 收紧与预算压力同时发生 | redaction 结果、被降级任务、生产 append 数 | 隐私和生产结算优先于“看起来完整” |

每条 profile 都须把 `plan size`、`owner append count`、`projection latency`、`agent activation count`、`replay time` 作为最小观测字段，并在 Harness 保存输入 digest 与结果 digest。这里的“耗时”用于建立同环境的回归基线，不可被表述成未经实测的全局 SLA。

每个正式 profile 还要声明：固定硬件/运行环境标识、合成数据集版本与样本数、预热与重复次数、统计值（中位数与高分位）、允许的回归阈值、Harness selector 名称，以及超阈后的处置。处置只能是标记证据失败、进入已有降级档或保持 no-op/requeue；不得用静默丢弃、减少审计字段或扩大生产写权来“通过”基准。

## 有序降级而非静默丢失

预算压力下的优先级是：

1. 保留已经提交的 owner 事实、outbox/replay 和近场安全/隐私路径；
2. 合并或降低远场 cohort 精度，保留其 source vector 与未处理桶审计；
3. 暂缓高成本图谱解释、branch 推演和非关键角色激活；
4. 将表现降低到确定性 LOD/fallback，但持续消费已提交 projection；
5. 仅在有正式 owner 规则时提交业务 intent；无法保证 revision 或 scope 时零写入并 requeue。

任何降级必须在 batch/activation/presentation audit 中写出 reason code、影响 scope、保留的 source vector 和下次重试条件。不能为了缩短队列而丢弃已结算 receipt，也不能把模型超时转换成默认的世界变化。

## 研究到验证的转换

OASIS、Sotopia 和 Generative Agents 给出的是规模、采样和记忆的实验思路；它们不构成 Paralls 的容量证明。KurrentDB 说明 expected revision、订阅和读模型有成熟实践，但也再次证明应测量既有脊柱，而不是在压力下引入第二事件库。正式 benchmark 将只采用确定性的输入、可公开的匿名化/合成测试数据与固定 seed，不读取真实私有角色记忆。
