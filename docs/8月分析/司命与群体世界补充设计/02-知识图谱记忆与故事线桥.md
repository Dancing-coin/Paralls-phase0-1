# 知识图谱、记忆与故事线桥

状态：`proposed amendment; HeavenlyGraph and character five-pool memory are implemented bounded`

## 为什么

角色需要保留主观、可误判的私有记忆；司命需要全局但受隐私约束的关系、传播和叙事上下文。两者不能合并，否则全局图会泄漏角色认知或成为第二世界库。

## 三层模型

1. **领域事实层**：owner event、receipt、scoped projection；唯一生产真相。
2. **司命派生图层**：引用事实来源的节点/关系、有效期、知识传播、故事线 obligation、激活优先级与推演上下文。
3. **角色私有记忆层**：Event、Observation、Knowledge、Social、Higher-Order 五池；只能由角色感知/授权输入沉淀。

## 修订

- 图谱节点必须有 `provenance`、`validity`、`revision`、privacy scope 和 source digest；推理结果不能伪装原始事实。
- 图谱到角色只产生其可知范围内的摘要/候选，不能覆盖角色 belief。
- 故事线是派生状态：记录 obligation、传播和未解线索；它可提出激活或 intervention，不能宣布剧情已经发生。
- 图谱 checkpoint 是派生重建/查询加速，不是生产 replay 的替代。

## 数据与运行细节

图谱写入只能由固定投影器消费 `authority event + scoped view + provenance digest` 产生。每个节点/边至少区分：`fact_ref`、`derivation_kind`、`visibility_scope`、`valid_from/to`、`graph_revision`、`source_event_vector`、`policy_revision` 与 `redaction_reason`。事实被补偿或更正时，图谱追加 superseding derivation，不删除历史来源。

故事线由图谱中的可解释模式派生，例如“供给下降 -> 已知范围扩大 -> 商户 obligation 未解 -> 玩家附近角色激活优先级上升”。它只能发出 `candidate`、`summary` 或 `activation_hint`，不得把“商户已停业”写为图谱事实，除非该状态已有 Organization/Economy owner event。

借鉴 MiroFish 的 GraphRAG 与 temporal memory 更新，但采用反向依赖：MiroFish 可从 seed 构建平行 sandbox；Paralls 生产图只从已提交 owner events 和被授权的角色摘要建图。借鉴 Generative Agents 的 memory stream/retrieval/reflection 结构，但 reflection 只能成为角色或司命的派生解释，不能覆盖五池记忆的来源和置信度。

## 执行状态

formal spec 先定义 graph projection reader、privacy redaction、source correction 和 graph replay equivalence；计划先补 contract tests，再实现一个 authority-event 到 graph 的投影和一个 graph 到角色摘要的窄读路径。

## 图谱读写、校正与分支规则

图谱是“可追溯的解释层”，不是把当前读模型复制一遍。一个查询必须显式带上 `(reader_principal, visibility_scope, valid_at, recorded_at)`；查询引擎只返回在该视角下可见、在指定双时间点有效的节点/边。`policy_revision` 变化、privacy 收紧或来源被补偿时，旧图谱结果不得继续被当作现行知识。缓存、checkpoint 和已派发摘要都必须携带 source vector、scope digest 与 policy revision；任一依赖被 supersede/retract/redact 时，查询缓存失效，checkpoint 从最后有效来源重建，未消费摘要撤回，已消费摘要只留下 redacted audit ref 而不尝试改写角色主观记忆。

| 来源变化 | 图谱动作 | 为什么 |
| --- | --- | --- |
| owner 追加新事实 | 追加 derivation 并更新引用向量 | 保留从哪些已提交事实推出该解释 |
| owner 更正或补偿事实 | 追加 `superseded`/`retracted` derivation，重算受影响的派生关系 | 历史来源仍要可审计，不能物理删除后假装从未发生 |
| privacy scope 收紧 | 追加 `redacted` 派生状态并在查询时裁剪 | 不泄漏曾经能见的私有内容，同时保留合规审计 |
| 图谱推理规则升级 | 保留旧 `derivation_kind + policy_revision`，在新 revision 下再派生 | 同一来源在不同规则下得到不同解释必须可区分 |

生产图谱只能消费许可白名单内的 owner event/projection；自由文本、模型总结和角色回忆必须带 `derivation_kind`，不能冒充 `fact_ref`。分支推演有独立的 source vector、seed、ruleset revision 和 branch id；分支节点不能与 production graph 合并，也不能通过“预测成功”反写生产真相。

## 四个可正式化对象

| 对象 | 作用 | 可写者 | 不能表示什么 |
| --- | --- | --- | --- |
| `StorylineThread` | 可解释的长期主题与关联 source refs | 固定图谱投影器/司命自有编辑流程 | 已经结算的剧情结果 |
| `NarrativeFollowUp` | 某角色、组织或区域尚待观察/解释/回应的叙事压力 | 图谱派生器，带来源和有效期 | 领域 obligation，例如税务欠款或库存承诺 |
| `ActivationHint` | 建议将某 CharacterRecord 提高到中场/近场的理由与预算等级 | 图谱/群体 consumer | 激活本身或角色的永久状态 |
| `PropagationHypothesis` | 关于信息、情绪或资源影响可能如何扩散的可检验假设 | 司命分析/branch | 已完成的信息传播事实 |

这四类对象可以被查询、版本化和审计，也可以成为受控能力的输入；它们都不能越过领域 owner。角色收到的仍是 privacy-filtered 摘要或可见事件，不是“司命认为它应该相信什么”。
