# 时间、空间与推进内核

状态：`proposed; cadence contract design; no new clock or scheduler`

对应母规格：[Character Simulation Memory Seed And Continuity Design](../../superpowers/specs/world-character-siming-authority-mainline/2026-08-22-character-simulation-memory-seed-continuity-design.md)，映射范围：cadence owner、窗口、checkpoint/tail 和 catch-up。

## 设计目标

群体模拟既要在玩家不在场时推进，也要在玩家靠近时及时交接。推进必须可暂停、可追赶、可回放，且不能依赖墙钟、进程顺序或模型随机性。

## 推进输入

每个 batch 固定：`world_mode_ref/revision + cadence_source_ref/revision + base_checkpoint + tail_boundary + source_revision_vector + policy_revision + selector_revision + seed + budget + report_scope`。

`world_mode` 和 cadence 只能来自现有已提交的 world-mode/activation/schedule projection。Siming、PopulationPlanner 和 Godot 都不能自行产生时间授权。缺失、过期、隐私不匹配或边界不连续时返回 `no_op/requeue`。

## 时间语义

| 状态 | 允许推进 | 结果 |
| --- | --- | --- |
| `running` | 执行当前 cadence 窗口内的批次 | proposal/candidate 或 owner-bound intent |
| `paused` | 不生成新的世界候选 | 只消费已提交 projection |
| `catch_up` | 按固定窗口和预算补算有限批次 | 每批保留 source vector，不跨越 owner revision |
| `replay` | 只重建历史派生结果 | 零 production write |
| `degraded` | 降低 cohort 数、模型等级或表现 LOD | 事实结算和隐私路径优先 |

追赶不能把多个窗口合并成一个无来源的大跳变。若 owner 生命周期要求逐窗口结算，必须逐窗口生成并校验；若只允许聚合，聚合规则必须是 owner contract 的一部分。

## 空间分区

空间只用于选择输入和 scope，不成为新的事实 owner。推荐四级分区：`world -> region -> zone -> place`。批次优先在同一 zone 内计算，跨区传播必须携带 source/target scope、传播窗口和边界 policy。玩家附近使用 place/zone 级投影，中场角色壳消费同一 CharacterRecord 的局部 snapshot。

## 参考项目翻译

- AgentSociety 的环境模块和 Ray task 说明“环境边界 + 可调度工作单元”是可扩展点；Paralls 只借鉴任务分片和 replay handle，不引入 Ray runtime 或第二 scheduler。
- OASIS 的 time-step/action loop 启发固定 step 与 action budget；Paralls 必须把 step 绑定到已有 cadence projection，而不是自行维护模拟时钟。
- MiroFish 的并行 sandbox 适合 branch/preview；生产推进仍必须走 owner event。

## 正式合同必须补齐

需要一个 cadence fixture 合同：source event family、mode revision、window start/end、catch-up limit、budget、暂停/恢复语义、tail boundary 和 stale/no-op reason。该合同获批前，不得把 wall-clock timer、后台循环或新 scheduler 写进 runtime。

第一条 cadence 与 owner receipt 的联合验证，采用 [13-群体模拟生产纵切与推进闭环设计](13-群体模拟生产纵切与推进闭环设计.md) 的 `schedule_gated_supply` 窄纵切；它不解除本文件对新 clock/scheduler 的禁止。

### Cadence fixture 最小合同

cadence 不是由司命、PopulationPlanner 或 Godot 生成的本地计时器，而是由既有
world-mode/activation/schedule projection 的 owner 提供的授权记录。最小 fixture 必须
明确：

```text
cadence_ref
cadence_owner_ref
source_event_family
mode_ref / mode_revision
window_start / window_end
base_checkpoint
tail_boundary
catch_up_limit
budget
pause_resume_policy
stale_reason / no_op_reason
```

运行规则：

1. `cadence_owner_ref` 缺失、未准入或 revision 失配时，只返回 `no_op/requeue`；
2. 一个窗口只能被同一 `(cadence_ref, window_start, window_end, source_vector)` 消费一次；
3. catch-up 必须逐窗口保留 source vector，不能制造无来源的大跳变；
4. `paused` 只停止新候选，不回滚已提交 owner receipt；
5. `replay` 只重建派生结果，零 production write；
6. `degraded` 只能减少 cohort、模型等级或表现预算，不能降低 owner/privacy 校验；
7. 当前没有对应 cadence producer 时，完整无人推进保持 `blocked`，不得用 wall-clock 或
   后台循环补齐隐含授权。
