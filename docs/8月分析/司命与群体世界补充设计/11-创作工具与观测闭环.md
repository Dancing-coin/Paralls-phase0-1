# 创作、工具与观测闭环

状态：`proposed; authoring and observability design; no creator write authority`

## 为什么补充

群体模拟不是只有运行内核。没有可编辑的 cohort、规则、传播场景、预算和回放工具，设计无法被内容团队验证；但创作工具也不能变成第二个生产写入面。

## 四类工具能力

司命已有读/写/编辑/执行方向，群体模拟必须把它们限制为：

| 能力 | 群体模拟用途 | 边界 |
| --- | --- | --- |
| Read | 读取 scoped projection、graph view、replay report、profile | 不读取未授权私有记忆或原始 owner store |
| Write | 写入 Siming candidate、scenario fixture、derived audit | 不写领域事实，不注册 owner |
| Edit | 编辑规则 revision、cohort selector、叙事优先级、测试 seed | 不编辑已锁定事实、receipt 或历史 replay |
| Execute | 运行 branch/preview、触发既有 admitted capability candidate | 不直接执行 owner、Godot 或 arbitrary event |

## 创作对象

创作者可编辑的对象必须版本化、可审查、可回滚：`CohortSelectorSpec`、`BehaviorKernelSpec`、`PropagationScenarioSpec`、`ActivationBudgetSpec`、`PresentationMappingSpec` 和 `CalibrationScenarioSpec`。每个对象携带 owner/read scope、ruleset revision、输入 schema、输出类型和 prohibited effects。

创作对象只生成 branch/preview 输入或 proposal。进入 production 前，仍需现有 `GovernedAuthorityContractCatalog`、owner validation、append receipt 和 replay evidence。

## 观测闭环

```text
source event/projection
-> batch/graph/activation decision
-> candidate/owner receipt
-> presentation/replay report
-> metric + audit
-> revised ruleset/selector (new revision)
```

每个 trace 必须能从玩家可见表现回溯到 semantic digest、owner event vector、batch ref、selector/ruleset revision 和 receipt；不能把模型 prompt 当作生产因果证据。

## 参考项目翻译

- MiroFish 的 seed upload、GraphRAG、ReportAgent 和模拟后交互启发“研究/创作工作台”，但其 God-view 变量注入只能留在 branch/preview。
- AgentSociety 2 的 environment modules、CodeGen/ReAct/Plan-Execute、JSONL replay、DuckDB 查询和 tracing 启发工具分层；Paralls 的工具输出仍必须经过 typed intent 和 owner admission。
- Sotopia 的 scenario sampler/evaluation 启发可复用的社会情境测试集；不能把 Redis/JSON runtime 当生产世界存储。
- AI Town 的局部 presence/UI 刷新启发表现调试，不赋予前端 mutation 事实权。

## Formalization 前置

先做一个只读 authoring fixture：创建 cohort、运行固定 seed、查看 graph/batch/presentation/replay 对照、导出 audit。完成前不得开放通用创作者 CLI、MCP 写入口或“自然语言直接改世界”功能。
