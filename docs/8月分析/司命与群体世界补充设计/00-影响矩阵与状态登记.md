## 状态迁移

`proposed -> formal-spec-approved -> plan-ready -> RED -> implemented bounded -> Harness verified -> implemented`。

任何 row 缺少 owner、event、revision、privacy、idempotency、receipt、replay 或 compensation 合同，必须保持 `blocked`，不得以本目录的架构语言绕过。

## 正式化分包与替代登记

分析包只有在下列分包分别获得 formal contract、对应计划和 Harness 证据后，才替代同主题中**尚未执行**的旧 broad 设计；替代不删除、也不重述历史完成证据。

| 分包 | 分析来源 | 应进入的 formal 范围 | 替代的未执行方向 | 不替代的已验证基础 |
| --- | --- | --- | --- | --- |
| SGC-1 司命能力 | 01 | capability admission、reader scope、decision/audit、固定 owner execute | 将“司命可调度世界”泛化表述改为准入 capability | 现有 Siming event producer/consumer/audit |
| SGC-2 认知图谱 | 02 | provenance、双时间查询、privacy/redaction、派生 replay | 图谱同时当全局记忆和世界库的说法 | HeavenlyGraph 与角色五池记忆的既有边界 |
| SGC-3 群体连续性 | 03 | cohort batch、fidelity state machine、PopulationPlanner 独立权限矩阵、activation/requeue、owner-bound intent | 独立 population truth 或常驻全角色 LLM | P3/INF-4 已验证的 planner/activation 窄切 |
| SGC-4 场景投影 | 04 | `PresentationView`、mapping digest、asset fallback、evidence ingress | 美术/场景状态可直接成为世界状态的说法 | visual facts、Godot 本地表现路径 |
| SGC-5 性能与证据 | 05 | benchmark 输入、load shedding、profile/Harness 证据 | 用外部项目规模声明替代本仓库容量证明 | append/outbox/replay/Harness 脊柱 |

正式化时必须先在本表把每个分包标记为 `formal-spec-approved`，并链接其 spec、plan、RED tests、Harness profile 和验证记录。没有这些链接，目录中的任何内容都只是设计意见。

[06-GitHub成熟实现参照与采纳边界](06-GitHub成熟实现参照与采纳边界.md) 是本包的外部研究索引。它提供“哪些成熟模式可被翻译为受控契约”的理由，不能提供 owner admission、性能完成或依赖引入授权。外部实现和本仓库现实发生冲突时，以上方的 source-of-truth 层级与现有 authority/replay 证据为准。

## 设计审查修订记录

`2026-08-17` 的文档审查已将以下 formalization blocker 收敛到分析合同中，状态仍为 `proposed`，未授权 runtime：

| 审查项 | 修订位置 | 已固定的结论 |
| --- | --- | --- |
| 避免第二 capability registry | 01 | `GovernedSimingCapability` 仅能是既有 immutable `GovernedAuthorityContractCatalog` 的静态 entry；catalog mismatch 在 plan 前零写入 |
| 批处理的时间/节奏可重放性 | 03 | world mode 与 cadence 必须来自既有已提交 projection，并各自 pin ref/revision；无来源时 no-op/requeue |
| 场景投影的隐私与跨设备确定性 | 04 | 每层带来源/可见性/redaction/identity policy；发布 manifest 与 renderer-local LOD/fallback 分离 |
| 派生图的撤回与角色认知边界 | 02 | cache/checkpoint/摘要按来源与 scope 失效；不得回写已形成的角色主观记忆 |
| 基准不可被静默降质“通过” | 05 | profile 固定环境、样本、统计、阈值、selector 与超限处置 |

这些结论要在相应 SGC formal spec 中转写为可执行 rejection rules 与 Harness selectors；未写入正式 spec 前，不得把本表视为 capability admission 或完成证据。
