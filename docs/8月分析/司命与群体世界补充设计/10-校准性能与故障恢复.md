# 校准、性能与故障恢复

状态：`proposed; evidence and operations design; no capacity claim`

对应母规格：[Character Simulation Memory Seed And Continuity Design](../../superpowers/specs/world-character-siming-authority-mainline/2026-08-22-character-simulation-memory-seed-continuity-design.md)，映射范围：固定 profile、故障恢复、回放和容量证据。

## 校准对象

群体模拟的“正确”不是模型说得像人，而是满足可观测约束：

| 维度 | 指标示例 | 证据来源 |
| --- | --- | --- |
| 因果 | source -> candidate -> owner receipt 链完整率 | event/replay/audit |
| 稳定 | 人口、资源、关系聚合在窗口内不无故爆炸/归零 | scoped projections |
| 多样性 | 行为熵、cohort 差异、重复轨迹比例 | batch reports |
| 连续性 | 远场计划与近场角色状态的冲突率 | activation/requeue |
| 可见性 | 玩家 scope 之外的事实泄漏率 | privacy tests |
| 成本 | token、激活数、batch latency、replay latency | Harness profile |

任何指标只能评估派生模拟质量，不能授予写权限。阈值按 vertical 和 seed 固定，不能为通过测试动态调参。

## 可复现校准

每次校准保存 `dataset_version + source_vector + policy_revision + seed + model_revision + budget + output_digest`。模型升级必须在新 revision 下跑对照，不得覆盖历史结果。MiroFish 的报告和并行 sandbox 可用于 scenario comparison；AgentSociety 2 的 JSONL replay、DuckDB reads 和 tracing 可借鉴为离线分析格式，但生产 replay 继续使用 GameplayEventStore。

## 故障恢复

| 故障 | 保留什么 | 恢复动作 |
| --- | --- | --- |
| 模型超时 | batch input、source vector、budget、audit | no-op/requeue 或降级 B0 |
| graph projection 失败 | owner event/outbox、last valid checkpoint | 从 checkpoint-tail 重建派生图 |
| activation lock 冲突 | lock ref、candidate、expected revision | discard/requeue，不双写 |
| presentation 资源缺失 | semantic digest、manifest revision | renderer-local fallback |
| owner rejection | typed intent、refusal receipt、source digest | 按 owner policy 重算或终止 |
| 进程重启 | existing event store/outbox/checkpoint | 重建派生状态，不产生第二 store |

恢复不能把未提交的候选提升为事实，也不能删除失败审计或重复提交已消费 idempotency key。

## 规模策略

采用分层预算而非先承诺 agent 数量：B0 批量规则优先，B1 小模型按 cohort，B2/B3 受 activation budget 限制，近场安全路径优先于远场精度。AgentSociety 的 workspace-bound stateless records、Ray task 分片和 replay handles 可作为未来性能研究参考，但 Paralls 不因此引入 Ray、Redis 或新的事件库。

## Formalization 前置

先为一个完整 vertical 建立合成 dataset、校准指标、故障注入和 replay report；未取得实测前，文档不得写“实时”“百万 agent”或“生产级高并发”。
