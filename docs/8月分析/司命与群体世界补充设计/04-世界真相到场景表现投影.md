# 世界真相到场景表现投影

状态：`proposed amendment; current visual fact and Godot local presentation paths are implemented bounded`

## 为什么

世界变化必须可见，但美术、LOD、音景和本地动画不应成为另一套世界状态。需要把已结算语义事实稳定映射为玩家可见的表现层。

## 目标链

`owner event -> outbox/scoped projection -> presentation mapping -> Godot local embodiment -> observation/evidence candidate`。

## 修订

- 映射可消费建筑、植被、材质、灯光、音景、密度、队列和行为 LOD 的 authority-scoped presentation view。
- 表现可延迟、合并、降级或重建；这些差异不改变业务事实。
- 玩家可见范围、隐私、设备预算和资产可用性只能裁剪表现，不可提升权限。
- Godot 的观测回流是 evidence/candidate，必须经 owner 才能成为成功事实。

## 映射与降级细节

`presentation mapping` 是 scoped projection 的纯/可重建消费者。输入为 owner event vector、可见性 scope、**发布内容 manifest** 的资产版本和映射规则；输出为场景语义层：`material_state`、`structural_damage_band`、`vegetation_band`、`light/audio mood`、`crowd density band`、`actor behavior seed`。每个层还必须携带 `source_ref`、layer visibility、redaction disposition 与 identity policy；`crowd density band` 只能输出满足正式聚合阈值的区间，`actor behavior seed` 只能指向本 scope 下已可见的 CharacterRecord，且不得编码私有关系、未公开地点或未结算结果。

同一 `(owner event vector, scope digest, manifest revision, mapping revision)` 必须产生同一语义输出 digest。设备等级、帧率、已安装资产和加载失败是 renderer-local 输入：它们只能将已经授权的语义层降到确定性的 LOD/fallback，不能改变 `PresentationView` digest、扩大可见性或产生新的业务状态。美术资源缺失只能降级为中性/占位表现并记录 audit，不可捏造业务状态。

AI Town 的 reactive presence/UI 模式可参考为“投影变化后局部刷新”，但不能采用单一数据 mutation 做跨域事实。Godot 继续是本地高频具身宿主：它可平滑插值、播放动作和收集观测，却不能把表现成功等同于 owner settlement 成功。

## 执行状态

formal spec 需先定义一个 owner event family 到 presentation view 的窄投影和 replay digest。计划从一个已验证环境/设施状态纵切开始，验证 privacy、asset-missing fallback、full/tail replay 以及不反写 truth。

## `PresentationView` 最小契约

presentation mapping 的稳定输入不是“场景当前看起来怎样”，而是一个可定位、可重建的只读视图。建议正式化的 `PresentationView` 至少含有：

| 字段 | 目的 |
| --- | --- |
| `basis_event_vector` | 说明视图由哪些已提交 owner events 构成 |
| `scope_digest` | 绑定玩家/观察者权限、地理可见范围与 redaction 规则 |
| `asset_manifest_revision` | 绑定经发布的语义映射资产；与设备本地资源和 LOD 明确分离 |
| `semantic_layers` | 保存业务无关但美术可消费的材质、损坏、植被、灯光、音景、密度与行为种子 |
| `mapping_revision` | 允许映射规则迭代且可精确重放 |
| `fallbacks` | 资产缺失、性能降级、隐私裁剪时采用的中性表现及其审计原因 |

`PresentationView` 是 projection，不是 owner，也不拥有独立 event stream。full replay 和 checkpoint-tail replay 都必须在同一 `(basis_event_vector, scope_digest, asset_manifest_revision, mapping_revision)` 下产生相同的语义层 digest；实际纹理加载、帧率和本地插值可不同。

## 三层表现与中场壳体边界

| 表现层 | 例子 | 是否可反写真相 |
| --- | --- | --- |
| 静态语义层 | 建筑破损档、作物状态、材质、植被、灯光基调 | 否 |
| 动态局部层 | 人群密度、队列、环境音、远处工作动作、天气粒子 | 否 |
| 交互表现层 | 中场角色壳、near agent 的动作/台词播放、UI 反馈 | 否；只可生成 observation/evidence candidate |

中场具身壳只消费同一 `CharacterRecord` 的已授权 snapshot、任务和 `actor behavior seed`。它可使用路径、动画、局部避让和镜头外 LOD，但不能自行决定交易成功、关系改变、任务完成或角色记忆成立。表现失败也同样不能回滚 owner 的已结算事实：它只能记录显示失败、重试或使用 fallback。
