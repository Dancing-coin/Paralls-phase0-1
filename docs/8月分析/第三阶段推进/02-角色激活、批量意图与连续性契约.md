# 角色激活、批量意图与连续性契约

状态：`incremental design; P3A/P3C formal spec required before implementation`

本文件将 Population Simulation 限定为“计划和激活适配层”。它读取已授权 projection，
生成候选意图，并把结果交还给 Character Core 与各 Gameplay authority；不拥有角色、家庭、
账户或库存状态。

## 1. 逻辑记录

以下是待正式 spec 确定的逻辑记录，不能直接视为现有 Python schema：

| 逻辑记录 | 作用 | canonical owner |
| --- | --- | --- |
| `ActivationRequest` | actor、world、mode、profile revision、原因和锁 | World runtime |
| `PopulationBatchPlan` | batch ref、候选 actor refs、预算、输入 digest、intent refs | Population planner |
| `PendingChangeSet` | 某 actor 的待合并变化、来源事件、base revision、冲突 | Character Core/World adapter |
| `ContinuityMergeReceipt` | 合并结果、提交事件、冲突/重试原因、projection digest | shared contract + existing store |
| `WorldModeProfile` | tick/cadence、batch limit、catch-up、reporting projections、active revision | World runtime |

这些记录只保存稳定引用和 revision，不复制 CharacterProfile、家庭账本或 Gameplay 投影。

## 2. 批量意图路径

```text
mode tick / explicit batch request
-> read pinned actor + household + organization projections
-> planner emits candidate typed intents
-> profile/capability/privacy filter
-> same GameplayCommandEnvelope as player/agent
-> owning authority builds SettlementPlan
-> GameplayEventStore.append_batch
-> outbox/projectors/mirror
-> continuity summary + next activation decision
```

普通采购、休息、消费和移动可以批量规划；谈判、冲突、重大雇佣、投诉和剧情高光升级到
高精度 CharacterAgent。两条路径的差别只有触发频率和计算预算，不是权限或结算规则。

## 3. 幂等、revision 与恢复

- batch plan 固定输入 projection digest、active world revision 和 deterministic seed；
- 每个 intent 拥有独立 idempotency key，并可关联 batch correlation；
- activation lock 防止同一 actor 同时被近场 agent 和批量 planner 激活；
- merge 使用 base revision，冲突进入 pending changes，不覆盖较新的 committed facts；
- catch-up 受 batch limit、catch-up budget 和 retry policy 限制，不能停服后无限补算；
- 失败只产生结构化 rejection/obligation，不能由 planner 直接修正 canonical state。

## 4. 隐私和可观测性

planner 只能获取其 world mode profile 授权的 projection。个人私有记忆、隐藏关系、
未公开工资、组织秘密和政府调查 workspace 不得进入低精度批量输入。每个 batch report
至少包含输入 digest、actor refs、intent status、committed event ids、rejection codes 和
负载摘要，供 Harness 和管理员审计。

## 5. P3 后置

本契约不解决动态价格、宏观供需、创新传播、文明能力、反事实分支或模型生成世界内容。
这些能力必须在 P4/P7 的正式 spec 中复用本契约，而不是向 Population planner 添加万能逻辑。
