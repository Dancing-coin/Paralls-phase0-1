# 面包店人口样板与第三阶段门禁

状态：`incremental design; P3D formal spec and Harness profile required before implementation`

本样板把 P2 的三个 authored actors 扩展成一个小型 bakery district。它证明角色可以在
持续世界模式中被激活、批量推进、升级到高精度交互并回写同一事实链，但不实现动态市场。

## 1. 样板角色

| 角色 | 来源 | P3 行为 |
| --- | --- | --- |
| 经营者 | 已授权 CharacterRecord | 排班、预算、处理异常、关闭窗口 |
| 烘焙师/店员 | 已授权 CharacterRecord | 接受工作、生产、休息、报告缺勤 |
| 顾客群 | Population 激活的角色集合 | 读取公开 quote，生成购买/投诉 intent |
| 供应商 | 已授权组织/角色 | 交付固定 quote 对应材料，生成付款/交付 evidence |
| 竞争对手 | 已授权组织/角色 | 发布公开参数 profile，不直接改本店事实 |
| 监管角色 | 政府授权角色 | 按固定政策检查 permit/inspection，提交 government intent |

角色数量由 population 配置决定，样板只要求一个可复现的小规模集合。没有通过
materialization 和权限门禁的角色，不得用 fixture 冒充正式 NPC。

## 2. 运行脚本

```text
activate district actors at revision R
-> batch open bakery windows and work offers
-> customer/supplier/competitor/inspector plans produce typed intents
-> owner authorities settle procurement, production, sale, tax and work evidence
-> suspend district
-> resume with checkpoint + tail
-> compare public/actor/manager projections and continuity receipts
```

P3 的销售仍使用 fixed quote 或受限 public quote；价格发现、订单簿和跨区交易留到 P4。

## 3. 门禁

- actor activation 不产生重复 CharacterRecord、账户、库存或家庭状态；
- simulation batch 与 high-fidelity actor 的同一 intent 经过相同 authority；
- pause/resume/catch-up 的 committed event 顺序和 projection digest 可复现；
- 顾客、供应商、竞争对手和监管角色只能读到公开或授权 projection；
- 角色缺勤、材料不足、支付失败和检查失败均可形成新 obligation 并恢复；
- no `NpcState` shadow writer、dynamic order book、second event store 或 direct planner write；
- P2 authored-agent Harness、P1D Harness 和 replay/checkpoint predecessor 全部通过。

通过后才允许进入 P4 的动态市场与制度经济；否则 P3 保持 `blocked-by-population-simulation`
或 `blocked-by-continuity-merge`，不能用静态人数报告替代。
