# 动态报价、清算与跨组织结算契约

状态：`incremental design; P4A/P4B formal spec required before implementation`

本阶段扩展已有 `MarketQuote`、fixed-offer purchase/sale 和 inventory reservation。具体
订单簿、报价存储和定价算法必须进入正式 spec，本文不固化新的表结构。

## 1. 逻辑流程

```text
public supply/demand projections
-> versioned quote/order proposals
-> quote policy + quantity/quality/delivery checks
-> pinned inventory/organization/contract revisions
-> pure clearing SettlementPlan
-> multi-stream GameplayEventStore.append_batch
-> custody transfer + account posting + fee/tax obligation
-> public/party scoped trade receipt
```

Population planner、CharacterAgent、玩家和组织 AI 都只提交 proposal。清算结果必须经
Economy authority 验证，不能由价格模型直接写 account 或 inventory。

## 2. 渐进策略

1. 先把 fixed quote 变成有有效期、数量上限、公开 digest 和 policy revision 的 quote；
2. 再允许多个公开 quote 并存，按确定性规则排序和部分成交；
3. 最后引入有界 order/offer cancellation、delivery window 和 quality/expiry 影响；
4. 每一步都保留 `bakery-single-owner` 的固定 quote compatibility path，直到迁移证据通过。

不在 P4 初期引入自由浮点随机价格、模型预测价格或跨区域汇率。随机需求必须固定 seed、
输入 digest 和规则 revision，清算结果必须可以 replay。

## 3. 争用与零部分写入

两个买方争用同一 lot、两个组织争用同一 supplier capacity 或同一 facility output 时，
所有相关 streams 都进入 expected revision vector。先提交者成功，后提交者得到结构化
`revision_conflict`/`quantity_exhausted`；失败者不能留下 hold、付款或税费残留。

贸易 receipt 至少关联 quote/order refs、matched quantity、custody event、account event、
tax/fee obligations、committed event ids 和 public/party projection digest。
