# 商业生态参考包与第四阶段门禁

状态：`incremental design; P4D formal spec and Harness profile required before implementation`

参考包从 P3 bakery district 扩展为一个小型商业街：两家 bakery、一个材料供应组织、
聚合/角色化顾客、一个辖区政府和有限信用提供者。它用于验证跨组织结算，不代表完整城市经济。

## 1. 必须观测的路径

- 两家 bakery 对同一材料供给产生确定性 quote/订单争用；
- 顾客需求变化影响公开报价或数量，但不绕过库存与账户 authority；
- 供应商交付延迟、质量不足或取消可形成恢复义务；
- 工资、采购、税费、许可、借款和还款进入同一 period/obligation 回放；
- 检查不通过会阻断或限制营业，并在授权 projection 中解释原因；
- 一个组织资金不足不会污染另一组织账户和库存。

## 2. 失败矩阵

| 场景 | 结果 |
| --- | --- |
| quote/order 过期 | `quote_expired`，无 hold/payment 残留 |
| 同批材料争用 | 一个 commit，另一个 `quantity_exhausted` 或 `revision_conflict` |
| 交付失败 | custody 不转移，创建 retry/remediation obligation |
| 税费/工资逾期 | obligation `overdue`，期末结算按 policy 阻断或降级 |
| permit 被吊销 | 新交易/生产拒绝，历史事件保留 |
| 信用违约 | 新授信受限，已有 claim 可重放 |
| policy revision stale | 零写入，要求重新 pin revision |

## 3. 通过门禁后可以声称

> 小规模多组织动态商业生态已通过 authority、回放、权限投影和恢复门禁。

仍不能声称宏观经济、完整金融体系、文明级监管或无限规模人口模拟完成。
