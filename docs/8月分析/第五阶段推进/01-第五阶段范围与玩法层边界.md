# 第五阶段范围与玩法层边界

状态：`incremental design; P5A-P5C formal spec required before implementation`

## 1. 分层

| 层级 | 负责内容 | 依赖 |
| --- | --- | --- |
| L1 行动/感知 | 结构化意图、观察事实、空间/可见性结果 | 现有 ESM、Character L1、Godot input |
| L2 技能/物品/生存 | 资格、成本、资源、身体和状态效果 | Skill、Inventory、Survival、effect registry |
| L3 任务/调查/社会 | 目标、证据、关系、知识、声望和身份 | P3 projections、P4 public facts |
| L4 冲突/制度后果 | 暴露、伤害、追捕、许可、赔偿和组织后果 | Conflict/Action owner、Economy/Government |

跨层动作必须遵循：

```text
typed ActionIntent
-> Physical/Logical Fact
-> skill/visibility/effect/social evaluation
-> owning authority SettlementPlan
-> append_batch
-> objective/relationship/state/mirror projections
```

普通行动可以沿用已落地 authority 的直接事件映射；只有新增跨域 adapter 才使用显式
预提交 `SettlementPlan`。不要因为 P5 增加任务或战斗就创建万能 `GameplayCoordinator`。

## 2. 可关闭和可调节

创作者只能通过版本化 package/ruleset 声明开启哪些 state group、任务规则、冲突规则和
Survival profile。关闭系统时，不能删除历史；新 revision 只影响允许的后续结算和 projection。

## 3. 门禁

- 任务完成必须由 evidence refs 和 owning authority 结果驱动；
- 关系/知识变化可追溯到事件、可见性和 policy revision；
- 潜行/冲突失败有结构化约束原因、trace 和可恢复后果；
- full replay、checkpoint-tail replay 与 mirror 结果一致；
- 表现层预测不能升级为 canonical success。
