# 任务、证据、关系与知识协作契约

状态：`incremental design; P5A/P5B formal spec required before implementation`

## 1. 任务与证据

Quest/Story authority 负责 objective lifecycle 和 evidence index，不拥有生产、库存、
关系或角色记忆。逻辑记录至少需要：

```text
Objective(objective_ref, package_ref, prerequisites, state, revision)
EvidenceLink(evidence_ref, source_event_refs, subject_refs, visibility_scope, verification_state)
ObjectiveProgress(objective_ref, evidence_refs, evaluator_revision, result)
```

证据必须来自已提交事件或受信任 provider，不能由自然语言、Godot node 或 planner 直接
标记完成。重复证据应幂等，过期/未授权证据应结构化拒绝。

## 2. 社会和知识投影

关系、声望、身份、知识 claim、belief 和 disclosure 继续沿用角色社会投影增量指导；
P5 只增加它们对任务、调查、价格可见性、岗位资格和冲突后果的读取 contract。

```text
dialogue / observation / contract evidence
-> social or knowledge intent
-> visibility + policy + relationship authority validation
-> committed social/knowledge event
-> actor-local memory and scoped projection
```

角色只能看到被授予的 claim、关系摘要和身份凭证。隐藏事实可以影响 authority 判断，
但不能被不授权的 prompt、Godot 或管理面板读取。

## 3. 与经济和组织协作

- 声望可成为公开 quote、岗位、信用或任务可见性的输入，但不直接修改余额或许可；
- 社会承诺可引用 typed contract，违约后果由 Contract/Debt/Economy owner 结算；
- 任务可以等待工资、交付、检查或生产 evidence，但不能替代这些事实；
- 关系/知识 projection 的失败不应回滚已经提交的经济事实，只能创建新的社会后果。
