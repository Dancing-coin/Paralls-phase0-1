# 玩法底座与经济跨域协作

## 1. 当前玩法底座

当前 Gameplay foundation 的强项是权威结算和跨域一致性，而不是内容数量。已有基础包括：

- Gameplay command、前置条件、revision、幂等和原子事件批次；
- event store、projection、replay、checkpoint、outbox；
- resources、body、status tags、effective stats；
- ability、skill path、grant、restriction、affordance；
- item、container、inventory、encumbrance；
- equipment、slot、modifier、container access；
- ownership、account、fixed offer、gift、debt、simple contract；
- embodied interaction、grab/carry/place 和 Godot mirror。

## 2. 当前可组合的参考玩法

`adventure-basic` 已经证明了以下组合：

1. 购买和装备长剑；
2. 受伤或 stamina 不足时阻断挥剑；
3. 装备储物戒并计算容器负重；
4. 地契物品和土地产权分离；
5. 赠与、债务、偿还和简单服务合同。

这些是可重放的参考闭环，不等于完整 RPG 玩法库。

## 3. 经济系统的正确定位

当前只能称为：

> 产权与经济基础原语 / 跨领域经济结算基础。

当前已有：

- 账户余额和原子扣款/入账；
- 固定报价购买；
- 物品赠与；
- 独立产权和凭证；
- 简单债务与偿还；
- 注册型简单合同；
- 交易记录、幂等、回放和隐私投影。

当前没有：

- 供需、动态价格、订单簿和拍卖；
- 生产、消费、库存周转和供应链；
- 劳动力市场、工资和岗位；
- 税收、许可证、货币发行、通胀和政府财政；
- 企业经营、成本、利润、信用、违约和破产；
- 租赁、股份、质押、许可和复杂权利；
- 跨区域、跨世界和持续经济模拟。

## 4. 经济必须和其他系统协作

| 系统 | 经济协作内容 |
| --- | --- |
| 技能 | 决定生产效率、岗位资格、服务质量、劳动力价格和学习成本 |
| 背包 | 管理原料、商品、工具、仓储、运输和容量 |
| 建造 | 提供建筑、工坊、商店、农田、道路和生产能力 |
| 生存 | 产生食物、住房、医疗、能源等持续需求和消费 |
| 商业组织 | 管理员工、岗位、账户、库存、订单、成本和利润 |
| 政府组织 | 管理税费、许可、监管、禁运、补贴、处罚和公共建设 |
| 产权 | 管理土地、建筑、企业、设备和资产权利 |
| 经济域 | 管理市场、价格、订单、工资、税费、债务和结算 |

## 5. 目标经济循环

```text
技能/劳动力
  -> 生产或服务
  -> 背包/库存/物流
  -> 市场交易
  -> 商业组织经营
  -> 生存需求消费
  -> 政府征税与监管
  -> 反过来改变技能、价格、组织和生产
```

例如，一家面包店不应只是一个“购买面包”的固定报价：

```text
员工技能 -> 面粉消耗 -> 工作台/建筑占用 -> 面包产出
-> 库存变化 -> 工资与成本结算 -> 市场价格
-> 居民食物需求 -> 销售收入 -> 税费 -> 企业利润
```

## 6. 跨域结算原则

经济不能直接修改技能、背包、建筑或生存状态。正确流程应是：

```text
生产/交易命令
-> 读取多个领域的 pinned revision
-> 生成 typed effect proposal
-> authority 统一校验
-> 一次 atomic settlement
-> 各领域分别追加自己的事件
-> projection、账目和镜像更新
```

例如“完成生产订单”需要由技能域确认能力，由背包域扣原料和生成商品，由建筑域确认工作站，再由经济域结算工资和成本。

## 7. 后续优先级

经济系统不应先做动态价格，而应按以下顺序补齐：

1. 生产/制作/服务订单；
2. 工作站、建筑能力和资源消耗；
3. 劳动力、岗位和工资；
4. 基础需求与周期消费；
5. 商业组织账户、库存、利润和权限；
6. 政府监管、税费和许可；
7. 市场价格、供需和区域经济；
8. 信用、违约、跨区域和链上收益结算。
