# 多呈现形态底座与具身交互

## 1. 核心原则

不同呈现形态不应复制角色智能体，也不应强行共享同一套低层控制器。应拆成四层：

```text
角色心智与记忆
-> 语义行动
-> 形态适配器
-> 本地物理/动画/表现
```

共享的主要是：

- 角色身份和档案；
- 私有感知和记忆；
- 目标、意图和语义行动；
- authority、状态和事件；
- 可观测结果和回放。

需要按形态重做的是：

- 感知输入；
- 可供性和动作词典；
- 运动/碰撞模型；
- 动画、表情、声音和 UI；
- 输入设备和反馈方式。

## 2. 3D RPG 底座

当前项目最接近这一形态：

- Godot 3D 场景；
- 角色节点、骨骼、动画和局部动作表现；
- 3D 空间感知、对象交互和 embodied action controller；
- 物理/碰撞由本地场景和后端 authority 协作；
- VRM 或传统绑定模型可以作为 presentation asset。

VRM 更像标准化角色资产和运行时交换格式；传统 3D 模型绑定骨骼后导入 Godot，更适合自定义战斗、复杂动画、物理和商业项目资产管线。二者都不应改变角色心智与 authority 层。

## 3. 2D、2.5D、箱庭和像素风

2D 可以复用上层心智和事件系统，但不能直接复用 3D 控制器：

- 2D 感知应使用屏幕坐标、图层、遮挡、帧状态和区域关系；
- 2D 运动通常是离散网格、平面速度或节点状态；
- 碰撞和可交互对象应使用 2D physics/affordance adapter；
- Live2D 重点是参数、表情、姿态和口型，不承担权威世界真相；
- 像素风重点是 sprite、tile、状态帧和有限动作集合；
- 箱庭/2.5D 可以在 2D 交互层与 3D 空间层之间做混合。

## 4. Live2D、VRM 与 VR 手套

Live2D 和 VRM 可以组合，但角色分工不同：

- VRM 提供 3D 角色、骨骼、表情和空间姿态；
- Live2D 提供 2D 立绘、面部参数、呼吸、视线和陪伴表现；
- 玩家触屏、手势、手套或控制器先转换成结构化意图；
- 角色决定是否接受、如何理解以及产生什么社会/情绪结果；
- 物理和接触结果由 VR/场景 authority 验证。

未来第一视角 VR AI 陪伴需要额外补齐：

- 头显视野和手部追踪；
- 手套触觉与接触反馈；
- 近身距离、注视、触碰和边界权限；
- 低延迟姿态/碰撞层；
- 隐私、同意、安全和玩家接管机制。

## 5. 建议的形态适配器

```text
Character Mind Core
  -> Semantic Action Contract
      -> Godot 3D / VRM Adapter
      -> 传统绑定 3D Adapter
      -> 2D/2.5D Adapter
      -> Live2D Adapter
      -> Pixel/Box-Garden Adapter
      -> VR/Hand-Tracking Adapter
```

因此未来需要多个“呈现底座”，但不应维护多套角色智能体核心。
