# V0 共享结算样板

状态：`domain sample for generic-contract validation; implementation requires formal plan`

V0 是通用契约的内部验证样板，不是第一阶段交付的完整游戏，也不是基础设施边界。
推荐使用“霜冻农田”，因为它能
同时验证环境 effect、事物状态、材料/产出引用、角色生存压力和经济投影；如果需要
更短的物理交互路径，可替换为“火焰橡木门”。两者只能选择一个进入正式 plan。

V0 的所有字段、事件和规则都必须作为领域扩展存在。任何只对农田或门成立的字段，
不得写入通用实体、语义、结算或调度 contract。

## 推荐场景：霜冻农田

```text
天气/环境事实
-> frost effect + resistance evaluation
-> farm plot / crop state transition
-> typed production-yield consequence
-> Gameplay authority atomic events
-> replay / creator trace / actor view / Godot mirror
```

V0 只处理一块农田、一个作物状态、一个环境 effect 和一个结果投影。它不实现完整
天气系统、生态模拟、默认元素化学、市场价格发现或完整农业生产链。

## Owner 分工

| 步骤 | 当前或计划 owner | 约束 |
| --- | --- | --- |
| 环境/场景事实输入 | `world_runtime`、ESM 与现有 fact path | 不直接修改 Gameplay stream |
| Entity/Thing/Environment 记录 | planned world-record adapter | 只实现 V0 所需字段 |
| tag/effect/resistance 求值 | planned semantic/effect registry；复用 status/Patch contract | 声明式、固定 revision、可追溯 |
| 作物/农田状态变化 | 新增或扩展领域 authority | 通过 `GameplayEventStore.append_batch` |
| 角色寒冷/需求影响 | Survival state group（可选） | disabled 时不产生 survival tick |
| 经济/产量投影 | Economy/production authority（V0 最小 slice） | 不实现动态市场 |
| Godot/creator/debug view | 现有 mirror/projection 路径 | 只能读 committed result |

## 必须证明

- frost effect 命中与 resistance 通过；
- effect 被拒绝或目标不存在时结构化失败；
- 同一命令重复提交返回原 receipt；
- revision 冲突和权限不足零提交；
- full replay 与 checkpoint + tail replay 一致；
- creator debug view 能看到 trace，但不能执行 authority write；
- Godot 只收到 scope-filtered committed result。

验收产物应进入 `.harness/verification/`，并挂接正式 contract/vertical-slice profile。
V0 通过只表示通用契约可用，不能替代面包店完整参考游戏的验收。
