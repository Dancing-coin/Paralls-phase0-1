## 每个门禁的共同检查

- canonical owner 唯一，不能由 ESM、System L6、Godot、角色智能体或创作者工具越权写入；
- command 有 principal、idempotency key、expected revision 和 correlation/causation refs；
- 成功、结构化失败、权限不足、revision 冲突和重复命令均可回放；
- projection、creator debug view、actor view 和 Godot mirror 按 scope 过滤；
- Survival 关闭时不产生隐性 tick 或状态惩罚；
- ActionIntent 只能通过验证的 PhysicalFact/LogicalFact 进入领域结算；
- Reservation/Hold 的 reserve、consume、release、expire 和 compensation 具有明确 owner、幂等和零部分提交语义；
- world profile 不改变 canonical event/settlement 语义，creator environment 不得冒充 world mode；
- ActiveSemanticSet、ActiveWorldRevision 和 package compatibility 在 session/command/replay 中固定；
- 新增能力复用 `GameplayEventStore.append_batch`、outbox、replay 和现有 Harness 模式；
- 至少两个异质样板使用相同 identity/semantic/causal/settlement/time contract；
- 新领域只新增 schema/authority/projection/package，不新增 store、bus、runtime 或隐藏 scheduler；
- 样板专用字段不得进入通用 schema，新增字段必须有 owner、revision 和迁移说明；
- 群体模拟未实现前，不得以 NPC 角色、人口账户、员工库存或顾客消费状态作为第一阶段证据；
- 任何新 runtime、第二个 event bus/store、任意脚本规则或影子 NPC 都自动阻断。
