# Econ-1 跨域垂直闭环

状态：`planned complete reference game; not a generic infrastructure definition`

Econ-1 是第一款需要真正“从开始玩到结束”的小型完整参考游戏，也是领域组合验证。
它使用现有技能、背包、装备、资源、状态、产权和固定经济原语，新增面包店所需的
建造生产、生存需求、组织经营、许可证和税费能力。这里的完整不是内容规模大，而是
玩家可以完成一个可重复的经营闭环，所有相关系统都经过实际结算。

## 完整游戏闭环

```text
创建/接管面包店
-> 购买或取得设施与初始资金
-> 采购材料并放入库存
-> 安排角色/员工与生产时段
-> 技能检查、消耗材料、生成面包
-> 设置报价并接待顾客
-> 销售、库存减少、账户入账
-> 支付工资、租金、税费和许可证费用
-> 结算角色食物需求、疲劳和劳动能力
-> 进入下一经营日
-> 根据现金流、声誉和债务判定继续经营或失败
```

该闭环必须至少支持一个玩家角色、一个设施、三类商品、一个配方和一个采购来源。
群体模拟未实现前，顾客使用聚合需求、员工工资为零或仅由已有真实 CharacterRecord
的多智能体配置触发；不得注入员工、顾客或供应商 NPC 状态。所有状态变化都由领域
authority 通过现有事件溯源提交。完整的参与主体、NPC 门禁和多智能体协作见
[Econ-1 商业生态与多角色经营实现方案](05-Econ-1商业生态与多角色经营实现方案.md)。

## 第一版完整范围

| 组成 | 第一阶段只做 | 不做 |
| --- | --- | --- |
| 世界 | 一个辖区、一家面包店、一个设施、一个经营日循环 | 跨区贸易、生态和宏观经济 |
| 商品 | 三类商品、一个配方、采购与库存 lot 路径 | 订单簿、拍卖、通货膨胀 |
| 技能 | 一个生产/服务技能和一个工作项，含成功/失败反馈 | 完整技能图和职业树 |
| 建造生产 | 一个设施、材料预留、生产 run、维护和停工 | 通用蓝图编辑器、复杂维护和批量工厂 |
| 生存 | 一个基础食物需求，支持 `disabled/narrative/lightweight/simulation` | 全部疾病、住房和人口模型 |
| 组织 | 一个商业组织、岗位、工资、预算、员工排班和期末结算；单玩家配置允许无员工 | 完整公司制、银行和破产 |
| 政府 | 一个许可证、销售税、租金/费用和一个检查结果 | 完整监管、法院和政治军事 |
| 顾客与经营 | 顾客购买、现金流、声誉、债务、经营成功/失败 | 大规模人口消费模拟 |

## 跨域流程

```text
技能/体力资格
-> 材料与工具 inventory reservation
-> 设施时段与生产 run
-> 产出进入库存
-> 周期性 quote
-> 居民购买/消费
-> 工资、销售税、许可证费用
-> 组织期末结算
-> Survival state projection 与下一周期计划
```

每个阶段是 owning authority 的原子状态迁移；跨周期的生产 run、工资义务和税务
负债以显式 obligation/record 保存，不能依赖内存变量。任何领域拒绝时，当前批次零
提交；不要求把整个经营周期伪装成一个无法重试的超大事务。

## 核心协作边界

- Skill Authority 只判断资格、质量或完成证据；不发工资；
- Inventory/Construction Authority 维护材料、设施和生产状态；不写账户余额；
- Survival Authority 只提出需求与消费意图；物品消耗和付款仍由对应 authority 结算；
- Economy Authority 维护报价、账户、工资、税务分录和义务；不拥有设施进度；
- Organization Authority 维护岗位、预算、经营计划和期末状态；不复制库存或账户事实；
- Government Authority 维护辖区、许可、政策 revision 和检查结果；不直接删除资产；
- NPC 与玩家提交同一 typed intent，不能为组织成员创建脱离世界的影子角色。

## Survival 可调整边界

Survival 是核心 state group，但按项目/世界/角色组启停。Econ-1 必须至少证明：

- `disabled` 时消费计划不会产生生存惩罚事件；
- `narrative` 只产生张力投影，不扣除资源；
- `lightweight` 产生低频数值变化；
- `simulation` 才允许需求、消费、身体后果和劳动能力反馈完整接合。

模式切换使用 ruleset revision，不直接覆盖正式角色状态。

## Econ-1 验收

必须覆盖生产成功、材料不足、技能不足、库存容量不足、资金不足、许可证过期、税费
计算、工资结算、生存关闭、重复 tick、revision 冲突、完整 replay 和过滤镜像。
必须能从新店开始，连续完成至少三个经营日，并证明采购、生产、销售、工资（或零
工资路径）、税费、生存、许可证和失败恢复都可重复执行。`reference_single_actor`
不得产生 NPC 状态；多角色/员工/顾客验收在群体模拟上线前保持
`blocked-by-population-simulation`。完成后才能把 8 月分析中 Econ-1 的 `planned`
更新为 `implemented`。

## 泛化约束

- Econ-1 必须只依赖 Phase 1A/1B 冻结的通用 identity、semantic/effect、causal、
  settlement、time、replay 和 projection contract；
- 生产、工资、消费、税费和许可证是可替换的领域 authority/package，不得创建新的
  event store、bus、runtime 或跨域万能 coordinator；
- Econ-1 通过后仍不能宣称底座已泛化，必须再通过一个结构不同的样板（例如调查/冲突、
  合同/债务或权限型物理交互）才能关闭第一阶段泛化门禁。
