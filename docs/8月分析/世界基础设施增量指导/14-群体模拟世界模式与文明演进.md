# 世界消费模式与群体模拟指导

状态：`INF-4 source projections、one schedule-gated owner settlement、bounded owner rows 和 isolated branch event/projection buffer 已验证；真实 branch scenario 演进与完整群体模拟仍未完成`

## 1. 同一世界的三种消费模式

Paralls 需要同时支持可玩游戏、持续社会模拟和可审计推演，但不应复制三套事实
模型。三者共享实体、规则、事件和 revision，只改变调度精度、智能体唤醒策略、
输入来源和报告视图。

| 形态 | 主目标 | 时间/智能体策略 | 不变量 |
| --- | --- | --- | --- |
| 游戏 | 可参与、即时反馈、叙事高光 | 近场高频，远场日级/长周期 | 正式 authority 与玩家后果 |
| 模拟 | 大规模社会连续性 | 分层批量，按关系和事件升级精度 | 个体身份、资产、关系和事件连续 |
| 推演 | 参数实验和反事实解释 | fixed seed、隔离 branch event/projection buffer、确定性批处理 | 输入版本、过程与结论可复现 |

模式 profile 不得降低规则正确性：当 `planned` 的跨域 adapter 使用预提交
`SettlementPlan` 时，快速路径与通用路径要使用相同语义与 authority，只在计算预算和
触发粒度不同；已落地的单领域 authority 仍沿用直接事件映射和 `append_batch`。

## 2. 群体模拟与角色激活

完整群体模拟仍是后置设计。当前仓库除 `RuntimePopulationPolicy` 外已有 P3A-P3D 的
profile-backed activation、world mode 和 bakery-district continuity slice；P3D 已回填为一条
event-derived `schedule_gated_supply` 在 activation lock 释放后经既有
`OrganizationAuthority` fragment 的真实结算。通用 batch intent merge 已 retire 为
`legacy_population_merge_retired` 零写 fence；这些窄行不负责完整生成人口、家庭、组织计划或
经济结算。现有 branch preview 有隔离的
 descriptor/candidate event/projection buffer，可由本地 checkpoint+tail 重建。INF-4F 可对
  两条已注册 owner fragment builder 做只读验证并记录 digest；INF-4G 可从 accepted fragment
  在隔离 buffer 重建脱敏 planned commitment/inspection consequence。INF-4N 另在既有
  `GovernmentAuthority` 证明一条固定 production consequence：同一 durable passed-inspection
  admission 和 Government branch scenario event 经 revision/identity 重验证后，才写既有
  production inspection stream。INF-4O 在既有 `OrganizationAuthority` 上以同样封闭的
  durable supply admission 和 Organization branch scenario 证明一个 commerce commitment
  production consequence；两者都不等同通用 branch scenario 演进。

2026-08-15 的用户决策将完整群体模拟延后，不把它作为当前 INF 连续收口的实施包；
这只是排程调整，不是完成声明。生产等价 branch promotion 除 INF-4N 的单一 Government
passed-inspection 合同、INF-4S 的单一 Government failed-inspection 合同和
INF-4O 的单一 Organization supply 合同外仍必须
`branch_promotion_unsupported` 且零写入，直到每个目标
authority 明确拥有 branch settlement、event family、scoped projection、receipt 与 production
writeback 合同。

角色不是“消费者 NPC”“雇员 NPC”等多个影子，而是同一 `CharacterRecord` 的
多重身份。它可以同时是父母、纳税人、工人、债务人、组织成员和派系参与者。
家庭、知识和信息不对称的具体 projection 见
[19-家庭人口与社会结构系统.md](../角色与社会投影增量指导/19-家庭人口与社会结构系统.md)
与 [20-知识信念与信息传播系统.md](../角色与社会投影增量指导/20-知识信念与信息传播系统.md)。

```text
即时脉冲：玩家交互、战斗、重大环境变化
日级结算：工作、消费、家庭库存、市场、日程
长周期结算：健康、技能、关系、制度与文明

ACTIVATE(character)
  -> activation lock -> scene-relevant snapshot -> high-fidelity agent
  -> pending_changes -> revision checked merge -> memory summary -> requeue
```

普通劳作、买卖和移动由规则、计划器或小模型批量运行。大模型只用于玩家互动、
重大选择、谈判、创新、道德两难和涌现模式的解释；司命只能提议、标记和调谐，
不得直接提交世界事实。

历史 P3C generic merge 曾从自由 payload 取得 stream/event 并以
`population.authority` 写入，无法对应既有 domain owner。该 production writer 已
retire 为 `legacy_population_merge_retired` 零写 fence；正式群体写入只能经已登记的
owner fragment/SettlementPlan/append/outbox/replay/scoped projection 路径。INF-4Z
Harness 的独立 `legacy_population_merge_zero_write` 断言覆盖调用方选择的
stream/event，并证明它不产生 event 或 outbox；不可达的旧 append 实现已删除。

## 3. 创新与动态内容治理

创新不是司命凭空把“风车磨坊”写进正式世界，而是受约束的因果链：

```text
失败或需求压力 -> 知识/记忆检索 -> 材料与技能检查
-> 小规模试验 -> 因果结算验证 -> proposal
-> schema/dependency/review -> signed revision -> 传播与采用
```

动态字段分为四类：已注册结算字段、受类型约束的扩展属性、仅叙事字段、未识别
候选字段。最后一类只能进入审查队列，不能由自然语言或自由 JSON 影响正式状态。

## 4. 与文明和社会模拟的交接

`CivilizationCapability`、六轴传导、金融/制造解锁和制度采用属于社会与制度玩法的
后期层，不由本文件或既有世界基础设施拥有。唯一已批准的例外是 INF-4Y-A 的
最小能力 lifecycle owner：`CivilizationCapabilityAuthority` 只拥有
`gameplay:civilization_capability:{jurisdiction_ref}` 上的 activated/revoked/
corrected canonical events 和 scoped read view。它不拥有进展、六轴、制度、消费方
资格或创作者控制面。世界基础设施只提供 profile、调度入口、event/revision 脊柱和
可回放约束；对应的 owner、门槛和非目标见
[文明能力与六轴传导](../玩法系统/社会与制度玩法/23-文明能力与六轴传导.md)。

## 5. 数据校准与反事实边界

推演模式可以引用现实统计、历史资料或创作者上传的参数集，但它们应作为版本化
`ReferenceDataset` 与 `CalibrationInput` 进入预览/推演环境：

```text
ReferenceDataset(dataset_ref, provenance, license, schema_revision, digest)
CalibrationInput(world_ref, dataset_ref, parameter_mapping, effective_revision)
```

外部资料只能用于初始化、校准或生成 proposal，不能直接覆盖角色、资产、事件
和规则真相。每份推演报告必须固定数据集 digest、映射、world snapshot、seed 和
ruleset，以便复现并区分“世界内因果”与“外部参数假设”。`license_ref` 仍只是
legacy 调用方 metadata，不能作为授权。已验证的 INF-4Z-A 窄 owner 是
`ReferenceDataAuthority`：仅 `authority:reference_data` 可在既有 event store 的
`gameplay:reference_data:{dataset_ref}` stream 上写入 registered/corrected/revoked
canonical dataset event，并派生 authority-scoped、revision/source-vector/digest 固定的
`ReferenceDatasetView`。只有冻结的 permitted view 可被
`BranchPreviewAuthority.preview_authorized()` 消费；revoked、forged、stale 或 scope
不匹配输入均 zero-write reject，公开 branch report 不暴露 license/provenance。证据为
`infra-reference-data-license-admission`。外部 ingestion、branch promotion 和生产世界
覆盖仍不准入；生产世界采用数据更新也必须走 revision、模拟、审核和 scheduled activation。
