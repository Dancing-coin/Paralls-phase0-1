# 生态、环境与灾害系统

状态：`INF-3 canonical ecology record/retire、闭源 seasonal process、固定 Construction/Organization/Economy consumer rows 已验证；完整生态 lifecycle、泛化 fanout 与多灾害传播仍未完成`

## 1. 领域职责

生态环境域维护区域、天气、土壤、水体、温度、资源再生、作物、生物群落和
灾害状态。它提供环境事实与 effect，不直接决定经济价格、角色记忆或战斗胜负；
其他领域通过统一因果结算消费这些结果。

当前已有一条闭源、单 region、caller-driven seasonal process：在 ecology owner stream 上
轮换固定 weather、增加 moisture、按已记录 regeneration 值恢复资源并增加作物 growth；
它不是通用天气模型、后台 scheduler 或多 region fanout。除此之外尚无过程性天气、资源
再生或作物生长 lifecycle；`chain_budget` 仅为 frost admission fence，不是已实现的逐步
传播引擎。除已验证的 frost -> construction 和 seasonal process -> construction
maintenance 外，其他 consumer edge 必须由目标领域 owner 单独准入并写自己的 stream。

已验证的 `INF-3C` 补充了 ecology-owned `neighbor_region_refs`、
`policy:ecology_weather_front_step@1` 和 source/target 双 stream
revision/idempotency contract，用于单一双向邻接、预算为一的 weather-front step。
它不授权从 `jurisdiction_ref` 或 `biome_tags` 推断传播边，也不授权多轮 fanout、
hazard 传播或 ecology 直接修改其他领域。因此预算化多 region weather/hazard fanout
仍是 `blocked`，等待其自身的 policy、边选择、source/target privacy 和每个 target-owner
consumer contract；现有 seasonal process 与单步 weather front 都不构成该广域能力。

## 2. 核心模型

```text
EnvironmentRegion
  region_id, climate_profile, biome_tags, carrying_capacity, jurisdiction_ref

EnvironmentalState
  region_ref, temperature, moisture, contamination, weather, source_revision

ResourceNode
  node_id, substance_ref, quantity, regeneration_policy, extraction_state

CropOrPopulation
  entity_ref, growth_or_population_state, health, habitat_refs

HazardEvent
  hazard_id, effect_templates, area, duration, severity, causal_parent_refs
```

气候、资源和灾害使用参数化 effect 进入语义因果层。霜冻、洪水、干旱、污染、
火灾和疫病可影响实体材料/状态、设施耐久、作物产量、角色身体和可达性，但
具体后果由对应领域 authority 写入。

## 3. 跨域传导

```text
环境状态/灾害 -> effect/resistance/meta-rules -> SettlementPlan
-> 农作物/设施/角色状态 -> 产量与供给 -> 价格/税收/救济
-> 迁徙、关系、任务、战争风险和角色记忆
```

传导边要带方向、阈值、衰减、时间和规则版本。例如一次霜冻先影响作物，不应
在同一 tick 无限制地递归改变全世界价格、情绪和战争；后续影响由 scheduled
obligation 和因果预算逐步结算。
