# 生态、环境与灾害系统

状态：`planned ecology extension; ESM object/environment facts and event/replay are reusable foundations`

## 1. 领域职责

生态环境域维护区域、天气、土壤、水体、温度、资源再生、作物、生物群落和
灾害状态。它提供环境事实与 effect，不直接决定经济价格、角色记忆或战斗胜负；
其他领域通过统一因果结算消费这些结果。

## 2. 核心模型

```text
EnvironmentRegion
  region_id, climate_profile, biome_tags, carrying_capacity, jurisdiction_ref

EnvironmentalState
  region_ref, temperature, moisture, contamination, weather, source_revision

ResourceNode
  node_id, substance_ref, quantity, regeneration_policy, extraction_state

CropOrPopulation
  entity_ref, growth_or_population_state, health, habitat_refs

HazardEvent
  hazard_id, effect_templates, area, duration, severity, causal_parent_refs
```

气候、资源和灾害使用参数化 effect 进入语义因果层。霜冻、洪水、干旱、污染、
火灾和疫病可影响实体材料/状态、设施耐久、作物产量、角色身体和可达性，但
具体后果由对应领域 authority 写入。

## 3. 跨域传导

```text
环境状态/灾害 -> effect/resistance/meta-rules -> SettlementPlan
-> 农作物/设施/角色状态 -> 产量与供给 -> 价格/税收/救济
-> 迁徙、关系、任务、战争风险和角色记忆
```

传导边要带方向、阈值、衰减、时间和规则版本。例如一次霜冻先影响作物，不应
在同一 tick 无限制地递归改变全世界价格、情绪和战争；后续影响由 scheduled
obligation 和因果预算逐步结算。

## 4. 当前与新增

- `implemented`：ESM 环境/对象状态基础、状态标签、资源/身体、事件/回放和
  Siming catalyst 边界；
- `reusable`：Ownership/Inventory/Resource-Body 的既有 authority 边界、Godot
  presentation 与既有事件/回放脊柱；Construction、Survival、Economy 的完整 proposal
  contract 仍分别属于 `planned` 领域；
- `planned`：实体/语义因果扩展、SimulationClock、region/environment records、
  天气/生态状态、resource node、作物/群落
  lifecycle、hazard scheduler、环境 effect、传导边与区域 projection。

创作者可定义区域、气候、资源节点、作物、灾害和恢复曲线；环境真实状态、
跨域因果预算、批量调度和正式事件写入保持闭源。
