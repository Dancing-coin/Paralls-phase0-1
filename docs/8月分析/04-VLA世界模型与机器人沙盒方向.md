# VLA、世界模型与机器人沙盒方向

## 1. 当前项目与 VLA 的真实关系

当前项目已经具备基础 VLA harness 形态，但应准确表述为：

> 角色智能体可以接收多模态/视觉/空间 advisory，并通过结构化行动请求进入具身执行链；VLA 不是世界真相，也不是低层运动控制器。

当前边界是：

```text
视觉/空间/多模态输入
-> PQF / percept bridge
-> 角色私有感知或 VLA advisory
-> L2/L3/L4 或交互编排
-> 结构化 action request
-> ESM / Gameplay / 物理与场景 authority
-> 结果和事实回写
```

VLA 可以建议“看到了什么、应该关注什么、可能采取什么动作”，但不能直接写入产权、资源、背包、世界状态或物理真相。

## 2. 世界模型如何接入

世界模型可以被接入为三种角色：

### 世界预测器

预测在当前世界状态下，某个行动可能造成什么结果，用于规划和预演。

### 世界生成器

生成场景布局、物体语义、可交互资源和视觉表现候选。但生成结果必须经过资产、碰撞、交互和安全校验，才能进入运行时。

### 世界压缩器

把大量历史事件、空间状态和玩家记录压缩成可查询的世界摘要，降低长上下文成本。

世界模型不应直接替代物理引擎。更合理的结构是：

```text
世界模型：预测/生成/建议
物理引擎：高频碰撞、运动、接触和动力学
世界 authority：接受或拒绝世界变化
事件系统：持久化、回放和审计
```

## 3. AI 游戏和机器人沙盒的区别

### AI 游戏

目标是体验、叙事、角色关系和玩家公平性。世界模型可以重点服务：

- 场景和内容生成；
- NPC 计划和行为预测；
- 对话、关系和剧情推进；
- 玩家体验调节；
- 可复用故事线和高光事件。

游戏需要稳定的权威状态、可回滚结果和公平的秘密/信息边界。

### 机器人沙盒

目标是安全、可验证、可复现的动作训练和脑内预演。世界模型可以重点服务：

- 未来状态预测；
- 轨迹候选；
- 反事实试错；
- 视觉-语言-动作规划；
- 失败风险评估。

机器人沙盒必须增加：

- 更严格的安全约束；
- 时间同步和传感器延迟模型；
- 动力学/碰撞高保真验证；
- sim-to-real 差异管理；
- 真实机器人权限和急停边界。

## 4. 未来的统一 harness

```text
Observation Adapter
  -> World State / Private Perspective
  -> Memory and Retrieval
  -> Reasoning Model
  -> World Model Prediction
  -> World Action Model Proposal
  -> Policy / Safety / Authority Gate
  -> Physics or Game Settlement
  -> Replay and Learning Trace
```

Codex 与 GPT 的类比可以保留在产品叙事中：harness 不替代模型，而是提供状态、工具、约束、执行、回放和恢复能力。

## 5. 当前距离目标的差距

- 当前 VLA 主要仍是 advisory/慢路径，不是低成本实时世界动作模型；
- 世界模型生成的资产尚未形成完整导入、碰撞、交互、LOD、导航和持久化流水线；
- 当前物理/场景 authority 和世界模型之间还需要正式的 proposal/validation 协议；
- 机器人沙盒需要独立的时间、动力学、安全和 sim-to-real 规格，不能直接把游戏运行时当机器人运行时。

结论：当前架构适合预留世界模型接口，但现阶段不应把世界模型当作运行时唯一世界真相。
