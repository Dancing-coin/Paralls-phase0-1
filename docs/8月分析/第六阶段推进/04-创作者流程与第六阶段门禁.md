# 创作者流程与第六阶段门禁

状态：`incremental design; P6D formal spec and Harness profiles required before implementation`

## 1. editor 的实际流程

```text
读取已授权 schema/projection
-> 创建角色/玩法/规则草案
-> UI 或 CLI/MCP 修改同一 draft
-> 运行静态校验、依赖校验和隔离 preview
-> 观察 diff、trace、失败矩阵和成本预算
-> 提交 review
-> admin 签名并 stage/canary
-> 在 revision boundary 激活
```

editor 可以基于底座做出自己的游戏，但只能在声明式 package、已开放 capability 和
受治理的 owner extension 范围内创作；不能替换闭源核心或编写新的 canonical writer。

## 2. 门禁

- reader/editor/admin 的 UI、CLI、MCP 权限决定一致；
- editor 无法读取闭源算法、私有角色 workspace 或正式玩家事实；
- 非法 schema、未声明依赖、任意代码、越权字段和不兼容 revision 都被拒绝；
- local preview 与 remote production 状态隔离；
- active revision 可回放、可审计、可回滚；
- 失败的激活、冲突的草案和撤销的授权不产生部分正式写入；
- P1-P5 predecessor、package validation、permission matrix、staging/canary 和 rollback
  Harness 全部 fresh-green。

通过后才可以把“创作者可以独立制作和发布自己的游戏内容”作为产品能力声明；仍不能
声明创作者获得闭源 core 源码或直接运行时管理权限。
