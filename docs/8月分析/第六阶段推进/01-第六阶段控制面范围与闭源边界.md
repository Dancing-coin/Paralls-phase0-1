# 第六阶段控制面范围与闭源边界

状态：`incremental design; P6A formal spec required before implementation`

## 1. 控制面只能管理声明和 revision

可编辑内容包括：

- 角色档案中已授权的可编辑层、关系/任务/资产绑定；
- 玩法包 manifest、schema、标签、规则参数、Survival profile 和公开经济参数；
- Godot/2D/VRM 等表现绑定、场景配置和 mirror 字段声明；
- preview world、测试 seed、Harness 场景和发布说明。

不可编辑内容包括：

- Character Core L1-L4 的闭源推理、记忆写回、原始私有 workspace；
- Gameplay authority 的原子写入、事件签名、迁移器和内部结算算法；
- 正式玩家账户、库存、身体/需求、关系秘密和历史事件；
- 模型密钥、部署凭证、审计密钥和服务端策略实现。

## 2. owner 矩阵

| 控制面组件 | 负责 | 不负责 |
| --- | --- | --- |
| Authoring API | 草案、proposal、schema validation、权限决定 | canonical settlement |
| Preview/Simulation | 隔离的预览事实、trace、报告 | 正式世界写入 |
| Package lifecycle | manifest、依赖、兼容性、签名、staging/activation 状态 | 修改玩家事件 |
| Authorization | reader/editor/admin decision、data classification、capability | 用 UI 按钮实现安全 |
| Closed core service | 角色、authority、migrator、签名验证等内部实现 | 向 editor 暴露可导入 writer |

控制面只能通过现有 backend session/scope、Patch/runtime lifecycle、`GameplayPackageManifest`、
revision activation 和 filtered projection 扩展，不能平行建立 `CreatorRuntime`。

## 3. 安全不变量

- 本地预览的 store、世界 revision 和角色状态与正式环境隔离；
- editor 提交 proposal 不能绕过 admin approval/signature；
- remote update 只能激活新 revision，不能修改旧事件；
- rollback 是选择旧的兼容 revision 或执行受信任 migrator，不是删除数据；
- 所有 UI/CLI/MCP 操作都产生 audit ref、actor/principal、project scope 和 payload digest。
