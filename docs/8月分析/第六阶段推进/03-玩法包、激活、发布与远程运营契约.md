# 玩法包、激活、发布与远程运营契约

状态：`incremental design; P6C formal spec required before implementation`

## 1. 玩法包生命周期

```text
draft
-> validated
-> previewed
-> reviewed
-> signed
-> staged/canary
-> active
-> superseded/rolled-back
```

玩法包只能声明 schema、规则参数、资产引用、依赖、capability、state group 和 mirror
binding。任意脚本代码、未注册字段、未经批准的 provider 或闭源 core import 都应在
validation 阶段拒绝。

## 2. 本地创作与远程正式运行

本地创作允许编辑草案、运行隔离预览和 Harness；不会写入正式玩家状态。远程正式运行允许
更新公开数值、内容和规则 revision，但每次变更都必须经过：

1. compatibility/schema validation；
2. migration and rollback check；
3. authorization and admin signature；
4. staging/canary observation；
5. explicit activation boundary；
6. committed activation event and audit report。

远程正式运行可以做数值参数调整和内容更新，但不能通过“远程调整”直接改玩家账户、
库存、角色需求或历史事件。

## 3. 版本和回滚

每个 active world revision 固定 package digest、schema registry、policy refs、core
compatibility version 和 migration ref。回滚只允许切换到兼容 revision 或执行受信任
migrator；不得在 replay 中执行创作者任意代码。
