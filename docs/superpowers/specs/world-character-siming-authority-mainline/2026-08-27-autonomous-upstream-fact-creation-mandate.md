# Autonomous Upstream Fact Creation Mandate

Status: `approved standing authorization; Goal active; August INF A-D not complete`

The main thread may autonomously close ordinary INF blockers by selecting a
product-significant row and, when the repository lacks a required upstream
fact, creating a strictly row-specific committed source or projection under an
existing truth owner. It may choose the package-local business literals,
subject binding, privacy, revision fence, idempotency, replay, terminal,
correction and compensation semantics needed by that row.

The source fact must be a real product input for the selected row, not a test
fixture or generic placeholder. Its owner, event family, stream, visibility,
receipt and replay reader remain fixed by the existing owner contract. The
decision record must state the product loop, rejected alternatives, fact
partition, downstream dependencies, and residual limitations.

If the conflict matrix proves no existing owner can legally own the new fact,
the main thread may admit one strictly row-specific new owner with its own
complete Owner-Admission Contract, descriptor/catalog row, tests, Harness, and
replay/privacy evidence. This does not authorize a generic owner or reusable
registration surface.

All permanent prohibitions remain active: no generic payment, transfer,
transform, promotion, router, registry, coordinator, writer, settlement
authority, caller-selected authority coordinates, combined cross-owner receipt,
or second runtime/store/bus/clock/scheduler. Every write still uses
`GameplayCommandEnvelope -> SettlementPlan -> GameplayEventStore.append_batch()`.

Continue in `INF-1 -> INF-2 -> INF-3 -> INF-4` order. Stop only for a true
contradiction, unavailable external fact/credential, incompatible platform or
schema change, forbidden generic expansion, or irreconcilable privacy/replay
evidence failure.
