## Bounded Candidate Reviewed: Branch Work Preview To Production Wage Accrual

This audit evaluates one concrete replacement for the generic promotion label:
a creator-debug branch `work` candidate promoted to an existing Economy
`wage_accrued` event. It does not repeat the terminal existing-owner discovery
audit.

There is useful but non-composable evidence on each side:

- `BranchPreviewAuthority` accepts a deterministic `work` candidate and can
  replay it only inside the isolated branch buffer. Its `production_replay()`
  deliberately excludes branch and branch-admission streams, and its generic
  `promote()` rejection remains `branch_promotion_unsupported`.
- The separately admitted INF-4Z Production-to-Economy wage vertical accepts
  only a committed, worker-scoped
  `gameplay.construction_production.work_completion_evidence_recorded` view.
  It pins that Production event/vector/digest and writes one actor-scoped
  Economy `gameplay.economy.wage_accrued` event. It is not a branch reader or
  a branch-promotion capability.
- The immutable branch-promotion catalog has exactly the Government inspection
  and Organization supply rows. Branch scenario settlement methods exist only
  for those two owner outcomes; no Economy wage promotion operation is
  registered.

The candidate is therefore not an executable existing-owner contract. A branch
`work` proposal is not a completed-work fact, must not be treated as Production
evidence, and has no permitted creator-debug-to-actor visibility translation.
There is no fixed Economy branch command, production stream/revision vector,
idempotency key, append-derived promotion receipt, or full/checkpoint-tail
reader that joins an isolated branch replay to the actor-scoped wage event.
The existing wage-accrual row also expressly leaves correction and compensation
to a future owner-local contract; none is defined for a branch promotion.

A future row-specific Owner-Admission Contract must first state all of the
following without using the branch candidate as a substitute for committed
Production evidence:

1. the sole source event and whether a branch may ever nominate it, with a
   fixed Production source event/stream revision and worker scope;
2. the exact Economy owner command, wage target stream/event family, read and
   write revision vectors, actor-only privacy projection, and idempotency key;
3. the append-derived receipt and a replay proof that preserves branch/
   production isolation rather than merging their histories; and
4. terminal, correction, retry, and compensation behavior for the one wage
   outcome.

No new Population, branch, social, or Economy truth owner is proposed here.
No generic promotion registry, branch settlement writer, or branch-to-Economy
router is authorized. The existing Production evidence wage consumer and the
two exact Government/Organization promotions remain unchanged.

Work may resume only when a separate, row-specific branch-to-Economy
Owner-Admission Contract is explicitly approved. It must preserve existing
domain ownership and cannot make generic `work`, group simulation, or any
other branch candidate eligible.
