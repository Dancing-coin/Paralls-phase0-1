# 群体模拟剩余六项闭环设计

日期：2026-09-16。范围来源：本任务中已经列出的六项缺口，以及用户“将6项编写成执行计划，作为目标完成，不要提交给我部分完成的内容”的要求。

状态：`planning_complete_requires_execution_evidence`。这是后续实施目标；不是六项实现完成证明。当前 Godot 状态仍为 `godot_unverified`。用户已指定在另一台机器执行真实 Godot 验收，本机准备实现、静态检查和可重放证据交接包。2026-09-18 用户将当前完成合同收敛为最高 1,000 人；10,000 人能力与入口保留为后续扩展，不阻塞本轮六项闭环。

执行入口：[完整执行计划](../plans/2026-09-16-population-production-runtime-closure-implementation-plan.md)。

## 目标与边界

在现有混合数据导向架构上，完整补齐服务响应、长局恢复、Godot 表现、混合负载、数据搬运、持续验收六项。Backend 继续拥有事实与裁决，Domain Owner 继续提交竞争资源结果，Character Core 继续拥有私有连续性，Godot 只负责本地表现与结构化输入。

不增加分布式集群、不新增第二个世界事实库、不删除历史以制造性能提升、不默认迁移 SoA/C++/GPU。基线热循环占比约 4.87%，目前先解决执行隔离、恢复与数据传递。

## 已确认的验收约定

- 100／1,000 人两档 1× 必须通过：1 秒仿真窗口对应 1 秒墙钟预算，端到端 p95 不超过 800 ms，连续 30 窗 backlog 不持续增长，最大推进延迟不超过一窗。
- 10× 为独立压测：同样两档、30 窗、80 ms p95 预算，必须真实运行并报告失败，但性能失败本身不否决原 1× 门槛。
- 10,000 人实现与通用参数继续保留，但本轮不采集、不进入聚合必过项；未来恢复万人验收时必须使用届时同一提交重新取得完整证据，不能复用本轮千人报告。
- 不以局部测试、后端通过、脚本静态检查、Godot editor import 或旧报告代替六项总验收。
- `docs/superpowers/` 为本地设计和执行文档，遵守当前 AGENTS.md，不纳入 Git 提交。

## 六项设计决策

1. **服务响应**：每局一个串行 runtime 写入执行域，先采用专用线程和有界标准库队列。ASGI loop 只管连接与 transport；Bus、Siming、Owner、runtime 读写走同一执行域。模型网络等待拆成冻结输入、纯 provider 调用、回到执行域按版本提交。若真实压力下 GIL 仍导致响应门槛失败，按计划中的固定分支改为每局一个本地进程，不引入多 writer。
2. **长局恢复**：SQLite 保存完整事实及幂等索引，正常启动不反序列化全历史。人口使用有摘要、规则身份和精确已交付锚点的 hot checkpoint，加有界尾部重放；dispatcher、driver 和 receipt 缓存同步去除历史线性增长。全历史深校验保留为迁移与显式离线 audit；正常启动校验 checkpoint 和读取的尾部，按需读取旧事实时继续校验。
3. **Godot 表现**：复用现有 WebSocket session、read scope、mirror snapshot/delta、gap/resync、backpressure 机制，新增逐 actor 的 population_public state group，沿用 allowed_actor_refs；位置使用明确标为非世界真相的探针展示布局，私有 hot字段不得公开。真实后端消息必须进入实际运行场景并改变表现；距离分档不能改变权威状态、激活、Owner receipt 或 replay hash。
4. **混合负载**：真实 Uvicorn 和 WebSocket 上做 100／1,000 人两档混合 30 分钟与 1,000 人 2 小时长测；覆盖 B0、B1/B2、到期波峰、Owner 竞争、模型成功及故障、断连恢复。另测 2／4 个 1,000 人独立局进程，给出单机实测容量。万人入口保留但不纳入本轮门禁。
5. **数据搬运**：分别记录内部对象物化、JSON/pickle 编解码、hash、落盘和真实 WebSocket 字节。保留校验、消费者隔离和 canonical hash；复用一次验证/编码结果，公开表现按授权观察范围发全量与增量。不得把内部约 7.59 MiB/window 误写成已测网络流量。
6. **持续验收**：CI 显式运行人口 correctness profiles，安装后端依赖与固定 Godot 版本；有渲染设备的固定机器执行绝对性能与 Godot 帧时间验收。总报告检查完整矩阵、源文件摘要、环境及原始产物，缺证据或状态未知都拒绝完成。

## 本计划采用的新增工程默认值

下列值是为使计划可执行而选择的初始验收合同。当前经用户确认的范围为 100／1,000 人两档 1×／10×；执行时不能看到失败后静默放宽。

| 项目 | 默认值和测量口径 |
|---|---|
| 服务接收响应 | 本机 HTTP health 与 WS transport accepted 的 p95 ≤ 100 ms；accepted 只表示入队，不表示事实已提交 |
| loop 延迟 | 10 ms heartbeat，p99 ≤ 50 ms，记录 max；不将 provider 首 token 延迟混入 loop 指标 |
| 非模型事实命令 | 单局混合稳态下完成 p95 ≤ 1,500 ms；保留其排队/执行分段指标 |
| runtime 队列 | 每局最多 128 个待执行命令；满时结构化 busy/可重试，不能无界排队 |
| provider 并发 | 验收运行每局最多 4 个在途请求；正常网络请求超时使用现有 provider 配置，不新增产品配置平台 |
| checkpoint | 每 16 个确认窗口保存一次，保留 2 代；正常尾部 ≤ 16 窗，上一代恢复 ≤ 32 窗 |
| 恢复 | 固定 1,000 人 roster、固定 8 窗 tail，1,000 与 10,000 历史窗各测 5 次；p95 ≤ 15 秒，读取/反序列化条数不随历史数增长，10k/1k 恢复时间比 ≤ 1.5 |
| 内存 | 热身后两小时 1,000 人运行最后 30 分钟 RSS 中位数相对最初 30 分钟增长 ≤ max(32 MiB, 10%)；有限缓存必须有精确数量上限 |
| Godot | 固定 1280×720、关闭 VSync、固定 renderer；热身 10 秒，两档各采样 60 秒，frame p95 ≤ 33.3 ms，记录 CPU/GPU 与 stutter |
| 表现人数 | N=100：32 near/68 far/0 invisible；N=1,000：32/128/840；轮换成员以检查销毁/重建/订阅。N=10,000 的 32/128/9,840 合同保留为未来扩展，不进入本轮报告 |
| 时长 | 两档各 30 分钟混合稳态；1,000 人另跑 2 小时；2／4 个 1,000 人独立局各 10 分钟容量探测 |

15 秒恢复目标只约束固定尾部的正常启动，不包含一次性旧库迁移、完整 rebuild 或 fixture 生成。未交付 outbox 不能被数量上限丢弃；按页查询和分批排空，并分别报告恢复 ready 与积压完全恢复的时间。

## 总完成合同

六项结果均为 `passed`，原四个人口 correctness profile、100／1,000 人两档 1×、两档 10× 完整压测、mainline、`change-lifecycle`、`all` 均有对应新鲜证据；其中 10× 的“完整压测”允许性能结果失败。Godot 必须为 `runtime_verified`，真实 provider 成功证明不能来自 fallback，CI 必须有对应代码的实际运行结果。10,000 人属于后续扩展门禁，不影响本轮聚合结果。

`not_run`、`blocked`、`static_only`、`godot_unverified` 均不是通过。不把实现计划写完等同于代码目标完成，也不把本地脚本通过等同于远端 CI 通过。遇到外部凭据、执行机器或设备阻塞时保留事实和可继续的记录，整体保持未完成。
