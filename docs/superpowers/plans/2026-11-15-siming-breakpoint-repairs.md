# 司命 S1–S8 修复实施计划

依据：用户本轮明确实施要求、`docs/reference/phase1-siming/Q1-Q2-decisions.md` 的 Q2，以及 `.harness/SIMING-ARCHITECTURE.md`。用户要求优先：不迁移 B0，不创建或修改 Owner。

## 范围与顺序

1. S3：复用现有 FactTypeRegistry，增加 gameplay schema 声明的启动覆盖验证；投影器构造时检查。测试缺失注册导致启动失败、既有 domain 不回退前缀猜测。
2. S2/S4/S5：观测器复用覆盖验证；节点注册器增加实例隔离、重复拒绝的动态注册接口并验证命名空间；世界事实增加可选、注册表校验的 fact_type_ref，现有记录保持可读，运行时写入填充真实事件引用。测试新事件观测、动态注册与隔离、无效引用拒绝及存储往返。完成后全后端回归。
3. S6/S1：非角色资格不能因 actor 存在而绕过；状态树输入字段通过司命本地类型化载荷契约读取，Owner 未提供结构声明时保留 Phase 2 标记。测试混合目标拒绝、类型契约和未知事件不臆测字段。完成后全后端回归。
4. S8：注入按事件解析的实际角色名册，主组合接入角色运行时；移除演示角色回退，无名册时不虚构目标，过滤 blocked actors。测试不同名册、空名册和实际 tick 行为。
5. Q2：统一从注册表显式订阅，启动前验证，更新已实施注释；保留 Phase 2 混合图/Owner 查询与 revision 对账边界。测试真实事件总线交付及未知事件不投影。完成后全后端回归。

## 执行与验收

每阶段先写失败测试，再最小实现并运行聚焦测试；按断点编号分别提交中文信息。沿用本轮 `main`，不切换分支，不推送。不加入示例中的其他模型署名。

最终运行 `python -m pytest backend/tests/ -q --tb=short -p no:cacheprovider` 与 `python scripts/verification/harness.py --profile all`。仅报告本轮结果，环境阻塞单列；遵循临时证据生命周期。新测试使用真实注册器、图存储和事件总线。

## Review Focus

- 新增 schema 后旧注册表不能静默漏订阅。
- 动态注册不能污染其他实例或绕过 namespace/privacy 限制。
- 旧世界事实无引用仍可读，新引用必须存在。
- 合格角色不能授权不合格物品/环境；无名册不能伪造角色。
- 未声明的 gameplay payload 不应被聚合事件字段约定误解释。
