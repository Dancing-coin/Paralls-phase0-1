# 架构文档建设规则

本目录下的架构文档必须说明模块所有权、边界、状态和验证方式。每个新增或实质修改的架构主题，必须同时提供：

1. 设计文档：目标、当前实现、计划能力、边界和非目标。
2. 说明文档：代码入口、配置、接入方式和验证入口。
3. 架构图：模块、所有权和依赖方向。
4. 时序图：关键调用顺序、反馈和失败路径。
5. 数据流转图：输入、转换、输出以及 authority 边界。

图表使用 Mermaid，并与对应主题文档放在同一主题目录或通过相对链接明确关联。图中必须区分 `current`、`planned` 和 `deferred`。缺少任一类图表的架构主题视为未完成。

## 通用基础设施规则

`通用基础设施/` 下的文档只描述跨场景复用的基础能力，不吸收具体玩法的 authority、HUD、伤害、剧情和目标选择规则。实现代码必须能映射到文档中的模块名；如果一项能力由多个模块合作完成，文档必须说明输入、输出、所有权和禁止越界。

新增主题应在自身 `README.md` 登记设计文档、说明文档、架构图、时序图和数据流转图。

角色新增文档必须区分资源包注册、骨架与动作库接纳、场景人物实例以及后端身份绑定。默认追加独立人物并保留已有实例；只有明确的替换需求才能定义替换行为。图表和说明必须标明当前初始化顺序与计划中的接纳流程，不能把报错后继续初始化、组扫描或显式注册 API 描述成已完成的事务接纳、动态发现或完全跨项目解耦。
