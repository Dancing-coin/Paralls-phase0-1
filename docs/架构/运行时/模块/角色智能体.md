## 边界

角色智能体运行时拥有 actor-private perception、memory writeback、
解释、规划和执行语义 staging。

它不拥有：

- world truth
- ESM authority
- Siming 全局态势判断
- 作为最终语义 owner 的 Godot 表现
- 直接 low-level physical state mutation

并且要继续守住这些桥接边界：

- `L1RuntimePerceptionBridge` 是感知桥，不是角色认知 owner
- `System L6` 是 public event bridge，不是角色私有感知桥
- `ESM` 负责 authority settlement，不拥有角色认知

当前真实状态：

```text
mind core：仓库事实中已完成
运行时路径：真实存在且已验证
最终 L4 -> CharacterActor 收敛：未完成
legacy compatibility shell：仍存在，但已经更薄
```

### Layered mind factor frame

The character agent keeps the existing four-layer runtime:

```text
L1 private perception
-> L2 subjective interpretation and cognition update
-> L3 goal arbitration and planning
-> L4 execution contract
```

The layered mind factor frame is a shadow read model above existing stores:

```text
profile + memory + relationship/social memory + need tension + dynamic state
+ goal state + unresolved tensions + supervision + affordances
-> CharacterMindFrame
-> L2/L3/L4 layer views
```

Completed flow after Phase 3-6:

```text
owned source stores
-> projection services
-> CharacterMindFrame
-> bounded L2/L3/L4/writeback views
-> MindDeltaLedger
-> writeback policy router
-> existing memory/state/goal/skill-evidence/drift boundaries
```

`char_b` 的五池长期记忆（event / observation / knowledge / social /
higher-order）已通过 actor-private scope 写入 SQLite Heavenly Graph，并通过
只读 memory store 接入角色 L2/L3 上下文；`char_a` 等轻量角色仍走内存路径。
图谱是长期记忆的持久化与追溯层，不替代 event/social memory 的所有权，也不让
L2/L3 直接写图。模型上下文进入网关前会按注意目标、目标状态、事件目标、时间、
显著度和置信度做有界召回；召回只改变 active context，不删除长期记忆。

It does not make ESM responsible for cognition, does not make System L6 a mind
bus, and does not move skill state into L4.

### Mind factor influence model

The seven mind factors are not peers in one flat list. They enter the runtime
at different horizons and influence one another through need tension, dynamic
state, interpretation, planning, and execution views.

```text
                           ┌──────────────────────┐
                           │        人格          │
                           │ 长期稳定倾向/红线/风格 │
```

Short form:

```text
人格 + 记忆 + 关系 + 当前事件
        ↓
需求被触发
        ↓
需求压力 NeedTensionState
        ↓
情绪/身体状态 CharacterDynamicState
        ↓
L2 主观解释
        ↓
目标组织 + 技能约束
        ↓
L3 策略排序
        ↓
L4 行动表现
```

Factor meanings:

- 人格：决定“我是怎样的人，什么会刺激我”。
- 需求：决定“我长期在意什么”。
- 记忆：决定“我过去知道什么、经历过什么”。
- 关系：决定“我怎么看这个人”，当前由 memory-owned social evidence 表达。
- 情绪/身体状态：决定“我此刻处于什么短期运行态”。
- 目标：决定“我现在围绕什么组织行动”。
- 技能：决定“我能用什么方式行动”，当前以 bounded affordance summary 进入心智视图。

Need tension is not an eighth peer factor. It is the runtime conversion layer
that turns long-term needs, current events, relationship evidence, and goal
conflicts into short-term pressure. That pressure then influences affect,
body state, L2 interpretation, L3 ranking, and L4 presentation. It must not
directly override authored personality, supervision, skill feasibility, or
ESM/world-truth settlement.

## authored profile / runtime state / drift 分层

角色智能体当前把长期档案、运行态和长期沉淀明确拆开：

- authored profile truth：稳定角色主档案，当前已显式包含 `personality_layer`、`need_hierarchy_layer` 与 `temperament_response_layer`
- effective profile：`authored profile truth + long_term_personality_drift_layer`
- runtime state：`NeedTensionState` 与 `CharacterDynamicState`
- long-term drift：只通过候选累计与 promotion gate 进入 `long_term_personality_drift_layer`

这里的关键约束是：

- `NeedTensionState` 独立于 `CharacterDynamicState`
- `CharacterDynamicState` 现在按 affect / tension / motivation 三组组织
- `affect_state` 覆盖 14 个即时情绪字段：`fear`、`anger`、`shame`、`sadness`、`relief`、`curiosity`、`affection`、`joy`、`calm`、`trust`、`gratitude`、`pride`、`confidence`、`hope`
- stress、social pressure、masking pressure 和慢性张力不是情绪维度，仍属于 tension / need pressure 路径
- 瞬时 runtime state 不能直接改写 authored profile truth

### Personality projection boundary

人格 authored truth 已从旧的 flat `trait_vector_layer` 迁移到
`personality_layer.big_five` + `personality_layer.facets`。旧
`trait_vector_layer` 暂时保留为 legacy/migration input，用于兼容既有 YAML
和投影 fallback；它不再是新的行为消费面。

行为层面对外统一读取 `personality_projection`。该投影由
`PersonalityProjectionResolver` 从 Big Five/facets、values、temperament、
conversation style、capability context 和 legacy traits 归一化生成，包含
`conflict_deescalation_bias`、`procedural_discipline`、
`stress_vulnerability` 等去重后的运行时偏置。

Duplicate-weight guard：

- L2/L3/L4 不应同时消费 `agreeableness`、`empathy`、
  `mediation_tendency` 这类重叠 raw fields 来重复加权。
- 当 projection 已覆盖某个心理含义时，行为 scoring 使用对应 projection
  entry，而不是 Big Five/facet/legacy trait 的并列求和。
- MBTI 不作为数值运行基础；如需作者标签，只能作为非行为数值输入的描述性
  metadata。

### CharacterDossier / runtime boundary

`CharacterDossier` 是可编辑的 authored truth 外层包。`CharacterProfile`
仍是其中的长期心理/行为 baseline；legacy `CharacterProfile` YAML 继续可
加载，并由 dossier loader 包成兼容 dossier。

运行时消费规则：

- raw dossier 不直接进入 `L2`、`L3`、`L4`。
- dossier 必须先经过 visibility-filtered projection，再进入
  `CharacterMindFrame` 的 shadow cards。
- `author_only`、raw secret content、未过滤 hidden truth 不能进入
  `L2/L3/L4` layer views。
- dossier projection 是 read model，不改变现有 L2/L3/L4 行为选择。

静态/动态身体边界：

- `EmbodimentProfile` 是 static 或 semi-static authored baseline。
- `BodyRuntimeState` 是后续独立运行态，负责当前 injury、fatigue、pain、
  load、temporary impairment 等动态身体事实。
- dossier hot reload 只能 invalidate embodiment / physical feasibility /
  skill-affordance projections，不能清除或覆盖运行中的 injury、fatigue、
  pain 或其他 body runtime state。

关系图与技能边界：

- `RelationshipSeedProfile` 只产出 social-memory initialization
  candidates；它不拥有 live relationship truth。
- `RelationshipGraph` 是后续 evidence-backed read model，来源仍应归属
  social memory。
- `CapabilitySeedProfile` 只产出 character-skill-state initialization
  candidates；它不执行 skill evaluation。
- `AbilityGraph` 是后续 read model，由 `CharacterSkillService` 查询和压缩。
- `L3` 只能消费 relationship / capability summaries，不能消费 raw graph、
  full skill registry 或 full action registry。

## 分层映射

### Character L1：私有感知

输入：

- `CharacterPerceivedEvent`
- `SelfBodyPerceivedEvent`
- Siming catalyst outputs
- settlement writeback summaries
- dialogue response writebacks

状态：

- 可见/可听实体
- 注意力目标
- 本地空间置信度
- 未解决信号和活跃异常
- 身体状态提示
- 警觉/分心状态
- 最近的世界变化和约束结果
- 最近一次 Siming catalyst

禁止：

- world truth mutation
- direct ESM settlement
- 在 actors 之间共享 private context

### Timeline 与记忆

写入：

- perceived events
- self-body events
- Siming outputs
- relational belief events
- reasoning requests
- interpretation events
- execution requests
- settlement and dialogue writebacks
- suggestion packets

当前存储：

- `char_b` 五池长期记忆：SQLite Heavenly Graph，支持 actor-private scope、
  双时态、revision、幂等和重启恢复
- working memory、session timeline、goal、dynamic state、need/tension、
  supervision：仍是运行态边界，部分通过可选 local JSON timeline 恢复，尚未
  作为完整角色行为快照统一持久化
- 召回预算、context hash、selected memory refs 和截断状态会附在模型上下文的
  `memory_recall` 元数据中，便于 replay 和行为评估
- 低分 settlement 生成的 `candidate_only` policy 会被下一次 L3 作为一次性
  runtime guardrail 消费；例如约束失败后的 `recovery_policy` 会抑制重复的
  failed intent，并保留可行候选（observe / self-protect / recovery path）。
  它不修改 authored profile，也不依赖 Harness 才生效

### Character L2：解释

输入：

- effective profile
- `NeedTensionState`
- `CharacterDynamicState`
- private snapshot
- working memory state
- recent world/constraint history
- model gateway output 或 local fallback

输出：

- interpreted summary
- salience
- ambiguity
- risk/opportunity
- attention target
- belief/social/higher-order deltas
- `dynamic_state_delta`
- goal hints
- reasoning trace summary

当前 needs/affect 路径：

- `NeedTensionEngine` 先基于 `effective_profile` 与事件/记忆更新 `NeedTensionState`
- `AffectEngine` 再从 temperament 与 need tension 导出 `dynamic_state_delta`；需求满足通过 `recent_satisfaction` 转成正面 affect delta
- `L2 -> dynamic_state_delta` 进入 runtime writeback
- runtime evidence 进一步进入 long-term drift candidate chain

禁止：

- direct command emission
- direct authority write
- 把 `dynamic_state_delta` 直接视作长期人格改写

### Character L3：规划

输入：

- interpretation
- goal state
- control mode
- memory and recent constraints

输出：

- selected intent
- recommended intents
- risk notes
- role consistency hints
- `char_c` 在 player-priority assisted 时产生的 suggestion packets

禁止：

- 绕过 L4 execution contract
- 覆盖 player-priority control mode

### Character L4：执行语义

输出：

- speech channel
- face channel
- body channel
- social-spatial channel
- physiology channel
- `actor_control_frames`
- `presentation_plan`
- `action_request_bundle`
- `execution_semantics`

当前事实：

- `L4Executor` 是真实 execution-plan owner。
- `L4Adapter` 仍是薄兼容层，从 execution plan 派生 legacy commands。

禁止：

- 在 `CharacterGoalCommand` compatibility 仍存在时，宣称已经完成最终单一路径收敛
- 让 Godot 表现层选择 role intent

### Character Skill System boundary

The skill system is introduced as an independent character-side service, not as
an ESM responsibility and not as a Kimodo responsibility.

Current runtime state:

- `L4Executor` can emit a shadow `CompositeActionProposal` alongside the existing execution bundle.
- `CharacterSkillService` evaluates skill paths in advisory shadow mode from runtime proposals.
- Runtime settlement can carry skill evaluation and primitive action metadata as advisory explanation/evidence inputs.
- Realization/Kimodo contracts can consume selected skill path and settlement outcome hints for presentation variants only.
- The existing `L4` `action_request_bundle` remains the compatible runtime delivery path.
- Large production skill/action libraries, default automatic promotion, persistent learned-skill storage, and a real Kimodo live success loop remain deferred follow-up work.

Current advisory seam:

```text
L3 selected_intent
-> L4 shadow CompositeActionProposal
-> CharacterSkillService SkillEvaluationResult (advisory, not runtime-loop authority)
-> interaction settlement advisory metadata / SkillEvidence
-> presentation-only realization hints
-> existing L4 action_request_bundle compatibility is preserved
```

The service produces advisory/pre-settlement skill information. World truth still
comes from ESM and the physical channel. Realization consumes selected skill path
and settlement result for presentation variants only.

## 完成标准

一个角色智能体 feature 的文档只有记录下面内容才算完整：

1. actor/control-mode behavior
2. input event 或 bundle shape
3. L1/L2/L3/L4 ownership
4. memory/timeline writeback behavior
5. Godot delivery behavior
6. compatibility path status
7. model-provider status
8. verification command and report artifact
9. explicit forbidden claims
