## 整体运行时时序

本时序展示对象/环境交互路径。若命令修改的是账户、背包、装备、状态、产权、债务或
合同等玩法领域事实，则由对应 Gameplay authority 直接进入其 event-store 提交路径，
不经 ESM 取得通用所有权。

```mermaid
sequenceDiagram
    participant Player as 玩家
    participant Godot as Godot 本地运行时
    participant Backend as 后端 authority 入口
    participant WorldRuntime as 世界运行时
    participant L1 as System L1
    participant Character as 角色智能体
    participant ESM as ESM/交互编排
    participant L6 as System L6 AuthorityEventBus
    participant Siming as Siming
    participant Projector as FrontendAuthorityEventProjector
    participant Presentation as Godot 表现层

    Player->>Godot: 提交结构化输入或交互意图
    Godot->>Backend: player_input / raw_fact_event / provider refs
    Backend->>WorldRuntime: 路由事实、采样 refs 与感知请求
    WorldRuntime->>L1: 空间、occupancy、projection 和 PQF 组装
    L1-->>Character: CharacterPerceivedEvent / PQF bundle
    Character-->>Backend: character_agent_execution
    Backend-->>Presentation: character_agent_execution WebSocket 投递
    Backend->>ESM: 交互结算或约束检查
    ESM-->>Backend: world_result / constraint_state_result
    Backend->>L6: AuthorityEvent publish / route / audit
    L6->>Siming: 公开 authority events 与态势输入
    Siming-->>L6: siming.* 高层 catalyst event
    L6->>Projector: AuthorityEvents for frontend projection
    Projector-->>Presentation: world_result / state_machine_transition / siming_output
    Presentation-->>Player: 可见对话、动作、对象状态变化或失败反馈
```

## Gameplay 领域结算

```mermaid
sequenceDiagram
    participant Caller as Godot / Character structured command
    participant Domain as Gameplay domain authority
    participant Store as GameplayEventStore
    participant Outbox as committed outbox
    participant Mirror as filtered gameplay mirror
    participant Godot as Godot presentation
    participant L6 as System L6 eligible notification path

    Caller->>Domain: typed command + expected revisions
    Domain->>Domain: validate domain ownership, costs and preconditions
    Domain->>Store: append AtomicEventBatch
    Store-->>Domain: receipt or typed rejection
    Store->>Outbox: committed entries only
    Store->>Mirror: rebuild/filter consumer view
    Mirror-->>Godot: scoped snapshot/delta or prediction resolution
    Outbox-->>L6: post-commit eligible AuthorityEvent
```

该路径的可回放事实由 `GameplayEventStore` 拥有；L6 只承接 commit 后的公共通知、
路由和投影。当前证据覆盖有界的 Gameplay Foundation 及 `adventure-basic` 参考闭环，
不覆盖动态市场、组织、税收或通用模拟时钟。

## 总体边界

- Godot 是本地输入、表现和高频具身 host，不是 world truth authority。
- 世界运行时是后端世界侧基础设施大类，承接 L1、PQF、VLA、provider readiness、调度和 continuity。
- System L1 是世界运行时下的事实、provider、PQF 和投影边界，不是角色脑，也不是 Siming。
- System L6 是跨层基础设施层，承接 authority event bus、路由、回放和审计辅助边界；前端投影由 `FrontendAuthorityEventProjector` 承接。
- Siming 消费公开 authority events 和全局态势输入，只输出高层 catalyst；进入 Godot 必须经过 `FrontendAuthorityEventProjector`，进入角色只能作为 catalyst input。
- 角色智能体拥有私有感知、记忆、解释、规划和执行语义，不拥有世界真相。
- ESM 与交互编排负责对象、环境和物理交互的 authority 结算与结果合并，不负责角色 cognition 或 Gameplay 的通用领域写入。
- Gameplay Foundation 的领域 authority 通过 `GameplayEventStore` 提交可回放的玩法事实；它是 authority substrate，不是另一个 runtime host。
- System L6 的 `AuthorityEvent` 路由不替代 Gameplay event store、账户账本或领域 replay。
- VLA 是已实现的视觉/空间慢路径运行时通道；它的输出必须经过受控消费路径，没有 authority 直接写权限。
- 模型服务通道记录 provider readiness 和真实调用证明，不直接改变世界或角色动作。
- Harness 记录验证证据，不替代运行时行为本身。
