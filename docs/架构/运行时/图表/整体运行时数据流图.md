## L1 事实与 Provider 到 PQF 消费方

```mermaid
flowchart TD
    GodotScene[Godot 场景节点] --> RawEmitters[原始事实发射器]
    GodotScene --> Providers[采样 provider]
    GodotScene --> PlayerIntent[玩家 / 交互意图]

    RawEmitters --> RawFact[raw_fact_event]
    Providers --> ProviderRefs[visual / spatial / auditory / body / skeletal / environment refs]
    PlayerIntent --> IntentEnvelope[player_input / interact_intent]

    RawFact --> BackendMain[backend/app/main.py]
    ProviderRefs --> BackendMain
    IntentEnvelope --> BackendMain

    BackendMain --> FactRouter[事实路由与处理器]
    FactRouter --> Candidate[CandidatePerceptEvent]
    Candidate --> PrivateFilter[逐角色感知过滤器]
    PrivateFilter --> CharacterPerceived[CharacterPerceivedEvent]

    BackendMain --> L1Bridge[L1RuntimePerceptionBridge]
    L1Bridge --> PQF[PerceptionQueryFrame]
    PQF --> CanonicalBundle[CanonicalPerceptBundle]

    CharacterPerceived --> CharacterL1[角色 L1 私有快照]
    CanonicalBundle --> CharacterL1
    CanonicalBundle --> SimingPublic[Siming 公开态势输入]

    CharacterL1 -. 禁止 .-> WorldTruth[世界真相变更]
    SimingPublic -. 禁止 .-> PrivateCache[角色私有 cache]
```

边界说明：

- L1 是事实、provider、投影边界，不是独立 brain 或 authority host。
- Provider refs 是采样输入，不能直接结算 world truth。
- `CharacterPerceivedEvent` 和 PQF 派生 bundle 必须保持 actor/private scope 隔离。

验证：

- `python scripts/verification/harness.py --profile l1-world-fact-runtime`
- `python scripts/verification/harness.py --profile godot-sampling-production-grade-providers`
- `python scripts/verification/harness.py --profile actor-scene-knowledge-lifecycle`

## 交互编排与 ESM 结果合并

```mermaid
flowchart LR
    GodotIntent[Godot interact_intent] --> Main[backend/app/main.py]
    Main --> Orchestrator[InteractionOrchestrationService]

    Orchestrator --> Policy[策略 / 通道选择]
    Policy --> Semantic[语义交互请求]
    Policy --> Physical[物理交互 refs]

    Semantic --> ESM[ESMService authority 结算]
    Physical --> PhysicalChannel[PhysicalInteractionChannel]
    PhysicalChannel --> ESM

    ESM --> Success[成功 result family]
    ESM --> Constraint[constraint_state_result]
    ESM --> Degraded[降级 / 拒绝 result]

    Success --> Merge[统一编排结果合并]
    Constraint --> Merge
    Degraded --> Merge

    Merge --> AuthorityEvents[System L6 Authority 事件总线]
    AuthorityEvents --> Projection[FrontendAuthorityEventProjector]
    Projection --> GodotResult[Godot world_result / 对象状态 / UI 反馈]
    AuthorityEvents --> Siming[SimingRuntime / 全局态势]
    AuthorityEvents --> CharacterWriteback[角色 timeline 回写]
```

边界说明：

- ESM 仍是结算结果的 authority。
- 交互编排负责选择和合并路径；它不是新的 cognition layer。
- Godot 展示投影结果，但不能本地伪造成功的 authority outcome。

验证：

- `python scripts/verification/harness.py --profile interaction-orchestration-service`
- `python scripts/verification/harness.py --profile esm-physical-channel-world-actuation`
- `python scripts/verification/harness.py --profile phase0`

## 角色智能体 L1/L2/L3/L4 到 Godot Ingress

```mermaid
flowchart TD
    Inputs[CharacterPerceivedEvent / SelfBody / Siming catalyst / settlement writeback] --> Runtime[CharacterAgentRuntime]
    Runtime --> Timeline[会话 timeline]
    Runtime --> Memory[工作 / 情节 / 关系记忆]
    Runtime --> L1Private[角色 L1 私有世界快照]

    L1Private --> L2[L2 解释]
    Memory --> L2
    Timeline --> L2
    L2 --> L3[L3 规划]
    L3 --> L4[L4 执行语义]

    L4 --> ExecutionEnvelope[character_agent_execution envelope]
    ExecutionEnvelope --> WebSocket[后端 WebSocket]
    WebSocket --> BackendBridge[BackendBridge.gd]
    BackendBridge --> LocalBus[LocalPresentationBus.gd]
    LocalBus --> Replica[CharacterReplica.gd]
    Replica --> RuntimeState[CharacterRuntimeState]
    RuntimeState --> PresentationInput[CharacterPresentationInput 形态数据]
    PresentationInput --> Skin[KnightRoleSkin / 本地具身]

    L4 -. 仅兼容 .-> LegacyCommand[character_agent_output command_type]
    LegacyCommand -. 薄适配 .-> LocalBus
```

边界说明：

- Mind core 运行时路径真实存在且已验证。
- 最终单一路径 `L4 -> CharacterActor` 收敛仍是已知缺口。
- Godot actor ingress 负责实现表现，不成为语义 owner。

验证：

- `python scripts/verification/harness.py --profile character-agent-execution`
- `python scripts/verification/harness.py --profile mainline-unified-runtime`
- `python -m pytest -q backend/tests`

## System L6、Siming 与前端投影

```mermaid
flowchart LR
    PublicL1[公开 L1 事实与 world refs] --> Authority[System L6 Authority 事件总线]
    Settlement[ESM / 交互 result families] --> Authority
    Dialogue[对话与角色事件] --> Authority

    Authority --> Situation[SimingGlobalSituationLayer]
    Situation --> Fairness[公平性 / 公开态势快照]
    Fairness --> Siming[SimingRuntime]
    Siming --> Candidate[候选 / 策略 / 可行性 / 审计]
    Candidate --> SimingOutput[高层 Siming output]

    SimingOutput --> Authority
    Authority --> Projection[FrontendAuthorityEventProjector]
    Projection --> Godot[Godot 观测面 / UI / 角色反应]
    Authority --> CharacterRuntime[CharacterAgentRuntime catalyst input adapter]

    Situation -. 禁止 .-> CharacterPrivate[角色私有记忆/cache]
    SimingOutput -. 禁止 .-> LowLevelMotion[低层动作或直接覆盖世界]
```

边界说明：

- Siming 消费公开 world/evidence/参考性 refs，并输出高层 catalysts。
- Siming 不能读取 actor-private cache，也不能直接写低层动作。
- Projection 是面向 Godot 与 debug observability 的兼容表面。
- `Authority -> CharacterRuntime` 只表示高层 catalyst input 适配，不是 `character_agent_execution` 投递路径。

验证：

- `python scripts/verification/harness.py --profile siming-global-situation-layer`
- `python scripts/verification/harness.py --profile mainline-unified-runtime`
- `python scripts/verification/harness.py --profile phase0`

## VLA 运行时通道

```mermaid
flowchart TD
    PQF[PerceptionQueryFrame / provider refs] --> Scheduler[VLA 慢路径 scheduler]
    Scheduler --> Registry[VLA model registry]
    Registry --> Provider[VLA provider 适配器]
    Provider --> Result[VLAProviderResult]
    Result --> Cache[带 scope 的参考性 cache]
    Cache --> PerceptBridge[参考性 percept bridge]
    PerceptBridge --> RuntimeConsumers[Character / Siming 受控消费方]

    Result -. 仅参考 .-> WorldTruth[World truth]
    Result -. 仅参考 .-> ESM[ESM authority]
    Result -. 仅参考 .-> ActorControl[Actor control]
```

边界说明：

- VLA 慢路径已经实现；其输出必须经过受控消费路径，不能直接写世界真相、ESM authority 或 actor control。
- VLA 的真实 provider 是否可用，由 `docs/架构/运行时/模块/模型服务通道.md` 记录。

验证：

- `python scripts/verification/harness.py --profile vla-provider-backend`

## 模型服务通道

```mermaid
flowchart TD
    CharacterGateway[角色模型 gateway] --> Readiness[模型服务 readiness ledger]
    SimingProvider[Siming candidate provider] --> Readiness
    VLAProvider[VLA backend adapter] --> Readiness
    ProductionModel[非运行时生产模型入口] --> Readiness

    Readiness --> ContractProof[契约/静态 readiness 证明]
    CharacterGateway --> TextOutput[角色文本模型输出]
    SimingProvider --> CandidateOutput[Siming candidate 输出]
    VLAProvider --> VLAOutput[VLAProviderResult]

    TextOutput -. 必须验证 .-> CharacterRuntime[角色智能体运行时]
    CandidateOutput -. 必须验证 .-> SimingRuntime[SimingRuntime]
    VLAOutput -. 进入受控消费路径 .-> VLARuntime[VLA 运行时通道]

    ContractProof -. 不能替代 .-> LiveProvider[真实 provider 成功调用]
```

边界说明：

- 模型服务通道记录不同模型入口的 provider readiness、配置、降级和真实调用证明。
- 它不等于 VLA 运行时通道；VLA 运行时通道只关心视觉/空间理解结果如何进入运行时并被安全消费。
- 没有凭证和成功 adapter 调用时，只能宣称 readiness 或契约证明，不能宣称真实 provider 已验证。

验证：

- `python scripts/verification/harness.py --profile model-provider-readiness`

## 非运行时生产管线边界

```mermaid
flowchart LR
    SourceAssets[场景 / 资产 / replay 来源] --> Extraction[语义抽取]
    Extraction --> Baking[空间烘焙]
    Baking --> Classification[多模态分类就绪]
    Classification --> Review[人工 / 策略审核门禁]
    Review --> Approved[已批准 artifacts 和 replay datasets]
    Approved --> RuntimeRefs[运行时可加载 refs]

    RuntimeRefs --> L1Scene[Scene3DSpaceModel / provider refs]
    RuntimeRefs --> HarnessEvidence[Harness 证据 artifacts]

    Extraction -. 不是运行时证明 .-> Completion[运行时完成声明]
    Classification -. 没有直接 authority .-> ESM[ESM / world truth]
```

边界说明：

- Production pipeline outputs 可以准备已审核 artifacts 和 replay data。
- 它们不是运行时完成证明，直到被运行时 verifier 消费。

验证：

- `python scripts/verification/harness.py --profile non-runtime-production-pipeline`
- `python scripts/verification/harness.py --profile docs`
