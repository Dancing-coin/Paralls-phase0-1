# 角色控制基础设施说明

## 接入步骤

1. 先检查人物资源包、骨架和动作库是否已有兼容注册；新骨架或新动作库才需要补充对应资源。资格化和语义能力检查见[设计文档的装配契约](角色控制基础设施设计.md#新增人物的装配契约)。
2. 项目追加一个继承或实例化 `CharacterActor` 的角色壳，赋予独立 `actor_id`，配置出生变换，并将它加入 `character_control_actor` 组。壳内模型挂载实现 `CharacterPresentationAdapter` 契约的适配器，并加入 `character_presentation_adapter` 组。已有场景人物保持原样。
3. 场景实例化一个 `CharacterControlFoundation`，在人物完成初始化后调用 `bind(root)`，默认通过组发现该 root 下的角色；需要 `actor_paths` 顺序时必须关闭 `discover_group_members`。
4. 根据需要挂载一个输入源，例如 `CharacterPlayerInputSource`、Agent adapter 或 scripted source。输入源只产生标准控制意图和语义动作 ID。
5. 每个物理帧把输入源产生的字典交给 `apply_player_frame` 或等价的控制意图入口。
6. 玩法适配器监听动作请求，再决定是否向项目自己的 authority/interaction 通道提交请求；通用层不要求使用街斗 coordinator。
7. 相机模块通过 `CharacterCameraController.setup(camera)` 和 `follow(actor, delta)` 工作，也可以替换为项目自己的相机策略。

当前步骤用于启动前的场景追加。运行过程中 `add_child()` 一个角色不会自动更新控制名单；增量接纳和身份冲突检查仍是 planned，不应通过替换当前玩家来绕过这一步。

## 跨建模接入

模型不需要叫 `StreetCharacterSkin`，也不需要使用固定 `VisualRoot` 路径。模型包应提供一个表现适配器节点，并实现需要的语义能力：

```gdscript
extends CharacterPresentationAdapter

func play_semantic_action(action_id: String, state: String, profile: String, speed := 1.0, realization := {}) -> Dictionary:
    # 将语义动作映射到本项目自己的 AnimationTree/AnimationPlayer
    return {"playback_accepted": true}

func consume_root_motion_delta() -> Vector3:
    # 只返回表现层产生的增量，不能直接修改 CharacterActor.global_position
    return Vector3.ZERO
```

模型的骨骼名称、AnimationPlayer 路径、clip 名称和材质都留在适配器及其 manifest 内；`CharacterActor` 只使用语义动作和表现契约。

### 骑士包接入示例

骑士不通过 `KnightRoleSkin` 接入通用控制场景。场景直接挂载 `CharacterPackagePresentationAdapter`，其子节点直接实例化 `crusader_knight.glb`，并在 `_ready()` 中依次注册：

`StreetCombatActorControlDemo` 保留原有 Bandage、JK、T，并新增独立的 `KnightCharacter`，actor ID 为 `crusader_knight`。控制基础设施通过组发现四个角色；包注册不替换已有角色实例。骑士当前仅供本地控制和动作预览，HUD 不给它显示后端 HP 或 stamina，后端战斗名单仍为原三人。

1. `skeleton_profile.json`：登记 `crusader_knight.skeleton.v1` 到 `humanoid.v1` 的映射和源 digest；
2. `native_motion_library.manifest.json` + `native_motion_library.tres`：登记骑士原生骨架上的动作库 `motionlib:crusader_knight.native@1`；
3. `manifest.json`：提供包身份、动作语义和两个注册文件的引用。

这不是街斗共享动作库。共享动作要在不同骨架间播放，必须另行生成并通过 retarget qualification；骑士当前使用 `package_native`，只保证自己的骨架、自己的动作库和通用语义动作入口一致。

骑士原动作交付不可用的 manifest 原因是 `replacement_workbench_active; existing knight actions are not accepted for delivery`，不能把该状态仅归因于骨架不匹配。骨架差异限制的是街斗共享库直接播放；原生库登记也不会重新开放已撤回的攻击能力。

当前场景对应关系：

| 场景节点 | 人物身份 | 资源包 | 接入范围 |
| --- | --- | --- | --- |
| `PlayerCharacter` | `street_bandage` | `female_bandage_external` | 原有后端战斗人物 |
| `AgentCharacterJK` | `char_a` | `female_jk_external` | 原有后端战斗人物 |
| `AgentCharacterT` | `char_b` | `female_t_external` | 原有后端战斗人物 |
| `KnightCharacter` | `crusader_knight` | `crusader_knight` | 新增本地预览人物 |

骑士装配结构可复用于其他包，节点名称由项目决定：

```text
NewCharacter (CharacterActor, 独立 actor_id, character_control_actor 组)
  ...项目的表现挂载点...
    PackagePresentation (CharacterPackagePresentationAdapter,
                         character_presentation_adapter 组)
      Model (GLB 实例)
```

在 `PackagePresentation` 配置 `package_id`、`manifest_path`、`qualification_report_path` 和 `motion_library_id`。当前通用包适配器的带资格报告注册路径针对原生动作预览；共享或重定向库还需项目提供相应接线，不能假设配置一个库 ID 就完成全部接纳。

## 角色包朝向校准 current

`CharacterPackagePresentationAdapter.apply_visual_alignment(manifest)` 将包的前向对齐到 CharacterActor 的本地 `-Z`。当前四个角色包将原来场景中的 180 度偏移迁入 manifest：

```json
"presentation_alignment": {"visual_yaw_degrees": 180.0}
```

该值是相对于 Actor 的展示偏移，不是出生朝向。适配器初始化时绝对赋值，重复应用或旧场景仍有同一偏移也不会累加；新场景无需手写模型旋转。不同包可使用 0、90、-90 等角度。未提供显式校准时按 `forward_axis` 推导，仅支持 Y 向上的水平前向；旧资格化 schema 仍要求规范 `-z/+y`，其他导入轴应先按项目资源规则资格化。非法配置停止表现初始化，后续场景接纳门禁仍为 planned。

朝向来源是资产声明与人工校准，不能从 `humanoid.v1` 标签推断模型正面。几何自动识别 deferred。根运动经包适配器 `root_motion_to_actor_local()` 转为 Actor 本地，保留模型变换和比例，CharacterActor 再转世界坐标；Motor 仍是唯一身体位移写入者。

验证入口：`godot --headless --path . --script res://scripts/verification/tests/test_character_visual_alignment.gd`，覆盖四个源前向、重复应用、错误配置、缩放和角色旋转，以及四人场景加载。角色包 GLB 或导入变换变更后，需重新在画面中核对实际面向，代码测试不能识别模型正面。

## 跨项目接入示例

Registry 已有显式注册 API；以下示例只登记资源，不会创建场景人物，也不会向已有表现适配器自动注入这份 Registry：

```gdscript
var registry := CharacterEmbodimentAssetRegistry.new()
var package_accepted := registry.register_project_package(&"my_character", "res://characters/my_character/manifest.json", "res://characters/my_character/qualification.json")
var library_accepted := registry.register_project_motion_library("res://motion/my_library.manifest.json", "res://motion/my_library.tres")
# 调用方须检查两个结果，成功后再装配独立人物。
```

项目可以显式提供 manifest 路径和资源，但 Registry 当前仍在构造时加载默认街斗资产，通用包适配器也自行创建 Registry。空目录启动、注册器注入和统一装配入口尚未完成；不能将这段代码作为无需改动即可迁移任意项目的证明。

## 代码入口

- `CharacterControlFoundation.bind(root)`：绑定角色。
- `CharacterControlFoundation.set_active_actor(index)`：切换当前控制角色。
- `CharacterControlFoundation.apply_player_frame(input)`：提交玩家控制帧。
- `CharacterPlayerInputSource.sample()`：采样移动和跑步意图。
- `CharacterPlayerInputSource.handle_input(event)`：发出动作、跳跃和切换信号。
- `CharacterCameraController.follow(actor, delta)`：执行相机策略。
