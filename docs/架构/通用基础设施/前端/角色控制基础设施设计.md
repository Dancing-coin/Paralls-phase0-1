# 角色控制基础设施设计

状态：`current foundation; planned extensions`

## 目标

为玩家、Agent、脚本测试和未来其他控制来源提供同一套 Godot 侧角色控制装配方式。控制来源只产生控制意图，`CharacterActor` 负责具身执行，`CharacterMotor` 负责身体运动，表现层负责动作和视觉反馈。

## 边界

通用化原则：控制基础设施依赖稳定的 `CharacterActor`、`CharacterControlIntent`、`CharacterPresentationAdapter` 和语义动作 ID，不依赖具体场景树、模型文件名、骨骼名称、动画 clip 名称或项目玩法 coordinator。模型和项目差异进入角色包 manifest、表现适配器和 Registry 配置。

基础设施内化：

- 控制源注册和当前控制角色切换；
- 控制意图规范化和每帧提交；
- `CharacterActor`、`CharacterMotor`、动作表现之间的连接；
- 物理帧、根运动消费和动作仲裁的入口约束。

模块化合作：

- 相机控制：由 `CharacterCameraController` 或其他相机策略实现，基础设施只提供当前 actor 和观察目标；
- 受击动画：由表现层和受击表现适配器实现，authority 结果触发，不能由本地输入宣布命中；
- 根运动：动作表现产生 root contribution，`CharacterMotor` 单次消费并参与碰撞计算；
- 音效：由音频表现适配器消费动作 marker、受击 marker 和 authority-only 事件；
- 特效：由视觉特效适配器消费 marker 或确认结果，不写角色状态；
- 镜头震动、慢动作和 UI：属于场景/表现协作者，不进入角色身体控制核心。

## 后续设计

### 角色包朝向校准

本次修复范围：`CharacterPackagePresentationAdapter` 在初始化时读取包 manifest 的 `presentation_alignment.visual_yaw_degrees`，以绝对角度设置展示节点的 Y 旋转。未声明显式校准时，以包 `forward_axis` 对齐 CharacterActor 的本地 `-Z` 前向；仅支持 Y 向上的水平朝向。不根据包名猜方向，也不累加场景已有旋转。错误配置返回失败原因并停止该表现适配器初始化。

将当前四个包的既有 180 度偏移移到各自 manifest，移除三个 StreetCombat 样例场景中的手写偏移。资源导入变换保留，场景 Actor 的出生朝向保持独立。当前模型经人工校准；从几何自动识别面部朝向为 deferred。

根运动保持 CharacterMotor 为唯一身体写入者。包适配器将采样的模型/骨架本地 delta 转为 Actor 本地 delta，CharacterActor 再转为世界 delta；同一展示层旋转只参与一次。测试检查不同源前向、显式覆盖、重复应用、非法配置、Actor 旋转与模型缩放，以及四个包的场景接入。

### 新增人物的装配契约

新增人物分为资源接纳和场景实例装配两个阶段。资源注册不决定场景人数，也不修改已有 `CharacterActor`。场景中的每个人物使用独立 `actor_id`；多个实例可以复用同一个 `package_id`、骨架 profile 和动作库。

| 身份 | 含义 | 新增时的规则 |
| --- | --- | --- |
| `actor_id` | 场景人物实例身份；接入后端时必须与其角色身份明确绑定 | 每个新人物独立，冲突应拒绝，不能按 ID 覆盖旧人物 |
| `package_id` | 模型及表现配置的资源包身份 | 相同模型包可复用 |
| `native_skeleton_profile_id` | 原生骨架、语义骨骼映射和源资源版本 | 已有且兼容则复用；骨架或绑定源版本改变则重新接纳 |
| `motion_library_id` | 动作库资源身份及语义动作目录 | 已有兼容库可复用，不要求每个人物新建一套 |

资源检查顺序：

1. 检查 manifest、资格报告、模型存在性和源 digest。
2. 检查真实 `Skeleton3D` 及骨骼映射。登记骨架是登记适配信息，不能仅凭 `humanoid.v1` 标签判定动作兼容。
3. 根据实际兼容性选择动作实现：同骨架可复用资格化共享库；自带动作使用原生库；异骨架共享动作须先在构建阶段重定向并资格化目标库。
4. 检查动作库资源、目标骨架、语义动作对应的 clip 和使用范围。未交付的攻击、受击等能力保持不可用；缺动作不能伪造成功。
5. 输出接纳结果、已接纳能力和失败原因，供场景装配使用。

场景装配规则：

- 默认追加一个新的 `CharacterActor`，挂载表现适配器及 GLB，配置独立身份、出生变换和物理参数，并加入 `character_control_actor` 组。
- 新增前后原有人物身份、模型包、位置和玩法绑定保持一致；新增成功后人数增加一人。资源检查失败应清理本次候选实例，保留原场景。
- 换肤或替换人物属于另一个显式操作，必须指明目标人物和替换范围；注册包、切换当前控制人物都不得隐式替换角色。
- 前端人物可单独用于本地预览。参与战斗、认知或世界交互时，项目再通过已有后端入口绑定角色和 authority 能力，不能自动复制旧人物的 HP、身份或权限。

这一流程由 Registry、表现适配器、场景装配和控制基础设施合作完成，不引入新的 runtime、调度器或 authority。

### 当前接入能力与待补齐部分

`current`：骑士采用静态场景追加，`CharacterPackagePresentationAdapter._ready()` 在 GLB 已实例化后调用 `register_project_presentation_package()`，检查模型摘要、真实骨骼和原生动作库。随后 `CharacterControlFoundation.bind(root)` 发现人物。现有测试覆盖原三人保留和骑士作为第四人可被控制。

`planned`：统一装配入口在候选实例接纳成功后才加入控制名单，检查 `actor_id` 冲突，并在失败时释放候选实例；按同一资源版本复用注册结果。当前适配器注册失败只报错，仍继续初始化，不能将它描述为已实现的场景接纳事务。

`planned`：控制名单增量加入和移除，保留当前控制对象与已有顺序。当前 `bind(root)` 重新扫描并选择索引 0，没有监听后来加入的节点，不能作为完整的动态新增接口。

`planned`：Registry 默认资源由项目装配配置提供，允许空目录启动和显式注入。当前 `_init()` 自动注册三个街斗包及街斗共享库；通用包适配器也创建自己的 Registry。显式注册 API 已有，但尚未实现完全独立的跨项目资产配置。

`deferred`：异骨架自动重定向的批量生产、骨架家族扩展和编辑器一键导入工具。当前骨架接纳仅覆盖 `humanoid.v1`，任意非人形建模需实现表现契约或补充相应 profile 支持。

### 相机控制

规划 `CharacterCameraPolicy` 接口，区分第三人称跟随、锁定目标、对话观察和受击镜头反馈。相机可以读取角色状态和事件，但不能修改角色速度、朝向或 authority 状态。

### 受击表现

规划 `CharacterHitReactionAdapter`。它接收 authority result 或本地可观察的受击事件，选择 recoil、硬直、倒地等已资格化表现。受击动画只改变表现和局部控制锁；伤害、生命和战斗结果仍来自 authority。

### 根运动

保留 `CharacterMotor` 为唯一位移写入者。表现层只提供经过资格化的 root contribution；每个物理帧最多消费一次，并记录动作实例、物理帧和消费状态。

### 音效和特效

规划 `CharacterAudioPresenter` 与 `CharacterVfxPresenter`。两者以语义动作、marker、受击事件和场景上下文为输入，输出本地音效/特效实例；禁止反向写入世界 authority 或角色认知。

## 非目标

- 不创建第二套角色 runtime；
- 不在前端声明命中、伤害、库存或世界状态；
- 不把 raw pose、原始 clip 或远程输入直接跨边界驱动身体；
- 不把街斗 coordinator、玩法 HUD 或目标选择规则放入通用层。

## 复用级别

| 层 | 可跨项目复用 | 项目需要提供 |
| --- | --- | --- |
| 控制意图与 `CharacterControlFoundation` | 是 | 角色实例和输入源 |
| `CharacterActor` / `CharacterMotor` | 控制与运动契约可复用，宿主仍需审计项目依赖 | 物理参数、场景碰撞配置与项目服务装配 |
| `CharacterPresentationAdapter` | 契约可复用，实现可替换 | 模型、骨架、动作树、root motion 适配 |
| `CharacterPackagePresentationAdapter` | 通用包适配器 current | package manifest、骨架 profile、native/retargeted motion library |
| Motion Registry | 显式注册 API current；默认街斗资源解耦 planned | manifest、qualification report、AnimationLibrary |
| 相机、受击、音效、特效 | 模块接口可复用 | 项目表现策略和资源 |

当前 StreetCombat 样板仍保留固定 `role_asset_scene_path` 和街斗 coordinator 兼容接线；这些属于迁移兼容，不是通用层契约。骑士样例已改为直接挂载 `CharacterPackagePresentationAdapter` 和 active GLB，不再通过 `KnightRoleSkin` 接入。

通用 `CharacterActor` 不再对任何具体模型路径做视觉 fallback；高亮、骨骼挂点和材质反馈由 `CharacterPresentationAdapter` 自己实现。
