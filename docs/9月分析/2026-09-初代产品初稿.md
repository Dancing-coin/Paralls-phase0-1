# Paralls 初代产品初稿

状态：`product draft; proposed and non-authorizing`

整理日期：2026-08-24

本文是基于当前产品共识的初稿，不是正式 spec、plan 或实现完成声明。文中所有判断均按以下标签区分：

- `[当前已实现]`：仓库已有代码、测试或 Harness 证据支持。
- `[已有设计]`：正式设计或计划已经定义，但不等于初代产品闭环已经完成。
- `[本线程提议]`：当前讨论产生的新产品决定，尚未正式化。

## 1. 一句话定位

`[本线程提议]`

Paralls 初代不是单一剧本杀，也不是空白房屋装饰游戏，而是：

> 一个以小镇为公共社会底座、以个人区域为长期私域、以角色智能体为关系主体的社交世界。玩家先在小镇认识朋友，再通过共同活动、桌游和剧本事件扩展关系网络。

体验参考可以借鉴：

- 小镇的日常生活、公共地点和居民关系密度，参考星露谷式小镇体验；
- 个人区域的归属感、布置和朋友来访，参考动森式个人空间体验。

这些只是体验参考，不复制相关 IP 的名称、角色、地图、规则、卡牌、图标、美术、包装或具体内容。

## 2. 事实边界

### 2.1 当前已实现

`[当前已实现]`

仓库当前可以明确宣称：

- 完整角色心智核心：L1 感知、五池记忆、动态状态、L2 认知、L3 目标与规划、控制仲裁和 L4 契约；
- 角色主动接触、接近、撤退、对话和社会空间行为的运行时基础；
- 有限人口连续性切片，但它不是完整小镇产品；
- 有限 ESM/Gameplay authority、事件溯源、`append_batch()`、回放和幂等验证；
- 有限对象/环境交互、设施生产、Godot 镜像和 Siming catalyst 路径；
- Phase 0 对话、语音或 stub voice、交互成功/失败和可见状态变化的 smoke path。

### 2.2 已有设计

`[已有设计]`

正式设计已经明确：

- Godot 是本地高频表现和输入宿主，不是世界真相 authority；
- Character Agent、ESM、Siming、Gameplay authority 的边界必须清晰；
- 角色使用合法能力和 Skill/Action 契约，不建立第二 world authority、第二 runtime 或第二 event store；
- 角色私有感知、记忆、关系、目标和执行契约应保持分层；
- 世界变化必须由既有 authority/event spine 结算并通过事件回放验证；
- P3 已有受限人口连续性设计和验证，但完整 population simulation 仍然延后；
- 对照依据见 [第三阶段范围与运行模式边界](../8月分析/第三阶段推进/01-第三阶段范围与运行模式边界.md) 和 [群体模拟与角色分级连续性](../8月分析/司命与群体世界补充设计/03-群体模拟与角色分级连续性.md)；
- 世界消费模式正式区分为 `game`、`simulation`、`replay`：三者共享实体、规则、事件和 revision，只改变调度精度、唤醒策略、输入来源和报告视图；
- 同一角色的连续性 fidelity tier 正式区分为“远场批量”“中场预热具身壳”“近场完整 agent”，并由 `dormant -> batch_planned -> prewarm -> active -> pending_merge` 生命周期承接；
- fidelity tier 不创建第二身份、第二记忆或第二关系真相；`prewarm` 不读取私有五池记忆，`active` 必须持有 activation lock，结果必须经过 revision checked merge/requeue。

### 2.3 本线程提出但尚未正式化

`[本线程提议]`

以下是本初稿的新产品层提议，不能当作已实现事实：

- 小镇作为产品主入口和公共社会底座；
- 玩家个人区域作为小镇中的私域节点；
- 新手教程中多个主动社交居民；
- 玩家选择一名“锚点朋友”作为首个关系支点；
- 锚点朋友带自己的本地朋友圈来个人区域玩桌游；
- 剧本杀角色作为小镇关系网络的增量；
- 关系、来访、共建和桌游结果写回长期角色/小镇状态；
- 小镇如何把正式的世界消费模式、角色 fidelity tier 和生命周期状态转译为玩家可感知的产品节奏。

## 3. 产品结构

`[本线程提议]`

```text
小镇公共社会空间
  ├── 广场、商店、工作坊、公共活动地点
  ├── 居民日常活动和朋友关系
  ├── 剧本事件入口
  └── 玩家个人区域入口

玩家个人区域
  ├── 住宅和小院/工作区
  ├── 桌游桌
  ├── 有限共建位置
  └── 纪念区

剧本世界
  └── 以高密度共同经历把新角色带入小镇关系网络
```

小镇不是装饰性大厅。它承担：

- 玩家第一次认识朋友；
- 角色主动来访、邀约和拒绝；
- 朋友之间的本地关系呈现；
- 个人区域和公共社会之间的连接；
- 剧本后角色能否继续出现在玩家生活中的连续性。

个人区域不是独立宇宙，也不是单纯家具容器。它承担：

- 玩家对空间的归属感；
- 共建成果的可见留痕；
- 朋友来访和桌游；
- 关系记忆的实体化。

## 4. 首发社会入口：锚点朋友

### 4.1 新手教程的目标

`[本线程提议]`

新手教程不应先教复杂菜单，而应让玩家感受到：

1. 居民会主动接近玩家；
2. 居民之间本来就有关系；
3. 玩家可以选择和谁变熟；
4. 关系会把玩家带入更大的社交网络；
5. 朋友真的会来到玩家的个人区域。

### 4.2 最小流程

```text
抵达小镇
  -> 认识 3~5 名主动社交居民
  -> 与其中一人完成 2~3 次共同经历
  -> 形成一名锚点朋友
  -> 锚点朋友提出介绍自己的本地朋友圈
  -> 朋友圈成员分别接受、拒绝或暂缓
  -> 在玩家个人区域完成第一局原创桌游
```

玩家只需要重点培养一名朋友即可进入桌游内容。其他居民不是收集门槛，也不是必须全部完成的好感度任务。

### 4.3 关系状态

`[本线程提议]`

首发使用少量可解释的关系状态，而不是只暴露一个数值：

```text
认识
  -> 有过共同经历
  -> 愿意单独来访
  -> 愿意介绍自己的朋友
  -> 稳定朋友 / 可共同规划活动
```

“带朋友来”必须是角色主动社会行为。系统可以提供候选活动和合法能力，但不能把它做成“好感度达到 X 后强制弹出奖励”的纯解锁。

### 4.4 朋友圈规则

`[本线程提议]`

- 锚点朋友拥有 2~3 名本地朋友圈成员；
- 朋友圈成员拥有各自的性格、关系和参加条件；
- 锚点朋友可以提出邀请，但不能替朋友做决定；
- 至少一名成员应能合理拒绝或暂缓参加；
- 玩家不需要同时收集或管理整个朋友圈；
- 朋友圈成员是否继续来访，受第一次桌游和后续互动影响。

## 5. 角色存在模式与首发数量

### 5.1 完整角色智能体

`[当前已实现] + [本线程提议的产品用法]`

完整角色智能体可以作为玩家、朋友、剧本参与者或桌游席位，不应被固定成只能提供对白的 NPC。它们具备：

- 长期人格和身份；
- 五池记忆和关系记忆；
- 能力和约束；
- 当前目标和动态状态；
- 合理拒绝、协商、犯符合人设的错误；
- 主动发起或退出活动。

### 5.2 统一角色与八月正式连续性模型

`[已有设计] + [本线程产品映射]`

三层人口模型只是同一角色的运行状态，不是三种角色物种，也不是九月新增的 runtime contract。必须先区分两个正式维度：

#### A. 世界消费模式

| 正式模式 | 初代产品中的用途 | 是否改变世界真相 |
| --- | --- | --- |
| `game` | 玩家在小镇、个人区域、剧本或桌游中的近场即时体验；需要高精度局部角色和可见反馈 | 可以产生经过 authority 结算的正式结果 |
| `simulation` | 玩家离开后按小时/日级 cadence 批量推进小镇居民的计划、行为种子和 owner-bound intent | 只能通过既有 owner admission 形成正式结果 |
| `replay` | 用固定 seed、固定输入和只读数据重建过去的结果、投影和证据 | 零 production write |

这三个模式共享实体、规则、事件和 revision，只改变调度精度、唤醒策略、输入来源和报告视图。它们回答的是“世界当前如何被消费”，不是“角色是什么人口层级”。

#### B. 同一角色的连续性 fidelity tier

| 正式 tier | 产品层解释 | 运行边界 |
| --- | --- | --- |
| 远场批量 | 玩家不在关注范围时，角色仍按自己的身份、资源、关系和目标推进生活 | scoped owner projection -> 区域/组织/家庭计划、行为种子、owner-bound intent；不能创建 shadow NPC 或直接写世界 |
| 中场预热具身壳 | 角色进入小镇或玩家邻域后，先以有位置、有动作的低成本具身壳出现 | 只装载同一 `CharacterRecord` 的 canonical snapshot、当前任务和可见行为种子；禁止加载私有五池记忆或创建独立关系状态 |
| 近场完整 agent | 角色参与直接对话、桌游、共建或重大关系节点 | 获取 activation lock 后载入获准私有记忆，运行完整 L1-L4；输出经 revision checked merge/requeue 和领域 owner 结算 |

角色生命周期沿用八月设计：

```text
dormant
  -> batch_planned
  -> prewarm
  -> active
  -> pending_merge
  -> dormant
```

读集过期、锁冲突或预算收缩时，应 `requeue` 或回到较低 tier，而不是双写或生成第二身份。玩家离开小镇不是角色消失，而是消费方式从 `game` 退回 `simulation`；验收回放时使用 `replay` 验证同一输入是否得到同一派生结果。

若产品沟通需要保留 `world_continuity`、`local_presence`、`agent_agency`，只能把它们标为九月产品层的解释性 shorthand，不得当作八月正式 runtime 名称：

```text
world_continuity ~= 远场批量 + dormant/batch_planned
local_presence  ~= 中场预热具身壳 + prewarm
agent_agency    ~= 近场完整 agent + active
```

这个映射不是一一对应：世界消费模式、fidelity tier、生命周期状态和控制优先权是四个不同维度。已有的 `agent_full_auto`、`player_priority_assisted`、`away_conservative_takeover` 和 `scripted_override` 仍是控制优先权模式，与上述三层连续性 tier 正交。

所有 tier 共享同一份 `CharacterRecord`、五池记忆、关系、动态状态、目标、物品、资源和地点事实。首发 3~5 名指需要重点验证“近场完整 agent”覆盖的角色数量，不是小镇总人口上限，也不意味着其他居民是永久的背景物种。

### 5.3 首发角色规模建议

`[本线程提议]`

推荐首发有 3~5 名重点覆盖近场完整 agent 的高质量角色：

- 1 名锚点朋友；
- 2~3 名锚点朋友的本地朋友圈成员；
- 1~2 名首个剧本角色作为后续增量，视内容成本决定是否首发全部开放。

这里的 3~5 名是高质量近场角色验证规模，不限制小镇可见居民数量。若首个剧本要求 4~5 名核心角色，则产品必须重新声明近场完整 agent 总数，不能继续用“3~5 名”模糊描述。

## 6. 剧本杀的位置

`[本线程提议]`

剧本杀不再承担“玩家第一次认识所有角色”的职责。它承担的是：

- 高密度共同经历；
- 让新角色进入小镇关系网络；
- 产生可写回长期记忆的关键事件；
- 让已有小镇朋友和新角色发生关系碰撞。

首个剧本建议：

- 一个封闭地点；
- 一个核心异常事件；
- 2~3 条证据路径；
- 每个核心角色一个能力优势和一个明确约束；
- 至少一次角色拒绝、隐瞒或立场冲突；
- 2~3 个可回放的结果状态；
- 不依赖模型自由发挥来决定案件真相。

剧本结束后，角色不自动成为居民，也不自动接受邀请。角色可以：

- 返回原有关系网络；
- 作为访客进入小镇；
- 接受、拒绝或附条件加入玩家活动；
- 因剧本经历改变对玩家或镇上朋友的态度。

## 7. 个人区域与第一局桌游

### 7.1 个人区域最小形态

`[本线程提议]`

首发只需要：

- 住宅；
- 一个小院或工作区；
- 一张桌游桌；
- 一个有限共建位置；
- 一个纪念区。

不首发：无缝开放世界、无限地块、体素、SDF、Construct 图或完整动森规模的自由建造。

### 7.2 第一局桌游的产品作用

`[本线程提议]`

第一局桌游不是独立内容菜单，而是锚点朋友把玩家带进本地朋友圈的结果：

```text
小镇认识朋友
  -> 朋友介绍朋友
  -> 朋友来个人区域
  -> 人类和智能体共同玩桌游
  -> 形成第一次群体共同记忆
```

首发桌游建议采用原创 P-A-E 合作防守方向：

- 玩家、2~3 名智能体，支持加入 1 名人类朋友；
- 15~20 分钟一局；
- 3 个短回合；
- E 施加公开威胁；
- 每位玩家拥有独立合法信息视图；
- 角色只能使用自身 Skill Pack 允许的行动；
- 由玩法 authority 结算成功、部分成功或失败；
- 结算结果可以生成关系/共同经历写回候选。

具体名称、规则、卡牌文本、棋盘、美术和世界观仍需独立原创设计。

## 8. 状态分层

### 8.1 Canonical Character / Town State

`[已有架构原则] + [本线程待正式化]`

包括：

- 角色长期人格、记忆和关系；
- 角色在小镇中的身份；
- 玩家与角色的关系状态；
- 朋友圈关系边；
- 来访、居住和活动承诺；
- 共建贡献；
- 桌游或剧本产生的长期共同经历。

### 8.2 Personal Area State

`[本线程提议]`

包括：

- 住宅、工作区和桌游桌；
- 共建项目进度；
- 物件和纪念物状态；
- 访问权限和当前来访安排。

### 8.3 Session State

`[已有架构原则]`

包括：

- 剧本当前身份、证据和临时目标；
- 桌游手牌、牌库和隐藏信息；
- 当前回合资源、压力、分数和临时状态。

Session State 结束后，只有 authority 确认的结果才能生成 Canonical State 写回。Godot 显示成功不能直接等同于长期状态已经改变。

## 9. 第一小时、第一周、第一月

### 第一小时

`[本线程提议]`

```text
0~10 分钟：抵达小镇，至少一名居民主动接近
10~25 分钟：认识 3~5 名居民，完成 1~2 次共同小行动
25~40 分钟：玩家选择一名锚点朋友，发生一次有分歧的互动
40~55 分钟：锚点朋友提出介绍本地朋友圈
55~75 分钟：朋友带人来到个人区域，完成第一局桌游
结束：桌游结果形成一条可见共同经历或关系变化
```

第一小时验收至少包括：

- 3 名居民主动向玩家发起过互动；
- 玩家可以选择一名锚点朋友；
- 锚点朋友拥有可见的本地朋友圈；
- 至少一名朋友圈成员可以拒绝或暂缓；
- 至少 2 名智能体和玩家完成一局桌游；
- 智能体没有读取非法私有信息；
- 桌游结果写入关系或共同经历；
- 玩家回到个人区域后观察到一次可见变化。

### 第一周

`[本线程提议]`

- 至少 2 次回到小镇并遇见已有朋友；
- 锚点朋友至少主动发起一次活动；
- 朋友圈至少有一名成员形成独立关系，而不是永远作为群体附属；
- 完成一次个人区域共建；
- 完成一次桌游重开或变体；
- 认识首个剧本角色并邀请其来访；
- 观察到一次关系修复、拒绝或条件协商。

### 第一月

`[本线程提议]`

- 小镇朋友和剧本角色之间形成至少一条新关系；
- 至少一名角色成为常客，另一名角色保持访客或疏远状态；
- 一个共建项目从计划走到完成；
- 桌游、共建或剧本结果影响下一次活动对白、来访意愿或活动选择；
- 角色主动发起活动，而不是所有内容都由玩家点选；
- 玩家能回忆并在系统中看到一段真实的共同经历。

## 10. 首发必须有 / 明确延后

### 必须首发

`[本线程提议]`

- 一个可重复进入的小镇入口；
- 一个“四倍以上面积、中心商业短环 + 娱乐社交环 + 滨水景区环 + 全镇长环”的旅游小镇地图，包含独立旧车站、独立档案馆、杂货铺/游客服务站、咖啡馆/茶馆/台球厅复合楼、酒吧、社区休闲中心、桌游馆、户外运动带、大型公寓、河湾/溪谷/山地外围和可识别居民住宅；
- 杂货铺的日用货架、纪念品、有限交换、体验预约和公开活动单；
- 居民房屋的公共门槛、半私域门廊、受邀请室内访问边界；
- 54 名有名字的可识别居民：6 名核心居民与 48 名家人/朋友/工作伙伴；详细 roster 见 [首发居民、住所与工作地点设计](2026-09-首发居民住所与工作地点设计.md)。
- 六名核心居民各自绑定一个住所、一个工作地点和一条可解释日常路线；

## 14. 小镇初步设计

`[本线程提议，待正式 spec/plan]`

### 14.1 小镇的定位

小镇是一个以旅游、短住、公共活动和地方记忆为核心的可步行、可重复返回的关系场景，不是完整开放世界，也不是把居民放在地图上的装饰层。它不承担农业、采矿或城市级生产职责，需要让玩家在十分钟内遇见人，在一周内形成稳定的活动路线，在一个月内看到关系网络发生变化。

小镇首发采用“中心能生活、外围值得走”的扩容结构：中心空间足够紧，让玩家记住地点和居民；外围空间提供路线、风景、住所和公共项目；关系密度仍由居民网络和事件回流决定，而不是由空地面积决定。

### 14.2 首发空间布局

详细地图、居住组团和空间循环见 [小镇地图与空间循环设计](2026-09-小镇地图与空间循环设计.md)；54 名居民、住所和工作地点见 [首发居民、住所与工作地点设计](2026-09-首发居民住所与工作地点设计.md)；完整镇级关系图见 [54 人镇级关系图设计](2026-09-54人镇级关系图设计.md)。

建议采用“中心商业核心 + 娱乐社交带 + 四个外围分区 + 四条环线”的扩容布局，所有首发节点均可步行到达，但不要求一次走完全图。中央广场保持开放通行，不放主要运动场地；运动带放在南部社区休闲中心外缘，咖啡馆、茶馆和台球厅采用上下楼复合，酒吧接入侧翼与后院：

```text
                         北：旧车站老街 —— 档案馆 —— 观景坡
                                |             \
             河湾景区 —— 中央广场 —— 中央商业区 —— 东部居民街
                |         /    |    \             |
        短桥入口       公告栏  杂货铺  娱乐复合楼 —— 大型公寓
                           |       |       |
                       工作坊庭院 —— 社区休闲中心
                           |              |
             河岸步道 / 个人区域核心 —— 活动草坪 —— 户外运动带
                              |              |
                   个人外缘 —— 南侧溪谷 —— 东南山地环线
```

首发包含 32 个主要节点和 80～100 个可辨识子地点：

| 区域 | 主要用途 | 产品作用 |
| --- | --- | --- |
| 中央广场 | 集合、公告、偶遇、短活动 | 让居民和玩家自然相遇 |
| 居民街/大型公寓/住宅门廊 | 住宅访问、长租短住、日常路线、短请求 | 展示“谁住在哪里”和关系边界 |
| 工作坊庭院 | 修理、手作体验、共建工序 | 连接能力、互助和公共项目 |
| 杂货铺/游客服务站 | 日用品、纪念品、有限交换、体验预约和公共活动单 | 连接居民生活、游客需求、活动和店主关系 |
| 咖啡馆/茶馆/台球厅综合楼 | 咖啡、茶饮、熟人聊天、台球约局、露天座位 | 形成白天到夜间的垂直社交入口 |
| 酒吧与夜间庭院 | 夜间聚会、居民演出、桌游复盘 | 传播晚间公共信息和朋友圈关系 |
| 社区休闲中心/桌游馆 | 社区活动、原创桌游、室内休闲和雨天替代 | 连接居民、玩家、运动带和公共项目 |
| 户外运动带 | 球场、综合草地、慢跑、拉伸、看台 | 提供低压力重复活动，不占中央广场 |
| 公告栏 | 居民请求、公共项目、活动安排 | 把系统事件转成可理解的社会入口 |
| 河岸公园 | 散步、观景、少量采集、私聊 | 支持低压力关系推进和地点共建 |
| 旧车站 | 剧本出入、城市接驳、短住抵达 | 把剧本和城市服务接入小镇 |
| 档案馆 | 公开地方记忆、事实核验、公开访客档案 | 把允许公开的共同经历接回小镇 |
| 河岸步道/观景小路 | 采风、带路、节庆布置和受控外部输入 | 提供旅游动线输入，不扩成开放世界 |
| 个人区域外缘 | 从核心产权地直接进入树林、山坡和溪谷 | 把个人区域从住宅扩展为长期探索与共建空间 |

地图尺度、四倍面积分区、四条环线、复合娱乐楼、社区休闲中心和外围节点见 [小镇地图与空间循环设计](2026-09-小镇地图与空间循环设计.md)。第一小时只要求玩家熟悉中心商业短环；第一周逐步记住娱乐社交环、滨水景区环、北部观景台、河湾码头、南侧溪谷和东南山地环线。

每个地点都必须同时提供一项可重复动作、一条关系入口和一个回流结果。杂货铺只做有限日用品、纪念品、交换和体验预约，不做自由市场；居民住宅和大型公寓采用公共门厅、半私域门廊、受邀请室内三层访问边界。首发不需要农田、矿洞、港口、重生产、城市商业街或多层地下空间；它们不属于初代旅游小镇职责。

### 14.3 公共空间与个人区域的关系

小镇和个人区域采用“公共关系、私域沉淀”的分工：

#### 杂货铺/游客服务站

首发只做一家小型杂货铺/游客服务站，作为日用采买、纪念品、体验预约和店主关系入口：

- 日用货架：少量食物、清洁用品、简单药品、灯具、文具、工具耗材和桌游消耗品，固定基础库存；
- 纪念品货架：少量本地手作、地图册和活动小物，固定基础库存；
- 手作交换：用活动成果、公共项目凭证或玩家制作物换取有限小物；
- 体验预约：提前预约工作坊、河岸导览或节庆准备时段，满席时店主可以协商替代或拒绝；
- 公开活动单：只显示公开活动、接待和公共项目需求，不泄露角色私有信息。

商店上午营业、下午处理日用补货、交换和体验预约、傍晚关闭。展示物、席位和交易结果由既有 authority 结算，不做无限刷货、自由市场或独立经济 authority。店主闭店后可以在茶馆、广场、公寓公共厅或楼上住宅出现，商店因此同时承担日用服务节点、游客服务节点和居民社交节点。

#### 娱乐复合楼与社区休闲带

中央商业区新增一栋垂直复合娱乐楼：一层为面向主街的咖啡馆和露天座，二层为较安静的茶馆与阳台，三层为台球厅；酒吧位于侧翼或后院，有独立入口、夜间营业时段、小型演出台和露天座位。咖啡馆负责游客和初次相识，茶馆负责熟人聊天和关系协商，台球厅负责低压力轻竞技，酒吧负责夜间聚会、居民演出、镇闻和桌游复盘。

桌游馆不挤进复合楼，而放在南部社区休闲中心内或侧翼，提供公共组局、规则教学和首款原创桌游。社区休闲中心还包含活动室、社区厨房、室内运动室、居民议事室、储物和面向户外的长廊。

户外运动带位于社区休闲中心南侧、活动草坪与南侧溪谷之间，不占中央广场。它包含多功能硬地球场、综合草地、环形慢跑步道、河岸拉伸区、半开放雨棚、小型看台、器材亭和夜间照明。中央广场保持集合、公告、偶遇和节庆通行功能；比赛、露天电影、社区活动和大型聚会主要在南部休闲带完成。

#### 居民房屋

居民住宅是角色的日常锚点，不是玩家可以随时进入的装饰室内。首发采用三层访问边界：

- 公共门槛：门廊问候、交付公开请求、确认是否在家；
- 半私域门廊：被邀请或关系稳定后短暂停留，进行低压力对话；
- 受邀请室内：预约后才能进入，用于深度对话、共同制作或纪念活动。

锚点朋友住宅强调共享物架和共同项目，朋友圈成员住宅强调兴趣物件和私人边界，店主住宅与杂货铺相连，剧本角色住宅单元记录访问期限和居住承诺。房屋状态至少包括 `home_presence`、`visit_permission`、`hosting_plan` 和 `private_boundary`；拒绝、闭门和改约都是合法关系结果。房屋访问需要消耗行动窗口、兑现承诺或承担关系风险，不能通过重复拜访刷好感度。

#### 首发居民与工作地点

首发用六名可识别居民把住所、工作地点和社会循环绑定起来：

| 居民 | 住所 | 工作地点 | 玩家可介入的工作 | 关系用途 |
| --- | --- | --- | --- | --- |
| 林澈 | 工作坊旁小院 | 工作坊庭院 | 交付材料、推进公共设施修理 | 默认锚点朋友，介绍本地朋友圈 |
| 许宁 | 档案馆后侧档案室 | 档案馆 | 查阅公开记录、整理地方事件 | 谨慎的朋友，决定哪些剧本回流可以进入公共记忆 |
| 周野 | 复合娱乐楼茶馆楼上 | 茶馆、台球厅、酒吧后院、桌游馆 | 预约桌游、组织聚会、澄清镇闻 | 组织朋友圈，但不能替别人承诺 |
| 顾岚 | 杂货铺楼上或大型公寓长租单元 | 杂货铺/游客服务站 | 处理日用采买、体验预约、纪念品和公共项目协作 | 连接居民生活、游客服务与项目，对欠约和改约保持敏感 |
| 唐禾 | 河岸边小屋 | 河岸公园/观景小路 | 维护观景路线和河岸设施 | 提供低压力关系入口，关系紧张时会避开人群 |
| 罗闻 | 居民街公共住宅 | 中央广场/公告栏 | 整理公开请求和活动安排 | 连接居民需求，但不替居民做决定 |

林澈、许宁、周野、顾岚是首发近场完整 agent 验证池；唐禾和罗闻先以较低 fidelity 运行，遇到长期承诺、重大公共事件或关系节点时可以升级。每名居民的工作地点只承担一个主要公共作用，正式进度、库存、任务和路线变化仍由 authority 写回。

- 小镇决定谁会遇见玩家、谁在和谁交往、哪些活动正在发生；
- 个人区域决定玩家愿意邀请谁、共同留下什么、下一次聚会在哪里发生；
- 角色可以在小镇主动接触玩家，再提出进入个人区域的访问请求；
- 玩家不能通过布置个人区域直接强制改变角色关系；
- 个人区域中的桌游、共建和纪念物结果，必须回到小镇关系网络中产生后续影响。

因此，个人区域不是小镇的替代品，而是小镇社会关系的一个连续私域节点；核心产权地和外缘扩展带共享同一份个人区域状态。

### 14.4 居民活动节奏

首发不做全天候精确模拟，采用可解释的三个活动时段：

| 时段 | 居民行为 | 玩家可感知内容 |
| --- | --- | --- |
| 上午 | 工作、采购、处理个人目标 | 在居民街或工作坊遇见居民 |
| 下午 | 广场活动、拜访、共同任务 | 适合推进关系和接受邀约 |
| 傍晚 | 茶馆、台球厅、酒吧后院、桌游馆、运动带和河岸露台 | 适合朋友组局、约局、运动和关系确认 |

角色不在线或不在场时，系统只推进受治理的连续性结果，不生成第二套 NPC 状态。这里沿用已有的人口连续性和节奏设计：世界运行时负责激活和调度，角色心智负责角色自身，既有 authority 负责正式状态写回。

### 14.5 可玩可循环的地图社会

小镇每天给玩家 2～3 个有意义的行动窗口，核心循环为：

```text
公告/镇闻
  -> 选择一个地点和一项承诺
  -> 遇见居民或响应请求
  -> 帮助、旁观、邀请、拒绝或暂缓
  -> 傍晚聚会、桌游、私聊或回家
  -> 结算关系、公共项目和共同经历
  -> 下一次返回出现人、事或地点变化
```

一周内并行存在三条线：居民请求、一个公共项目工序、一次社交活动。玩家不需要全部完成；未完成内容进入下一轮生活简报，不静默重置。每次返回至少由“居民主动邀约/关系分歧”“公告或项目进度”“地点功能或路线变化”中的两项构成理由。

首发可重复活动只有三类：

- 帮忙与共建：公告栏、工作坊、河岸；推进公共项目和共同劳动记忆；
- 小型社交：广场、居民街、河岸、咖啡馆、茶馆、酒吧后院；改变信任、承诺、邀请或暂缓；
- 室内/户外活动：台球厅、桌游馆、社区活动室、球场、综合草地和慢跑道；产生约局记录、能力表现和共同经历；
- 私域同桌活动：个人区域和个人区域外缘；产生桌游结果、共建记忆和下一次私域邀请意愿。

这套循环参考星露谷的“地点 + 路线 + 时段 + 周期事件”结构，但不引入完整农业、货币、天气或四季生产链。

### 14.6 居民与正式连续性模型

建议首发小镇显示 6~8 名有名字的居民，但不把他们永久分成“完整角色”和“背景居民”两种物种。所有居民共享同一种 `CharacterRecord`，只是按世界消费模式和关注度使用不同 fidelity tier：

- `game`：玩家当前在小镇、个人区域、剧本或桌游中，优先驱动中场预热具身壳和近场完整 agent；
- `simulation`：玩家离开后，以远场批量推进受治理的个体计划和行为种子；
- `replay`：用固定输入重建历史和投影，零生产写入。

角色 tier 按八月状态机从远场批量进入中场预热具身壳，再在获取 activation lock 后进入近场完整 agent；交互结束后经 `pending_merge` 完成写回或重排队。九月文档中的 `world_continuity` / `local_presence` / `agent_agency` 仅是解释性 shorthand，不是正式 runtime contract。`agent_full_auto`、`player_priority_assisted`、`away_conservative_takeover` 和 `scripted_override` 仍属于正交的控制优先权模式。

3~5 名是首发需要重点验证近场完整 agent 的角色规模，不是其他居民永远没有完整心智。其他居民可在低关注时保持远场批量，在关系建立、地点接近或重大事件触发时进入更高 fidelity tier；不得创建独立 shadow state。

### 14.7 小镇朋友网络

锚点朋友不是“第一位可收集角色”，而是玩家进入小镇社会的关系入口。每个锚点朋友至少有：

- 两名本地朋友圈成员；
- 一条与其中一人的亲近关系；
- 一条尚未解决的分歧或边界；
- 一个可以和玩家共同完成的活动；
- 一个会影响桌游邀请的个人条件。

朋友网络应通过事件表现，而不是只显示关系图 UI。例如：

- 锚点朋友在广场主动叫住玩家；
- 他在工作坊提到某位朋友最近不愿意参加活动；
- 玩家帮助完成共同任务后，他提出带朋友来个人区域；
- 其中一名朋友因为与玩家第一次接触不佳而暂缓参加；
- 桌游结束后，朋友圈成员之间的下一次见面方式发生变化。

### 14.8 新手教程路线

推荐教程就是一条穿过小镇的短路线：

```text
旧车站抵达
  -> 中央广场遇见第一位居民
  -> 居民街认识另外两人
  -> 工作坊完成一次小型协作
  -> 玩家选择锚点朋友
  -> 广场或河岸发生一次分歧/拒绝
  -> 锚点朋友邀请自己的朋友圈
  -> 进入个人区域完成第一局桌游
```

教程结束时，玩家应记住“地点 + 人 + 关系”三件事，而不是只记住一组功能按钮。

### 14.9 小镇的首发纵切边界

小镇第一版只需要证明：

1. 玩家能从公共入口进入并走熟十个中心地点，并能在一条 15～25 分钟环线中理解北部双节点、东部住宿区、河湾、溪谷和外围扩展的关系；
2. 至少三名居民能主动发起有原因的社交接触；
3. 锚点朋友能把玩家带入本地朋友圈；
4. 个人区域能接待访客并承载第一局桌游；
5. 桌游或共建结果能在下一次小镇访问时被角色引用；
6. 剧本角色能从旧车站或事件入口进入小镇关系网络；
7. 小镇状态、个人区域状态和桌游局内状态可分别回放；
8. 玩家连续返回三次时，至少有两类变化可观察：居民路线/邀约、公告/公共项目、地点功能/布景；
9. 一周循环中居民请求、公共项目和社交活动至少有一条未完成线能进入下一轮生活简报，而不是静默重置。

首发不要求：

- 每个居民都能全天候自由行动；
- 小镇拥有完整经济、农业、职业和人口出生系统；
- 玩家可以改造全部地形；
- 居民从远场批量到中场预热、近场完整 agent 的切换没有可解释的触发、锁、写回和回放证据。

## 15. 当前结论

初代产品的核心不是“做一个小镇、一个房子和一款桌游”，而是验证一条连续关系链：

```text
小镇主动社交
  -> 选择锚点朋友
  -> 朋友介绍本地朋友圈
  -> 朋友圈来到个人区域
  -> 人类/智能体共同桌游
  -> 共同记忆和关系变化
  -> 剧本角色作为新关系增量进入小镇
```

只有当这条链条在 authority、事件回放、合法信息视图和角色长期记忆边界内成立，初代产品方向才算得到可验证的证明。当前仓库已经提供其中部分角色、社会接触、人口连续性和运行时基础，但小镇产品闭环仍属于待正式化的产品目标。
