# Paralls 初代 54 人镇级关系图设计

状态：`product draft; proposed and non-authorizing`

整理日期：2026-08-25

本文把首发 54 名居民单独做成关系图可视化规范。它属于 `[本线程提议，尚未正式化或实现]`，不代表当前仓库已经实现 54 名居民、完整关系 authority 或关系图运行时。

## 1. 图要证明什么

这张图不是角色名单海报，而是首发小镇的社会结构证明。它必须同时让人看见：

1. 6 名核心居民之间有一张可观察的关系骨架；
2. 48 名网络居民有自己的关系、住所和活动锚点；
3. 六个 roster 圈只是内容编排单位，不是六条平行社交线；
4. 至少 24 条跨圈桥接边把不同生活圈连接起来；
5. 玩家可以从锚点朋友进入其朋友圈，再沿桥接边认识其他圈层；
6. 任何居民都不应只是某个核心居民的无关系附属 NPC。

## 2. 可视化规则

### 2.1 节点

| 节点类型 | 数量 | 视觉建议 | 说明 |
| --- | ---: | --- | --- |
| 核心居民 | 6 | 大圆节点、深色描边 | 有完整档案、稳定住所/工作锚点和首发近场验证责任 |
| 网络居民 | 48 | 中等圆节点、按关系圈使用浅色底 | 有名字、居住安排、社会锚点和至少一条核心关系 |
| 玩家 | 1 个外部入口节点，可选 | 金色六边形 | 不计入 54 人；只在产品体验图中显示，不进入居民关系总数 |

### 2.2 边

| 边类型 | 线型 | 语义 |
| --- | --- | --- |
| 家庭/亲属 | 实线 | 兄妹、父女、姨母、表亲等长期关系 |
| 工作/协作 | 虚线 | 工作伙伴、学徒、公共项目协作 |
| 旧友/活动 | 点划线 | 老朋友、桌游、聚会和散步伙伴 |
| 张力/竞争 | 红色双向线 | rivalry、公开边界争论、资源优先级冲突 |
| 跨圈桥接 | 粗线 | 连接不同核心生活圈的关系种子；不是固定剧情锁 |

一条边可以同时拥有多种标签。例如“顾槐—唐青”既是工作协作，也有公共项目优先级冲突。正式数据应将其保存为一个关系边集合，而不是复制成多个角色。

### 2.3 分组

图中使用 6 个 subgraph 只是为了排版和内容生产预算：

```text
林澈圈、许宁圈、周野圈、顾岚圈、唐禾圈、罗闻圈
```

分组不能作为关系边界。跨圈桥接边必须穿过分组，且图中不能出现六个彼此隔离的岛。

## 4. 核心居民之间的 15 条骨架

| 关系边 | 类型 | 可观察表现 |
| --- | --- | --- |
| 林澈—许宁 | 工作互信/公开边界分歧 | 修理档案馆时争论哪些记录可公开 |
| 林澈—周野 | 老朋友/活动互助 | 工作坊完成后安排茶馆聚会 |
| 林澈—顾岚 | 日用与项目欠情 | 日用品、体验预约和公共项目优先级发生冲突 |
| 林澈—唐禾 | 公共设施合作 | 河岸维护与工作坊共建顺序协商 |
| 林澈—罗闻 | 公共项目合作 | 共同决定公告栏下一项工序 |
| 许宁—周野 | 证据与传闻张力 | 周野想公开镇闻，许宁要求核实 |
| 许宁—顾岚 | 记录与日用边界 | 公开服务记录和居民隐私产生协商 |
| 许宁—唐禾 | 安静空间互相尊重 | 河岸口述记录需要唐禾同意 |
| 许宁—罗闻 | 公共记录协作 | 罗闻需要许宁确认公告事实范围 |
| 周野—顾岚 | 活动服务伙伴 | 茶馆活动、日用品和预约席位互相影响 |
| 周野—唐禾 | 社交节奏差异 | 唐禾可能暂缓周野的聚会邀请 |
| 周野—罗闻 | 活动排期合作 | 广场活动与桌游时间冲突时协商 |
| 顾岚—唐禾 | 维护与日用交换 | 河岸维护需求与店铺日用安排互相影响 |
| 顾岚—罗闻 | 公开活动单合作 | 罗闻整理需求但不替居民下单 |
| 唐禾—罗闻 | 维护优先级张力 | 罗闻想公开推进，唐禾重视安静维护 |

## 5. 图的产品使用方式

### 玩家入口

玩家不需要从 54 人名单中自由挑选。第一小时只突出一名锚点朋友，例如林澈：

```text
玩家 -> 林澈 -> 周野/许宁 -> 茶馆与档案馆关系桥
             -> 顾岚/唐禾 -> 日用、共建、河岸路线
             -> 罗闻 -> 公告栏和公共项目
```

锚点朋友可以介绍人，但每名被介绍者都要独立接受、拒绝、改期或提出条件。图上的边是关系可能性，不是强制任务顺序。

### 三种阅读视图

1. **全镇拓扑视图**：展示 54 个节点、核心骨架和跨圈桥接，产品评审用。
2. **关系圈聚焦视图**：选中一名核心居民，显示其 8 名网络居民、相邻核心和最近桥接边，玩家 UI 或生活简报用。
3. **事件影响视图**：选中一次桌游、共建或访客事件，只高亮受到影响的居民和地点，不把全图变成一团线。

## 6. 图的运行时边界

这张图是产品层关系 fixture 和可视化输入，不是第二套关系真相：

- `[当前已实现]`：仓库已有角色心智、关系、记忆和有限社会接触基础；
- `[已有设计]`：关系字段、人口连续性、`game` / `simulation` / `replay` 和 authority 边界；
- `[本线程提议]`：54 人名单、15 条核心骨架、24 条跨圈桥接边、可视化图和小镇关系入口。

正式关系变化仍应经过角色/Gameplay authority 和现有 event spine、`append_batch()`；图本身不能写入关系、记忆或地点状态。玩家在图上看到一条边，只代表存在可解释的关系种子，不代表双方当前同意参加活动，也不代表玩家可以读取双方私有记忆。

## 8. 不应从图中推断的内容

- 54 名居民已经在当前产品中完整实现；
- 54 名居民每天同时以近场完整 agent 运行；
- 所有边都是正向友好关系；
- 玩家可以查看所有关系的私有原因；
- 图上的边等同于好感度数值或固定剧情锁；
- 六个分组可以独立发布成六条平行剧情；
- 档案馆、旧车站或个人区域已经拥有对应 authority。
