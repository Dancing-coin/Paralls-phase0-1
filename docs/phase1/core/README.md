# docs/phase1/core 目录结构

## 定位

- `core = Phase 1 必做`，属于 Phase 1 验收硬门槛。
- 仅放置当前阶段必须落地的能力，不承载 Phase 2+ 预研主题。

## 目录分层

- `00-总纲`
  - 产品白皮书
  - 技术架构总纲
  - Godot源码底层基础设施与运行时约束
- `01-运行时核心`
  - 司命设计文档
  - 角色智能体设计文档
  - 角色智能体/00-角色智能体总索引
  - 事件总线/00-事件总线总索引
  - 事件总线与感知链路设计
  - 视觉事实系统/00-视觉事实系统总索引
  - 信息共享与知识状态设计
  - ESM设计文档
- `03-玩法与内容`
  - 核心玩法机制设计
  - 目标与任务系统设计
  - 剧本创作模板
  - AI陪伴与小世界设计
- `04-商业与阶段`
  - 商业与生态设计
  - Phase 1 项目计划书

## 与 expansion 边界

- 创造系统文档群位于 `docs/phase1/expansion/02-创造系统/`，不属于 Phase 1 必做 core。
- 证据/世界状态/算力扩展专题位于 `docs/phase1/expansion/`。

## 维护规则

- 新增文档先判断是否为 Phase 1 验收必做；是则放 `core`，否则放 `expansion`。
- 总纲层只保留边界与约束，不承载字段级细节。
- 字段级协议优先落在专题文档，并在总纲中保留引用。
- 若某一运行时模块持续增长为“总纲 + 协议 + 实现前附录”混合体，应优先拆成文档簇，并保留原入口页路径。
- `Phase 0` 验证轨已独立到 `docs/phase0/`，不再挂在 `core` 目录语义下。
