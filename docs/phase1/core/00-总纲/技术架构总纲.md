## 2. 当前冻结结论

- `L1` 是“同源输入 + 确定性执行层”，不是纯渲染前端。
- `L2` 是“智能体与叙事决策层”，不是中央动作控制器。
- `L3` 是“表现增强层”，核心含点云过渡与视觉障眼法。
- 消息语义严格分层：世界原始事件、候选感知事件、角色感知事件、司命高层消息、环境状态事件、L3状态事件。
- 感知链路固定为：`原始世界事件 -> 可感知信息编译层 -> Per-Character 感知过滤器 -> 角色感知事件`。
- 司命不能越权替代角色决策与 `ESM` 物理结算。
- `ESM` 负责毫秒级确定性状态执行，不做证据解释和动机推理。
- 世界引擎交付形态是 `Godot` 运行时 + 规则封装，不重写引擎底座。
- Godot 客户端应被视为“本地高频具身执行器 + 玩家输入终端”，而不是角色认知与世界真值的宿主。
- 采用“先闭环后扩展”：`Phase 1` 只做首个可玩闭环必需底座。

## 3. 总体架构设计

### 3.1 设计目标

- 稳定跑通 `Phase 1` 单局动态剧本杀闭环。
- 保证 AI 与人类玩家在同一世界事实下互动。
- 保证实时性、可解释性、公平性与信息不对称共存。
- 为 `Phase 2+` 的跨局叙事、持续世界、创造生态预留接口。

### 3.2 顶层原则

- 三层职责分离：`L1` 执行、`L2` 决策、`L3` 表现。
- 决策与执行分离：司命/角色做策略，`ESM` 做物理执行。
- 事实与叙事分离：`T2` 后事实不可改写，叙事仍可涌现。
- 语义分层优先：先定义消息对象，再定义传输与编码。
- 云地一致性：部署路径可变，语义边界不变。

### 3.3 三层架构

#### 3.3.1 L1 确定性空间层

职责：

- 接收玩家输入与 AI 动作回写。
- 执行交互、物理、空间音频、基础状态变化。
- 上抛精确世界事件（位置、接触点、作用范围、结果）。

非职责：

- 不做叙事判断。
- 不做角色动机推理。

#### 3.3.2 L2 智能体交互层

职责：

- 角色智能体心智决策。
- 司命叙事催化与公平守护。
- 可感知信息编译、角色感知过滤、知识共享执行。

非职责：

- 不直接执行 L1 物理规则。
- 不替代 L3 表现渲染。

#### 3.3.3 L3 表现增强层

职责：

- 点云过渡、视觉障眼法、镜头与记忆表现编排。
- 在预算与设备约束下完成降级执行。
- 回写表现状态，不改写事实状态。

非职责：

- 不改写业务判定。
- 不替代 L1/L2 主循环。

### 3.4 总体运行链路
### 3.5 Phase 1 层级优先级（冻结）

在总体六层架构视图下，Phase 1 技术总纲采用以下优先级：

- 一级优先：L1/L2/L3/L6（首个可玩闭环硬依赖）
- 二级优先：L4/L5 的最小可验证切片（不做完整生态）

执行规则：

- L6（事件总线、房间与状态、持久化/存档）按基础设施硬门槛建设。
- L4/L5 在 Phase 1 只保留接口预留与最小能力，不承诺完整市场、治理或创作者平台。

```text
玩家输入 / AI动作
  -> L1 执行与事件上抛
  -> 事件总线分发
  -> L2 决策 / ESM 结算
  -> 状态回写总线
  -> L1 呈现
  -> L3 按需增强
```

## 4. 系统分解设计（系统 / 子系统 / 孙系统）

## 4.1 系统总览

系统按职责分为四大域：

- 运行时执行域（L1）
- 智能决策域（L2）
- 表现增强域（L3）
- 跨层治理域（L6在 Phase 1 的核心落位：总线、房间状态、持久化与存档）

### 4.1.1 Phase 1 子系统族总表

| 域 | 子系统族 | 本阶段子系统 |
| :--- | :--- | :--- |
| `L1` 运行时执行域 | 交互执行系统族 | 客户端交互系统、空间音频系统 |
| `L1` 运行时执行域 | 环境执行系统族 | `ESM` 环境状态管理器 |
| `L2` 智能决策域 | 角色决策系统族 | 角色智能体引擎（含 Per-Character 感知过滤器孙系统） |
| `L2` 智能决策域 | 叙事编排系统族 | 司命、模型路由调度器 |
| `L2` 智能决策域 | 感知与知识系统族 | 可感知信息编译层、信息共享执行系统 |
| `L3` 表现增强域 | 表现渲染系统族 | 点云过渡系统、视觉障眼法系统、高光编排系统 |

### 4.2 运行时执行域（L1）

#### 4.2.0 子系统族：交互执行系统族

#### 4.2.1 子系统：客户端交互系统

职责：

- 执行玩家交互、角色移动、物品使用、UI 触发。
- 生成交互结果与行为事件。

孙系统：

- 输入适配器：采集操作与设备输入。
- 动作执行器：落地交互动作。
- 事件上抛器：输出精确事件对象。
- 感知事实上抛器（原始感知特征提取）：上抛视觉/听觉/嗅觉/热感等原始感知特征事实。

#### 4.2.2 子系统：空间音频系统

职责：

- 基于 `Steam Audio` 在 `L1` 执行声源定位、距离衰减、物理遮挡与环境混响。
- 处理声源传播、衰减、遮挡、清晰度分区。
- 生成听觉相关世界事件与人类音频流。
- 为人类玩家输出 3D 音频，为 AI 链路输出可编译的听觉事实输入。

孙系统：

- `Steam Audio` 适配器：Godot 侧集成与运行时参数桥接。
- 声学传播引擎：距离/材质/遮挡计算。
- 清晰度分层器：`clear/muffled/silent`。
- 音频流输出器：WebRTC/客户端播放流。
- 听觉事实上抛器：把听觉相关世界事实上抛到事件总线。

边界：

- 空间音频系统属于 `L1` 运行时执行域，不属于事件总线或角色智能体子系统。
- 事件总线只做传输和路由；听觉候选事件的编译由可感知信息编译层完成。
- 感知事实上抛器只负责“原始感知特征事实上抛”，不承担候选感知事件编译。

#### 4.2.0 子系统族：环境执行系统族

#### 4.2.3 子系统：ESM 环境状态管理器

职责：

- 执行环境与实体状态机，输出确定性结算结果。

孙系统：

- 规则执行器：环境规则命中与状态迁移。
- 状态机库：角色/物体/环境状态模板。
- 结算回写器：回抛环境状态变化事件。

边界：

- 不做证据解释。
- 不做角色动机推理。

### 4.3 智能决策域（L2）

#### 4.3.0 子系统族：角色决策系统族

#### 4.3.1 子系统：角色智能体引擎

职责：

- 承载角色 `L1-L4` 心智链路与行动决策。

孙系统：

- Per-Character 感知过滤器：按角色感官档案与状态对候选感知事件做私有裁剪，输出角色专属感知事件。
- 感知接入器：接收过滤后的角色感知事件，不直接接收候选感知事件或原始世界事件。
- 理解与记忆器：更新事件/观察/知识/社交/高阶记忆。
- 规划与执行器：输出行为候选与执行意图。

#### 4.3.2 子系统：司命

职责：

- 维护单局叙事节奏、公平性与冲突催化。
- 输出 `impulse/fact_reveal/opportunity` 高层消息。

孙系统：

- 事实核心：说法-时间线矛盾比对。
- 天平系统：局势与倾向评估。
- 干预引擎：高层催化消息生成。

边界：

- 不直接控制玩家动作。
- 不替代角色自主决策。
- 不替代 `ESM` 物理执行。

#### 4.3.3 子系统：可感知信息编译层

职责：

- 将原始世界事件编译成多感官候选事件。
- 生成阶段化感知标签（`intent/execute/complete`）。

孙系统：

- 通道编译器：视觉/听觉/嗅觉/热感/触觉拆分。
- 上下文融合器：光照/噪音/遮挡/环境参数融合。
- 阶段标签器：动作阶段语义标注。

边界：

- 不做角色私有裁剪。
- 不替代 `Per-Character` 感知过滤器。

#### 4.3.0 子系统族：叙事编排系统族

#### 4.3.4 子系统：模型路由调度器

职责：

- 在规则程序/小模型/大模型间分配任务并做降级回退。

孙系统：

- 任务分级器（`P0-P4`）。
- 路由决策器（性能/成本/时延权衡）。
- 超时回退器（降级与兜底）。

#### 4.3.0 子系统族：感知与知识系统族

#### 4.3.5 子系统：信息共享执行系统

职责：

- 执行信息主权与传播规则，维护知识状态。

孙系统：

- 共享动作解析器（公开/耳语/展示/带看/投递）。
- 知识状态更新器（公开/共享/高阶）。
- 审计记录器（传播链追踪）。

## 5. 统一消息架构设计

### 5.1 消息对象分层

- 世界原始事件：来自 `L1/ESM/空间音频`
- 候选感知事件：来自可感知信息编译层
- 角色感知事件：来自 `Per-Character` 感知过滤器
- 司命高层消息：`impulse/fact_reveal/opportunity`
- 环境状态事件：来自 `ESM`
- L3 表现状态事件：`start/success/fallback/fail`

### 5.2 统一消息矩阵（核心路径）

| 发送方 | 接收方 | 消息对象 | 说明 |
| :--- | :--- | :--- | :--- |
| `L1` 交互/场景层 | 事件总线 | 精确世界事件 | 事实底座入口 |
| 事件总线 | `ESM` | 精确世界事件 | 物理结算 |
| 事件总线 | 司命 | 精确世界事件/系统事件 | 全局叙事判断 |
| 事件总线 | 可感知信息编译层 | 精确世界事件 | 候选事件编译 |
| 可感知信息编译层 | `Per-Character` 感知过滤器 | 候选感知事件 | 角色私有裁剪 |
| 感知过滤器 | 角色智能体 `L1` | 角色感知事件 | 角色默认入口 |
| 司命 | 事件总线 | 高层消息 | 催化，不是动作控制 |
| `ESM` | 事件总线 | 环境状态事件 | 状态变化上报 |

## 6. 关键数据流设计

### 6.1 主循环流

```text
玩家输入 / AI动作
  -> L1 执行与事件上抛
  -> 事件总线分发
  -> L2 决策 / ESM 结算
  -> 状态回写总线
  -> L1 呈现
  -> L3 按需增强
```

### 6.2 感知流

```text
L1/ESM 原始事件
  -> 可感知信息编译层（候选事件）
  -> Per-Character 感知过滤器（角色私有裁剪）
  -> Per-Character Sensed Event
  -> 角色 L1 感知 -> L2 理解
```

### 6.3 司命-ESM 协作流

```text
世界状态监听
  -> 司命高层催化意图
  -> ESM 可行性检查并执行
  -> 状态变化回写
```

### 6.4 证据流

```text
交互/接触/环境/伤害事件
  -> 事件总线
  -> 流转追踪/痕迹管理/ESM
  -> 持久化
  -> 司命事实核心比对
```

### 6.5 L3 表现流

```text
状态变化 + 司命触发意图
  -> L3 判定（点云/障眼法/混合）
  -> 预算与设备档位检查
  -> 执行或降级
  -> 回写表现状态事件
```

## 7. 基础设施架构口径

当前采用混合通道：

- 客户端实时交互：`WebSocket`
- 服务端硬实时：内存队列/本地直连

- `Godot 4.x`
- `Steam Audio`
- `Python / FastAPI`
- `Redis`
- `MinIO`
- 本地小模型 + 云端大模型

## 8. 分阶段架构切片

### 8.1 Phase 0（原型）

- 单场景 + 2 AI + 基础对话 + 空间音频 + 1 交互物品

## 9. 架构风险与控制

### 9.1 职责漂移

- 风险：司命/ESM/总线/证据链边界混写。
- 控制：每个系统固定“职责/非职责”双清单，评审强制检查。

### 9.2 实时性与成本冲突

- 风险：高并发导致延迟和成本双升。
- 控制：任务分级、模型路由、TTL、降级策略。

### 9.3 范围膨胀

- 风险：远期能力前置，挤压 `Phase 1` 验证。
- 控制：严格执行 `Phase 1` 必做/不做清单。

### 9.4 语义塌缩

- 风险：把原始事件、候选事件、角色感知事件混成单一广播对象。
- 控制：联调与验收按消息分层做检查，不通过不得合并。
