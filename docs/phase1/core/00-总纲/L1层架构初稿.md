# L1层架构初稿

## 状态

- 状态：初稿（未冲突部分收敛版）
- 主来源轮次：`104`、`214-215`、`302-304`、`352-353`、`380`、`398-400`
- 补充来源轮次：`406-437`
- 基线文档：`技术架构总纲`、`决策总表`、`overall-architecture/架构设计`

## 当前冻结结论

- `L1` 是“同源输入 + 确定性执行层”，不是纯渲染前端。
- `L1` 负责交互执行、空间音频执行、环境状态执行与精确事件上抛。
- `L1` 只上抛原始世界事实，不做叙事推理、不做证据意义解释。
- `L1` 到 `L2` 的感知主链路入口固定为“原始感知事实上抛”。
- `Godot` 客户端本地应先完成高频采样、语义抽取与线程安全收束，再把结构化视觉事实送入业务总线，而不是把原始骨骼/表情流直接广播。
- `L1` 在 Phase 1 只承载首个可玩闭环必需能力，不提前承诺后期完整生态能力。

## 3. 系统定位

`L1` 是世界事实执行层，负责把“玩家操作、AI 行为意图、环境规则结算”转成可复现的物理与交互结果，并产出结构化事件供上层消费。

`L1` 的输出要同时服务：

- 人类玩家感知（画面、音频、交互反馈）
- AI 链路输入（结构化原始事件）

## 4. 子系统分解（Phase 1）

### 4.1 子系统族：交互执行系统族

#### 4.1.1 子系统：客户端交互系统

职责：

- 执行玩家交互、角色移动、物品操作、基础 UI 触发
- 生成精确交互事件并上抛

孙系统：

- 输入适配器
- 动作执行器
- 事件上抛器
- 感知事实上抛器（原始感知特征提取）

#### 4.1.2 子系统：空间音频系统

职责：

- 执行声源定位、遮挡、距离衰减、清晰度分区
- 同时输出人类可听音频与 AI 可编译听觉事实

孙系统：

- `Steam Audio` 适配器
- 声学传播引擎
- 清晰度分层器
- 音频流输出器
- 听觉事实上抛器

### 4.2 子系统族：环境执行系统族

#### 4.2.1 子系统：ESM 环境状态管理器

职责：

- 执行环境与实体状态机
- 结算可交互实体的物理状态变化
- 回写环境状态事件

孙系统：

- 规则执行器
- 状态机库
- 结算回写器

边界：

- 不做证据意义解释
- 不做角色动机推理

## 5. 原始感知事实上抛口径（八类）

`L1` 当前采用八类原始感知事实上抛器：

- 视觉事实上抛器
- 听觉事实上抛器
- 触觉事实上抛器
- 热感事实上抛器
- 嗅觉事实上抛器
- 生理状态事实上抛器
- 社交距离与空间行为上抛器
- 角色状态事实上抛器

说明：

- 八类上抛器只负责采集与上抛原始事实
- 候选感知事件编译由 `L2` 可感知信息编译层负责

### 5.1 会话机制相关的硬依赖上抛器

若要支撑“偷听 / 接近 / 加入对话 / 排斥 / 私密沟通”这类运行时会话机制，Phase 1 至少要求以下四条事实上抛链稳定存在：

- 视觉事实上抛器：上抛“谁在场、谁看见了谁、谁出现在门口或入口、会话圈是否可见”
- 听觉事实上抛器：上抛“谁在发声、音量档位、声源位置、耳语/正常/喊叫模式、环境噪音基础事实”
- 社交距离与空间行为上抛器：上抛“靠近、停留、退开、围拢、回避、转移站位、进入/离开 `scene`、进入/离开 `zone`、与关键对象的距离变化”
- 交互/状态回写链：由客户端交互系统或 `ESM` 回写“开门、关门、开窗、关窗、拉帘、移物形成遮挡、制造掩护噪音”等会改变会话隐私边界的事实

其中“视觉事实上抛器”现已从零散条目提升为独立文档簇，后续统一以下游文档为准：

- [Godot源码底层基础设施与运行时约束](/d:/Projects/Paralls/docs/phase1/core/00-总纲/Godot源码底层基础设施与运行时约束.md)
- [视觉事实系统/00-视觉事实系统总索引](/d:/Projects/Paralls/docs/phase1/core/01-运行时核心/视觉事实系统/00-视觉事实系统总索引.md)

这四条链负责支撑：

- `approach_detected`
- 偷听候选是否成立
- 私密性是否收紧
- 成员资格判断所需的底层空间与声学证据

### 5.2 原始会话事实与派生会话事实的边界

`L1` 只上抛原始事实，例如：

- 谁走近了
- 谁进入了哪个 `scene/zone`
- 门关没关
- 音量压低没压低
- 谁停留了多久

`L1` 不直接上抛以下派生结论：

- 谁已经成为对话成员
- 谁知道别人知道自己在场
- 谁被排斥出了当前会话
- 会话是否完成加入转换

这些派生结论必须由 `L2` 在接收 `L1` 原始事实上升出运行时语义，不能由 `L1` 反向虚构。

## 6. 与上层的接口边界

### 6.1 L1 -> 事件总线

上抛对象：

- 精确世界事件
- 环境状态变化事件
- 感知原始事实事件

约束：

- 事件需包含可追溯的时空与对象关系
- 不在 `L1` 事件中混入主观推理结论

### 6.2 L1 <- L2/L6

接收对象：

- 角色执行意图回写
- 司命高层催化后的可执行请求（经角色/规则链路落地）
- 房间状态与同步控制消息

约束：

- `L1` 不接受“绕过角色决策的低层强控指令”

## 7. Phase 1 实现优先级

先做：

- 客户端交互系统主链
- 空间音频基础执行与听觉上抛
- `ESM` 基础交互级结算
- 八类事实上抛最小字段集
- 与事件总线的稳定消息对接

后做：

- 更细的多感官扩散数学模型
- 更复杂的跨区域优化
- 非闭环必需的高成本表现强化

## 8. 延后项（本稿不纳入）

- 完整体素沙盒执行链
- 完整天气 / 生物成长 / 长周期环境推演
- 持续运行世界所需的全时段环境模拟
- 后期生态层对 `L1` 的完整商业化/治理化扩展能力
