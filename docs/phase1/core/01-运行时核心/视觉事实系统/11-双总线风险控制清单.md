# 11-双总线风险控制清单

## 1. 文档目标

本文档把《开本》双总线架构下的主要风险，收敛成一份可执行的控制清单。

这里的“双总线”指：

1. 后端权威叙事/事实总线
2. Godot 本地表现总线

本文档不重新定义双总线本体，而只回答：

- 风险是什么
- 何时会触发
- 怎么监控
- 怎么缓解

## 2. 使用方式

每条风险统一按以下字段描述：

- `风险`
- `触发条件`
- `影响`
- `监控信号`
- `缓解措施`
- `升级处理`

建议把这张表同时服务于：

- 架构评审
- 联调前检查
- 线上异常归因
- 回放与工作台调试

## 3. 风险分级

建议统一分四级：

- `R0`：直接破坏世界真值或角色主观链
- `R1`：严重影响角色行为一致性或表现稳定性
- `R2`：影响体验与调试效率，但不立即破坏闭环
- `R3`：维护性和演进性风险

## 4. 风险清单

### 4.1 真值分裂

- 等级：`R0`
- 风险：
  - 后端权威总线和 Godot 本地表现总线分别持有不同版本的“当前状态”
- 触发条件：
  - 客户端本地缓存被当成业务真值
  - 表现 revision 未能覆盖旧状态
  - 本地推断结果被误当成世界事实
- 影响：
  - replay 无法解释
  - 玩家看到的和后端认定的不一致
  - 角色行为与表现脱节
- 监控信号：
  - 同一 `character_id` 在同一 `correlation_id` 下出现冲突状态
  - 本地 `revision_seq` 落后于服务端最新版本
  - 工作台中 intent / execution / visible state 不一致
- 缓解措施：
  - 后端权威总线是唯一世界真值源
  - Godot 本地总线只持有表现态
  - 所有跨边界消息必须带：
    - `revision_seq`
    - `causation_id`
    - `correlation_id`
- 升级处理：
  - 一旦发现冲突，以后端状态强制回收客户端状态
  - 记录异常 replay 样本

### 4.2 边界消息过粗

- 等级：`R1`
- 风险：
  - 后端发给 Godot 的消息太粗，导致本地表现无法稳定落地
- 触发条件：
  - 只传 `suspicious`、`fearful` 这类抽象状态
  - 不传 `FACS/SACS activation set`、execution packet 等表达层对象
- 影响：
  - 客户端只能做粗粒度动画切换
  - 无法支撑精确 gaze、局部姿态、微表达
- 监控信号：
  - 本地表现层大量回退到默认 idle / generic gesture
  - `SkeletonModifier3D` 参与率低但表现需求高
- 缓解措施：
  - 跨边界最小消息必须至少包含：
    - `IntentPacket`
    - `ExpressionCoreState`
    - `FACS Activation Set`
    - `SACS Activation Set`
    - `ExecutionPacket`
- 升级处理：
  - 对消息 schema 做缺字段告警

### 4.3 边界消息过细

- 等级：`R1`
- 风险：
  - 把原始骨骼流、全量面部权重流当成业务总线输入
- 触发条件：
  - Python / 后端逐帧发送每根骨骼的 position / rotation
  - 把全 AU 权重每帧广播到后端
- 影响：
  - 总线流量膨胀
  - 表现 jitter 直接暴露给业务链
  - 资产耦合进入事实总线
- 监控信号：
  - 单角色消息频率异常高
  - 业务总线 payload 出现具体骨骼名、blendshape 名
  - 回放记录体积异常
- 缓解措施：
  - 跨边界只传高层语义，不传全骨骼高频流
  - 骨骼/表情原始流只留在 Godot 本地和调试副通道
- 升级处理：
  - 拦截非法 payload schema
  - 在工作台高亮“资产耦合字段”

### 4.4 时序乱序

- 等级：`R0`
- 风险：
  - 新旧 revision 乱序应用，导致旧状态覆盖新状态
- 触发条件：
  - 网络延迟抖动
  - deferred 调用顺序和业务事件顺序脱节
  - 多通道异步更新无统一版本
- 影响：
  - 中断失效
  - 表现状态回滚
  - 角色视觉事实采样错位
- 监控信号：
  - 同一角色 `revision_seq` 倒退
  - intent 已变更，但本地仍执行旧 expression packet
  - 工作台显示跨周期错位
- 缓解措施：
  - 所有表现更新必须显式版本化
  - 客户端只接受比当前更新的 revision
  - 中断策略只允许：
    - `soft_release`
    - `hard_cut`
    - `hold_until_safe`
- 升级处理：
  - 发现倒序直接丢弃旧 revision

### 4.5 重复语义实现

- 等级：`R1`
- 风险：
  - 后端和 Godot 本地都各自做一套“姿态 -> 语义事实”判定
- 触发条件：
  - 在后端重复做 gaze / concealment / recoil 语义识别
  - 本地和后端的 feature / threshold 不一致
- 影响：
  - 同一事实出现两套不一致判定
  - replay 和工作台中出现冲突解释
- 监控信号：
  - 同一 `source_event_id` 生成多个相互冲突的视觉事实
  - 后端和本地 semantic label 不一致
- 缓解措施：
  - 视觉语义抽取只在 Godot 本地进行
  - 后端只消费结构化 `VisualFactEvent`
- 升级处理：
  - 禁止在后端再次做骨骼级语义分类

### 4.6 本地总线越权长成第二业务总线

- 等级：`R0`
- 风险：
  - Godot 本地表现总线开始持有知识真值、角色信念或司命图谱结果
- 触发条件：
  - 客户端开始缓存高阶知识
  - 本地开始判定谁在撒谎、谁已成会话成员
- 影响：
  - 权威真值源丢失
  - 客户端与后端职责混乱
- 监控信号：
  - 客户端缓存中出现 belief / knowledge / membership 真值字段
  - 调试对象中出现不属于表现层的业务判定结果
- 缓解措施：
  - Godot 本地只做：
    - 采样
    - 语义抽取
    - 表现执行
    - UI 呈现
  - 不做：
    - 全局事实判断
    - 高阶知识图谱判断
    - 角色信念真值更新
- 升级处理：
  - 对客户端可持有字段建立白名单

### 4.7 回放链断裂

- 等级：`R1`
- 风险：
  - 后端总线和本地总线之间没有统一追踪链
- 触发条件：
  - 缺少 `source_ref_id`
  - 缺少 `causation_id`
  - 缺少 `correlation_id`
  - 本地 sample 无法追到业务事件
- 影响：
  - 不能解释“为什么这样动”
  - 不能追到视觉事实上抛前的姿态来源
- 监控信号：
  - 工作台存在无源 event
  - replay 节点无法回跳上一层
- 缓解措施：
  - 两边统一追踪字段：
    - `event_id`
    - `source_ref_id`
    - `causation_id`
    - `correlation_id`
    - `revision_seq`
- 升级处理：
  - 对无追踪字段对象做录入失败或高亮告警

### 4.8 性能优化方向错位

- 等级：`R2`
- 风险：
  - 把本地执行瓶颈误判为后端总线问题，或反之
- 触发条件：
  - 只看总耗时，不看链路分段耗时
  - 本地 modifier 开销和后端语义编排混到一个指标里
- 影响：
  - 优化投入错位
  - 重构方向错误
- 监控信号：
  - 单一“总延迟”指标无法解释体验问题
- 缓解措施：
  - 分开记录：
    - 后端权威总线延迟
    - Godot 本地表现总线延迟
    - sampler / extractor / emitter 耗时
    - animation / modifier / UI 耗时
- 升级处理：
  - 先做分段 profiling 再做优化裁决

### 4.9 团队理解漂移

- 等级：`R2`
- 风险：
  - 不同成员对双总线和视觉事实系统层级理解不一致
- 触发条件：
  - 有人把 Godot 当纯渲染壳
  - 有人想让 Python 每帧全骨骼遥控
  - 有人把视觉事实系统放进 `L2`
- 影响：
  - 设计反复回滚
  - 文档与实现脱节
- 监控信号：
  - 代码或方案中出现与文档明显相反的边界实现
- 缓解措施：
  - 所有相关设计先读：
    - [Godot源码底层基础设施与运行时约束](/d:/Projects/Paralls/docs/phase1/core/00-总纲/Godot源码底层基础设施与运行时约束.md)

- 升级处理：
  - 方案评审中强制做“层级归属与消息边界检查”

### 4.10 视觉事实系统两头受压

- 等级：`R1`
- 风险：
  - 视觉事实系统过度靠前端，变成局部表现噪声
  - 或过度靠后端，变成认知层重复实现
- 触发条件：
  - 事实抽取结果不稳定
  - 事实抽取逻辑被后端复制
  - 事实事件设计成高度解释化心理真值
- 影响：
  - 视觉事实系统既不可信，也不可维护
- 监控信号：
  - `VisualFactEvent` 中出现心理真值字段
  - 视觉事实与 `L2` 解释结果边界模糊
- 缓解措施：
  - 视觉事实系统位置固定为：
    - 本体在 `L1`
    - 输入来自 Godot 本地
    - 输出进入后端业务总线
  - 只负责：
    - 可观察视觉事实
  - 不负责：
    - 最终心理解释
    - 最终证据定性
- 升级处理：
  - 对视觉事实 schema 做心理真值字段审计

## 5. 联调前检查清单

联调前至少检查：

1. 是否存在客户端私持业务真值字段
2. 是否存在跨边界原始骨骼流广播
3. 是否所有表现更新都带 `revision_seq`
4. 是否 replay 链统一带 `causation_id / correlation_id`
5. 是否 Godot 本地总线只做表现执行和采样语义抽取
6. 是否后端没有重复做本地骨骼语义分类
