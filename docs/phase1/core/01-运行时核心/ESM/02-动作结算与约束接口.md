# 02-动作结算与约束接口

## 1. 文档目标

本文档冻结 `ESM` 在实现前必须先明确的动作结算 contract：

- 谁可以发请求
- 请求长什么样
- 成功结果长什么样
- 失败约束结果长什么样

## 2. 核心定义

`ESM` 的动作结算接口不是角色决策接口，也不是司命导演接口。

它只回答：

- 这个动作在当前物理 / 状态约束下能不能成立
- 成立后改变了什么
- 不成立时被什么约束挡住

## 3. 请求来源

当前允许的请求来源固定为：

1. `player_input_bridge`
2. `character_runtime`
3. `siming_orchestrator`
4. `system_rule_runtime`

不允许直接来源：

- 任意调试台直接改世界
- 角色内部未提交候选动作
- 司命直接写既成结果

## 4. `ActionRequest`

建议最小字段：

- `request_id`
- `request_type`
- `room_id`
- `scene_id`
- `zone_id`
- `source`
- `target_entity_refs`
- `action_profile`
- `intent_strength`
- `constraints_hint`
- `producer_ts`
- `causation_id`
- `correlation_id`

### 4.1 `request_type` 建议枚举

- `interact`
- `move`
- `use_object`
- `apply_force`
- `toggle_state`
- `environment_request`

### 4.2 `source` 建议结构

- `source.layer`
- `source.system`
- `source.actor_id`
- `source.object_id`（如有）

## 5. `ActionResolutionResult`

建议最小字段：

- `result_id`
- `request_ref`
- `resolution_status`
- `resolved_entities`
- `applied_state_changes`
- `stable_state_summary`
- `producer_ts`
- `causation_id`
- `correlation_id`

### 5.1 `resolution_status` 建议枚举

- `accepted`
- `partially_accepted`
- `rejected`

## 6. `ConstraintStateResult`

建议最小字段：

- `constraint_result_id`
- `request_ref`
- `constraint_type`
- `constraint_code`
- `constraint_summary`
- `blocking_entity_refs`
- `producer_ts`
- `causation_id`
- `correlation_id`

### 6.1 `constraint_type` 建议枚举

- `distance_constraint`
- `occlusion_constraint`
- `collision_constraint`
- `lock_state_constraint`
- `material_constraint`
- `state_transition_constraint`
- `cooldown_constraint`
- `resource_constraint`

## 7. 最小请求矩阵

### 7.1 玩家输入链

- `interact_intent`
  -> `ActionRequest(request_type=interact)`

### 7.2 角色行为链

- `ActionRequestIssued`
  -> `ActionRequest(request_type=move/use_object/apply_force)`

### 7.3 司命环境链

- `environment_request`
  -> `ActionRequest(request_type=environment_request)`

## 8. 成功与失败边界

### 成功

- 生成 `ActionResolutionResult`
- 如有状态变化，再生成：
  - `ObjectStateResult`
  - `EnvironmentStateResult`
  - `BodyStateResult`

### 失败

- 不伪造结果
- 只生成 `ConstraintStateResult`

## 9. 一句话收束

`ESM` 的动作结算接口不是“执行建议”，而是“世界权威结算口”：任何请求都必须先变成 `ActionRequest`，然后被收敛成 `ActionResolutionResult` 或 `ConstraintStateResult`。
