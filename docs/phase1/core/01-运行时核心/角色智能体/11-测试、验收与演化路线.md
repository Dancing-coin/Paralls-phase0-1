# 11-测试、验收与演化路线

## 1. 文档目标

本文档冻结角色智能体系统的测试层级、Phase 1 验收闭环、失败分级、回归组织方式与后续阶段演化路线。

## 2. 五层测试结构

建议固定分：

1. `Schema Tests`
2. `Logic Unit Tests`
3. `Simulation Scenario Tests`
4. `Narrative Consistency Tests`
5. `Performance & Degradation Tests`

## 3. Phase 1 核心体验验收维度

1. 人格一致性
2. 感知边界正确性
3. 记忆与知识分层
4. 规划合理性
5. 执行一致性
6. 玩家接管正确性
7. 可解释与可回放

## 4. 必测场景

建议至少做：

- 私密对话半途接入
- 模糊异常声响
- 关键物品藏匿
- 撒谎对峙
- 伤病/失温/中毒
- 玩家挂机
- 玩家回归
- 高压力边缘状态

## 5. 失败分级

- `S0`：读全局真相、挂机替玩家做不可逆决策、司命越权直控、执行层绕过 `ESM`
- `S1`：持续严重 OOC、关系跳变、表达层和内在状态严重不一致
- `S2`：模糊感知、误判机制、回放链或过滤器调度不稳
- `S3`：微表现略机械、建议文本不自然等轻微问题

## 6. 阶段演化

### Phase 1
- 单局完整版角色智能体成立
- 玩家接管与挂机接管成立
- 小世界轻量承接成立

### Phase 2
- 跨剧本记忆承接
- 角色资产化
- 长期关系网增强
- 多同伴共存

### Phase 3
- 群体级角色分层
- 按需注入角色
- 长期社会关系演化
- 大规模持续世界调度

## 7. 不可回退核心

从 Phase 1 开始就不能丢：

- 统一底层
- 五池记忆
- 双回路玩家模型
- 三重过滤器
- `FACS/SACS + Binder`
- 回放解释链

## 8. 一句话收束

角色智能体的测试与验收不能围绕“会不会说话”展开，而必须围绕“边界是否守住、链路是否成立、人格是否连续、行为是否可解释、玩家是否仍有主导权”展开。
