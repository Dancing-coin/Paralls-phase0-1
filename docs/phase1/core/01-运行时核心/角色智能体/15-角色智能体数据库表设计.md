# 15-角色智能体数据库表设计

## 1. 文档目标

本文档冻结角色智能体系统在数据库和缓存层的落表策略：哪些对象持久化、哪些放热态缓存、哪些服务于回放和审计。

## 2. 总分区

建议分成五个逻辑区：

1. `Profile Zone`
2. `Memory Zone`
3. `Runtime State Zone`
4. `Decision Trace Zone`
5. `Embodiment Zone`

## 3. Profile Zone

至少包括：

- `character_profiles`
- `character_origin_seeds`
- `character_life_backbone_events`
- `character_value_profiles`
- `character_trait_vectors`
- `character_capability_profiles`
- `character_expression_bias_profiles`
- `character_conversation_personality_profiles`

## 4. Memory Zone

五池记忆分别落表：

- `event_memories`
- `observation_memories`
- `knowledge_memories`
- `social_memories`
- `higher_order_memories`

## 5. Runtime State Zone

推荐主要放 Redis：

- `char:{id}:runtime_state`
- `char:{id}:snapshot`
- `char:{id}:attention`
- `char:{id}:conversation_state`
- `char:{id}:active_execution`

## 6. Decision Trace Zone

建议正式落表：

- `decision_cycles`
- `decision_cycle_inputs`
- `interpretation_results`
- `belief_update_deltas`
- `social_inference_deltas`
- `candidate_actions`
- `triple_filter_results`
- `intent_packets`
- `decision_human_summaries`
- `character_replay_index`

## 7. Embodiment Zone

至少需要：

- `embodiment_profiles`
- `expression_core_states`
- `facs_activation_sets`
- `sacs_activation_sets`
- `execution_packets`

## 8. 原则

- 核心主键/外键/枚举/状态字段结构化
- tags、refs 和 adapter 配置允许 JSON
- 热态与持久化边界清楚
- 决策链必须能从数据库完整重建

## 9. Phase 1 范围

Phase 1 必须落下：

- 档案主表
- 五池记忆主表
- 决策周期主链
- 表达链主表
- 资产接入配置表
- Redis 热态键空间

## 10. 一句话收束

角色智能体的数据库设计必须围绕“可追踪角色主观链路”展开，而不是围绕“方便存日志”展开。
