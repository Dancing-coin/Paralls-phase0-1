# 09-运行时服务拆分、模型路由与性能预算

## 1. 文档目标

本文档冻结角色智能体系统的工程拆分、快慢链路、规则/小模型/大模型分工与性能预算。

## 2. 总体原则

- 角色智能体不是一次 LLM 调用壳
- 快链路和慢链路必须分开
- 规则优先，模型补足
- 表达层与认知层应解耦演化

## 3. 六个运行时模块

建议固定拆成：

1. `Perception Runtime`
2. `Memory & Belief Runtime`
3. `Planning Runtime`
4. `Expression Runtime`
5. `Player Override Runtime`
6. `Character Orchestrator`

## 4. 推荐部署形态

Phase 1 建议收敛为两个后端服务：

- `character-service`
- `expression-service`

逻辑上仍保留上述六模块边界。

## 5. 快链路与慢链路

### 快链路
- 感知过滤
- 私有世界快照更新
- 基础状态变化
- 生理层更新
- 注视与社交距离微调

### 慢链路
- 长上下文社交判断
- 复杂关系重估
- 候选行动深排序
- 复杂决策建议

## 6. 模型路由

固定三层：

1. `Rule Layer`
2. `Fast Model Layer`
3. `Deep Model Layer`

### Rule Layer
处理硬边界、硬约束、硬时延。

### Fast Model Layer
处理短上下文主观解释、简单建议与轻量语言组织。

### Deep Model Layer
处理复杂关系推理、长上下文决策与高价值场景表达。

## 7. 角色任务分级

建议固定：

- `C0` 硬实时
- `C1` 近实时
- `C2` 交互实时
- `C3` 慢推理
- `C4` 后台维护

## 8. Godot 连接边界

Godot 不直接连事件总线。客户端只连：

- `gateway/session service`
- `voice realtime service`
- `expression sync channel`

## 9. 降级策略

- 一级：deep model 回落到 fast model + 规则模板
- 二级：fast model 回落到规则化行为和短语模板
- 三级：仅保留生理、空间和保守行为链路

## 10. 并发预算

角色建议分三级：

- `Primary`
- `Secondary`
- `Peripheral`

不同角色等级使用不同算力与表达预算。

## 11. Phase 1 范围

Phase 1 必须冻结：

- 六模块结构
- 双服务主切法
- Rule / Fast / Deep 三层路由
- `C0-C4` 任务分级
- 快慢链路分离
- 基础降级策略
- Godot 经 gateway 访问后端

## 12. 一句话收束

角色智能体在工程上必须被实现为“快链路保连续、慢链路保深度、规则保边界、模型保弹性、表达层独立演化”的分层运行时系统，而不是一个统一的黑盒 AI 角色服务。
