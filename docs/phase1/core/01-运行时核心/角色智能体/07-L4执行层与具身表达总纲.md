# 07-L4执行层与具身表达总纲

## 1. 文档目标

本文档冻结角色如何把已经选定的行动意图落成可见、可听、可感知的表现。

## 2. 核心定义

`L4` 不是动作播放器，而是多通道执行协调层。它把“我要这样做”翻译成“别人将如何看见我、听见我、感受到我”。

## 3. 五条并行主通道

执行层固定拆成：

1. `Speech Channel`
2. `Face Channel`
3. `Body Channel`
4. `Social-Spatial Channel`
5. `Physiology Channel`

## 4. Speech Channel

负责：

- 说还是不说
- 说得快还是慢
- 是否压低声音
- 是否停顿、吞字、强撑平稳

## 5. Face Channel

负责面部表达。输入不是情绪标签，而是 `FACS` 单元、语音联动、注视目标、压抑和泄露策略。

## 6. Body Channel

负责姿态、头颈、手臂、手部、重心、步态和动作叠加。输入核心是 `SACS` 单元。

## 7. Social-Spatial Channel

负责空间中的社交行为：

- 靠近还是后退
- 与谁保持距离
- 朝向谁
- 是否形成私密交谈圈
- 是否靠墙、挡路、侧身回避

## 8. Physiology Channel

负责自动生理表现：

- tremor
- breath
- pain guarding
- instability
- fatigue
- involuntary micro actions

这条通道必须常驻，不能完全受主动意志控制。

## 9. AI 与玩家分流

AI 角色五通道全自动。

玩家角色：主动说话、主动移动、主动交互由玩家控制；但微表情、微动作、社交距离微调、生理自动层仍由系统维持。

## 10. 与 L1/ESM 的关系

`L4` 只发动作请求和表达计划，不判定动作是否成功。动作是否成立、门是否真的打开、某人是否真的被扶住，必须由 `L1/ESM` 结算。

## 11. 与 FACS/SACS / Binder 的关系

统一链路：

`L4 Intent -> FACS/SACS Planner -> Embodiment Binder -> Canonical Face/Body Control Graph -> Asset Adapter -> Godot Runtime`

## 12. Phase 1 范围

Phase 1 最少要支持：

- 五通道执行框架
- AI/玩家双模式
- 挂机保守接管
- `FACS/SACS + Embodiment Binder` 最小闭环
- 与 Godot AnimationTree / IK / shape key 的衔接

## 13. 一句话收束

`L4` 执行层不是把动作做出来的单点模块，而是角色将意图分解为语音、面部、身体、社交空间和生理自动表现的多通道一致性引擎。
