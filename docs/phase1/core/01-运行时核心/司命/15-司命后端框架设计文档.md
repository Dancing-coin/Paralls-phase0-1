# 15-司命后端框架设计文档

## 1. 文档目标

本文档把 `Phase 1` 司命从“设计概念 / 协议簇”落成可实现的后端框架：

- 后端服务如何分层
- 单局内如何持续推演剧情
- 如何接入 PlotPilot 的叙事核心思想
- 如何与事件总线、角色智能体、`ESM`、Godot 前端协作
- 哪些对象需要持久化、缓存、审计和工作台展示

本文档不负责：

- 替代 [司命设计文档.md](../司命设计文档.md)
- 重写事件总线、角色智能体、`ESM` 的协议
- 冻结具体 ORM / 中间件 / 云部署供应商
- 引入 PlotPilot 的完整小说生成、章节扩写、写作前端或自动驾驶流水线

一句话：

> 本文档定义的是“司命后端运行框架”，不是“剧情生成器整包迁移方案”。

## 2. 上游约束

本框架必须服从以下已冻结口径：

1. `Phase 1` 司命是受边界约束的完整单局导演，不是纯被动守门人。
2. 司命在活动单局内持续 `ingest`、周期性 `tick`、持续推演局势。
3. 小世界离线期不采用司命持续后台常驻；玩家回来时做关键事件补全与简报。
4. 司命不能重写已锁定事实，不能直接控制角色，不能替代 `ESM` 写物理结果。
5. 司命对外只回写高层催化对象：`impulse`、`opportunity`、`fact_reveal`、`environment_request`、`none`。
6. 所有关键决策必须可 replay / audit / 工作台解释。

## 3. 最小验证与可扩展框架原则

`Phase 1` 是最小化验证阶段，但司命后端框架不能写成一次性 demo。

当前正确目标是：

```text
最小实现能力
+ 稳定模块边界
+ 可版本化 schema
+ 可插拔扩展点
+ 非破坏性迁移路径
```

而不是：

```text
为了快速验证，把所有逻辑写死在一个流程里
```

### 3.1 最小实现不等于临时结构

`Phase 1` 可以只实现少量 auditor、少量干预带、短 horizon 推演和薄 read model。

但下列边界必须从第一版就稳定：

- `SimingOrchestrator` 是唯一主编排入口
- `EventBus` 是唯一跨系统事实通信入口
- `FairnessStateSnapshot` / `InterventionCandidate` / `InterventionDecision` 是 `Phase 1` 稳定领域对象
- `NarrativeStateSnapshot` / `ProjectionRun` / `EventChainCandidate` 是 `Phase 2+` 扩展对象，`Phase 1` 只允许保留 stub 或只读占位
- `Dispatcher` 只能发高层消息，不能绕过角色、`ESM` 或 Godot 表现边界
- `Audit` 必须保留所有关键对象引用链

### 3.2 扩展优先走插件点，不改主链

后续新增能力应优先挂到这些扩展点：

- auditor 扩展：新增公平维度或专门审计器
- projection 扩展：新增事件链生成策略
- priority 扩展：新增戏剧优先级评分因子
- guardrail 扩展：新增越权 / 安全 / 体验检查
- execution path 扩展：新增 Godot / L3 表现路径
- read model 扩展：新增工作台字段

主链仍保持：

```text
ingest
-> fact
-> fairness
-> policy
-> feasibility
-> dispatch
-> audit
-> read model
```

`narrative projection` 是 `Phase 2+` 扩展插槽，不进入 `Phase 1` fairness 主链。

### 3.3 Schema 版本化

所有对外或持久化关键对象都应带版本信息。

建议字段：

- `schema_version`
- `producer_system`
- `created_at`
- `causation_id`
- `correlation_id`

适用对象：

- `FairnessStateSnapshot`
- `NarrativeStateSnapshot`
- `ProjectionRun`
- `EventChainCandidate`
- `InterventionCandidate`
- `InterventionDecision`
- `InterventionAuditRecord`
- `NarrativeReadModel`

后续字段新增应优先采用可选字段，不要求旧数据立即迁移。

时钟字段采用双层口径：

- 事件总线公共信封使用 `producer_ts/event_id` 排序，不把 `world_ts` 放入公共信封。
- 司命领域对象可以保留 `world_ts` 和 `sim_tick_ts`，分别表示房间世界时间和司命裁判周期时间。
- replay 串链优先依赖 `correlation_id -> causation_id -> event_id`，再用 `world_ts/sim_tick_ts` 解释时间关系。

### 3.4 Feature Flag 与能力注册

后续能力不要直接写死启用。

建议司命启动时加载：

```json
{
  "enabled_auditors": [],
  "enabled_projection_strategies": [],
  "enabled_execution_paths": [],
  "enabled_guardrails": [],
  "read_model_detail_level": "thin"
}
```

这样 `Phase 1` 可只启用最小能力，`Phase 2+` 可以通过注册新增模块扩展，而不是拆主链。

### 3.5 迁移边界

可以变化：

- scoring 权重
- auditor 数量
- projection horizon
- read model 细节
- 工作台展示字段
- 具体缓存 TTL

不应破坏性变化：

- 事件总线公共信封
- 司命只发高层消息的边界
- `environment_request -> ESM resolution -> world fact event` 闭环
- `SimingHighLevelMessage -> Character L2/L3 -> action/result feedback` 闭环
- audit 链最小字段
- room 级隔离

## 4. 与 PlotPilot 的关系

司命借用 PlotPilot 的不是“写小说流程”，而是以下工程思想：

- `stateful narrative model`
- `checkpoint`
- `guardrail`
- `read facade`
- `orchestrator / daemon`
- `quality monitor`
- 叙事状态投影与运行时面板

对应到司命：

| PlotPilot 思想 | 司命落点 |
| --- | --- |
| `WritingOrchestrator` | `SimingOrchestrator` |
| `PlotStateMachine` | `SimingPhaseController` |
| `Foreshadow / NarrativeDebt` | `NarrativeObligationLedger` |
| `Checkpoint` | `SimingCheckpoint` |
| `QualityGuardrail` | `InterventionGuardrails` |
| `ContextBuilder` 洋葱模型 | `SimingContextAssembler` |
| `Runtime Projection` | `SimingWorkbenchProjection` |

明确不接：

- 章节生成
- 字数控制
- BeatSheet 扩写
- 小说正文质量评分
- Tauri / Vue 写作工作台
- Prompt package 整包
- 自动长篇小说流水线

## 6. 核心服务拆分

### 6.1 `SimingOrchestrator`

司命主编排器。

职责：

- 绑定 `room_id`
- 消费权威事件
- 维护 tick 周期
- 调度 auditor 与叙事推演核心
- 合并快照、候选、决策
- 触发 dispatch / audit / read model

它不负责：

- 直接生成物理结果
- 直接控制角色动作
- 直接持有 Godot 节点引用

建议主方法：

```python
ingest_event(event) -> None
tick(room_id, sim_tick_ts, world_ts) -> SimingTickResult
recover_room(room_id) -> SimingRuntimeState
shutdown_room(room_id) -> AuditSummary
```

### 6.2 `FactCore`

事实核心。

职责：

- 管理 `T0-T3` 锁定边界
- 校验事实矛盾
- 阻止重写已成立真相
- 为叙事推演提供不可越界的事实基底

输出：

- `FactCoreSnapshot`
- `fact_lock_violations`
- `timeline_conflict_flags`

### 6.3 `FairnessAuditEngine`

公平审计引擎。

职责：

- 调度 auditor
- 生成 `FairnessStateSnapshot`
- 给出当前主失衡类型与优先级

最小 auditor：

- `information_auditor`
- `participation_auditor`
- `conversation_access_auditor`
- `suspicion_auditor`
- `evidence_auditor`

### 6.4 `NarrativeProjectionCore`

持续叙事推演核心。

这是本文档新增的后端扩展层。`Phase 1` 可以保留接口 stub，但不得把完整事件链搜索、长 horizon 推演或戏剧优先级模型列为最小验收阻塞项。

职责：

- 基于当前事实、公平、知识与会话状态，持续推演接下来一段时间内的可能剧情链
- 生成 `EventChainCandidate`
- 评估每条候选链的戏剧价值、公平收益、风险与可执行成本
- 给策略层提供候选，不直接写事实

关键约束：

- 推演结果只是候选，不是世界事实
- 必须带 `basis_snapshot_ref`
- 必须能解释“为什么认为这条链值得推动”
- 必须经过 policy / feasibility / audit 后才可能 dispatch

内部子模块：

```text
SimingPhaseController
NarrativeStateBuilder
NarrativeObligationLedger
EventChainComposer
DramaticPriorityModel
ProjectionSandbox
```

### 6.5 `SimingPhaseController`

单局阶段控制器。

建议阶段：

```text
setup
exploration
escalation
convergence
resolution
```

用途：

- 决定是否允许开新线
- 决定何时提高收束压力
- 决定何时优先 `fact_reveal`
- 决定何时禁止低价值新冲突
- 决定何时组织结局演绎方向

与 PlotPilot 的差异：

- 不按章节百分比推进
- 改按房间阶段、关键事件密度、公平失衡、证据链进度、玩家参与状态推进

### 6.6 `NarrativeObligationLedger`

叙事义务账本。

`Phase 1` 不要求实现完整账本；可以只在 `NarrativeReadModel` 中保留薄字段，记录当前最明显的未闭合公平义务。

它不是小说伏笔表，而是单局内未闭合的运行时义务：

- `unresolved_fact`
- `unseen_evidence`
- `blocked_conversation`
- `stalled_actor_window`
- `pending_environment_consequence`
- `overheated_suspicion_chain`
- `underused_character_motive`

输出给：

- `NarrativeStateSnapshot`
- `EventChainComposer`
- `NarrativeReadModel`
- 工作台

### 6.7 `EventChainComposer`

事件链候选生成器。

输入：

- 事实快照
- 公平快照
- 叙事义务
- 当前阶段
- 角色可行动窗口
- `ESM` 可见环境机会
- 视觉事实与证据投影

输出：

```json
{
  "chain_id": "chain_001",
  "basis_snapshot_ref": "fair_snap_001",
  "trigger_condition": "char_a enters corridor while evidence_x is visible",
  "required_conditions": [],
  "expected_effect": "relieve_evidence_bottleneck",
  "candidate_band": "opportunity",
  "risk_tags": [],
  "trace_refs": []
}
```

### 6.8 `DramaticPriorityModel`

戏剧优先级模型。

`Phase 1` 不要求实现完整模型；如果保留，只能作为简单排序 stub，不得覆盖公平优先级、可执行性和审计可解释性。

职责：

- 排序事件链候选
- 平衡戏剧价值、公平纠偏、可玩性、角色自主性、可执行性

建议评分维度：

- `dramatic_value`
- `fairness_delta`
- `playability_gain`
- `role_autonomy_safety`
- `fact_lock_safety`
- `execution_cost`
- `audit_clarity`

### 6.9 `InterventionPolicyEngine`

干预策略引擎。

职责：

- 把公平失衡与叙事候选映射为最小干预带
- 在 `none / impulse / opportunity / fact_reveal / environment_request` 中选择
- 控制强度与 cooldown

它只决定“该推什么”，不决定“引擎里怎么落地”。

### 6.10 `ExecutionFeasibilityLayer`

执行可行性层。

职责：

- 判断当前候选是否能在 `Godot / L1 / ESM / L3` 自然落地
- 选择执行路径
- 降级或拒绝不可解释路径

可选路径：

- `character_input_path`
- `environment_change_path`
- `visual_fact_path`
- `l3_highlight_path`
- `no_action`

### 6.11 `InterventionDispatcher`

干预分发器。

职责：

- 把 `InterventionDecision` 转成总线事件
- 分发给角色、`ESM`、视觉事实路径或 Godot 表现路径
- 保留 `causation_id` / `correlation_id`

禁止：

- 直接改角色状态
- 直接写环境成功结果
- 绕过事件总线私发不可审计消息

### 6.12 `CheckpointAuditService`

检查点与审计服务。

职责：

- 写入干预前 checkpoint
- 写入干预候选、决策、分发、结果
- 写入干预后 checkpoint
- 形成 replay 链

最低可回放链：

```text
World Events
-> FactCoreSnapshot
-> FairnessStateSnapshot
-> InterventionCandidate
-> InterventionDecision
-> Dispatch Event
-> Observed Effect
-> AuditRecord
```

若启用 `Phase 2+` 叙事投影，可在 `FairnessStateSnapshot` 和 `InterventionCandidate` 之间插入 `NarrativeStateSnapshot -> ProjectionRun -> EventChainCandidate`，但最小 replay 不依赖这些对象。

### 6.13 `NarrativeReadModelService`

只读叙事表面服务。

职责：

- 给工作台、QA、运营、大玩家控制台提供当前局势摘要
- 不作为世界真值
- 不暴露角色私有完整心智链

内容：

- 当前阶段
- 当前失衡
- 热点角色
- 热点会话
- 热点证据
- 活跃叙事义务
- 最近推演候选
- 最近干预结果

## 7. 单局持续推演循环

### 7.1 活动房间运行模式

`Phase 1` 活动房间采用公平裁判主循环：

```text
consume queued events
-> update fact core
-> update knowledge state
-> build fairness snapshot
-> generate intervention candidates
-> policy select
-> feasibility evaluate
-> dispatch / no_action
-> audit
-> refresh read model
```

叙事投影扩展循环属于 `Phase 2+` 或 `Phase 1` 可选 stub：

```text
build narrative state snapshot
-> run narrative projection
-> generate event chain candidates
-> rank by dramatic priority
-> feed optional candidate hints into policy
```

`Phase 1` 验收不得依赖 `NarrativeStateSnapshot`、`ProjectionRun`、`EventChainCandidate` 或 `DramaticPriorityModel` 的完整实现。若保留这些对象，只能以 nullable/stub/read-only 形式存在，且不得覆盖公平优先级、可执行性和审计可解释性。

### 7.2 时间粒度

建议分三档：

- 毫秒级：事实硬规则、危险兜底、低延迟约束拒绝
- 秒级：公平快照、普通候选、普通干预
- 分钟级：阶段推进、冲突升级、收束压力、结局组织

### 7.3 离线期

离线期不常驻运行司命。

恢复流程：

```text
player returns
-> load last checkpoint / read model / cooldown
-> collect offline key events
-> build catch-up narrative state
-> generate brief summary
-> resume active tick
```

禁止：

- 离线期间完整世界快进
- 完整居民生活模拟
- 长周期关系网自动演化
- 把补全摘要伪装成逐帧发生过的事实

```json
  "phase_marker": "escalation",

  "recent_decision_refs": [],
  "cooldown_state": {},
  "runtime_pressure": "normal"
}
```

### 8.2 `NarrativeStateSnapshot`

`Phase 2+` 对象。`Phase 1` 只允许作为可选 stub 或 read model 的派生摘要字段。

```json
{
  "snapshot_id": "nar_snap_001",
  "room_id": "room_01",
  "world_ts": 123456.78,
  "phase_marker": "escalation",
  "active_conflict_refs": [],

  "story_pressure": "medium",
  "convergence_pressure": "low",
  "derived_from_fairness_snapshot_ref": "fair_snap_001"
}
```

### 8.3 `ProjectionRun`

`Phase 2+` 对象。`Phase 1` 不把 projection run 作为验收阻塞项。

```json
{
  "projection_id": "proj_001",
  "room_id": "room_01",
  "basis_snapshot_ref": "nar_snap_001",
  "horizon_seconds": 180,
  "candidate_count": 3,
  "selected_chain_ref": "chain_001",
  "result_status": "candidate_generated"
}
```

### 8.4 `EventChainCandidate`

`Phase 2+` 对象。`Phase 1` 的 `InterventionCandidate` 必须能直接由 `FairnessStateSnapshot` 生成，不依赖事件链候选。

```json
{
  "chain_id": "chain_001",
  "projection_ref": "proj_001",
  "room_id": "room_01",
  "trigger_condition": "evidence_x is visible but under-discovered",
  "expected_effect": "open evidence access window",
  "candidate_band": "opportunity",
  "target_actor_ids": ["player_02"],
  "dramatic_value": 0.72,
  "fairness_delta": 0.31,
  "risk_score": 0.18,
  "execution_cost": 0.25,
  "trace_refs": []
}
```

## 9. 数据层建议

本文档不替代 [12-司命数据表与缓存键设计.md](12-司命数据表与缓存键设计.md)，但建议在其 6 张主表基础上增加叙事推演相关表：

以下表属于 `Phase 2+` 或 feature flag 后扩展，不进入 `Phase 1` 最小数据层验收：

1. `siming_narrative_state_snapshots`
2. `siming_projection_runs`
3. `siming_event_chain_candidates`
4. `siming_dramatic_priority_records`

缓存键建议：

- `paralls:siming:room:{room_id}:narrative:latest`
- `paralls:siming:room:{room_id}:projection:latest`
- `paralls:siming:room:{room_id}:chain:candidates`
- `paralls:siming:room:{room_id}:phase:state`

数据层扩展规则：

- 新增能力优先新增表或 JSON 子字段，不改旧字段语义。
- 长期对象保留 `schema_version`，读路径允许兼容旧版本。
- `room_id`、`sim_tick_ts/world_ts`、`correlation_id`、`causation_id` 不得从司命领域主查询路径移除。
- `world_ts` 不得被写回事件总线公共信封；需要发布到总线时必须放在司命 payload 或领域对象内。
- 新增 read model 字段不得反向污染世界事实表。

## 10. 通信边界

### 10.1 输入

司命后端可订阅：

- 原始 / 结构化世界事件
- `ESM` 结果事件
- 视觉事实事件
- 会话状态事件
- 知识状态事件
- 角色行为回写
- 系统阶段与时钟事件

### 10.2 输出

司命后端只允许输出：

- `impulse`
- `opportunity`
- `fact_reveal`
- `environment_request`
- `none`
- 工作台只读 read model
- audit / replay 数据

### 10.3 Godot 前端

Godot 前端只消费高层结果并做本地表现：

- UI 提示
- 镜头 / 高光
- 本地表现总线
- 角色输入材料展示
- 环境结果表现

Godot 不承载：

- 司命真值
- 高阶知识图谱真值
- replay / audit 真源
- 角色心智结论

## 11. 后端接口建议

### 11.1 WebSocket

`WS /rooms/{room_id}/stream`

用途：

- Godot 客户端上报结构化输入
- Godot 客户端订阅高层结果
- 工作台订阅 read model 更新

### 11.2 HTTP

`Phase 1` 最小接口：

- `POST /rooms/{room_id}/events`
- `POST /rooms/{room_id}/siming/tick`
- `GET /rooms/{room_id}/siming/read-model`
- `GET /rooms/{room_id}/siming/audits`
- `GET /rooms/{room_id}/siming/snapshots/{snapshot_id}`
- `GET /rooms/{room_id}/siming/decisions/{decision_id}`
- `GET /rooms/{room_id}/siming/replay-chain?correlation_id=...`

`Phase 2+` 或 feature flag 后接口：

- `GET /rooms/{room_id}/siming/projections/latest`
- `GET /rooms/{room_id}/siming/event-chains`

说明：

- `tick` 接口主要用于调试、测试和手动推进；生产环境由 orchestrator 周期触发。
- projections / event-chains 是工作台只读视图，不是世界事实接口，且不进入 `Phase 1` 最小验收。

接口扩展规则：

- 对外接口优先新增 endpoint 或新增可选字段，不改已有字段语义。
- WebSocket 事件继续使用事件总线公共信封，不引入平行私有信封。
- 新增司命事件类型必须明确是否 `replayable`、`reliable` 或 `realtime`。
- 新增前端能力只能消费 read model 或高层结果，不读取司命内部推理私有态。

## 12. 失败与降级

### 12.1 推演失败

若 `NarrativeProjectionCore` 失败：

- 保留 `FairnessStateSnapshot`
- 跳过叙事候选
- 允许 policy 输出保守 `none` 或低强度 `impulse`
- audit 标记 `projection_failed`

### 12.2 候选过多

按以下顺序截断：

1. `fairness_delta`
2. `dramatic_value`
3. `execution_cost`
4. `risk_score`
5. `audit_clarity`

### 12.3 可执行性失败

降级顺序：

```text
environment_change_path
-> visual_fact_path
-> character_input_path
-> no_action
```

### 12.4 高负载

高负载下优先保留：

- ingest
- fact core
- fairness snapshot
- decision
- audit

可降级：

- projection horizon
- event chain count
- dramatic priority 解释细度
- read model 次级字段

## 13. Phase 1 最小实现范围

必做：

1. `SimingOrchestrator` 活动房间 tick
2. `FairnessStateSnapshot`
3. 五个 auditor：`information`、`participation`、`conversation_access`、`suspicion`、`evidence`
4. `InterventionCandidate`
5. `InterventionDecision`
6. `Checkpoint / Audit / ReadModel`
7. Godot WebSocket 高层结果下发
8. 关键对象 `schema_version` 字段
9. dispatch / audit 幂等键
10. `environment_request -> ESM resolution -> world fact event` 闭环
11. `character_input_path -> character ack/result` 闭环
12. `visual_fact_path` 只引用已成立事实的可观察性放大请求

后补：

- `NarrativeStateSnapshot`
- `NarrativeObligationLedger`
- `EventChainCandidate`
- `DramaticPriorityModel`
- 离线回来关键事件补全与简报
- 能力注册 / feature flag 完整配置
- 插件式 auditor / projection strategy 注册接口
- 多步复杂事件链搜索
- 长时程剧情弧优化
- 自适应权重学习
- 跨局种子库
- 世界级持续运行说书人

这些后补能力必须优先通过扩展点接入，不应要求重写 `SimingOrchestrator` 主链。

## 14. 非目标

`Phase 1` 不做：

- 完整 PlotPilot 迁移
- 完整小说写作引擎
- 完整离线世界快进
- 跨局叙事种子进化
- 大规模世界持续推演
- 司命直接控制角色
- 司命直接写环境成功结果
- 为了短期 demo 把协议、schema、调度主链写成不可扩展的一次性结构

## 15. 一句话收束

司命后端框架的核心不是“调用一个大模型写剧情”，而是：

> 在活动单局内持续消费权威事件，维护事实、公平与叙事状态，沙盘推演可能的事件链，再用最小、可执行、可审计的方式推动角色、环境和信息流自然发生变化。
