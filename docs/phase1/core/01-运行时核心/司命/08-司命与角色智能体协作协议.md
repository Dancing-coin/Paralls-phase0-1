# 08-司命与角色智能体协作协议

## 1. 文档目标

本文档冻结司命与角色智能体之间的正式协作边界：

- 司命给角色什么
- 角色如何承接
- 哪些链路必须经过角色自己的 `L2/L3`
- 哪些对象允许进入 replay / audit / 工作台

它不重写：

- 角色智能体四层心智结构
- 事件总线公共信封
- `ESM` 物理结算
- `Godot` 本地具身表达细节

它只定义**司命与角色智能体之间的高层协作协议**。

## 2. 核心定义

司命是：

- `L2` 全局叙事裁判与催化者
- 拥有更广视野的运行时核心智能体

角色智能体是：

- 世界内角色的统一运行时本体
- 必须对输入做主观解释、信念更新、规划和执行决策

一句话：

> 司命只制造动机、窗口、压力和揭示条件；角色仍按自己的主观世界和人格结构决定是否接住这场戏。

## 3. 协作总原则

### 3.1 高层输入原则

司命给角色的只能是高层催化输入，不是低层动作命令。

### 3.2 主观承接原则

任何司命消息进入角色侧后，都必须先变成角色的输入材料，而不是直接变成角色结论。

### 3.3 自主性保护原则

司命不能跳过角色自己的：

- `L2` 理解
- `L3` 规划
- 三重过滤器

### 3.4 可追溯原则

任何一次司命到角色的影响，都必须能被回放成“消息进入角色后如何改变了角色候选行为空间”。

## 4. 司命允许发给角色的对象

`Phase 1` 允许正式发给角色的高层对象固定为：

1. `impulse`
2. `opportunity`
3. `fact_reveal`
4. `public_event_hint`（预留）
5. `pressure_shift_hint`（预留）

### 4.1 `impulse`

作用：

- 施加主观推动
- 提高某类行动或表达的被考虑概率

它不是：

- 已决定的行为
- 必须执行的指令

### 4.2 `opportunity`

作用：

- 告诉角色某个行动窗口已打开
- 让角色有资格把某行为列入候选集

它不是：

- 行动已成功
- 角色必然注意到并接受

### 4.3 `fact_reveal`

作用：

- 让角色在当前时刻合法接触到某条高价值信息
- 缩短信息匮乏状态

它不是：

- 直接替角色下最终结论
- 直接写“你现在相信 X”

## 5. 角色如何承接司命输入

角色对司命输入的承接顺序必须固定为：

```text
SimingHighLevelMessage
-> L2 Interpretation
-> Belief / Affect Delta
-> L3 Candidate Shift
-> Three Filters
-> Intent Selected / Rejected
-> L4 Expression / Action Plan
-> L1 / ESM Resolution
```

### 5.1 `L2` 承接

`L2` 负责回答：

- 这条消息对我意味着什么
- 它和我当前信念是否冲突
- 它会提高我的怀疑、压力、冲动还是行动欲

### 5.2 `L3` 承接

`L3` 负责回答：

- 我现在有哪些候选行动
- 是否值得顺着这条司命输入做事
- 是否会违反人设、逻辑或得失判断

### 5.3 `L4` 承接

只有当角色已经形成通过过滤器的意图后，才允许进入：

- 对话
- 移动
- 互动
- 表情与姿态表达

## 6. 玩家角色是否遵循同一协议

是。

玩家角色也收同一类高层消息，但在玩家接管模式下，它们主要转化为：

- 冲动提示
- 风险提示
- 候选建议
- 角色主观倾向补全

玩家自己决定是否采用。

### 6.1 玩家角色的特别边界

司命不能把消息写成：

- 强制 UI 操作
- 强制视角切换
- 强制代做关键决定

玩家接管主动决策，系统只补全角色连续性与主观张力。

## 7. 司命不能对角色做什么

司命不能直接对角色做以下事情：

1. 下发低层动作命令
2. 直接设定角色最终信念
3. 直接宣布角色已经决定做某事
4. 直接写角色情绪真值
5. 直接设置角色面部 / 骨骼姿态结果
6. 绕过 `ESM` / 世界约束宣告行动成功

不允许的典型对象包括：

- `go_to_position`
- `kill_target_now`
- `believe_X_now`
- `choose_Y_now`
- `set_expression_state`
- `set_skeleton_pose`

## 8. 角色侧需要暴露给司命的回流对象

为了让司命理解“干预是否生效”，角色侧必须回流最小结构化结果：

1. `IntentCommitted`
2. `SpeechActPublished`
3. `ActionRequestIssued`
4. `SocialSignalPublished`
5. `InformationShareIssued`
6. `AutonomyModeChanged`

司命不需要角色的完整 chain-of-thought，只需要：

- 该消息有没有改变候选空间
- 最终有没有形成行为
- 产生了什么外部可见后果

## 9. 最小字段建议

### 9.1 司命下发对象

建议最小字段：

- `message_id`
- `message_type`
- `room_id`
- `scene_id`
- `target_actor_ids`
- `source_siming_module`
- `world_ts`
- `reason_tag`
- `strength`
- `ttl`
- `payload`

### 9.2 角色承接回执

建议最小字段：

- `ack_id`
- `message_ref`
- `target_actor_id`
- `interpreted_as`
- `candidate_shift_level`
- `filter_result`
- `intent_result`
- `observed_external_effect`

## 10. replay / audit 链要求

最小可回放链必须支持：

```text
SimingHighLevelMessage
-> CharacterInterpretationSummary
-> BeliefDelta
-> CandidateActionShift
-> FilterDecision
-> IntentCommitted / Rejected
-> ExternalObservedEffect
```

最少要回答：

1. 司命给了什么
2. 角色怎么理解
3. 角色为什么没接住或接住
4. 结果怎样影响了局势

## 11. 与工作台的关系

司命工作台与角色工作台在这条链上应能互相跳转：

- 从司命侧看：本次干预影响了哪几个角色
- 从角色侧看：本次行为受到了哪条司命消息影响

必须支持的联跳对象：

- `message_id`
- `target_actor_id`
- `intent_ref`
- `correlation_id`
- `causation_id`

## 12. `Phase 1` 最小实现要求

必做：

1. 司命只发高层消息
2. 角色先经 `L2`
3. 再经 `L3`
4. 三重过滤器必须参与
5. 角色结构化回写必须可观察
6. 整条影响链必须可 replay / audit

后补：

- 更细的情绪增量字段
- 更复杂的多消息叠加效应
- 更长时程的行为趋势反馈

## 13. 一句话收束

司命与角色智能体之间的正确关系，不是“导演让演员照做”，而是“导演只制造动机、窗口、压力和揭示条件；角色仍然经过自己的理解、过滤和规划，决定要不要把这场戏真正演出来”。
