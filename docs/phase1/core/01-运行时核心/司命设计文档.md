## 0. 架构视图（系统 / 子系统 / 孙系统）

司命是 `L2` 的全局叙事智能体，运行在“世界原始事件输入 -> 叙事评估 -> 高层催化回写”的闭环中。

系统边界：

- 上游：事件总线、`ESM`、房间状态、知识状态

- 禁止越权：不直接下发低层动作命令，不直接执行物理结算

### 0.2 系统分解

#### 0.2.1 子系统：事实核心

职责：维护事实锁定链、矛盾比对、证据一致性检查。
孙系统：事实索引器、矛盾检测器、锁定阶段协调器。

#### 0.2.2 子系统：天平系统

职责：评估局势倾斜、节奏风险与可玩性风险。
孙系统：势能评估器、偏移监测器、回稳建议器。

#### 0.2.3 子系统：冲突与案件生成器

职责：在事实边界内生成冲突机会与次生事件。
孙系统：机会枚举器、触发条件判定器、后果链预估器。

#### 0.2.4 子系统：高阶知识图谱引擎

职责：维护“谁知道什么、谁知道别人知道什么”的层级关系。
孙系统：知识态更新器、高阶关系推断器、传播范围约束器。

#### 0.2.5 子系统：干预执行器

职责：把司命决策编码为高层催化消息并通过总线回写。
孙系统：消息组装器、通道选择器、回写审计器。

### 0.3 核心接口约束

- 输入：精确世界事件、环境状态事件、知识状态变化、房间阶段状态
- 输出：`impulse` / `fact_reveal` / `opportunity`
- 非职责：角色动作控制、物理结果改写、证据定性替代

## 2. 核心定位与系统边界

司命是《开本》`L2` 智能体交互层中唯一拥有全局叙事视角的运行时核心智能体。

它的职责不是“替世界演完故事”，而是：

- 守护事实
- 管理知识状态
- 评估局势失衡
- 催化冲突与机会
- 控制叙事节奏
- 保护游戏可玩性与公平性

### 2.1 系统身份

- 所属层级：`L2`
- 系统角色：运行时核心智能体
- 权限特征：全局可见、跨角色、跨系统、叙事优先
- 上位约束：事实锁定、世界规则、四原则、Phase 范围

### 2.2 不是什麽

司命不是：

- 中央控制脚本
- 角色动作执行器
- `ESM` 的上位物理引擎
- 事件总线本身
- 可以在 `T2` 后随意改写真相的“全能作者”


### 2.3 ESM 的职责

`ESM` 是 `L1` 独立环境状态管理器，负责：

- 毫秒级确定性物理规则
- 物体/材质/天气/火焰/血迹等环境状态机
- 环境交互结果执行
- 可复现的底层世界状态演化

### 2.4 司命的职责

司命负责：

- 解释这些环境变化的叙事意义
- 判断它们是否触发新矛盾、新机会、新危机
- 决定是否据此做叙事催化

### 2.5 明确边界

当前冻结口径：

- `ESM` 负责“能不能发生、具体怎么发生”
- 司命负责“这意味着什么、是否值得推动、该如何包装成戏”

换句话说：

- `ESM` 计算门是否被火烧坏
- 司命判断门被烧坏后，会不会制造封锁、恐慌、证据破坏或新的对峙机会

### 2.6 司命不能替代 ESM

司命不能：

- 直接生成违反物理状态机的结果
- 不经 `ESM` 直接令环境跳变
- 把物证、火势、破损、尸体状态写成纯叙事文本结果

它只能：

- 提出高层催化请求
- 等待 `ESM` 在规则允许范围内执行
- 接收回报并继续组织叙事


### 2.7 锁定规则

- `T0`：锁世界观、角色基础设定、场景、规则
- `T1`：锁案件框架
- `T2`：锁本局完整事实
- `T3`：事实不再变化，但演绎、理解、误导、揭示、冲突与结局继续涌现

### 2.8 司命能改什么

在 `T2` 之后，司命仍能改变：

- 信息揭示顺序
- 角色相遇时机
- 事件升级节奏
- 机会窗口开闭
- 公众关注焦点
- 结局演绎方向

### 2.9 司命不能改什么

在 `T2` 之后，司命不能改：

- 真凶是谁
- 谁做过什么
- 已锁定的时间线事实
- 已成立的物理后果

因此，“司命实时编剧”成立的前提，是它编排的是叙事路径，而不是重写真相。


### 2.10 旧倾向

`340` 曾出现“为了让小世界看起来活着，司命持续后台运行”的倾向性表述。

### 2.11 当前修正

`341` 明确修正为：

- 玩家下线时，司命也下线
- 不要求 Phase 1 持续常驻模拟
- 玩家回到小世界时，再由司命快速补齐离线期间关键事件

### 2.12 Phase 1 当前采用

Phase 1 采用：

- 登录时关键事件补全
- 简报式叙事输出
- 轻量“世界还在继续”的错觉维护

不采用：

- 持续后台推演
- 完整居民生活模拟
- 全量关系网离线快进

这条边界必须与小世界文档保持一致。

## 3. 五大核心子系统

### 3.1 事实核心

职责：

- 管理 `T0-T3` 锁定边界
- 存储本局不可变事实与已确认事实
- 检查时间线和说法矛盾
- 拒绝会泄露未知信息的输出

边界：

- 它守护真相，不负责把真相讲得好看
- 它能否决催化，不替代催化器生成戏剧方案

### 3.2 天平系统

职责：

- 评估局势偏斜
- 发现僵局、滚雪球、边缘化玩家
- 判断是否需要叙事纠偏

主要关注：

- 线索是否过度集中
- 节奏是否停滞
- 某阵营是否近乎无解
- 某玩家是否长期缺乏有效参与窗口

### 3.3 冲突与案件生成器

职责：

- 识别角色目标冲突
- 识别秘密暴露、独处、能力匹配等机会窗口
- 生成可供锁定或催化的次生事件候选

基本判断链：

1. 动机是否成立
2. 知识条件是否成立
3. 物理条件是否成立
4. 人设是否允许
5. 可玩性是否允许
6. 叙事价值是否成立

### 3.4 高阶知识图谱引擎

职责：

- 维护“谁知道什么”
- 维护“谁知道别人知道什么”
- 记录公开、共享、偷听、怀疑、误判等知识状态
- 为司命和角色层的信息博弈提供底层判断依据

在会话机制中，高阶知识图谱还负责：

- 确认“谁知道某人已进入当前对话面”
- 确认“某人是否知道别人知道自己已在场”
- 区分“偷听者”与“沉默成员”
- 结合排斥信号判定成员资格变化

工程边界：

- 空间接入、发声、门窗、遮挡、站位变化等底层事实必须来自 `L1/ESM`
- 高阶知识图谱只基于这些事实推断会话社会语义，不反向虚构空间接入事实

Phase 1 最小要求：

- 公共知识
- 共有知识
- 必要的一阶、二阶、有限三阶知识判断
- 会话相关的一阶、二阶互相知晓判断

v0.1 当前只收敛“会话与知识可见性”最小模型，不直接展开完整世界级知识图谱。当前至少要能稳定表示：

- 哪些角色进入了同一会话面
- 哪些角色只是偷听者，哪些已成为候选成员、沉默成员、主动成员或被排斥者
- 某角色从什么时间点开始真正接入这场会话
- 某条信息是通过公开对话、局部对话、私密对话、偷听、显式分享还是推断获得

#### 3.4.1 v0.1 最小对象

当前最小对象集建议至少包括：

- `Actor`：会产生感知、知识和会话行为的主体
- `Conversation`：一段运行时会话实例，不等于纯文本
- `InformationItem`：可被传播、共享、偷听或误解的信息单元
- `PerceptionAccess`：某角色对会话或信息的接入记录
- `MembershipState`：角色与会话之间的成员关系判定结果
- `KnowledgeClaim`：某角色当前对某条信息持有的知识状态
- `AwarenessRelation`：谁知道谁在场、谁知道别人知道自己在场

#### 3.4.2 v0.1 最小输出

当前最小输出集建议至少包括：

- `MembershipResolution`：成员资格结果
- `AccessResolution`：接入质量与接入起点
- `KnowledgeResolution`：知识状态与知识来源
- `AwarenessResolution`：互相知晓确认结果
- `PrivacyRiskResolution`：暴露风险与隐私破坏风险
- `ConversationBoundaryChange`：会话开放度变化

最低闭环中，`MembershipResolution`、`AccessResolution`、`KnowledgeResolution` 三类输出必须先成立，因为它们分别回答：

- 我是不是成员
- 我从什么时候开始真正接入
- 我现在到底知道了什么

事件级边界：

- 这三类输出都是司命高阶知识图谱对外回写的确认事件，不是 `L1` 原始事实
- `MembershipResolution` 只回答会话中的社会身份
- `AccessResolution` 只回答接入质量与接入时间点
- `KnowledgeResolution` 只回答某条信息当前的知识状态及其来源
- `AwarenessResolution` 负责表达会话中的知晓关系，必要时应支持二阶知晓目标
- `PrivacyRiskResolution` 只表达图谱侧风险判断，不等于角色本地主观 `privacy_pressure`
- `ConversationBoundaryChange` 只表达传播边界变化，不等于成员资格变化
- 六类输出不得折叠成一个“确认包”

#### 3.4.3 v0.1 最小判断流程

当前更适合写成依赖关系，而不是唯一固定流水线：

1. `L1/ESM` 上抛原始空间与声学事实
2. 事件总线封装公共信封并分发
3. 可感知信息编译层生成候选会话上下文
4. 高阶知识图谱先做接入判定
5. 互相知晓判定依赖接入判定
6. 成员资格判定依赖接入与互相知晓
7. 知识状态判定依赖接入结果，并通常受成员态与共享路径影响

最低硬约束：

- 不得先判成员资格，再判是否接入
- 不得先给知识状态，再判是否真正听到
- 暴露风险与会话边界变化可以伴随事实变化反复重算，但都不得伪装成原始事实

边界强调：

- 高阶知识图谱输出的是推理结果，不是原始事实
- 角色侧只接收自身可知版本的结果，不读取全局图谱真值
- 本稿当前只冻结会话相关最小模型，不冻结完整图数据库结构、跨局继承或持续世界级知识传播

### 3.5 干预执行器

职责：

- 把“应干预”的判断变成实际可执行动作
- 选择最小足够干预
- 在发出前通过四原则审查

干预阶梯：

1. `Lv1` 冲动注入
2. `Lv2` 环境催化
3. `Lv3` NPC / 事实唤醒
4. `Lv4` 公共事件 / 节奏打断

原则：

- 能用弱干预就不用强干预
- 能用局部干预就不用全局打断
- 能用合理世界事件包装，就不用裸露系统提示

## 4. 干预原则与可执行约束

### 4.1 产品隐喻

在产品叙述里，司命可以被描述为：

- 活着的实时编剧
- 兼具编剧与导演气质的世界意识
- 负责让戏“发生起来”的看不见的手

这些表述来自 `107-113`、`130-131`，可以保留为愿景和产品语汇。

### 4.2 可执行约束

但在系统实现里，司命必须被明确限制为：

- 不能改写 `T2` 后锁定事实
- 不能绕过角色人格与三重过滤器
- 不能直接下发低层动作指令
- 不能代替 `ESM` 生成违反物理规则的结果
- 不能为了戏剧性破坏公平性与可推理性

因此，“实时编剧”应理解为：

- 实时安排揭示顺序
- 实时创造冲突机会
- 实时调节叙事节奏
- 实时组织次生事件

而不是：

- 实时重写真相
- 实时附体控制角色
- 实时编造脱离规则的结果


司命所有主动输出都必须满足以下四原则。

### 4.3 间接性

允许：

- 推送冲动
- 创造独处窗口
- 调整环境条件
- 合理触发公共事件

不允许：

- 强制角色执行行动
- 替玩家完成选择
- 直接指定“你现在必须去做 X”

### 4.4 不可见性

允许：

- 让干预伪装成自然发生的世界变化
- 让催化以角色应知事实或场景变化表现出来

不允许：

- 无解释的系统跳变
- 破坏沉浸的裸露操盘痕迹

### 4.5 逻辑自洽性

允许：

- 基于人设、知识和物理条件催化事件

不允许：

- 让人物突然做出严重 `OOC` 行为
- 让违背物理规则的结果直接发生

### 4.6 公平性

允许：

- 在过度倾斜时做平衡修正
- 给不同阵营补回合理机会窗口

不允许：

- 为了高潮删证据
- 为了戏剧性硬保某一方


暗杀催化是司命最容易越界的区域，必须单独冻结。

### 4.7 当前采用规则

- 除硬背景任务外，司命不直接下达“去杀谁”的命令
- 只要动机与条件成立、且不破坏可玩性，司命可以主动催化机会
- 真正的执行仍由玩家选择或角色智能体自主决策完成

### 4.8 典型判断前提

至少检查：

- 动机是否成立
- 独处窗口是否成立
- 物理可行性是否成立
- 角色能力是否匹配
- 人设是否允许
- 事后是否仍然可玩

### 4.9 司命可以做什么

- 调整独处与目击窗口
- 延长或压缩时间差
- 推送风险与机会信号
- 组织事后证据与后果回写

### 4.10 司命不能做什么

- 直接触发“杀人已完成”
- 为了戏剧性清空后果
- 让不符合人格的人无条件越界

一句话收束：

司命可以让“机会变得可发生”，但不能让“行动跳过决策地发生”。

## 5. 接口契约

这是司命文档必须压实的当前重点。

### 5.1 司命接收什么

司命接收的是更广泛的原始/结构化世界事件与跨系统状态通知，例如：

- 角色动作意图、执行、完成事件
- `ESM` 状态变化
- 物体状态更新
- 感知传播结果
- 信息共享动作
- 时间推进与阶段切换
- 公共事件结果

这些事件默认应带有足够的空间与感官字段，例如：

- `actor_position`
- `source_item` / `target_item`
- `contact_point` / `impact_point`
- `environment_conditions`
- `perception_ranges`

这意味着：

- 司命的订阅面比角色更宽
- 司命可以看到全局事实链路
- 司命不是靠角色视角拼图来工作

### 5.2 角色接收什么

角色智能体不直接消费全局原始世界事件流。

角色收到的是经过 Per-Character 感知过滤后的“我此刻感知到了什么”，例如：

- 我看见某人正在靠近
- 我听见楼上传来坠物声
- 我闻到焦糊味
- 我注意到桌上多了一把不该出现的刀

因此，司命与角色并不是订阅同一层消息。

### 5.3 司命回写什么

司命只能向角色发送高层消息：

- `impulse`
- `fact_reveal`
- `opportunity`
- 少量状态询问或催化信号

这些消息的本质是：

- 倾向
- 唤醒
- 机会
- 提醒

而不是动作控制。

### 5.4 司命不能回写什么

司命不能直接下发：

- “去到坐标 X”
- “现在杀死 Y”
- “立刻打开门并拿走物品 Z”

这类低层动作命令。

所有来自司命的高层消息，仍必须经过角色自身：

- `L2` 理解层
- `L3` 规划层
- 三重过滤器

之后才能变成行为。

## 6. 高并发与编排治理

### 6.1 运行形态

司命采用 `Harness + LLM + Rule Engine` 的复合智能体形态。

- `Harness`：任务编排、优先级路由、超时与降级、结果分发
- `LLM`：模糊叙事推理、动机判断、机会生成、结局叙述、复杂局势解释
- `Rule Engine`：事实锁定、约束校验、阈值判断、原则过滤、安全兜底

### 6.2 决策分流

- 硬边界、硬时延、硬规则：优先走规则引擎
- 模糊叙事判断、冲突价值评估、催化方案生成：走 `LLM`
- 所有 `LLM` 输出在执行前都必须经过规则层回审

### 6.3 高并发分级治理

司命在高负荷状态下必须按分级通道处理任务：

- `P0`：硬实时抢占（如致命风险与关键机会窗口）
- `P1`：规则并发通道（事实记录、知识更新、状态同步等）
- `P2`：推理排队通道（复杂叙事判断与定制化催化）
- `P3`：可降级 / 可丢弃通道（低价值氛围增强与延后任务）

关键约束：

- `L3` 调度任务也必须进入同一分级治理模型
- 队列积压时优先保障 `P0/P1`，`P3` 允许降级或丢弃

### 6.4 与 L3 的调度边界

当前采用：

- 司命负责“是否触发、何时触发、是否通过叙事与信息安全检验”
- `L3` 负责“如何执行、选哪种生成策略、如何降级”

这意味着司命调度 `L3`，但不越权替代 `L3` 的技术执行。

### 6.5 子智能体与模型路由扩展方向

在不破坏当前边界的前提下，司命可以扩展为：

- 司命总导演 + 子智能体分工执行
- 规则程序 / 本地小模型 / 高能力模型的任务分层路由

适用原则：

- 高频低复杂任务优先下沉到规则 / 小模型通道
- 关键叙事决策保留在高能力推理通道
- 不能用扩展方向覆盖既有事实锁定、四原则和消息边界

### 6.6 与总体架构的关系

- 上游输入：原始/结构化世界事件、角色行为回报、环境状态变化、知识传播结果、系统时钟与阶段信号
- 横向协作：角色智能体、事件总线、可感知信息编译层、知识图谱、模型路由
- 下游输出：`impulse`、`fact_reveal`、`opportunity`、公共事件触发建议、环境催化请求、结局判定与叙事结果

上游输入的最低要求不是“谁做了什么”的摘要，而是：

- 发起者、目标、媒介、动作类型
- 发起位置、接触点、落点、作用方向
- 环境条件与结算结果
- 不同感官的传播范围与可感知强度

没有这层输入精度，司命的事实核心、知识传播判断、叙事催化与公平性控制都会退化成脆弱猜测。


## 7. 运行时主循环

结合 `276`、`303`、`352-353` 的当前口径，司命主循环可抽象为：

```text
L1 / ESM / 角色 / 交互系统产生原始或结构化事件
  -> 事件应至少包含 actor / target / source point / contact point / perception ranges
  -> 事件总线分发给司命
  -> 事实核心校验锁定边界与硬冲突
  -> 知识图谱更新“谁知道什么”
  -> 天平系统评估当前局势
  -> 冲突与案件生成器产出候选机会或次生事件
  -> 干预执行器选择最小足够干预
  -> 向角色或环境发出高层催化
  -> 新结果再回写事实、知识与后果链
```

时间粒度：

- 毫秒级：硬规则过滤、事实检查、低延迟危险兜底
- 秒级：局势更新、普通催化判断、知识传播修正
- 分钟级：节奏推进、冲突升级、阶段收束、结局组织

## 8. Phase 1 范围与延后项

### 8.1 Phase 1

当前以 `267`、`398-400` 为准：

- 司命是受边界约束的完整单局导演
- 覆盖事实核心、知识管理、天平评估、基础冲突催化、暗杀机会催化、结局收束

### 8.3 Phase 3

- 持续运行世界
- 大规模势力与群体叙事

### A.2 冻结结论

- 司命的原型不是“中央导演程序”，而是与角色智能体平行的运行时核心智能体；“催化、修剪、守护”比“控制”更早确立且必须延续
- 司命是《开本》的运行时核心智能体，不是中央控制脚本
- 司命是全局叙事催化者、修剪者、守护者，不是角色行为控制器
- “活着的实时编剧 / 导演”是产品隐喻，不等于司命拥有无限改写权
- 司命的上游输入不是模糊剧情摘要，而是精确世界事件、环境状态变化与跨系统通知；事件至少要包含空间作用链和多感官传播范围
- 司命接收比角色更广的原始/结构化世界事件，但回写给角色的只能是高层消息
- 司命不替代 `ESM` 做底层物理模拟，不替代事件总线做消息基础设施
- `T2` 之后本局事实锁定，司命只能推动叙事路径、冲突和揭示顺序，不能重写既定真相
- Phase 1 的司命采用“受严格边界约束的完整单局导演”口径，不采用 `266` 中“仅被动守护者”的旧分拆
- 小世界离线阶段不要求司命持续常驻运行；Phase 1 采用登录时关键事件补全，而不采用完整后台永续推演
- 司命要把 `L3` 视觉增强纳入统一调度：司命负责触发与检验，`L3` 负责策略与执行
- 司命高并发场景必须采用分级通道治理；`L3` 调度负载不能被遗漏
- 子智能体分工与模型路由是高并发优化方向，但不替代既有分级与熔断边界
- 云地部署策略不改变司命消息边界：无论本地或云端执行，司命仍只回写高层催化消息

### A.3 当前统一口径

后续所有文档提到司命时，应统一采用以下口径：

- 司命是运行时核心智能体，不是中央控制器
- 司命是催化者、修剪者、守护者，不是替玩家写结论的脚本
- 司命的“实时编剧”能力指向叙事组织，不指向真相重写
- 司命接收更广的原始/结构化事件，角色接收的是过滤后的专属感知事件
- 司命回写给角色的只能是高层消息，不能直接发动作指令
- 司命不替代 `ESM` 做环境物理演化
- Phase 1 的司命是完整单局导演，而不是纯被动守护者
- 小世界离线期采用登录补全，不采用司命持续后台常驻

### C.2 与 L3 协作的未冲突口径

### C.3 子智能体方向的当前定位

- 负载与平衡子智能体
- `L3` 调度协同子智能体

- Phase 1 保留轻量实现或接口占位
