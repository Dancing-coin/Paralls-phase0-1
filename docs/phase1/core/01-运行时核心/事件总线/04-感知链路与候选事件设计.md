## 1. 文档定位

本文件负责冻结感知主链：

`原始世界事实 -> 候选感知事件 -> 角色感知事件`

并说明：

- 候选感知事件处在什么位置
- `Per-Character` 过滤器到底过滤什么
- 会话接入、偷听与私密边界如何落入这条链

它不负责：

- 角色内部记忆与理解细节
- 司命高阶知识图谱内部结构
- 视觉事实系统内部采样与模板规则

## 2. 三层对象

### 2.1 原始 / 结构化世界事件

表达世界中实际发生了什么。

至少包括：

- 谁在什么位置
- 用什么对什么做了什么
- 接触点、落点、命中点
- 造成了什么物理状态变化
- 哪些感官在理论上可以感知到

它的消费者至少包括：

- `ESM`
- 司命事实核心
- 物品流转追踪器
- 痕迹相关系统
- replay / audit

### 2.2 候选感知事件

候选感知事件是编译层和角色私有过滤器之间的中间对象。

它负责承接：

- 原始世界事实
- 视觉事实
- 听觉事实
- 空间关系事实

它仍不是角色最终正式感知结果。

### 2.3 角色感知事件

角色感知事件表达：

> 这个角色此刻看到了 / 听到了 / 闻到了 / 感觉到了什么。

它是候选感知事件经过角色私有裁剪后的结果，而不是原始世界事件的原样转发。

## 3. 主链定义

当前固定主链为：

`L1/ESM 上抛原始事实 -> 可感知信息编译层生成候选感知事件 -> Per-Character 感知过滤器裁剪 -> 角色感知事件 -> 角色 L1 感知层`

这条链必须成立，因为：

- 没有候选层，就无法在“世界事实”和“角色私有版本”之间插入工程化转换
- 没有私有过滤层，角色就会默认看到同一份世界
- 没有这条链，司命与角色之间的信息不对称无法稳定成立

## 4. Per-Character 过滤器的职责

每个角色都有独立的感知过滤器实例。

它不做业务推理，只做一件事：

把候选感知事件裁剪成“这个角色此刻能感知到什么”。

它至少考虑：

- 感官启用状态
- 距离
- 遮挡
- 当前朝向
- 环境噪音
- 当前身体与心智状态
- 注意力修正

## 5. 多感官候选事件

当前候选感知层至少覆盖：

- 视觉
- 听觉
- 嗅觉
- 热感
- 触觉

其中：

- 听觉候选事件承接空间音频输出的事实语义
- 视觉候选事件承接视觉事实系统输出的视觉语义事实

## 6. 会话机制如何落入感知链

会话机制中，候选感知层至少需要承接：

- 接近 / 停留 / 退开
- 进入 / 离开 `scene`
- 进入 / 离开 `zone`
- 耳语 / 正常 / 喊叫等声学模式
- 私密边界变化
- 新监听者接入可能性

但必须强调：

- 候选感知层不直接判定成员资格
- 偷听成功率不是候选层直接下结论
- 互相知晓不是候选层直接下结论

它只负责把“值得被角色感知系统继续判断的候选接入语义”送给私有过滤器和后续图谱链。

## 7. 视觉事实在感知链中的位置

视觉事实系统不属于候选感知层本体，但它的输出会进入候选感知层。

正确位置是：

- Godot 本地先完成：`Raw Pose State -> Canonical Pose Projection -> Temporal Sampler -> Delta / Change Detector -> Semantic Feature Builder -> Semantic Resolver -> Visual Fact Emitter`
- 业务总线接收 `Visual Fact Emitter` 产出的结构化视觉事实
- 可感知信息编译层再把这些视觉事实编译为候选视觉感知事件

因此：

- 原始骨骼 / 表情高频流不进入候选感知层
- 候选感知层消费的是“视觉事实语义输出”

## 8. 典型结果

最终角色收到的不是：

- 全局事实流
- 骨骼高频流
- 高阶知识图谱真值

而是：

- 我看见了什么
- 我听见了什么
- 我闻到了什么
- 我感到什么异常

## 9. 一句话收束

感知链路的正确主口径不是“把世界直接塞给角色”，而是：

> 先用 `L1/ESM` 和视觉/听觉事实系统产出可工程化的候选事实，再由 `Per-Character` 过滤器把它们裁剪成角色私有世界版本。
