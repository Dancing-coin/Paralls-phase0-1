## 1. 文档定位

本文件只回答一件事：

> 视觉事实系统已经独立成文档簇后，业务总线到底接什么、不接什么，以及它在总线中的位置是什么。

本文件不负责：

- 重写视觉事实系统总纲
- 重写首批 12 个高价值视觉事实
- 重写 `M1-M2` 开发顺序
- 重写视觉特征模板与阈值

这些内容以下游视觉事实系统文档簇为准。

## 2. 固定位置

视觉事实系统当前固定位置如下：

- 本体归属：`L1`
- 服务对象：`L2`、司命、证据链、replay / audit
- 一级源域：
  - `character`
  - `object`
  - `environment`
  - `spatial_relation`
- 派生层：
  - `evidence_projection`

因此它不是：

- 业务事件总线内部一个零散 emitter
- 角色智能体的私有子系统
- 司命内部的附属推理器

## 3. 与双总线的关系

### 3.1 和后端权威叙事/事实总线的关系

业务总线接收的是：

- `Visual Fact Emitter` 产出的结构化视觉事实
- 基于视觉事实投影出的 `evidence_projection`

业务总线不接收的是：

- 原始骨骼 `(x,y,z)` 高频流
- 全 `AU` 高频流
- 本地姿态缓存
- 本地 `AnimationTree` 中间态
- 本地 `SkeletonModifier3D` 精修中间态

### 3.2 和 Godot 本地表现总线的关系

Godot 本地表现总线负责：

- 本地高频姿态更新
- `AnimationTree` 主轨
- `SkeletonModifier3D` 精修轨
- 本地安全 deferred 应用

视觉事实系统与本地表现总线并行协作，但不等于它：

- 本地表现总线负责“怎么表现”
- 视觉事实系统负责“从本地高频状态中抽取什么语义事实可以上业务总线”

## 4. 固定主链

当前必须采用以下主链：

`Raw Pose State -> Canonical Pose Projection -> Temporal Sampler -> Delta / Change Detector -> Semantic Feature Builder -> Semantic Resolver -> Visual Fact Emitter -> 后端权威叙事/事实总线`

边界强调：

- 原始姿态流止步于 Godot 本地
- `Visual Fact Emitter` 是跨边界出口
- 业务总线只承接语义视觉事实，不承接姿态高频流

## 6. 接入业务总线后的用途

视觉事实进入后端权威叙事/事实总线后，至少服务于：

- 可感知信息编译层
- 司命高阶知识图谱与事实核心
- 证据链与 `evidence_projection`
- replay / audit

它们不直接等于：

- 角色私有感知事件
- 角色知识状态
- 司命高层消息

这些都需要下游进一步加工。

## 7. 一句话收束

视觉事实系统接总线的正确口径不是“把骨骼和表情直接广播出去”，而是：

> 在 Godot 本地完成高频采样、姿态规范化和语义抽取，再由 `Visual Fact Emitter` 把结构化视觉事实送入后端权威叙事/事实总线。
