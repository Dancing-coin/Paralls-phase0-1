## 1. 文档定位

本文件负责冻结《开本》事件总线体系的统一定义和主边界。

它负责：

- 给出事件总线的双总线总览
- 冻结 `L1 / L2 / ESM / 司命 / 角色智能体` 的主消息边界
- 给出主消息分层
- 冻结 `Phase 1` 的最小实现边界

它不负责：

- Godot 本地表现总线的线程 / 安全执行细节
- 视觉事实系统内部特征与模板
- 会话确认事件字段级 schema
- replay / audit 细节

这些内容由下游专项页承担。

## 2. 统一定义

事件总线不是一个单一中间件名字，而是《开本》跨层消息体系的统一称呼。

当前固定采用：

- 后端权威叙事/事实总线
- Godot 本地表现总线
- 一条从 `L1` 原始事实到 `L2` 候选感知与角色私有感知的主感知链

一句话：

> 后端权威叙事/事实总线负责“世界里什么成立”，Godot 本地表现总线负责“本地如何安全而高频地把它表现出来”。

## 3. 双总线总览

### 3.1 后端权威叙事/事实总线

负责：

- 原始 / 结构化世界事实
- 候选感知事件
- 角色感知事件
- 司命高层消息
- `ESM` 结果
- replay / audit
- 角色行为回写

不负责：

- 角色认知推理
- 证据意义判断
- Godot 本地骨骼与动画树直接驱动

### 3.2 Godot 本地表现总线

负责：

- 角色副本更新
- 表达计划 `revision`
- `AnimationTree` 参数更新
- `SkeletonModifier3D` 精修触发
- UI 提示
- 本地安全 deferred 执行

不负责：

- 世界真值判断
- replay / audit 真源
- 替代后端权威叙事/事实总线

### 3.3 两层总线的固定关系

- 后端总线输出权威事实与确认结果
- Godot 本地表现总线消费这些高层结果并安全落到本地表现层
- 两层总线不是一个东西，也不能混写成同一种通道或同一种消息面

## 4. 上下游系统边界

### 4.1 与 L1 的边界

`L1` 的正确身份是：

- 本地高频具身执行器
- 玩家输入终端
- 原始世界事实生产层

它不是：

- 角色认知宿主
- 世界真值解释层

### 4.2 与司命的边界

- 司命订阅更广的原始/结构化世界事件
- 司命只回写高层消息与会话确认结果
- 司命不能借事件总线直接低层控角

### 4.3 与角色智能体的边界

- 角色默认不直接消费全局原始事实流
- 角色正式消费的是经过编译和 `Per-Character` 过滤后的角色私有感知事件
- 角色回写的是对世界有意义且可重放的结构化行为结果

### 4.4 与 ESM 的边界

- `ESM` 负责环境和具身物理事实是否成立
- 事件总线负责把这些事实和结果传给司命、角色、证据链与 replay
- 事件总线不替代 `ESM` 做物理结算

## 5. 主消息分层

当前稳定分层为：

1. 原始 / 结构化世界事件
2. 候选感知事件
3. 角色感知事件
4. 司命高层消息
5. `ESM` 结果事件
6. 视觉事实事件

其中必须强调：

- 视觉事实事件来自视觉事实系统的语义输出
- 原始骨骼 `(x,y,z)` / 全 `AU` 高频流不进入业务事件总线

## 6. Phase 1 当前冻结边界

当前先冻结：

- 双总线边界
- 主消息分层
- 角色与司命的订阅差异
- 后端总线与本地表现总线的不同职责
- `L1` 非纯渲染前端定位
- 视觉事实系统接总线的位置

当前不冻结：

- 最终编码格式
- 具体 SDK
- 持久化 schema
- 完整世界级图谱
- Godot 本地完整执行细节

## 7. 一句话收束

事件总线体系的当前主口径不是“一个总线吃掉所有消息”，而是：

> 用后端权威叙事/事实总线守住世界事实与协议边界，用 Godot 本地表现总线守住高频具身执行与安全应用边界，再用一条明确的感知主链把 `L1` 事实转换成角色私有世界版本。
