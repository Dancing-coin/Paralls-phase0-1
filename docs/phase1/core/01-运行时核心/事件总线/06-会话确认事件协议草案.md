## 1. 文档定位

本文件只负责：

- 给出六件套确认事件的 core 摘要
- 明确三件套最小闭环与后三类支撑上下文的关系
- 明确最关键的 payload 语义与依赖边界

本文件不负责：

- 完整字段表
- API appendix 的生产者/消费者/校验规则全量细节
- 最终编码格式

## 2. 六件套目录

### 2.1 最小闭环

- `MembershipResolution`
- `AccessResolution`
- `KnowledgeResolution`

### 2.2 支撑与修正上下文

- `AwarenessResolution`
- `PrivacyRiskResolution`
- `ConversationBoundaryChange`

## 3. 三件套的职责

### 3.1 MembershipResolution

回答：

- 角色在当前会话中的社会身份是什么

最小 `payload` 语义至少包括：

- `conversation_id`
- `actor_id`
- `membership_role_state`
- `previous_membership_role_state`（如有）
- `membership_started_at`
- `last_state_changed_at`
- `join_path`
- `mutual_awareness_confirmed`
- `exclusion_signal_level`

### 3.2 AccessResolution

回答：

- 角色从何时开始真正接入、接入了多少

最小 `payload` 语义至少包括：

- `conversation_id`
- `actor_id`
- `information_item_id`（如有）
- `access_quality`
- `access_started_at`
- `access_modalities`
- `access_path`
- `bounded_by_private_context`

### 3.3 KnowledgeResolution

回答：

- 角色当前到底知道了什么

最小 `payload` 语义至少包括：

- `information_item_id`
- `actor_id`
- `knowledge_state`
- `knowledge_started_at`
- `knowledge_source`
- `derived_from_access_quality`
- `supersedes_previous_state`（如有）

## 4. 后三类支撑事件

### 4.1 AwarenessResolution

回答：

- 谁知道谁在场
- 谁知道别人知道自己在场

最小 `payload` 语义至少包括：

- `conversation_id`
- `subject_actor_id`
- `object_actor_id`
- `target_actor_id`（表达二阶知晓时）
- `awareness_level`
- `awareness_started_at`
- `derived_from_access_quality`
- `supports_membership_resolution`

硬边界：

- 必须能表达会话所需的二阶知晓目标
- 不得替代 `MembershipResolution`

### 4.2 PrivacyRiskResolution

回答：

- 当前这场会话对某角色而言是否正在变得更容易暴露

最小 `payload` 语义至少包括：

- `conversation_id`
- `actor_id`
- `exposure_risk`
- `risk_source`
- `risk_started_at`
- `bounded_by_private_context`

硬边界：

- 它只表示图谱侧风险判断
- 不等于角色本地主观 `privacy_pressure`

### 4.3 ConversationBoundaryChange

回答：

- 当前会话的开放边界是否发生了收紧或放宽

最小 `payload` 语义至少包括：

- `conversation_id`
- `previous_conversation_open_level`
- `conversation_open_level`
- `changed_at`
- `change_cause`
- `boundary_scope_snapshot`（如有）

硬边界：

- 它只表达传播边界变化
- 不等于成员资格变化

## 5. 依赖关系

当前必须保持：

- `AccessResolution` 不回答成员资格
- `MembershipResolution` 不回答具体知道了什么
- `KnowledgeResolution` 不得跳过 `AccessResolution`
- `AwarenessResolution` 依赖接入关系
- `MembershipResolution` 依赖接入与知晓
- `PrivacyRiskResolution` 依赖边界变化、接入变化与当前开放度

## 6. 一句话收束

六件套确认事件的正确关系不是“一个全知确认包”，而是：

> 先用三件套建立最小闭环，再用知晓、风险和边界变化三类上下文结果去支撑和修正这条闭环，而不重新压平它。
