## 1. 文档定位

本文件只负责：

- 定义事件总线公共信封字段
- 定义司命确认字段处在哪一层
- 明确哪些字段属于角色本地状态，不属于总线公共信封
- 明确哪些字段不应进入总线侧

本文件不负责：

- 六件套确认事件的完整 payload 说明
- 角色本地会话状态字段细表
- 最终编码格式与传输协议

## 2. 顶层公共信封

所有事件当前至少应包含：

- `event_id`
- `event_type`
- `producer_ts`
- `priority`
- `source`
- `routing`
- `payload`

## 3. Canonical 命名口径

当前 canonical 口径统一采用：

- `source.layer`
- `source.system`
- `source.actor_id`
- `source.object_id`（如有）
- `routing.audience_mode`
- `routing.routing_mode`
- `routing.dialog_group_id`（如有）
- `routing.target_ids`（如有）

当前不再采用平铺旧口径：

- `producer`
- `source_actor_id`
- `target_actor_ids`
- `world_ts`

统一改为：

- `producer_ts`

说明：

- 旧字段只保留为迁移背景，不再作为并列 canonical
- 后续所有新 schema、新契约、新 appendix 一律以本节为准

## 4. 公共信封字段表

以下字段属于跨模块运行时契约，应放在事件总线公共信封中：

- `event_id`
- `event_type`
- `room_id`
- `scene_id`
- `zone_id`
- `source.layer`
- `source.system`
- `source.actor_id`
- `source.object_id`（如有）
- `routing.audience_mode`
- `routing.routing_mode`
- `routing.dialog_group_id`（如有）
- `routing.target_ids`（如有）
- `priority`
- `ttl`
- `durability`
- `producer_ts`
- `causation_id`
- `correlation_id`
- `payload`

可选扩展：

- `sequence_domain`
- `dedupe_key`

这些字段回答的是：

- 这是什么事件
- 它来自哪里
- 它属于哪一局 / 哪一场景 / 哪一区域 / 哪一对话组
- 它应如何传播

## 5. 司命确认字段

以下字段不是原始世界事实，而是司命高阶知识图谱基于原始事实给出的确认结果。若需回写，应作为独立事件类型的 `payload` 出现，而不是反向污染原始事实事件：

- `conversation_id`
- `conversation_role_state`
- `knowledge_confirm_level`
- `join_transition_result`
- `exclusion_result`
- `rejoin_result`
- `conversation_open_level`（如需）
- `mutual_awareness_confirmed`（如需）

这层回答的是：

- 基于事实与高阶知识推理后，这个角色在当前会话中的社会语义位置是什么

## 6. 角色本地状态字段边界

以下内容不应作为总线公共信封共享，而应留在角色本地运行态或记忆系统中：

- `primary_conversation_id`
- `heard_from_ts`
- `member_from_ts`
- `privacy_pressure`
- `speech_entitlement`
- `attention_focus_in_conversation`
- `active_conversation_refs`
- 角色私有完整会话历史
- 角色主观怀疑值与内心独白

这些字段属于：

- 角色本地会话运行态
- 角色五类记忆沉淀

不属于：

- 公共信封
- 司命全局真值快照

## 7. 不应出现在总线侧的字段

以下内容不应出现在 `L1` 原始事实上抛或总线公共信封中：

- “某人已经成为正式会话成员”这类未经司命确认的高阶结论
- “A 知道 B 知道自己在场”这类高阶知识真值
- 角色主观怀疑值、压力解释结果、内心独白
- 全局高阶知识图谱快照
- 原始骨骼 `(x,y,z)` 高频流
- 全 `AU` 高频流
- 角色本地完整会话历史或整段对话文本回放

## 8. 一句话收束

本文件的核心原则是：

> 先分清“公共信封字段”“司命确认字段”“角色本地状态字段”三层，再讨论具体 schema；不要把角色主观状态或高阶知识真值偷偷塞回总线公共层。
