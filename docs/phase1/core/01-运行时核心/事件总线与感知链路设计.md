## 2. 统一定义

事件总线不是单一中间件名字，而是《开本》跨层消息体系的统一称呼。

当前统一口径是：

- 后端权威叙事/事实总线
- Godot 本地表现总线
- 一条从 `L1` 原始事实上抛到 `L2` 候选感知与角色私有感知的主感知链

一句话：

> 后端权威叙事/事实总线负责“世界里什么成立”，Godot 本地表现总线负责“本地如何安全而高频地把它表现出来”。

## 3. 四条总边界

### 3.1 与 `L1` 的边界

`L1` 是：

- 本地高频具身执行器
- 玩家输入终端
- 原始世界事实生产层

`L1` 不是：

- 角色认知宿主
- 世界真值解释层

### 3.2 与司命的边界

- 司命订阅更广的原始/结构化世界事件
- 司命回写高层消息与会话确认结果
- 司命不能借总线直接低层控角

### 3.3 与角色智能体的边界

- 角色默认不直接消费全局原始事实流
- 角色正式消费的是经过编译和 `Per-Character` 过滤后的角色私有感知事件
- 角色只回写对世界有意义且可重放的结构化行为结果

### 3.4 与 `ESM` 的边界

- `ESM` 决定环境和具身物理事实是否成立
- 事件总线负责把这些结果送往司命、角色、证据链与 replay
- 事件总线不替代 `ESM` 做物理结算

## 4. 当前统一结构

事件总线体系当前固定由两部分构成：

### 4.1 主干设计

1. 双总线总纲
2. 后端权威叙事与事实总线
3. Godot 本地表现总线
4. 感知链路与候选事件
5. 事件信封与字段分层
6. 会话确认事件协议
7. 视觉事实系统接入总线
8. 回放、审计与联调边界

### 4.2 关联专项

1. 视觉事实系统文档簇
2. 角色智能体与事件总线契约
3. 司命高阶知识图谱 `v0.1`
4. 会话确认事件 schema / API appendix / implementation ownership

## 7. 当前采用规则

后续任何文档提到事件总线时，应统一采用以下口径：

- 主架构是“后端权威叙事/事实总线 + Godot 本地表现总线”，不是单总线
- `L1` 是本地高频具身执行器，不是认知与世界真值宿主
- 原始骨骼 `(x,y,z)` / 全 `AU` 高频流不进入业务事件总线
- 视觉事实系统本体归属 `L1`，但服务于 `L2 / 司命 / 证据链 / replay`
- 角色默认不直接消费全局原始事实流，而是消费经过编译和 `Per-Character` 过滤后的角色私有感知事件
- 六件套会话确认事件已经进入当前 core 协议边界
- replay / audit 真源属于后端权威叙事/事实总线，而不是 Godot 本地表现总线
