# 完整版模拟预测底座文档约定

本目录是“通用模拟底座 + 金融场景适配方案”的独立整合稿，当前索引为 00–26 共 27 份编号设计文档。原目录中的文档仅作为历史参考；本目录不覆盖、不修改原文档。

## 文档约定

- 文件采用 `NN-中文主题.md` 命名，`00` 为入口，`20` 为贯通案例。
- 每份架构文档必须包含：目标与范围、关键合同、模块边界、现有/计划/后置状态、架构图、主交互时序图、数据流图、验收不变量。
- Mermaid 图中的状态标签：`现有可复用`、`计划建设`、`后置能力`。设计图不表示实现已经完成。
- 统一使用 `Entity`、`Observation`、`Event`、`State`、`Mechanism`、`Organization`、`DynamicCohort`、`Scenario`、`Branch`、`OwnerReceipt`、`PointInTime`、`FDE`、`Laya`、`Siming/司命`。
- 观测、假设、模型估计、模拟候选、owner 接纳事实、结果必须分开保存；新观测不能覆盖历史事实。
- 角色私有信息、权限过滤、owner 唯一事实写入、revision/receipt/replay 是硬边界。
- 接入外部模拟盘时，外部引擎负责其内部市场机制；底座负责 FDE 对齐、主体编排、结果接纳和回写。
- 金融案例中的未注明数字都是合成参数，不代表真实市场持仓、机构策略或预测效果。
- 文档只描述设计，不自动授权代码变更、现实交易或自动批准流程。
- 文件编号必须唯一，README 完整收录 00–26；显示标题可与历史文件名不同，不为统一标题批量重命名。
- 分开登记修订日期、合同版本、建设状态及验证证据；修订文档不自动提升实现、性能或预测成熟度。
- 主合同优先级按职责划分，见 README；21 负责共同合同映射，不能笼统覆盖各域合同及 WOG-R01/R02/R04 决议。冲突须显式登记版本与迁移。
- 文档校验入口为 `python scripts/verification/check_simulation_foundation_docs.py`；它检查静态结构，不证明 Mermaid 渲染、模拟运行、真实适配或性能。

## 状态标记

| 标记 | 含义 |
|---|---|
| 现有可复用 | 可复用项目已有后端/图谱/权限/回放设施，仍需由实现验收确认 |
| 计划建设 | 本套底座需要新增的协议、模块或领域适配 |
| 后置能力 | 在基础合同稳定后再建设的优化、物理孪生或高阶训练能力 |

## 通用记录最小合同

以[03-类型化数据与统一记录合同](03-类型化数据与统一记录合同.md)为唯一字段主合同。各篇可以给出业务载荷示意，但不能重定义一套不兼容的 Record。

记录必须能定位世界和分支、身份与 schema、载荷、事件及有效时间、来源与血缘、修订、口径、空间、适用域、权限、质量和不确定性。`available_at` 是按主体／渠道解析的 `AvailabilityRef`，不允许退化成全体同时可知的单一发布时间。状态写入须保留相应 owner 回执。

## 统一权限写入边界

```text
观察者/模型/角色 -> Proposal
Proposal -> 领域 owner 校验 -> OwnerReceipt
OwnerReceipt -> 世界真相层的新 revision
新 revision -> 派生图谱、回放、视图和结果
```
