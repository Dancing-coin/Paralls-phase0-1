# 角色表现资产自动应用流程

`character_presentation_bindings.json` 是 Godot 可读取的运行时绑定清单。
`MainDemo` 中的 `CharacterPresentationAssetResolver` 会在场景就绪后自动读取它，
只应用状态为 `approved` 的条目。

## 填写顺序

1. 将角色模型、服装、道具、动画和贴图放入
   `assets/artpacks/<资源包ID>/`，并完成 Godot 导入。
2. 为角色模型建立符合现有 role skin 契约的场景。至少需要支持
   `configure_role(actor_id)`、`set_state(state_name)` 和
   `set_motion_profile(state_name, profile_name)`。
3. 从 `character_presentation_bindings.example.json` 复制条目到
   `character_presentation_bindings.json`；`role_scene_ref` 必须是可加载的 `res://`
   PackedScene 路径。
4. 先保持 `binding_status: "candidate"`，完成模型、骨架、服装槽位、道具锚点和
   动作测试后，再改为 `approved`。
5. 启动场景。解析器按 `actor_id` 找到 `CharacterReplica` 并自动挂载 approved
   role scene。新资源加载失败时，原角色 skin 保持可用。

同一 `actor_id` 只能有一个 `approved` 条目；重复条目会被拒绝并保留第一个，
以避免同一角色在启动时被不确定地替换。

## JSON 条目示例

```json
{
  "actor_id": "char_a",
  "binding_status": "candidate",
  "visual_assets": {
    "artpack_id": "archive_attendant_v1",
    "role_asset_id": "role:archive_attendant:v1",
    "role_scene_ref": "res://scenes/artpacks/archive_attendant/ArchiveAttendantRoleSkin.tscn",
    "skeleton_profile_id": "skeleton:archive_attendant:humanoid_v1",
    "compatibility_level": "full_action_ready"
  },
  "wardrobe_assets": {
    "default_outfit_id": "outfit:archive_uniform:v1",
    "slots": []
  },
  "equipment_and_props": {
    "default_equipment_ids": [],
    "slot_bindings": []
  },
  "action_assets": {
    "supported_action_tags": ["speak", "inspect"],
    "animation_descriptors": []
  },
  "voice_assets": {
    "approved_tts_voice_binding_ref": "assets/tts/voice_bindings.json#char_a"
  }
}
```

服装、装备、道具和动作字段会原样交给 role skin 的可选
`apply_asset_binding(binding)` 方法。若 role skin 未实现该方法，解析器仍可挂载
角色模型，但不会假装已完成服装或装备挂载。

## TTS 自动应用

本 JSON 只处理 Godot 视觉表现。声线自动应用由后端的
`TTSVoiceProfileResolver` 完成：在 `assets/tts/` 或部署路径中添加 approved
音色 catalog/binding，开启 `TTS_VOICE_PROFILES_ENABLED=true`，并保证 provider、
model、语言和 catalog revision 一致。

原始声线参考音频仍放在受控存储；`voice_sources/` 只保留其授权清单。不得把
原始录音、签名 URL 或 API key 填进本 JSON。
